## Confirmed trace and contract

Contract/decomposition was recorded before coding in `I10-contract.md`. C07's missing ownership is confirmed in the actual C# trace: online RPC started `RefreshCatalogsInBackground` and retained no owner after the observer callback. The credential-requiring OpenRouter personalized overlay calls `RefreshKeyAsync`, then the runtime's `ResolveCatalogOAuthKeyAsync`, then `StoredOAuthLifecycle`. The latter already stops forwarding caller cancellation after mutation admission; `AuthJsonCredentialStore` awaits replacement and writes/flushes it without caller cancellation. The missing guarantee was the process-level join, not token mutation cancellation. **Consequence calibration:** ordinary remote overlays (including Anthropic) do not resolve OAuth, and the default OpenRouter flow refresh is identity. Built-in token-rotation loss is therefore not demonstrated; the regression explicitly admits a synthetic rotating OpenRouter flow through the existing runtime `OAuthFlows` hook. C12 is confirmed: `RequestPiShutdown` only set a flag consumed by input/run post-settlement callbacks, leaving an idle reader asleep forever.

## Changes

- PiCommand retains one online RPC catalogue task and joins it in `finally`, including EOF, first signal and stream acquisition failure. Existing 15-second cooperative refresh deadline and ignored catalogue errors remain. Once OAuth rotation starts, no extra exit deadline abandons persistence.
- Signal exit status is sampled after the catalogue join: EOF followed by a first SIGTERM while persistence is held still returns 143. The explicit EOF→input disposed→SIGTERM→release persistence regression covers this ordering.
- Profile shutdown forwards one synchronous intent immediately. RPC owns graceful idle admission: input attached, startup finished, no command responses pending, no running agent and no post-origin callbacks. Checks run on request/startup/command/run settlement outside extension execution contexts. The existing dispatcher owns and joins shutdown.
- RPC input readiness starts only after the actual reader activity begins, preventing startup shutdown from disposing an unstarted reader. Cancellation is checked before resuming a suspended reader.
- First signal remains graceful even after EOF/extension shutdown started. A repeated real signal forces exit with that signal's conventional status. Synthetic tests inject the force-exit action; they cannot terminate the test runner.
- Per-session Anthropic thread cleanup (API owned by I02) runs when a profile runtime attachment retires; it does not clear unrelated sessions.
