## Finding: P2 — complete Fable metadata is retained but Anthropic behavioral flags are not bound

The shipped direct `anthropic/claude-fable-5-2` model declares `compat.supportsStrictTools`, `compat.supportsMidConvoSystemMessages`, and `compat.supportsMidConvoToolChanges` true. Ordinary catalog/native routes leave all three `AnthropicMessagesRequestOptions` values at their false defaults. `src/PiSharp.AI/Protocols/AnthropicMessages/AnthropicCatalogCompatibility.cs:14-16` binds only temperature and message-thread metadata; `AnthropicMessagesSimpleRequestFactory.cs:125-133` adds thinking/adaptive/effort but does not bind these flags. CLI `LiveSessionSelection.AnthropicCompat` and Durable `NativeModelRoutes.AnthropicCompat` likewise bind effort/off/fallbacks without the three capabilities.

Concrete reproduction from the normal catalog selection: construct a Fable request with an initial system entry containing a tool and a later system entry changing the instruction and adding/removing/redefining a tool. The projector folds system entries instead of preserving them, and `AnthropicMessagesRequestProjector.cs:349` cannot enter native tool-change handling because both capability flags remain false. A constrained-sampling tool marked strict prefer similarly goes out without strict. The JSON equality tests pass because metadata survives storage; request behavior is the missing piece.

The broader established Anthropic fields `allowEmptySignature`, `supportsCacheControlOnTools`, and `supportsEagerToolInputStreaming` also have no metadata readers in the reviewed source. `supportsLongCacheRetention` is read for OpenAI paths but not the Anthropic path. Their defaults therefore also override applicable shipped true/false values on model selection. These are established fields, not newly invented 1.5.2 shapes.

Reported to root and catalog owner. Root assigned the shared Anthropic binding fix and focused request regressions to `/root/ai_discovery`. This report describes the pre-fix state; that worker's completed change and serialized test results must close the finding. Explicit model/user compatibility overrides must remain effective.

Follow-up source review: the owner's shared `AnthropicCatalogCompatibility.Apply` now binds the established flags and affinity defaults on direct/catalog/resolved/dynamic/Simple paths. Nullable explicit options distinguish an omitted value from an explicit false, and raw projector comparisons retain the prior defaults. The four `AnthropicCatalogBindingCases` groups inspect actual request behavior. No further concrete contract/precedence defect or obvious nullable use error was found in that source review; the finding is addressed in source, with build/runtime confirmation still owned by the validator.
