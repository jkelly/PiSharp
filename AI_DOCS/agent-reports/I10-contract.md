# I10 lifecycle contract (before implementation)

Scope: C07/C12. Verified against local code and upstream `rpc-mode.ts` / `model-runtime.ts` at `7d073328e44337d3292a7db9b0f0308f679c5e97`.

1. Catalogue work: `PiCommand` starts one background registry refresh for online RPC. A credential-requiring overlay resolves OAuth via `StoredOAuthLifecycle.ResolveAsync`; once its serialized mutation begins, caller cancellation no longer cancels rotation or the credential write. `AuthJsonCredentialStore.ModifyAsync` awaits the mutation, then writes and flushes without caller cancellation. The current discarded outer task allows process return before those guarantees finish. Retain that original task in the RPC branch and join it in `finally`, including EOF, signal, startup failure and throwing stream acquisition. Keep the existing 15-second cooperative catalogue timeout and ignored background errors; never impose a second wait timeout that abandons credential writes.
2. Extension shutdown: profile requests are synchronous intent, never an await of their own command. RPC owns a graceful-idle stop flag. Requesting it schedules a check outside extension execution context; actual shutdown requires attached input, finished startup, no pending commands, no active run, no active post-origin settlement, and completed native session-idle originals (including independent compaction). Recheck on startup/command/run settlement; retain and join a session-idle waiter when needed. Existing dispatcher shutdown remains the single owner of input cancellation, command/run drain and output disposal. Thus idle timers wake blocked reads, while command responses and run-settled records are flushed before shutdown.
3. Signals: first termination signal remains graceful across EOF/extension shutdown and joins all retained work. Only a repeated OS signal explicitly forces process exit; direct synthetic signals use an injected force-exit observer for deterministic tests. No second timeout silently truncates cleanup.
4. Validation packages: (a) fake OAuth rotation with a persistence barrier in a real registry refresh under EOF/first signal; (b) real Node extension idle/startup/command/run shutdown, output order, and repeated intent; (c) signal policy and exception-path ownership. All tests use the serialized GapValidation helper and synthetic credentials. Runtime cleanup of Anthropic session thread state coordinates with I02; its store remains I02-owned.

Runtime validation correction: only `PersonalizedCatalogOverlay` (OpenRouter) currently requires a credential. Ordinary remote overlays, including Anthropic, do not resolve OAuth for catalogue refresh. The default OpenRouter OAuth refresh returns the current credential unchanged. The rotating regression therefore uses the existing runtime `OAuthFlows` admission for a synthetic rotating OpenRouter flow. This proves the ownership/persistence invariant through the real registry path; it does not establish built-in Anthropic/OpenRouter token-rotation loss.
