## Architecture and ownership

`Legacy/Cluster/Contracts.cs` freezes `ILegacyReloadHost` and `ILegacyPreparedReload` with LG2. LG2 owns actual object activation, candidate staging, roots, resource retention and retirement. LG1 owns protocol 4 negotiation, transport codecs, holds, state streams, calls and relays. LG3 supplies cluster membership/discovery/coordination and process ownership; it does not reinterpret protocol 2 as legacy behavior.

The cluster coordinator snapshots synced host participants, retires prior code before prepare, registers vote deadlines before sending, waits for unanimous prepare, installs parent code and sends every child commit before new-code callbacks can run, and aborts/rolls back failures. Client peers are excluded. Child operations are registered before loading, cancelled on abort or parent loss, and cannot commit after cancellation. Catch-up reloads real child modules; it never relabels old code. Late hellos wait until the running reload ends; behind children are fenced. Longest host-prefix mappings and removed-module tombstones survive catch-up. Retirement watermarks are sent before catch-up prepare.

`LegacyNetwork` routes by configured child identity, handles replacement parent links without an old close clearing the new parent, checks route authority before and after asynchronous discovery, and admits spawned links even when the requesting operation expired. Discovery belongs to the host; cancellation of one reference cannot orphan a newly spawned host. LG1 uses `ResolveRelayAsync` so direct-child lookup cannot bypass route authorization for relayed requests.

`LegacyBindingRetention<TKey,T>` implements refcounted remote-binding sharing with hydrated-only idle retention, bounded LRU eviction, idle timers, cancelled timers on reacquisition, idempotent release and close. Released lease objects clear both binding and owner references. LG2 wired the equivalent policy directly into its actual object-owned remote lifetime, since a separate generic binding pool would duplicate that ownership. Its runtime also owns root/reference CTS disposal and removal of disposed objects. The standalone suite tests both the reusable pool and the actual remote host policy, including reconnect with `again:true`.

`LegacyHostManager` serializes start/stop/replace, admits only ready children, retains one process, handles fatal/timeout/exit, tracks busy-to-idle transition, stops through keep-alive policy, and waits for process exit before replacement. Reporting callbacks cannot poison the ownership queue.

## Deliberate native mappings

* `LegacyProcessDriver` is a native .NET driver. It preserves legacy `chord2` and `chord2control` JSON envelopes over a private user-only named pipe with explicit little-endian length/UTF-8 framing. This framing is **not Node's child_process IPC**. LG1 separately exposes its actual Node IPC-channel adapter interface.
* The child acquires `CHORD2_LOCK` before data access. A Windows first-instance named-pipe handle or Linux/Android abstract Unix socket supplies the kernel lifetime lock with the baseline SHA-256 name; the driver deletes inherited lock configuration before applying the child's explicit lock. Closing/crashing releases the handle without stale-lock takeover races. Other systems use an exclusive file handle whose inode remains stable; that native fallback does not interoperate with Node's pathname-socket lock.
* Process-tree ownership now reuses `PiSharp.Tools.Processes.OwnedChildProcess`: suspended admission into a private Windows Job Object and retained Unix process-group admission, with original output readers and stop tasks joined before reporting exit. This replaces the first implementation's post-start Job Object assignment, whose startup race was identified during review. Chord now explicitly references PiSharp.Tools, bringing its native process lifetime implementation and transitive Agent/AI dependencies; the older Contracts/Telemetry-only package claim is historical. Unix runtime qualification remains delegated to centralized validation.
* `LegacyFacetAssemblyLoader` loads explicit native assemblies implementing `ILegacyFacetModule`, registers all resolution roots before evaluation, shares the Chord/Contracts/Telemetry ABI from the default load context, deduplicates normalized file paths per generation, and releases collectible load contexts after physical kernel retirement. `ILegacyFacetLifetimeHost` also checks installed facet identity: unrelated reloads cannot unload an unchanged module that still serves in a newer version. Bound disposal releases logical facet handles but defers actual unload until physical retirement, including when host close returned at its timeout while a resource still drains. Normal host close retires its current generation after drain. This is the .NET legacy-module mapping, not a TypeScript source evaluator.
