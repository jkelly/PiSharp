# R4 — native exec combined capture

Implementation: `SeparatedProcessCapture.cs`, `NativeProcessRunner.cs`, `Unix/UnixProcessRunner.cs`. Focused tests: `NativeProcessRunnerTests.cs`, `UnixProcessRunnerTests.cs`.

An explicit `ProcessRequest.CaptureLimitBytes` now replaces the ordinary per-pipe retention limit. Both stdout and stderr share the requested byte budget. The buffers allocate on arriving output, not from the requested maximum. Exactly reaching the budget is allowed; the next nonempty bytes signal overflow. Incomplete terminal UTF-8 bytes are dropped only after overflow, preserving normal EOF replacement semantics.

Both process pumps continue their existing stop/drain/join sequence. They forward only the admitted prefix to the separate raw-output accumulator; discarded bytes cannot create a second output-limit error. Its raw-byte ceiling grows to the explicit budget, so its ordinary 64 MiB ceiling cannot override a 256 MiB exec budget. The model/structured output bounds and behavior of requests without an explicit capture budget remain unchanged. Values above the native exec runtime bound (0x3FFFFFDF bytes) are refused before launch.

Regression coverage includes concurrent captures exceeding 1 MiB on each pipe; exact and over-limit combined boundaries; split UTF-8; UTF-8 overflow trimming; zero-byte limit; ordinary independent per-pipe bounds; invalid budgets; real Windows stdout/stderr/both above 1 MiB using a deliberately smaller raw ceiling; overflow with confirmed process cleanup; explicit-capture cancellation; and a simulated admitted Unix lease proving large/exact/overflow behavior and joined cleanup.

Validation is pending the shared serialized validation queue. No real Unix/macOS process was run; Unix tests use admitted fake leases. No credentials, paid APIs, or commits.
