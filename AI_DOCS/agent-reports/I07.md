## Implemented behavior

- EditPlan maps normalized line boundaries back to the original UTF-8 text. It copies all decoded text outside replacement spans verbatim, including BOM, CRLF, lone CR, LF, trailing whitespace, and compatibility glyphs. Fuzzy matches map Unicode text elements to original spans and retain exact submatches when another edit requires a fuzzy basis. Diff NewContent is computed from the actual preserved result. Existing diff-before-write, mutation queue, atomic edit write and cancellation paths remain unchanged.
- PiGrepTool consumes rg JSON match/context events instead of rereading matched files. This uses rg's UTF-16 decoding, merges overlapping context naturally, preserves lone CR content, and caps retained result text near the 50 KiB output budget. It continues counting without storing discarded output. Directory searches run with cwd=searchPath and target '.', including symlink roots; leading './' glob prefixes (also negated prefixes) are stripped. Authorization of displayed file text remains explicit.
- Grep stops only after proof of an additional match, retaining the last accepted match's trailing context. Find requests limit+1 and emits at most limit. Find/grep/ls normalize finite limits to floor(value), minimum one; internal integer limits saturate below Int32.MaxValue to permit lookahead. Exact counts do not claim truncation; ls verifies a usable extra entry after stat failures. Shared UnicodeText.SliceHead prevents split-surrogate grep snippets at the 500 UTF-16 unit boundary.
- PiSearchProcess caps each serialized stdout line at 4 Mi UTF-16 units and retained stderr at 64 Ki characters. Overlong records fail explicitly; process stop, exit, stderr drain, and cancellation are joined. This also bounds malicious/oversized rg records rather than moving the old file-read allocation into JSON line buffering.
- Optional IStreamingFileOperations.OpenReadAsync returns an owned readable/seekable stream. LocalFileOperations implements it. Large text input uses two bounded-buffer passes: count lines, then collect a bounded selected range. Output follows existing offset/limit, 2000-line/50 KiB, continuation and BOM behavior. Images retain MaximumReadBytes; legacy adapters keep the existing bounded ReadAsync call, including checking oversized returned buffers. No requirement to implement the new interface is imposed on existing hosts.

## Resource and platform boundaries

Large text reads scan for total-line continuation metadata, so memory is bounded but work remains proportional to file length. The streaming adapter currently requires seekability; non-streaming/custom hosts retain bounded legacy behavior. Read and edit malformed-byte decoding remains the existing UTF-8 replacement policy (this task does not change that historical contract); UTF-16 grep decoding is rg's responsibility. Int32 metadata counters saturate for byte totals beyond 2 GiB. Concurrent file changes between the counting and selection passes do not provide snapshot isolation. Symlink creation requires platform support; tests report a skip explicitly when unavailable. No live endpoints, global settings, commits, or publication were used.
