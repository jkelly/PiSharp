## API and integration

- `PiSharp.Env.RemoteExecutionEnv(RemoteExecutionEnvOptions)` implements the existing `PiSharp.Durable.Env.IExecutionEnv`. Options carry caller-owned `Connection`, filesystem `Id`, `Cwd`, optional shell path/environment and `RemoteWatchOptions`.
- No existing Durable interface signatures changed. The Env project references Durable explicitly and suppresses its opted-in experimental diagnostics.
- Native protocol-1 operation names and JSON/payload layout follow pinned `upstream-v150/packages/env/docs/protocol.md` / `remote-env.ts` at `7d073328e44337d3292a7db9b0f0308f679c5e97`. Filesystem results preserve the existing error and metadata shapes.
- `RemotePaths` interprets POSIX and Windows paths using remote hello metadata, including `~`, file URLs, UNC roots, drive-relative paths and remote per-drive working directories. It never calls local `Path.GetFullPath` for remote paths.
- Whole-file and positional reading, UTF-8 text-line reading with BOM handling, scans, directory readers, byte-sorted POSIX `ListDir`, `listFiles` feature negotiation/limits, writes/appends/truncation/fsync/rename, temporary paths, and watcher creation are implemented through actual wire requests.
- Typed remote handles carry the opening session on every read/write/close. Old handle operations cannot reconnect and accidentally address a reused numeric handle. Close is idempotent and never restarts a dead session.
- Binary reads request at most 256 KiB; whole-file reads at most 512 KiB; line reads at most 64 KiB; writes at most 512 KiB. Positional reads and chunked writes use at most eight in-flight requests, draining them before close/error and restarting short positional reads from their actual end. Return values that explicitly represent a whole file/list naturally retain that result in memory.
- Text-line reads commit read position and decoder state only after checking cancellation. Mutation requests are not replayed; once a short mutation is dispatched it is allowed to settle, matching upstream cancellation semantics. Chunked replacement checks cancellation between writes; append finishes dispatched chunks before reporting cancellation.
- `RemoteShell.cs` maps argv/script, environment inheritance, timeout, output-window/omission metadata, spill configuration/path, callback errors and per-command cancellation. The selected current-upstream timeout fix covers connection startup and path resolution as well as the daemon command; first-cause tracking preserves caller abort versus timeout and callback-error precedence. Environment cleanup kills only its own tracked requests, closes its handles and stops its watches; it does not dispose the shared connection.
- E04 owns `RemoteWatcher` and `RemoteWatchOptions`, consumed through `OpenAsync(Connection, targets, callback, options, cancellationToken)`. E05 owns low-level `RemoteProcess` / daemon processes; E06 owns PTY. No duplicate process or PTY implementation is introduced here.
