# Final bounded Anthropic JSON read/write audit

Scope: every `.Name`, `GetString`, `GetProperty`/`TryGetProperty`, `JsonNode.Parse`, `ToJsonString`, `JsonSerializer.Serialize`, `WriteString` and `WriteTo` occurrence under `src/PiSharp.AI/Protocols/AnthropicMessages`, plus the narrowly authorized shared source-event validation comparison below. Current test/build ownership is I13. The separately confirmed shared public wire-reader metadata roundtrip gap is assigned to `review_core_changes`; its reader changes are outside I02 ownership.

## Generic paths corrected

* DTO and HTTP walkers decode arbitrary names/values with `JsonUtf16` after strict syntax, decoded-duplicate and depth admission. Protocol known-field lookups use a native fast path plus object-only enumeration fallback: native System.Text.Json can fail while searching past an unrelated surrogate-named field. Missing fields, wrong kinds, bad numbers/enums and duplicate owned DTOs remain errors.
* Direct/prepared key and authenticated body paths preserve nested and arbitrary root hook names/values. Root-body byte counting and the rare UTF16 root encoder use matching quoted-name representations; normal roots retain their prior encoder. Prepared max tokens, numeric, root shape, beta-header ASCII and payload/depth limits remain.
* Thread mutable payloads, replay prefixes and hashes use `MutableNode`/`ToJsonString`. Historical keys remain distinct from U+FFFD, and reply replay uses effective authentication-selected projection options. Known response IDs and thread error code reads retain UTF16 code units.
* Optional source snapshots use `MutableNode` and UTF16-safe writing when replacing cost or omitting the native-only error classification. `JavaScriptEncoder.Default` is explicit, matching the former default writer for valid strings; only malformed UTF16 needs the existing raw-escape path. The native emitted frames are unchanged.
* Provider input-transformation diagnostics may contain arbitrary JSON in `type/path/reason`; copying those values, appending earlier diagnostics and writing the final diagnostic now preserve names/values through the same helpers. Strict/thread fallback error messages use `StringNode` and the default encoder. HTTP hook failures can carry provider error strings, so they use conditional `StringData` too.
* `StringData` retains the original JsonSerializer spelling for well-formed values (including `s\u002B`) and uses `JsonUtf16.Quote` only for lone surrogates. Exact response-ID tests cover the rare case without changing valid-string lexical expectations.
* Simple context estimation reads arbitrary text/thinking/section values and tool names through `JsonUtf16.GetString`; it still counts UTF16 units and uses the same budget formula. Metadata lookup uses the safe property helper while existing model identity/effort validation remains.
* Actual new capture coverage exposed native `JsonNode.DeepEquals` rejecting write-only surrogate-argument nodes during shared source-event validation, before provider snapshot rewriting. The parent authorized `PiWireJson.SourceEvents` comparisons to use existing `Own` plus `JsonUtf16.DeepEquals`, with direct typed string guards to retain exact identity/content mismatch rejection. Signature comparisons use direct owned JSON values. No emitted writer was changed. Controls reject mismatched surrogate values, numeric content, array order, unpaired-versus-U+FFFD identities/text/thinking and unequal signatures, while accepting equal surrogate signatures. The new capture trace uses a fixed injected clock for its separate native/captured runs so exact diagnostic parity is deterministic.

## Remaining ordinary calls and why they stay

* `OriginalAnthropicUsageCostProjection` and the native binary64 cost construction serialize only numbers. Temperature and argument-number `JsonNode.Parse` receive validated generated numeric text. No arbitrary name/string passes through them.
* HTTP header-name/value reads, beta arrays, service tier fields, thinking effort, role/block type and stop-reason identifiers are known ASCII/enum/identity validation surfaces. Their strict checks remain; arbitrary JSON body fields are handled separately.
* Request-projector `ToJsonString` comparisons in strict-schema/type/null/additionalProperties predicates only compare validation representations with fixed literals; they do not publish generic JSON. The request emission itself already uses `JsonUtf16.ToJsonString` with its established relaxed encoder. Root schema composition restrictions remain unchanged.
* `WriteString` for tier fields and the tier byte counter handle the mapped protocol option fields. Generic root property names use the rare UTF16-safe branch. All payloads still pass the final exact byte bound.

## Controls

Dedicated Threads tests cover direct/prepared parity with surrogate key **and** value, echo-hook copying, arbitrary root hook names/values, historical create/continue and U+FFFD mutation, exact response IDs, known-field/duplicate/budget no-send refusals, and a simple text-codeunit estimate. Compatibility covers positive unknown-name pings, missing/wrong known fields, bad enum/number, decoded duplicates and actual captured initial/preview/terminal frames. The captured test checks both success and EOF failure, immutable historical frames, native content equality, committed cost equality and arbitrary transformation diagnostic key/value preservation. HTTP tests run the actual executor on a valid key and prove a later strict JSON failure grants no authority.
