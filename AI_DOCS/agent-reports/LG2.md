The actual cluster suite's remaining post-commit deadlock is traced to LG1's synchronous shape callback; its correction rerun is pending.

D14 explicitly requires protocol 4 and a separate legacy kernel. Namespace: `PiSharp.Chord.Legacy`.

## Implementation

- `Legacy/Contracts.cs`: distinct immutable legacy description, sorted canonical JSON, UTF-16 two-lane hash, placement, native opaque identity, structural coverage and version adapters. These do not reuse next's normal form or contract type.
- `Legacy/Errors.cs`: public `ChordException(code,message,reason,details,cause)` with the legacy retryable codes, shared with LG1/LG3.
- `Legacy/Runtime/Schema.cs`: pi-schema compiled validation, default/clean/identity rules and conservative coverage matching the source algorithm. Native local method calls admit delegate values explicitly through `CallNativeAsync`.
- `Runtime/{Contracts,Context,State,Object,Reference,Host}.cs`: name-bound C# declarations, cells and synchronous derivations, host/ref lifetimes, eager host objects, resource dependency/open/reverse-close handling, async state initialization, declarations sealed after factory return, native exposures/listeners/tasks, principal identity, root references/cancellation/expiry, registries and immutable generation tables. Host transitions use the existing implementation-neutral FIFO dispatcher; asynchronous effects release the queue.
- `Runtime/Reload.cs`: prepare/commit/rollback boundary, candidate declaration and dry validation, retained cells and native resources, state version migration, exclusive-resource gate/rollback, uses/consumer compatibility, previous generation retirement, parent retirement watermark and bounded forced retirement. The public prepared-reload interface is LG3's actual cluster seam.
- `Runtime/Retirement.cs`: callable retirement is separate from physical cleanup. Root, invocation, activation and disposal work retain the old generation until settled; removed resources finish closing before `Retired` or the public retirement watermark advances. Notifications remain ordered when a later cleanup finishes first. Host close also retires its current generation, waits up to its configured deadline and reports pending cleanup without unloading it early. A subsequent reload has a bounded `upgrade_conflict/retirement_cleanup` failure if prior cleanup still owns code.
- `Runtime/Network.cs`: real LG1 `LegacyPeerSession` provider/consumer integration and LG3 network/cluster coordination. Runtime gets, methods, state and cancellation use protocol 4; hosted roots carry root ids/code versions and remain retained until root_end. Reconnect re-holds existing references with `again`; remote idle lifetime uses a hydrated-only LRU/TTL (default capacity 4). Principal invalidation reaches objects, sessions and downstream hosts, with restamping delegated to the network.

## Validation

Added 17 `legacy.runtime.*` native cases in `tests/PiSharp.Chord.Tests/Legacy/RuntimeCases.cs`: description/default identity, coverage/opaque, actual local method+state+native resources, invalid arguments/expired context, native delegate method, host lifetime and registry, normalized addressing, dependency order/cycles, state/code retention across reload, prepare failure rollback, new eager-object preparation/rollback, old root code retention, atomic derived validation, late resource cancellation, an actual two-host protocol-4 method/state exchange, a held old resource close with ordered/bounded late retirement, and six reloads with weak sentinels captured by a kept resource, state listener, task, registry and cancellation registrations.

LG1 owns independent wire/codec captures and protocol/session tests. LG3 additionally authored actual host cluster reload, collectible-module lifetime, remote LRU/reacquisition, and reconnect tests. I13 owns serialized SDK execution; no private build or test process was started by LG2.

I13's `Chord-legacy-runtime2-ddf7ba011f3e49c58bcdb0d0d4d58cd5` run executed 31 combined legacy cases with 3 failures: 2 LG1 failures and the LG2 native delegate case. The 14 other LG2 cases passed in that run. The callable bug arose because pi-schema's compiled type table supports JSON types and bytes, while `JsFunction` is value-model metadata, not an accepted `type:function`. `AssertNative` now explicitly requires a CLR delegate for the local callable type and compiles the remaining schema constraints without that type keyword; non-callable schemas remain strict. The existing case also checks callable results, invalid function results, no delegate invocation during validation, delegate identity and retained non-type constraints.

The loader review subsequently found that the original `RetireGeneration` scheduled old native closes and emitted `Retired` immediately. That could request collectible ALC unloading before a still-running old close first-loaded a private dependency. Retirement now owns and drains those operations before signaling. LG3 owns the actual ALC/private-dependency regression and deferred bound-loader disposal; the two new native runtime cases check the public lifetime and retained-capture behavior separately.

`Chord-full-stable8-4485082fbe664d08ba6e4a384065d679` built successfully and executed 875 groups: every LG2 runtime group passed, with one unrelated structural allowlist failure reported to its owner. `LG3-cluster-stable8-7f025351ab26428681564b0ed93e8906` built successfully and passed 24/25 groups, including the actual ALC, held close/private-dependency, unchanged-facet, LRU, reconnect, and all manager cases. Its sole remaining failure was the post-reload retained-reference call. LG2 and LG3 traced the exact lock cycle: child connection processes `commit` and waits for host commit; host publication calls the provider's shape listener; that listener synchronously dispatches back to the waiting connection. LG1 is changing that callback to an ordered nonblocking post. Both stable8 receipts have `changedDuringRun: true`; their passing observations are recorded without claiming final immutable-snapshot qualification.

## Explicit mapping and review boundaries

TypeScript mapped properties are expressed as `Member(name)`, `Native(name)`, `CallAsync` and local-only `CallNativeAsync`; native values are not falsely serialized through protocol 4. C# declaration/schema snapshots are immutable copies. Local runtime schema checks are stricter than TypeScript's compile-time-only local method signatures; callers using native function values have the explicit native method delegate/call pair.

Remaining acceptance work is the final centralized stable rerun, including the corrected actual cluster call.
