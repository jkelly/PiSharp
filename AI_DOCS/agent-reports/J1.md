## Implemented

- `src/PiSharp.Chord/Jobs`: `JobDefinition.Define`, checked closed JSON argument/result schemas, singleton state policy, persistence policy, older-version adapters, exact hash64 argument/result/state normal-form fingerprint.
- `IJobHandle`, `IJobRun`, `JobImplementation`, `JobContext` (composes `CallContext`), `RunState`, `StartOptions`, `AbortResult`, outcomes/errors, and `ISelf.Job` extension. Transient results remain CLR objects, including bytes; persisted result records are JSON.
- Intent admission checks arguments before same-transaction dedupe and concurrency. `ITx.Start` joins existing `Stage`/`Staged` hooks and returns the run before commit; discarded starts reject their handles and execute nothing. Finishes exclude their own run from dedupe/concurrency, permitting atomic same-key successors.
- Run invocation is admitted to the host drain before executing plugin code. Persisted runs reserve `running` durably before effects. Invocation state fences close at settlement; explicit abort can still flush final state until then. Outcome publication and finish are separate object transactions.
- Finish retries use the host time provider and attempt cancellation; five failures block a run. Explicit abort drops blocked records without another finish. `Running` is a JSON source with precise entry/state-path delta operations and immutable published snapshots.
- Object-owned records survive attempt/reload handover. Matching versions or explicit older-version adapters resume; incompatible versions/fingerprints block. Missing job declarations block waiting work until a later declaration. Rerun/abandon, stopped-vs-interrupted distinction, five-interruption limit, progress restart-counter reset, deferred state deadlines, outcome flush, close writer, and state migration use existing Documents/Persistence/Store primitives.
- Persisted records use namespace `chord.jobs`, state namespace `chord.job-states`, header `{version:1,fingerprint:"chord.job-run.1"}`, original conditional field omission and wire error shape. Namespace claims remain owned by the Chord object and released by the host after close.

## Integration handoff (implemented with H1/H2)

- H1 owns `IJobOwner`/`IHostedJob`, `Self.DeclareJob(name, factory)`, load/live/seal/handover/close drain calls and `CountRuns` object keepalive. J1 delegates through those seams and host `Dispatcher`; no semaphore is held across asynchronous effects.
- `HostedJob.Reconcile(documents, names)` is called at activation so a removed declaration blocks retained records. `HostedJob.Check(documents, definition)` is read-only for recording factories.
- H2 `RecordingSelf` implements J1's internal `IJobDeclarer`; recording job handles admit no work. `JobExtensions.Job` detects that hook before real `Self`. H2 preserves eligible old job invocations through an in-place swap and owns old-attempt retirement.
- Only `src/PiSharp.Chord/Documents/Transaction.cs` changed outside Jobs: `ITx.Start` and its concrete routing. `PiSharp.Durable.ITx` remains I17-owned.
