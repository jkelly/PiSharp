## F09 schema applicability and public contracts

- `JsonSchemaValidator.Validate(JsonNode?)` returns `JsonSchemaValidationResult<JsonNode>`. It checks without coercion, defaults, property removal or mutation. `Ok` distinguishes a successful JSON null from failure; success returns the exact original node, failure returns default plus errors. This also applies to coercing validators; existing `Parse` remains the conversion entry point.
- `JsonSchemaValidator.Equal(JsonNode?, JsonNode?)` exposes the existing engine equality rules: object key order ignored, array order significant, numbers compared using the engine's IEEE 754 double model.
- `JsonSchemaBuilder.Recursive` produces a portable JSON Schema resource; a generic overload associates it with a CLR type. The callback receives a fragment self-reference (`#`), so directory-bearing relative IDs resolve correctly. Fragment-bearing resource IDs are explicitly rejected. Supplied callback output is cloned.
- `JsonSchemaBuilder.Unsafe<T>` creates a snapshotted `JsonSchemaDefinition<T>` without claiming the JSON schema and CLR type are proven equivalent. `ToJsonSchema` returns a defensive copy. `Compile` produces `TypedJsonSchemaValidator<T>` with Check/Errors/Validate, serializing through caller-supplied `JsonSerializerOptions`. Strict validation returns the original CLR value on success. Serialization failures propagate; typed validation never deserializes or coerces into T. Caller naming/converter choices must match the schema.

Intentional applicability decisions:

- TypeScript `Static`, schema brands, optional marker types and TypeBox's compile-time kind inference have no direct CLR reflection-free counterpart. They are not represented as fake inferred C# types. The explicit generic association plus actual serialization/validation supplies the useful native contract.
- Raw JSON schema construction is already supported through `JsonObject`/`JsonArray` and Compile. TypeScript primitive/object/union builder shorthand does not add runtime capability and is not reproduced as a parallel factory API in this patch.
- JavaScript `undefined`, BigInt and Uint8Array builder exports describe non-JSON runtime values. No new public JsonNode API attempts to encode them as JSON or confuses BigInt with C# integer precision. Existing engine compatibility behavior is retained.
- Model/provider catalogue aspects of F09 belong to the catalogue/provider work packages, not this schema ownership.

All new public API types retain the existing experimental `PISHARP_SCHEMA001` designation. No public signature is removed; the internal annotation helper gains its base argument.
