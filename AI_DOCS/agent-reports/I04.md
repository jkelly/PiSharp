## Public contract and precedence

All additions are body-init properties, preserving positional constructor/deconstruction signatures:

- `CompletionsKeyAuthRequestOptions.RequiresToolsWithToolHistory: bool?`: explicit value, then model `compat.requiresToolsWithToolHistory`, then false. No active tools omits `tools` by default even with history; true sends `tools: []` only when history contains tool calls/results. Nonempty tools are unaffected.
- `CompletionsTranscriptProjectionOptions.RequiresNonNullAssistantContent: bool?`: explicit value, then model `compat.requiresNonNullAssistantContent`, then false. Textless replayed assistant messages use empty string when enabled. This does not insert a synthetic assistant; the existing `RequiresAssistantAfterToolResult` behavior remains independent and still implies nonnull content.
- `CompletionsKeyAuthRequestOptions.PromptCacheKeyMode`, `ResponsesKeyAuthRequestOptions.PromptCacheKeyMode`, `AzureResponsesOptions.PromptCacheKeyMode`: nullable string restricted to `auto`, `enabled`, `disabled`. Explicit mode wins over model compatibility; null inherits metadata then auto. Existing model-authoritative behavior for older compatibility options remains unchanged.
- Completions auto sends cache key on the OpenAI endpoint or supported long retention. Enabled sends with active caching even on a compatible proxy; disabled omits the generated field. Responses auto/enabled retain existing active-cache behavior, disabled omits the generated key. Azure auto/enabled preserve its existing session-key behavior; disabled omits it. Cache retention and affinity headers are independent from key suppression. Existing model/level/request sampling merge remains last and can explicitly replace named fields.
- Simple transports preserve these settings through their existing `DirectOptions` and model metadata. Native Responses direct, catalogue and alternate provider bindings all share the updated metadata binder. Request-scoped session/thinking factory cloning retains the new fields.
- Responses generated affinity uses `session-id`; Completions keeps `session_id`; Azure behavior is unchanged. Existing caller header override/deletion precedence remains.
- Both retry classifiers recognize only the specific substring `cut short after the reply had begun`, with existing permanent/quota exclusions evaluated first.
- CodingAgent model JSON schema accepts the three new compatibility fields, preserving the public models configuration route.
