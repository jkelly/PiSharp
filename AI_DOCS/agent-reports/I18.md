The implementation follows frozen upstream `7d073328e44337d3292a7db9b0f0308f679c5e97` `packages/durable/src/storage/sqlite/{commit,statements}.ts`. One transaction prefetches affected global IDs, document records, latest revision versions and live addresses in bounded JSON-array queries. Sequential shared `StorageRules` checks observe transient state advanced only after acceptance. The accepted net effect accumulates by table; pending writes flush before copy reads and before metadata/COMMIT. No public API, package, SQL schema or version change.

Small rows use one fixed INSERT SELECT/json_each SQL shape per table and chunks of at most 512 Ki characters. Rows containing more than 8 Ki characters of string cells use bound VALUES with power-of-two row counts and at most 100 parameters. Task/submission replacement retains the last accepted value; document revision retention follows existing current-only base/retirement rules. Existing lossless encoded identity strings remain encoded within the outer JSON arrays.

All prefetch/decoding failures occur outside semantic-refusal handling and reject the transaction. Copy materialization retains I12 watched decoding, so semantic copy refusal preserves the valid prefix but corrupt persisted sources reject everything. Decode-before-check means corruption in any requested affected persisted row rejects the call even when an earlier semantic refusal would otherwise stop iteration, consistent with upstream prefetch and the storage-error contract.

This is a **single latency-injection sample per variant**, not a raw SQLite throughput benchmark: the wrapper awaits `Task.Delay(1)` before every SQL executor call while the transaction is held. Actual Windows scheduling makes those waits longer than one millisecond; the baseline's ~12 seconds illustrates cumulative round-trip waiting. The 770-to-5 call reduction is directly counted; the wall-time difference reflects this artificial delay and cannot support a general 153x SQLite performance claim. Counts include metadata/check/write operations within the transaction callback but exclude the driver's BEGIN/COMMIT calls. Initial root creation is excluded from timed wall time and Calls, but MaxParameters was not reset after warmup, so the reported candidate maximum 2 is not a statement that its measured commit needed two bindings. Both variants assert 256 stored batches; the candidate additionally enforces <=8 executor calls.
