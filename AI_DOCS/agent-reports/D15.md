## Decision and existing foundation

Implement the native C# daemon and C# client for Windows, Linux and macOS, with an explicit shared protocol. Use a tiny native Unix PTY spawn shim; never execute managed child setup after `fork`. Android is a separate distribution gate: the existing platform layer hardcodes `/bin/sh` and only admits Linux/macOS/Windows, so it cannot substantiate Termux support. An explicitly verified upstream daemon backend can cover Android while native support is developed. Do not mark Android supported merely because a remote path or RID string exists. No binary hashes or package availability have been fabricated.

Native core is justified by these existing implementations:

- `src/PiSharp.Durable/Env/{FileSystem,Shell}.cs`: complete `IExecutionEnv`, positional/file/line/directory readers, optional bounded `ListFilesAsync`, typed errors, output windows and skips, and tagged `FileChange` / `IFileWatcher.StopAsync`.
- `src/PiSharp.Durable/Env/Local`: local file operations, line scanning, gitignore-aware listing, native/polling watches, native file identity and symlink handling.
- `src/PiSharp.Durable.Tools/Env/LocalExecutionEnv.cs`: shell resolution, exact environment precedence, spill files, callback errors, timeout/cancellation and process cleanup.
- `src/PiSharp.Tools/Processes/WindowsProcessLifetime.cs`: suspended process launch, restricted handle inheritance, private non-breakaway kill-on-close job, asynchronous pipes.
- `src/PiSharp.Tools/Processes/Unix/PosixSpawnProcessAdmission.cs`: atomically admitted process groups and pipe ownership, including an anchor preventing premature process-group identity reuse.
- `src/PiSharp.Durable/Testing/EnvConformance.cs`: reusable runner-independent conformance tests.

The local `LocalProcess` wrapper is insufficient for protocol processes: it exposes output and exit, but hides the underlying PID and does not keep stdin open. The underlying Unix lease does expose PID. Add an explicit interactive-input lease path; do not alter the existing `ProcessRequest.StandardInput` contract (bytes then EOF). Existing callers must retain their shutdown guarantees.

The existing Windows ConPTY code is a console-test fixture, not a reusable Unix daemon terminal. Windows `pty` returning `ENOTSUP` is the precise upstream baseline and is a valid implemented result; replacing a terminal with plain pipes is not.

Compared with shipping upstream binaries for every platform, the native core reuses substantial tested code, avoids Node/npm at runtime, and permits the stronger existing Windows pre-resume job assignment. Binary mode gives exact upstream platform behavior and smaller implementation scope, but needs immutable source/artifact/hash provenance and still requires the entire C# client. Keep protocol interoperability so either backend is testable; do not silently download an arbitrary daemon at runtime.

## Frozen E01 C# interface

`PiSharp.Env.Protocol` is BCL-only, net10.0. `PiSharp.Env` references it; E03 adds Durable. The daemon can reference Protocol without importing the client.

```csharp
namespace PiSharp.Env.Protocol;
enum FrameType : byte { Request=1, Result=2, Error=3, Event=4, Cancel=5, Ping=6 }
sealed record ProtocolFrame(FrameType Type, uint Id, JsonObject Json,
    ReadOnlyMemory<byte> Payload = default);
static class FrameCodec {
    const int MaxFrameBytes = 16 * 1024 * 1024;
    const int MaxPayloadBytes = MaxFrameBytes - 64 * 1024;
    byte[] Encode(ProtocolFrame frame);
    ValueTask<ProtocolFrame?> ReadAsync(Stream input, CancellationToken ct = default);
    ValueTask WriteAsync(Stream output, ProtocolFrame frame, CancellationToken ct = default);
}
// Complete frame with invalid JSON: can answer EINVAL and continue; framing errors are fatal.
sealed class ProtocolJsonException : IOException { FrameType Type; uint Id; }

namespace PiSharp.Env;
sealed class Connection : IAsyncDisposable {
    Connection(ConnectionOptions options);
    Task<RemoteInfo> InfoAsync(CancellationToken ct = default);
    Task<long> SessionAsync(CancellationToken ct = default);
    Task<RemoteReply> RequestAsync(string op, JsonObject json,
        RemoteRequestOptions? requestOptions = null, CancellationToken ct = default);
    void Kill(uint id, long session);
    void Close();
    ValueTask DisposeAsync();
}
sealed record RemoteReply(JsonObject Json, byte[] Payload, long Session);
sealed record RemoteRequestOptions {
    ReadOnlyMemory<byte> Payload;
    long? Session;
    Action<JsonObject, ReadOnlyMemory<byte>>? OnEvent;
    Action<uint,long>? OnStart;
}
```

`ConnectionOptions` accepts exactly one of an argv `Command` or `CommandFactory(CancellationToken)`. The factory token belongs to the shared startup, not one caller; cancellation of one operation only stops its wait. Original factory tasks remain owned/observed after a startup deadline. Disposal cancels shared work and joins the admitted starts, original factories and process sessions. Defaults: start timeout 60 s (including factory), heartbeat 5 s, silence limit 30 s, cancel grace 1 s, shutdown timeout 5 s. An uncooperative factory causes an explicit failed disposal at the shutdown deadline, while its original task remains owned/observed; it is never reported as cleanly disposed. Optional `OnLog` observes diagnostics and `ValidateHello` enforces an artifact-specific version check before ready. Time overrides exist for deterministic offline tests.

`RemoteInfo` contains Protocol, Version, Os, Arch, Home, Tmpdir, Separator, Cwd, Pid, DriveCwds and Features. Absent features becomes an empty list. `RemotePlatformNames.NodePlatform` maps windows→win32, macos→darwin, x86_64→x64, aarch64→arm64, x86→ia32. `RemoteError` preserves Code, Path, cloned Fields and IsConnectionLost.

## Protocol and ownership rules

Source: `packages/env/docs/protocol.md`, `src/connection.ts`, `daemon/src/frame.rs`, `daemon/src/main.rs` in the frozen upstream checkout.

- Start argv appends `serve --token <32 lowercase hex characters>`. The 128-bit random token identifies stdout sync, not authentication. Skip bounded shell startup noise until exact `PI-ENV <token>\n`.
- Frame: big-endian uint32 bytes-following, byte type, uint32 ID, uint32 JSON length, UTF-8 JSON object, remaining raw payload. Length is 9..16 MiB, excluding the initial uint32. Zero-length/truncated/malformed length is fatal. Invalid request JSON is EINVAL when identity is recoverable. File payloads never round-trip through text.
- hello protocol 1 is first. All hello path/platform values describe the remote machine. Client request IDs never recycle; exhaustion requires a new connection. A numeric handle belongs only to the session that opened it; after loss it fails without starting/reaching a replacement daemon.
- Lost requests fail `unknown` with `lost:true`. No mutation is replayed. Next unbound request may create a new daemon. Closing is permanent.
- After send, cancellation sends cancel first and waits at most 1 s for the daemon result/error, preserving spill details if returned. Late answers after local settlement are ignored. Pre-start wait cancellation returns promptly and leaves shared startup alive. Exec also enforces its timeout locally, including connection bootstrap.
- Daemon inserts request control before dispatch, preventing immediate cancel races. `cancel {mode:"kill"}` kills without setting abort; shell cleanup receives killed exit status. Ordinary cancel produces aborted. Watches resolve after stopped.
- File pool work is bounded. Writes to one open handle are sequenced in arrival order; the first failed chunk poisons later chunks with EBADF. ptyWrite/processWrite/close-input enqueue in arrival order on the frame reader, never race on arbitrary worker tasks.
- One output writer preserves complete frame atomicity. Replies, errors, heartbeat and watch changes precede bulk command output; >64 KiB result payloads use bulk scheduling too. Each unwindowed command backpressures above 4 MiB unsent; windowed output retains at most one queued update per command and accounts exact skipped bytes/newlines.
- EOF, silence timeout and Unix TERM/INT/HUP stop every owned process and close files/watches before exit. Windows job lifetime protects children even if the daemon dies abruptly. Do not signal a PID/group after its identity ownership has ended.
- Startup diagnostics retain <=2,000 chars, display <=20 nonempty trailing lines, strip terminal escapes/control bytes; ready-process exit fails promptly even if descendants hold pipes open.

## File and shell adapter contract

Map every current IFileSystem/IShell method; preserve signatures. The adapter's Id is caller supplied; Cwd lives in the remote namespace. Never use the local `System.IO.Path` to resolve a remote Windows path on Unix or vice versa. Path helper covers slash normalization, `~` from hello.home, `file://`, UNC, drive absolute and drive relative, hello.cwd and driveCwds. Strings encode lone surrogates as replacement characters. Metadata uses remote byte size and UTC epoch milliseconds.

Wire op map: `lstat`, `realpath`, `write`, `writeChunk`, `truncate`, `fsync`, `rename`, `mkdir`, `rm`, `mkdtemp`, `open`, `pread`, `fstat`, `scanLines`, `opendir`, `readdir`, `close`, `listFiles`, `exec`, `watch`, `pty`, `ptyWrite`, `ptyResize`, `ptyForeground`, `process`, `processWrite`, `processCloseStdin`. Field names/result schemas are exactly frozen `docs/protocol.md`, not new JSON-RPC envelopes.

Binary readers open regular files with optional noFollow and retain the opened object after renames. `open {mode:"read"}` is a separate raw stream path for whole-file/text readers and may open non-regular files; it cannot simply call the regular-file-only reader. Whole-file regular reads stop at size-at-open; unknown-size reads continue to EOF. Client positional transfer uses 256 KiB chunks/depth 8, whole-file reads 512 KiB or 64 KiB for unknown size, line reads 64 KiB, writes 512 KiB/depth 8. Keep all outstanding operations observed/drained after errors. Text whole-file decoding retains BOM; line/exec decoders strip the leading BOM and preserve per-stream UTF-8 state. Reuse existing decoders rather than `StreamReader` defaults.

`listFiles` is capability-gated; old daemon yields NotSupported without sending the op, allowing existing fallback. Listing payload records are kind byte f/d/l + UTF-8 relative slash path + NUL; JSON count/truncated must agree. Existing local listing already works in process; no reason to require a local daemon for it.

Exec environment: daemon base → environment ShellEnv → per-call Env when inheritEnv; otherwise only per-call Env. Empty values remain set. Validate finite positive seconds <=2,147,483.647. Array commands run directly and refuse Windows batch files; string commands use configured/discovered bash. CallbackError precedes timeout/abort, spill failure and exit code. Return nonzero exit as a result, not transport failure. `CleanupAsync` kills only commands owned by this environment; it does not close a borrowed shared connection or another environment's commands.

## Process, terminal and watch contracts

RemoteProcess uses required argv/cwd, raw per-stream byte callbacks, pid, Task<int> Exited, ordered input chunks <=1 MiB, input-close after prior input, close/abort and IAsyncDisposable. Advertise `process` only if fully registered. Opening against older daemons fails NotSupported. New Windows interactive lease retains stdin and the already correct suspended job admission; existing one-shot input callers are unchanged. On program exit kill remaining owned descendants, drain output to EOF or 100 ms inactivity, then settle. On Windows cancel asynchronous reads so a silent descendant holding a pipe cannot hang settlement.

RemoteTerminal uses optional argv (default login shell), cwd/env/inheritEnv, cols/rows integers 1..4096, raw merged output, pid, Task<int> Exited, write, resize and ForegroundAsync. Follow-up requests are session bound. Native Unix shim owns all child-side work (openpty, fork, setsid, controlling terminal, descriptor dup, signal reset, execve/error pipe); no managed allocation or callbacks between fork and exec. Foreground reports tcgetpgrp different from the program group, plus best-effort Linux `/proc/.../comm` or macOS proc_name. ENOTSUP on Windows is intentional baseline behavior.

RemoteWatcher waits for `ready`, delivers Paths/Overflow/Failed, catches observer exceptions, stops on Failed, and prevents new callbacks after StopAsync completes. Reconnect only on transport-lost, delays 1/2/4/.../30 s and emits Overflow once coverage is regained. Stop wakes and joins reconnect waits. Daemon oversized watch path event becomes overflow before serialization, never terminates the only writer. Reuse native/polling local watches; force polling when platform/filesystem requires it.

## SSH and release contract

Use system ssh via structured argv. Preserve upstream BatchMode, -T/-a/-x, ClearAllForwardings, ForwardAgent/ForwardX11 disabled, ControlMaster/ControlPath disabled, RemoteCommand none, PermitLocalCommand no, SendEnv -*, strict known-host checking with caller's known-hosts file and stable HostKeyAlias, ConnectTimeout 15, ServerAliveInterval 15. Validate host/user/alias/port and correctly escape configuration paths (including literal %).

Scan keys only into an isolated temporary file using the same route; return lines/fingerprints for explicit trust. Accept only requested alias and valid key fields; serialize/atomically replace known-hosts edits; changed keys require explicit forgetting first. No hidden acceptance in connect.

Detect Unix/macOS/Linux/Android and Windows default shell; PowerShell uses UTF-16LE encoded commands. Deploy immutable content-addressed daemon path under remote home. Validate local artifact against manifest SHA-256; verify remote SHA-256 before each startup, upload to temporary file, verify, chmod where applicable, atomic rename. Preserve active binaries and only prune names owned by the bootstrap. Missing hash tools or missing verified artifact is a typed failure. Upload deadlines/diagnostics are bounded. Lazy connection performs no network at construction; eager connect detects/deploys and returns connection state.

Native builds target six Windows/Linux/macOS x64/arm64 outputs plus the Unix PTY shim. Published package contents are separately checked. The upstream Rust build matrix explicitly covers Android API24 with NDK 27.2.12479018; a future Android backend must carry exact source commit, locked crates, artifact SHA-256, license and test status. It cannot be synthesized from the absent git `bin/` directory. NativeAOT and Android runtime support have not been claimed as tested in this Windows checkout.
