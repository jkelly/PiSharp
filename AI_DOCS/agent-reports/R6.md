Native Responses model metadata, Azure metadata and Codex metadata propagate `supportsAdditionalTools`, `supportsToolSearch`, and existing mid-conversation-system capability.

- **none**: with neither effective inline nor search capability, top-level tools are the current set as before; transcript text behavior remains unchanged.
- **changes**: mid-conversation system support plus additional-tools capability declares every batch in `additional_tools` input items, including initial tools. No top-level duplicate declarations. Repeated declarations replace earlier inline definitions. Actual removals are announced as text, with incremental notices preserving still-unavailable names across later loads. A remove+add of the same name is a redefinition, not a removal notice.
- **additions**: tool search without full changes support folds top-level declarations through the last removal or same-name redeclaration (and at least the initial system message). Later additions stay anchored as paired client `tool_search_call` and `tool_search_output` items. Search-result definitions carry `defer_loading:true`. This invalidates the cached prefix once at a non-additive change, then preserves it for later loads.
- Additional-tools alone without mid-conversation system support remains none. Tool search without mid-conversation support sees the collapsed final system state, so all current tools remain top-level.
- Azure now supports these declared capabilities and grammar declarations instead of blanket refusal. Existing strict conversion and resource admission apply to inline and top-level batches.
- Codex shared input generation observes the same modes while retaining its separate instructions field and initial prompt omission. `ChatRequest.DisableContinuation` now prevents cached previous-response use for that invocation; socket reuse itself is unchanged.
