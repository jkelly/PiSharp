Implemented shell `auth login <provider> [--api-key] [--no-browser]` and `auth logout <provider>` through the existing provider catalog, `ProviderLoginHost`, and `AuthJsonCredentialStore`. An additive `--provider` alias is accepted. Login requires an interactive terminal; default account login selects the first provider method, while no-browser selects another offered method and suppresses browser opening. API-key input is read without echo. Console prompts poll cancellably so a browser callback can withdraw a manual-code prompt without leaving a blocked console read. Login waits for the store write and never prints the credential. Logout removes only the selected stored entry and reports an already absent entry accurately. Existing check/print commands remain intact.

`McpCommand` now directs provider-auth login/logout to shell provider commands. Provider-auth HTTP 401 responses are classified as requiring sign-in, with provider-specific guidance in both text and JSON reports. Existing provider token transmission and interactive-session guidance were preserved. I09 explicitly handed ownership of these CLI guidance changes to I19. I10 confirmed awaited shell login needs no additional lifecycle scope.

Package updates now return typed per-source results (`Changed`, `Unchanged`, `Offline`, `Warning`) with scope and observed before/after versions or commits. The command renders those results rather than claiming all packages updated. npm metadata failure, stale registry installation, unavailable post-install version, unavailable git head, and incomplete git cleanup are warnings; pinned/no-op and offline operations are distinguished. Existing update failures still return a nonzero command result through the existing error path. npm batching and bounded git concurrency remain.
