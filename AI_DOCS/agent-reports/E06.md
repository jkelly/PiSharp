## Contract and implementation

The inspected reference is `7d073328e44337d3292a7db9b0f0308f679c5e97`, `packages/env/src/terminal.ts`, `daemon/src/pty.rs`, `daemon/src/sys/unix.rs`, `docs/protocol.md`, and `test/terminal.test.ts`. A local `git diff v1.5.0 -- packages/env/src/terminal.ts packages/env/daemon/src/pty.rs` returned no differences, confirming these terminal contracts also match the frozen v1.5.0 tag.

- `src/PiSharp.Env/RemoteTerminal.cs` adds `TerminalOptions`, `TerminalForeground`, and session-bound `RemoteTerminal.OpenAsync`, `Pid`, `Exited`, raw `Write`, resize, foreground query, close, and disposal. Input is split into 1 MiB wire writes; every control is pinned to the opening connection session. Errors before `started` reject open; later failures reach `Exited`; close uses request cancellation and reports `aborted`.
- `src/PiSharp.Env.Daemon/Operations/TerminalOperations.cs` implements `pty`, `ptyWrite`, `ptyResize`, and `ptyForeground`. E02 composes the operations and dispatches terminal controls in reader arrival order. Dimensions are constrained to 1–4096; unknown handles return `EBADF`; Windows returns `ENOTSUP`. Output remains raw bytes and waits on E02's bounded output writer. The post-exit 100 ms silence grace does not run out while a received frame is awaiting transport delivery.
- `src/PiSharp.Env.Daemon/Native/pisharp_env_native.c` is the actual Unix spawn boundary: `openpty`, close-on-exec pipes/descriptors, `fork`, `setsid`, controlling-terminal setup, `dup2`, signal reset, `chdir`, and `execve` all run in C. No managed child callback executes after fork. An error pipe distinguishes failed exec from a successful child. A shared piped-spawn path supplies E05's process implementation.
- `Native/UnixNativeProcess.cs` supplies managed lifetime, nonblocking polling streams, `ioctl` resize, `tcgetpgrp`, Linux/macOS process names, group cancellation, and cleanup. Native `waitid(...WNOWAIT)` retains the leader until group cleanup plus `waitpid`, preventing group-id reuse before cleanup. Descriptor access is locked through close to prevent poll/read/write races against fd reuse.
- E02's request ownership/release contract handles disconnect during startup and releases completed terminal state. Ordered writer channels are drained on disposal rather than retaining abandoned payloads.

## Build and deployment

`Native/PiSharp.Env.Native.targets`, imported by E02's daemon project, compiles the shared library automatically on Linux/macOS. `cc` and platform C development headers are prerequisites; Linux uses `libutil`. Windows does not attempt native compilation.

For E07 single-executable deployment, daemon-local `PublishAot=true` (through `PiSharpEnvNativePublish`) builds a static C archive on Unix, adds `DirectPInvoke`/`NativeLibrary`, and excludes the development shared library from publish output. Publish on the target OS/architecture; cross-compilation is not configured. The recipe is in `Native/README.md`. E08 r4 passed actual Windows NativeAOT code generation/linking; its later license-bundle stage failed before runtime smoke. Unix shim compilation/linking and PTY execution remain outstanding.
