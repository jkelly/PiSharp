# E05 — Native exec and piped process

## Scope and source

Implements the D15 exec/process contract against upstream `7d073328e44337d3292a7db9b0f0308f679c5e97` (`packages/env/daemon/src/{exec,process,window}.rs`, `packages/env/src/process.ts`). Exec/window were compared directly with `v1.5.0`; piped processes are one of the explicitly selected newer fixes and did not exist in that tag.

Requested model/effort: `gpt-6.1-sol`, xhigh, ultrafast; the effective service tier was not exposed/verified. No subagents, network services, credentials, live SSH, commits, or publications were used.

## Implementation

- `src/PiSharp.Env.Daemon/Operations/ProcessOperations.cs` explicitly registers `exec`, `process`, `processWrite`, and `processCloseStdin`. Cwd/environment/argv checks precede launch; Windows resolution follows the upstream cwd/PATH, `.com`/`.exe`, and batch-refusal contract. Shell discovery reuses the existing Tools implementation, including legacy WSL stdin command transport.
- `src/PiSharp.Env.Daemon/Native/WindowsPipedProcess.cs` adapts the proven Tools lifetime without changing existing one-shot callers: suspended `CreateProcessW`, restricted inherited handles, non-breakaway kill-on-close job assignment before resume, persistent async stdin, separate output pipes, and joined process/job cleanup.
- Unix launches use E06's native shim and `UnixNativeProcess`. No CLR code executes between native fork and exec. Its waitable unreaped leader reserves the process-group identity until group cleanup and final reap. Session ownership is attached immediately after spawn and released after disposal.
- The output reader uses a bounded eight-chunk channel; raw pipe chunks are 16 KiB and remain separate by stream. `process` emits `started`, byte-exact output events and final exit status. Stdin writes and EOF are serialized by the session's per-target request ordering and the process input gate. A wrapper's exit kills the remaining owned group/job.
- Exec decodes each stream independently with the existing `StreamDecoder`, strips its leading BOM, flushes incomplete UTF-8 at EOF, preserves complete raw spill output, and coalesces output windows with exact skipped UTF-8 byte/newline accounting. Event text is chunked at Unicode boundaries below the daemon frame scheduler's bulk threshold. Window delivery has one outstanding update while collection continues.
- Abort/timeout independently request group/job termination even if output delivery or stdin is blocked. Abort produces `aborted`, timeout produces `timeout`, and cleanup kill produces the killed exit code. Output draining and task cleanup remain owned.
- `src/PiSharp.Env/RemoteProcess.cs` exposes `RemoteProcessOptions`, `OpenAsync`, `Pid`, `Exited`, serialized/chunked `WriteAsync` plus convenience `Write`, ordered `CloseStdinAsync`/`CloseStdin`, `Close`, and `IAsyncDisposable`. It gates on the daemon's `process` feature and binds control requests to the original session.

E03 owns the Durable `RemoteExecutionEnv.ExecAsync` adapter; E02 owns the router, output scheduler, resource release hook, feature registration, and control request sequencing; E06 owns the Unix shim. These paths were coordinated rather than duplicated.

## Validation

`tests/PiSharp.Env.Process.Tests` contains ten offline integration cases using actual local child processes and the real native daemon operations:

1. Byte-exact >3 MiB stdin/stdout transfer, independent binary stderr, ordered EOF, and nonzero exit.
2. Split UTF-8, BOM stripping, malformed/final incomplete characters, and raw spill preservation.
3. Window skipped-byte/newline accounting, retained Unicode tail, and complete spill.
4. Timeout versus abort versus non-aborting kill.
5. Wrapper exit kills its descendant.
6. Explicit process close and connection loss terminate the admitted process (the separate wrapper case checks a descendant).
7. Concurrent processes preserve request and stream isolation.
8. A blocked stdin writer remains cancellable.
9. Callback failure cancels the owned process and preserves the exception.
10. Invalid/absent process controls and an older daemon's feature gate.

## Limits

The passing receipt exercises the Windows process/job implementation through the real session and native operations, hosted by the test executable's daemon mode. It does not prove the standalone daemon CLI registration, Unix execution, analyzer results, fault-injected launch failures, or native publish. Unix ownership covers descendants remaining in the admitted process group, as the upstream contract does; a descendant deliberately calling `setsid`/`setpgid` can leave that group. Windows job ownership is stronger. The full Unix/Windows distribution matrix and SSH/bootstrap verification belong to E06/E07/E08. No Android support is claimed.
