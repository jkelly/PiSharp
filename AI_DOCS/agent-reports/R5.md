# R5 — incremental source snapshot allocation

Scope: W16/R5; `TextState.cs`, `PiMessagesEventMapper.cs`, and focused cases in `PiSharp.MistralConversations.Tests`. No Anthropic or Completions files changed. No live requests, commits, or package changes.

## Implementation

- Mistral now retains each frame's immutable message header, immutable tool argument values, and persistent text fragments behind the existing deferred source-emission factory. The former tool-present whole-message serialization path is removed. Newly changed argument values receive the same additional message nesting validation before a provider chunk is published; rejected chunks retain the existing rollback behavior. Final argument parsing and `argumentsError` remain unchanged.
- Pi Messages retains a persistent `ImmutableList<JsonData>` of content-block versions, replacing only a changed block. Unchanged tool previews share their previous block. Each frame captures owned envelope/header values and the list version; serialization happens on observation. Envelope nesting is checked eagerly. A conservative byte/character bound selects the original exact, eager admission path near configured payload limits.
- These are lazy snapshots of retained immutable state, not omitted snapshots. Observing all full historical snapshots still necessarily allocates their full serialized output. The normal compact-frame path no longer constructs every growing full message merely to retain evidence.

## API compatibility

No public signatures, constructors, options, default values, event kinds, or wire fields changed. `SourceEmissionSnapshot` remains non-null wherever it was captured before; its existing public `JsonData?` getter returns a cached owned immutable value. Record copies clearing the snapshot still clear its factory. `CaptureSourceSnapshots=false`, `Current`, terminal messages, provider error partials, undefined-path evidence, tool identity replacement, and final authoritative arguments retain their existing contracts. Deferred factories capture immutable block/header versions; later interleaved tool writes cannot change older frames.

The allocation control uses fixed 1 KiB argument fragments at 64 KiB, 256 KiB, and 1 MiB; it retains compact frames with capture enabled and verifies final content. It reports allocation byte counts and requires each fourfold input increase to stay below sevenfold allocations, rather than imposing elapsed-time or absolute-byte thresholds.
