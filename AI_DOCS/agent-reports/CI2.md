# CI2 — bounded gap regression runner

Implemented in the gap-implementation worktree. Requested model: gpt-6.1-sol/high; requested Ultrafast tier is unverified. No commits, product builds, provider calls, hosted workflow runs, or external live calls were made.

## Changes

- `tools/ci/run-gap-suites.ps1` delegates to the standard-library Python runner and propagates its actual exit code. `gap-regressions.yml` installs Python 3.12 and executes the offline runner contract tests on Windows, Linux, and macOS before the product suites.
- `owned_process.py` launches hidden, suspended Windows children, assigns them to a kill-on-close Job Object before resume, disables inherited Windows error dialogs, restricts inherited handles through Python's `close_fds` implementation, terminates the owned job, and waits for its active count to reach zero. Unix children run in a new session/process group and that owned group receives SIGKILL during cleanup. Cleanup also runs when the direct child exits before a grandchild, launch callbacks throw, a deadline expires, or cancellation occurs. No process-name/global SDK termination is used.
- `run_gap_suites.py` records a complete suite plan before checkout/build execution, atomically updates a manifest at stage transitions, preserves each unique run directory, and writes a final manifest from `finally`. Every stage records the current checkout SHA, start/finish, command, timeout, process ID, actual exit/termination result, separate stdout/stderr paths, and SHA256 digests. Build and test deadlines default to 600 seconds; checkout is bounded to 20 seconds. Cancellation returns 130 and leaves subsequent suites explicitly `not-run`; nonzero test exits retain their original diagnostics and partial emitted evidence.
- `gap-suites.json` declares report formats and completion contracts for all 22 suites. JSON results preserve actual IDs/status/raw entries and reject absent, empty, malformed, count-mismatched, duplicate or nonpassing results. Truncated JSON retains complete emitted result objects as partial evidence, with failure. Named console cases and TAP plans are supported; summary-only suites explicitly have no individual-case evidence and their assertion totals are never expanded into invented results. Unexpected explicit skips fail even with exit code zero.
- The existing Windows daemon FIFO skip and non-Windows legacy Job Object skip are narrowly allowed by exact line and reason, and their later misleading PASS lines are recorded as SKIP rather than credit. Such a run is `passed-with-policy-skips`, not `passed`. Linux/macOS must execute the FIFO case; Windows must execute the Job Object case. CLI Windows-only MCP command resolution and native terminal versus Windows ENOTSUP tests have explicit platform-specific required IDs. Other named console suites have full expected-ID lists, including all 25 legacy cluster cases across its registration files.

## Required production runtime installer gate

Coordinated with I13 and R8 to add `production-runtime-installer` to the reusable gap workflow. The Ubuntu job runs the actual `PiSharp.ExtensionParity.Tests` case `runtime.pi-packages-installed-with-verified-provenance`, through bounded `runtime-installer` runner execution. `PISHARP_TEST_INSTALL_PI_RUNTIME=1` and the exact `EXTPARITY_FILTER` are scoped only to that invocation. Runner preflight rejects a missing/mismatched opt-in/filter or an existing/nonabsolute runtime directory; CI supplies a fresh run-specific path under the runner temporary directory. The result contract requires exactly one declared case with the exact installer identity and passing status, consistent failure/skip totals, and no skipped result. Empty, missing, extra, fixture-only, or `SKIP_NO_PRODUCTION_RUNTIME` evidence fails.

The original case calls `PiNodeRuntime.EnsureAsync` and checks actual installed package versions and registry integrity provenance. Its ledger labels this evidence `production-runtime-install-and-registry-integrity-verification`; raw logs and actual production `provenance.json`/`package-lock.json` upload separately from the existing `npm ci` fixture and ABI lanes. CI registry network access is intentional; no production install or registry call ran locally. One Ubuntu install avoids three redundant public-registry installations; existing cross-platform fixture/bridge coverage remains separate.

The job has no skip/continue-on-error condition and belongs to `gap-regressions.yml`, which release already invokes at `github.sha` and requires before publication. No core or release workflow edit was needed. Local YAML checks verified this dependency, exact suite policy, and that only the dedicated installer step sets the production opt-in. I13 was asked to review the added gate.
