## Behavior

- Facet setup records a plugin-local declaration table; duplicate names, invalid host shapes, incompatible accepts tables, repeated contributions and invalid registry providers refuse that plugin without partial publication. Retained setup capabilities reject use after setup.
- Reload runs recording factories against effect-free declaration handles. It checks document version/fingerprint compatibility, persisted owner claims, native declarations, table migration needs, jobs, dependency requests and implementation shape without opening resources, running jobs, changing documents, claiming ownership or publishing contributions.
- A failed setup or recording retains the previous successful plugin. External compile/evaluation failures in `ReloadOptions.Failed` also retain its generation. Staging repeats until the compatibility closure stabilizes; it includes requests from retained/unchanged consumers, not just replacement factories.
- Accepted plugin metadata, registry providers and facet contributions publish in one host batch. H1 preserves identities of unchanged providers/contributors. The replacement attempt withdraws prior object contributions in the batch publishing its new contributions.
- Native-free live objects swap using the same incarnation and existing document slot container. Scalar and keyed readers keep following the old instance's admitted commits while its replacement attaches, then follow the new instance. Native-bearing objects and eager table migrations restart after old calls drain and admitted document steps settle; source detachment and native close occur after that settlement barrier. Non-live objects retry. Removed types end their objects while local and cooperating remote holders stay waiting for a future provider.
- Old calls retain their original delegate/argument/result mapping and token until drained. Job invocation ownership is handed over through J1's interface; old jobs finish against their original implementation without a normal reload applying the call-drain timeout to them. Actual object/host end still provides bounded abandonment. Retired work and removal teardown are retained until settled and exposed through additive `DrainReloadsAsync`, used by N1 before collectible-generation release.
- Cancellation before commit publishes nothing. After commit it cancels only the report wait and throws `ChordError("aborted")` with `Details.committed` listing added/changed/removed/failed plugins. Reloads queue in request order without blocking the host dispatcher across waits.
- Older-version state mappings are lazy shared derives, including mapping removed members from the complete current variant state. Keyed watch mappings share one derive per document/source, with the final watcher releasing its mapping and residency pin. H1 drops per-version adaptations when the final holder leaves. Method argument/result adapters reuse the existing checked provider machinery.

## Document slot mapping

## Deliberate C# mappings

- Recording capabilities are typed inert handles; attempting asynchronous reads/writes during a factory declaration throws instead of returning JavaScript's recursively inert proxy. Declaring members and capturing handles remain supported.
- Adapted keyed members expose the existing `IKeyedHandle` surface, but mutation through an older adapted shape is refused with `released/version`; provider-owned current-version handles remain the write surface.
- The closure additionally protects an unchanged consumer's previously bindable provider when another plugin fails or updates incompatibly, as required by the full-gap acceptance contract.
- `DrainReloadsAsync` is an additive generation-release barrier; ordinary `ReloadAsync` retains v1.5.0 first-dependency-check report timing, so plugin managers must not equate a report with all old calls having drained.
