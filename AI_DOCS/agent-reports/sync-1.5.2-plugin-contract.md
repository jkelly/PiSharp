# Native plugin 1.5.2 contract

- Existing string roots and manifest constructors remain accepted. `PluginRoot` adds required-root handling. Discovered plugins/problems retain canonical root, required flag and layout. A manifest directly in a root is a directory plugin; otherwise immediate child folders are scanned. Native package metadata (`chord.plugins.json`) explicitly lists relative plugin folders; nested overlaps and links escaping the package/root are rejected.
- `AppApi` lists accepted version strings newest first. `PluginKindDescriptor` provides exact shared assemblies for a kind. A configured API requires the manifest's API name/version and validates managed assembly references at build and load. Dependency closure checks apply to every managed DLL; `AssemblyLoadContext` is identity isolation, not a permission sandbox. Reflection, arbitrary file access and process execution by plugin code are not confined.
- `BaseInputs` records SHA256 bytes and directory membership with bounded traversal, excludes dependency/output/VCS folders and refuses directory symlinks. `FromHashes` accepts hashes from the actual build/copy reads. `Capture` is only a point-in-time scan: it cannot establish what a concurrent compiler previously read. Watch registration compares immediately; restored identical bytes clear the base mark. Dynamic assembly inputs omitted by callers cannot be watched.
- Build results include their input record. Project-reference source closure inside the canonical plugin root is watched. With strict API policy external relative project/assembly/source references and executable/custom MSBuild imports are refused; ordinary libraries are not plugin-kind modules.
- Explicit installation supports Git checkouts at a pinned ref and local native ZIP packages (not npm packages). It claims an owned staging/destination lock, validates all manifests and cross-root names, then publishes by directory rename. Failed/cancelled operations only delete their owned staging. Git dependency restoration is never automatic. No installation is performed by this update.
- JavaScript/TypeScript, CSS modules, esbuild and CommonJS are unsupported by this native assembly adapter. Single-file source is not implicitly recognized. Browser/surface builders are separate adapters.

## Implemented source and verification handoff

- `BaseInputs` / manager registration compares current bytes to explicit build-read hashes, handles new/missing files, restores identical content, and serializes over native worker messages. Scans are bounded and reject linked input trees; supplied loaded/dynamic dependencies remain the caller's responsibility.
- Discovery supports required roots, direct-root manifests, native package folders/globs/exclusions, duplicate precedence, overlap and realpath containment. App API/kind admission is shared by builder/runtime; per-kind managers omit explicitly different kinds.
- Managed dependency metadata is checked on configured-policy builds and evaluation. Private resolution outside the immutable artifact is rejected. Public runtime APIs can still execute arbitrary trusted native plugin code; this is not hostile-code isolation.
- Installer supports explicit Git refs and local native ZIPs, exclusive destination claims, owned cleanup, collision/traversal checks and configured size/file limits. Dependency restore is explicit, locked and bounded. No install/restore was executed. Crash-stale staging is intentionally not removed automatically: another process's ownership cannot be established by this adapter. NuGet package download/version resolution and single-file C# compilation are not implemented adapters.
- `PluginTesting.TestPluginAsync` uses the production build/evaluation path and a caller-provided fresh memory-store factory, reports host errors, adds collecting providers to a fixed point and exposes unserved requests. Readers requiring a specific typed composed value should supply their real typed provider as a stub; the generic collector exposes raw contribution tables.
- Added `PluginDiscoveryTests.RunAsync` (Hosting test project) for content restore/deletion/new inputs, JSON record transport, required/optional/root/duplicate/overlap discovery, required load failure, API/kind refusal, archive collision/traversal cleanup. Root must register and execute this case. Existing real ALC/late dependency/cached-facet tests remain unchanged.
- Only whitespace/diff source check executed here; builds and runtime tests belong to the root's serialized verification. Requested ultrafast tier is unverified.
- `PluginRuntime.JoinOriginalsAsync` is the ownership join after host close: it initiates disposal, tolerates only the bounded public timeout, then waits for every tracked actual generation retirement before callback resources may close.
