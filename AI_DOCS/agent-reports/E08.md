# E08 — NativeAOT packaging and qualification gate

Status: implemented; actual local Windows NativeAOT publication reached and passed final code generation/linking in r4. The gate then failed in license-bundle integrity comparison before daemon execution; that comparison is now corrected for signed NuGet content hashes and queued for a fresh I13 run. Full package/runtime and hosted-platform success remain unclaimed.

Added `.github/workflows/env-native.yml` with PR/main/manual triggers and reusable `workflow_call(source_sha)`. The independent Ubuntu 24.04, Windows Server 2022, and macOS 15 jobs verify/install documented native prerequisites, derive the actual host RID, publish the daemon with NativeAOT and trim warnings as errors, and run the isolated executable. Root owns wiring this workflow into release prerequisites.

`tools/Env/Publish-NativeDaemon.ps1` stages one executable with a distributable license/notices bundle, verifies the smoke report's SHA-256 against that binary and distribution manifest, and on Unix runs all required native terminal cases against the same copy. Package artifacts upload the complete directory only on success; environment, publication, test logs and exact-source/binary evidence upload even on failure.

`tools/Env/native-smoke.mjs` is an independent Node protocol driver, not a managed app referencing daemon assemblies. It verifies every package file against the distribution manifest, exactly one executable, no managed/native sidecars, native format/architecture, and performs startup, hello, binary file reads/writes, descriptor metadata, line scan, malformed-JSON recovery, native process raw stdin/stdout/stderr plus exit, polling watch events/cancel, Windows PTY refusal, and clean EOF shutdown. Accompanying files are notices/metadata rather than executable dependencies. It disables development-library path overrides. Failure cleanup closes stdin before forcing termination.

The PKG admission follow-up added `tools/Env/Write-NativeNotices.ps1`. It copies actual repository MIT/adaptation and filesystem-port notices; exact selected runtime and NativeAOT package notices/metadata; and pinned Jint 4.16.3/Acornima 1.7.0 notices retained in the repository because their restored NuGet archives omit full license texts. The inventory derives from the exact RID restore target plus selected runtime/NativeAOT download inputs, records package SHA-512 and source commits, and hashes all distributed files. Missing versions/notices or changed unreviewed package versions fail closed without network access. Runtime/compiler .NET metadata must agree on source commit and MIT declaration before sharing the copied runtime MIT text.

Local source inspection confirms the current daemon references Durable.Tools → Codemode → Jint/Acornima. NativeAOT's selected Windows targets link runtime, aotminipal, zlib/Brotli and system interop libraries from the selected runtime/compiler packages; their supplied third-party notices include the associated runtime/compiler contributions. The license inventory is deliberately a conservative restored-graph superset, not a claim that all Jint/Acornima methods survive AOT trimming. IDE/compiler executables and operating-system libraries are not copied. Bundling notices does not itself establish redistribution acceptance or runtime qualification.

The real publish/link step remains the authority for remaining trim/AOT issues.

Package identity/version, notice availability, source-commit and per-file hash requirements remain intact. A read-only check against the actual signed Acornima 1.7.0 archive independently reproduced the restore content hash and passed signed payload validation; no daemon was executed by this check.
