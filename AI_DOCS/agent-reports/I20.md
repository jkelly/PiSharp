## Contract and implementation

The classifier transports already honor `compat`; they were not changed. `NativeExtensionModelOperations.CreateDefaultRegistry` now accepts `modelsPath` for standalone/default construction and has an internal overload sharing the Pi run's current models.json snapshot. Each operation provider's dynamic source reuses `ModelProviderComposer.Compose`, so provider `baseUrl` applies to every model, classifier `compat` merges shallowly, and `models`/`modelOverrides` retain their chat-only semantics. Existing classifier API routing and llama provider rewrites remain in place.

Configured API keys are applied only without an explicit request key or stored credential; unavailable/unsupported stored credentials still own their provider. Configured provider headers use the established resolver and are then subject to model/request header precedence. Provider identity continues to select credentials and API implementation; configured URLs only affect the selected model's endpoint. OAuth handling and refresh stay in the existing lifecycle.

`PiExtensionModels` shares its chat registry's models.json layer, with an offline refresh callback before extensions reload. `ctx.modelRegistry.refresh()` now refreshes that registry using the runtime's existing PI_OFFLINE policy. A file edit alone does not mutate a snapshot. After refresh, new model lookups see current configuration, while a previously returned model keeps its supplied URL/compat and resolves credentials against the current snapshot, matching the upstream request contract.

They cover provider routing and isolation, configured headers, explicit image form and opt-in overrides, omitted-compat detection, chat/classifier same-ID isolation, explicit/stored/configured/environment key precedence, unresolved/unsupported credentials, reload snapshots, held model/current credential semantics, native Pi host reload, and custom extension registration/removal. No paid provider, real credentials, commits, or historical captures are used.
