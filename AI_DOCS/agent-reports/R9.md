## Contract and implementation

- Public plan/case/task/result types; globally unique complete case validation; equal case-content cohorts discovered before execution; odd/even repetition arm alternation; identity by case/model/repetition/arm.
- Explicit scored/unscored/skipped/pending/errored statuses. Missing, duplicate, unexpected, non-scored, invalid-score/metric and mismatched-content observations block comparison. CLI exits nonzero for blocked reports and configuration failures.
- Paired category quality/metric comparisons and per-arm totals; unavailable values remain JSON null with measurement coverage. Multi-turn partial usage remains unavailable instead of becoming an incomplete sum.
- Stable ordering, protocol SHA-256, deterministic synthetic fixture results, deterministic task artifact names, imported-observation comparison CLI. Synthetic fixture is the default and explicitly labelled; it makes no quality claims.
- Explicit `--live` and runtime directory/entry/provider/model/docs/output required for executable runs. Stages supplied published runtime and documentation with digests; verifies unchanged bytes. Native CLI JSON parsing, exact trimmed answer scoring, nonzero/malformed/failed/timeout handling, continued execution after arm failures, bounded stdout/stderr capture, process cancellation kills/joins children.
- Fresh workspace, agent/home and session directories per arm. Same runtime snapshot, control without docs, treatment with docs and routing hint. Disabled ambient extensions/skills/templates/MCP discovery. Credential environment variables are explicit and cannot override isolation settings.
- Optional container runtime uses the same pinned image and read-only runtime mount, fresh `docker run --rm --read-only --pull=never`, independent writable workspace/home/session mounts, temporary `/tmp`, capability drop and no-new-privileges. No Docker/provider execution occurred during validation.
- PiSharp-specific smoke, extension interface, frozen model catalog and prompt-template answer cases replace TypeScript API exercises. Their score means literal-answer correctness, not code execution. Host process/container smoke checks remain distinct from paired model scores.

## Limits / integration

Live credentials, local pinned Docker image and compatible published runtime are optional prerequisites; neither paid live execution nor real Docker availability was qualified. Process mode is configuration isolation, not an OS sandbox. Container mode supplies filesystem isolation, with network deliberately available for opted-in provider calls. The supplied runtime snapshot is hashed; the caller is responsible for selecting the current build and compatible architecture. Published-runtime embedded docs are identical in both arms. Tests prove the orchestration/recording path offline, not provider quality.
