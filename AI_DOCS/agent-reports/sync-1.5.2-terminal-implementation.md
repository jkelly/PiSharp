# C-TUI terminal boundary — 1.5.2

Contract published before implementation. Source: frozen upstream `b4afdddf44e059c67ccf5097e5317d913521b470`, `packages/chord/src/tui/*` and `src/node/tui/*`.

- `PiSharp.Chord.Hosting.Terminal` owns typed launcher/client messages, the upstream big-endian pipe framing, bounded readers, `TerminalChannel`, `TerminalRelayLink`, `BridgeTerminal`, `TerminalScope`, output filtering, user-confirmed actions, credentials and a trusted native launcher session.
- Launcher-owned tokens never occur in bridge start/messages. Only launcher-side network operations receive credentials. Terminal file requests are constrained to same-origin `/_chord/tui/<file>` or `/_chord/tui/plugin/<file>`. HTTP responses are streamed with an 8 MiB maximum; redirects are not followed by the built-in transport.
- Pipe frames are at most 17 MiB and headers at most 1 MiB. Output frames are at most 64 KiB, split at 16 Ki UTF-16 units without cutting escape sequences/surrogates. OSC/DCS/C1/unsupported controls and modes are rejected from client output. Limits are 4 connections, 8 requests, 16 MiB queued bytes per connection and 1 MiB output held during confirmation.
- Confirmations belong to the launcher: single active action, 300 ms key quarantine, fixed visible attributes, resize redraw and triple Ctrl-C/1s exit 130. Copy and URL checks happen before confirmation; file lookup happens only after a textual path confirmation, resolves links, reconfirms changed targets and checks opened file identity and regular-file/16 MiB bounds.
- `TerminalScope` uses native Chord holds/watchers/registry acquisition; its cancellation/disposal prevents further callbacks. Page state/messages/terminal theme delegate to the portable `Surfaces` API. Optimistic actions remain visible until all calls in the shown group settle.
- No .NET AssemblyLoadContext is called a sandbox. No Node adapter is installed or bundled in this change. The downloaded JavaScript entry point explicitly throws `PlatformNotSupportedException` before credentials/network access. Native sessions accept caller-trusted C# clients only. Browser DOM/React execution and secure downloaded terminal execution remain explicitly unavailable; their APIs are not faked with C# hook lookalikes.
- Root owns project references, shared test registration, builds and execution. Separate `Terminal152Cases.cs` supplies fake-I/O functional/security regressions. Verification results will be recorded after root executes them.

## Implemented

Added `Bridge.cs`, `TerminalPipe.cs`, `TerminalOutput.cs`, `TerminalChannel.cs`, `TerminalLauncher.cs`, `TerminalActions.cs`, `TerminalNetwork.cs`, `PiTerminalIo.cs`, `TerminalScope.cs` and `TerminalRuntime.cs`. The runtime composes the shared native `Surfaces.Client`, so script-set updates, reconnect policy, user theme and live language use the same implementation as other native clients. The `ResolveTrustedScript` seam returns an already trusted managed delegate, never a downloaded DLL or JavaScript evaluator.

Native attachments use a stronger handle-pinning variant of the source identity check: open non-blocking on Unix, reject nonregular handles, obtain the actual opened handle's path, show a second prompt if different, and read that same retained descriptor. Windows uses `GetFileInformationByHandle`/`GetFinalPathNameByHandle`; Linux/macOS use `fstat` plus the descriptor path. No post-confirmation path reopen can substitute another file. Platforms other than Windows/Linux/macOS explicitly refuse attachments.

Root test registration requested: `FramesAndFilter`, `LauncherAndChannel`, `ConfirmationBoundsAndShutdown`, `ActionsAndNetwork`, `ScopeAndOptimistic`, `ActualAttachment`, `NativeRuntime`. These cover fragmented binary frames, malformed bounds, escape isolation, socket/request ceilings, input/resize relay, copy confirmation and quarantine, held-output bounds, actual native file reads, path/URL policy, streamed body cutoff, shared scope state and optimistic rejection settlement. `NativeRuntime` connects a real Chord server through the launcher/channel and native Surface Client to render and close a terminal application. No worker builds or tests executed; all .NET execution remains serialized by root.
