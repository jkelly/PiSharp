## Implemented behavior

- Real bidirectional remote holds, method invocation and cancellation, state replicas, failure/recovery and variant rebinding.
- Per-origin provider call admission (256), per-origin two-frame bound/state window, fair pending-state versus pending-binding draining, and bounded leaf folding through existing `PendingOps`.
- Envelope-only relays preserve part bytes, carry independent monotonic origin ids, return acknowledgements to the originating upstream, reject replies from stale upstream links, and emit one closed-origin message per upstream when downstream closes.
- Incoming holds stamp caller principal/incarnation at their trust boundary. Only a parent may supply forwarded caller fields. Child-carried origins and compressed child arguments are protocol errors.
- Reconnecting paths retain references, replace their snapshots, and reject rather than replay old calls. Call waiting uses the announced peer limit; queued cancellation does not consume an id or free an occupied slot.
- Every known bound/state frame is fully prepared before host state adoption; the decoder dictionary is cloned during preparation. Structural failure closes the link without partial adoption. Owned oversized parts fail/release only their hold.
- Routes authorize each hold, serialize one resolve per address, retain a late resolved link after an initiating reference is released, retry once after a completed handshake drops, and stop on pre-handshake failure until a new hold or explicit retry. Suspension and retry are public controls.
- Revocation protects the host's own principal, preserves its parent connection, closes matching children, handles unbound holds and disconnected remote references, and forwards revocations to routes.
- Reload removal returns incoming requests to waiting; pure swaps retain the prior indexed call names while their new bound waits for a slot.
