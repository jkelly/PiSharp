# Native Chord hosting

This is the native .NET mapping of the v1.5.0 `next-node/plugins`, `next-node/http`, and `next-node/workers` operations. It depends on the Chord v2 host and uses that host's transport and reload contracts. It does not alter the coding-agent extension loader. Experimental package admission is prepared, with publication and final validation pending; see [the admission contract](../../docs/contracts/gap-package-admission.md). Consumers require the ASP.NET Core shared framework and suppress PISHARP_CHORD001.

## Plugin generations

A root contains one directory per plugin, with `chord.plugin.json`:

```json
{"name":"app.notes","assembly":"Notes.dll","type":"App.NotesPlugin","project":"Notes.csproj"}
```

The entry type implements `IChordPlugin.CreateFacet(PluginContext)`. `PluginContext.Kind` selects the host role (`server` by default, `worker` in WorkerMain); an entry may return different declarations for each role. Omit `type` for a contracts-only project. Omit `project` to load an already-built assembly and its sibling dependencies. Discovery reads only manifests and resolves symlinks; duplicate names use the first root and report the later directory. Assembly, project, and `PluginContext.File` paths must stay within the plugin directory.

`PluginBuilder` runs the explicitly supplied absolute .NET SDK path through `PiSharp.Tools.Processes.OwnedChildProcess`, with one deadline spanning admission, process exit, and joined diagnostic readers. The shared owner establishes the private Windows job before resume, or a Unix group with a retained identity anchor, and stops descendants even when the build leader exits naturally. Diagnostic capture is bounded; build outputs and MSBuild artifact paths are unique. Restore is explicit (`Restore = true`); no runtime or package manager is installed implicitly. The application owns the artifact directory and must retain shipped builds for every worker that may start from them.

`PluginRuntime` shares the exact loaded Chord, Hosting, Contracts, and Telemetry assemblies. Add application contract assemblies to `SharedAssemblies`. Other managed and native dependencies resolve from the generation's build output. Each evaluated generation gets a declaration identity wrapping the original setup delegate unchanged; this permits shared-library cached/static Facets without duplicate owner registration or rooting retired contexts through a shared static key. Unchanged build digests reuse the existing identity. Plugins are trusted application code; a collectible load context isolates dependency identities and lifetime, not permissions.

Load and reload take the complete `PluginBuildSet`. A build/evaluation failure retains the previous successful plugin and participates in the host's closure check. Unchanged digests reuse the exact facet. The runtime registers a host callback lifetime resolver before loading. Both the callback's actual assembly and immutable declaring facet identify its generation, including callbacks manufactured by shared libraries. Registry contributions carry an opaque declaring owner; HTTP preserves it through composition and original wrapper chains. After a committed reload, call `DrainRetiredAsync` to wait for old calls/resources and release the retired facet handles. Original host methods, native open/close and attachment resource lifetimes, HTTP snapshots, and each original plugin callback task retain generation leases, including after a cancelled request stops waiting. A callback's completion releases its lease; only then may the context unload. `CallbackDrainTimeout` (30 seconds) bounds the caller's retirement/disposal wait and reports timeout; it never unloads code still executing. An ignored cancellation can therefore retain its own context until it settles. Disposal preserves the original cleanup result across repeat calls. The weak references in `RetiredContexts` let tests verify actual ALC collection. Close HTTP, then the host, before disposing its runtime.

`PluginManager` watches roots, marks changes, builds in sequence, and rolls out through explicit `IPluginRolloutStep`s. Results identify each host's failures, refused plugins, or explicit stop. Failed hosts/plugins do not prevent later steps from running; an explicit stop does. Dirty generations survive failed rollouts and changes made during an older build/rollout. A worker rollout retries previously failed held addresses and stores the shipped set for later starts. A file change never applies code by itself. C# project references replace copied JS modules; shared CLR contract assemblies are explicit. Browser/TypeScript bundling is not claimed by this package.

The runnable [NativePlugins sample](../../samples/chord/NativePlugins/Host/Program.cs) loads a real manifest/project, calls its method, then rebuilds/reloads while retaining the old generation on failure. It has a shared contracts assembly and a private dependency. `PiSharp.Chord.Hosting.Tests` adds transitive private dependencies, an old call overlapping a reload, and collectible-context verification.

## HTTP

Create `ChordHttp`, then load its `Facet` under `chord.http` together with application/plugin contributions. It serves `HttpRegistries.Http` and `Authenticators`. `Port = 0` selects a real ephemeral loopback port; omit `Port` and mount `HandleAsync` in an existing ASP.NET pipeline. `ListeningAsync` returns the actual listener URI.

Contributions contain typed routes, wrappers, sockets, allowed hosts, relay validators, frame origins, and CSP sources. Admission uses the actual connection and Host header. Foreign unsafe browser requests require the admitted origin; cross-site webhook routes always receive an anonymous root. Authenticators run in contribution order, honor cancellation, and never run for an anonymous webhook.

Each route, stream, or socket runs in one Chord root, so acquired references remain alive until its response settles. JSON, text, HTML, redirects, empty responses, pulled byte bodies, file bodies, single ranges, HEAD, bounded request bodies, signed cookies, and WebSocket upgrades are supported. Plugin WebSocket receives enforce the contribution's frame bound. A links endpoint passes a `WebSocketLink` directly to `ChordHost.Accept`; it does not define another wire protocol. Router updates revoke sockets whose host, relay, or handler disappeared.

Call `ChordHttp.CloseAsync` before `ChordHost.CloseAsync` to drain requests up to `CloseTimeout`; after the bound, their scopes are canceled. The listener is a host-owned native resource, so host close also stops it. The default listener is 127.0.0.1. Signing keys are supplied only to server-side `SignedCookies` helpers and are never emitted as response data.

## Native workers

Create `ProcessWorkers` before host load (routes are declarations), then include its stable `Facet` among core facets so host close owns its shutdown. Supply an executable, argument list, plugin build provider, principal factory, authorization function, and a lock directory. The first authorized reference starts a worker for that address. `WorkerMain.RunAsync` is the executable's entry point; its callback builds the child host and calls `WorkerContext.LoadPluginsAsync`.

Workers use separate current-user named pipes for private control and Chord traffic. Object messages use `FramedPipeLink` and the existing v2 protocol; control messages only coordinate start/reload/shutdown. Native process framing is explicitly distinct from Node's IPC serialization. The shared process owner retains descendant containment through natural exit and crashes. A parent asks for graceful shutdown, then stops the retained tree after the close bound; no global PID kill fallback is used. The child records its connected host before initialization returns, so pre-ready shutdown closes known native resources. A noncooperative initializer remains process-owned until the child's three-second cleanup bound or the parent's tree stop, without unloading underneath that initializer. Address locks use OS mutex ownership, wait without polling, and are released after a process crash. Activity drives idle shutdown; admitted reloads suppress idle stops. Crashes remain failed until `Retry` or rollout retries them. A startup whose initiating reference disappears still admits the child. Reload waits are caller-cancellable without abandoning the actual reply slot.

The hosting tests execute the same test assembly as a real worker process, obtain its PID through a remote Chord method, ship a reload, stop it, restart it, and verify a different PID. No in-memory transport is used as process evidence.

This package maps native plugin/worker/HTTP behavior; it does not claim arbitrary Node child compatibility, JavaScript module evaluation, npm installation semantics, browser asset compilation, or legacy Chord protocol 4.
