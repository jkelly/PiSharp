# Graceful Ctrl+C result — source only

Base `bc62530e9b079b35ddaebccbb4374c713d6a4602` is preserved. No build, native test, source-runtime comparison or live call was executed.

Pinned upstream `interactive-mode.ts` at `d86654abb8862e201933517d6f1fce9f88dd117f` treats a second Ctrl+C within 500 ms as interactive shutdown and exits 0 after stopping the terminal and disposing its runtime (lines 4145–4153 and 4167–4213; SHA-256 `444b21cb8677d061807d92562b3ac4ef7ea703dba186e08ea6b343d9f99d690f`). This change finishes the native Ctrl+C exit result without claiming full source shutdown ordering, child cleanup, or physical terminal qualification.

Only the actual terminal interrupt callback marks user shutdown. The native input owner opts into treating cancellation of its own token as a clean exit after joining all admitted work. Its reader translates cancellation only from its exact linked token. Late physical-read, render, receipt and cleanup errors take precedence over that expected cancellation. The renderer likewise translates only its own linked token; an unrelated cancellation exception is a failure even when Ctrl+C concurrently cancels the caller.

The terminal passes an internal optional user-shutdown predicate to the RPC host. This predicate is consulted only after normal dispatcher shutdown, session disposal/commit checks and before the return whose await-using cleanup must also succeed. It does not change the standalone RPC path, startup errors, cleanup exceptions or plugin composition. The terminal returns success with no failure diagnostic only when host/input/renderer cleanup succeeded. External cancellation remains failure, including external cancellation arriving while user-triggered terminal restoration is held. Escaping input-owner cancellation exceptions are not generically suppressed by the terminal wrapper.

Seven new, unexecuted cases invoke the public `RunConfiguredAsync` entry point. They cover successful Ctrl+C with held terminal restoration; restoration I/O failure; an unrelated restoration cancellation; external cancellation; external cancellation during user restoration; a late held-paint I/O fault; and a held paint throwing a different canceled token. The existing observed-entry-point held-paint test now expects 0 and empty diagnostics for clean Ctrl+C. Original operations and cleanup are directly awaited; timeouts observe gates only. The terminal plan is now 77 units. Two held-I/O member pins (TerminalChatInput and VtRenderer) are migrated; all eight historical scenarios/assertions remain unchanged.
