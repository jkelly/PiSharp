Base: `51d208bb1580021cbd646212641c497612d62dbe`. No build, test, native process, source-runtime comparison or live call was executed for this change.

The pinned upstream interactive source (`d86654abb8862e201933517d6f1fce9f88dd117f`, `interactive-mode.ts` SHA-256 `444b21cb8677d061807d92562b3ac4ef7ea703dba186e08ea6b343d9f99d690f`) uses the first Ctrl+C to clear the editor and another within 500 ms to shut down (lines 4145–4153). Escape while streaming restores queued messages and aborts (around 2973 and 4611–4628). Idle Escape does not clear a nonempty editor.

The native input producer now recognizes distinct configured `app.clear` presses with a monotonic clock. The first remains an ordered editor clear; the second within 500 ms invokes the existing shutdown cancellation, even while a physical paint or restoration sender is held. Kitty repeat/release do not arm or trigger shutdown. A new session generation starts a new gesture. Existing legacy callers without the native frontend retain their prior behavior and physical joins.

The frontend tracks streaming from actual startup/run/settled/switch records. Streaming Escape uses `pisharp_interrupt`, carrying the admitted session generation and current editor text. The request is revalidated inside the frontend state lock; command and request identity must both match its response. The original bounded restoration input deferral and single-claim editor receipt remain in use. Idle Escape preserves the draft; repeat Escape does not issue a second interrupt.

The RPC command shares the authoritative atomic queue-take preflight. After validating the owner and dispatcher generation under the existing transition lock, it cancels only that attachment, not the replaceable owner's global abort path. It captures the original session-idle and dispatcher-settled tasks, releases the transition before physical output, then releases the publication gate before joining those tasks. Thus settlement can publish its own output without a semaphore cycle. Caller cancellation cannot detach postcommit delivery or captured run cleanup. An unrestorable/oversized queue remains intact, but a valid noncanceled interrupt still aborts the run. A stale generation or a cancellation before admission does neither.
