`pisharp_restore_queue` requires a captured positive integer `generation` and bounded `currentText`. Under the existing queue-publication gate and short admission transition, the dispatcher checks the actual owner/dispatcher attachment, captures the in-process authoritative snapshot, and preflights the complete combined editor text plus both serialized output frames. `RpcQueueRestorationPlan.TryCommit` calls the core `TryClearPendingInputQueues` once. A stale, foreign, changed-mode or ABA snapshot rejects without removal; there is no unconditional clear or implicit retry. The core's opaque revision token and complete ordered entry-reference comparison prove that the preflight response describes exactly the removed snapshot. No token enters the wire.

After commit, the dispatcher releases the admission transition and directly awaits the prebuilt empty `queue_update` followed by `{generation,text,count}` in the correlated success response. Caller cancellation cannot detach either physical write or roll back removal. The queue-publication gate keeps later queue publications and session-switch callbacks behind these frames. New admissions can proceed during held output and publish their later snapshot afterward. Before-commit cancellation, unsupported content, stale generation, capacity failure, and response-budget failure do not remove messages.

Native limits: at most 512 messages, 65,536 UTF-16 characters for the combined editor value, valid UTF-16, and the configured RPC output budget. Only text-only user messages are supported; system messages and image/nontext content are rejected intact instead of silently losing their semantics. All-whitespace blocks follow ECMAScript trim filtering, while retained blocks preserve raw spacing, duplicates and multiline text. The bounded implementation conservatively rejects a queued block over the editor limit even if it consists entirely of whitespace.

The frontend has one outstanding restoration request. Only its matching response can yield a single-claim receipt for the original editor lifetime, text and session generation. Preview arrays, duplicate responses, stale generations and foreign editors grant no edit authority. Malformed replies retire the waiter before failing the output observer. Success is visible in the actual draft paint rather than an optimistic status. The existing SetText path preserves normal edit/undo behavior. Empty results preserve cursor/draft state; configured key-release/repeat records do not repeat the action.

While restoration is pending, ordinary editor keys retain their order and remain charged to the existing 32-input limit. Focus and selector events continue through the same consumer, avoiding an output/input wait cycle. Restoration-era keys carry their original session generation and cannot replay into a switched session. Shutdown retires unconsumed focus admissions, cancels only the response wait, and joins the original sender, reader and physical output. Original operation joins have no timeout wrapper; observation deadlines are protected by cleanup that releases holds and directly joins originals.
