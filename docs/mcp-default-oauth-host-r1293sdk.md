# Explicit default MCP OAuth host

This leaf composes the reviewed discovery, state provider, authenticated HTTP replay and serial OAuth orchestrator for one application generation. `McpDefaultOAuthHost.Install(McpDefaultOAuthHostResources)` takes every external resource explicitly. It creates no HttpClient, browser, entropy source, credential store, environment reader or network permission.

Supply the exact MCP server, redirect URI, client metadata, state store, clock, 32-byte entropy operation, browser redirect operation, response-state validator, physical HTTP factory, endpoint/purpose admission predicate and affine cancellation admission. Optional authorization-state and custom client-authentication callbacks are single-cast. Every proposed discovery, registration, code, refresh and browser endpoint is checked before invoking its physical resource. Responses and requests are bounded by MaximumBytes.

`CreateAuthenticatedRequestFactory(physical)` uses the existing exact-server authenticated HTTP replay owner. `AuthorizeAsync(Options())` begins authorization or refresh. Code responses use `CompleteAuthorizationAsync(code, returnedState, scope, token)`; the required supplied state validator settles before code HTTP. The code/refresh/registration translators never save state. The existing orchestrator is the sole owner of client, verifier and token persistence, invalidation and the original one-retry policy. Wire OAuth errors retain status/code provenance; local malformed-token/authentication failures remain ordinary refresh fallback errors.

The generation supplier places the host's stable DisposeAsync original in its own NativeResources. It stops/joins the channel and joins host close independently. Cancellation that enters supplied callbacks, including after an await, must use the host's required CancellationAdmission and directly join CancelAsync. Callback reentry into the same authorize/close owner is refused before effects. Cancellation begins the physical Stop original before a held Send is joined; send/body/stop/disposal faults are retained together. Borrowed store/browser/HTTP resources are not disposed by the host beyond each acquired request owner and response.

CapturedOriginals retains actual Tasks, first-observed Task.Exception aggregates and direct exceptions. Aliases intentionally share Task references. Internal admission witnesses expose actual acquired originals to deterministic held controls; they do not create substitute operations or cache pending Task.Exception. Six source-only controls cover discovery/dynamic registration/PKCE, validated code completion, wire invalid-grant versus local fallback, pre-effect admission and reentry, held browser cancellation/close, shared unauthorized refresh, faulted OCE versus genuinely canceled send, and actual body/store/stop faults.

No controls are registered in a shared Program, compiled or executed by this source handoff. The MCP application installer may consume the new authenticated factory through its admitted channel supplier; the existing profile/canonical CLI hook remains untouched and requires the separately owned integration patch. This is not a full OAuth/browser/default-profile/runtime or package acceptance. JSON duplicate-key, finite-bound and CLR DTO policies remain the admitted native boundary; malformed URL/query corner semantics have not been paired against the original JavaScript.

Original source references are the pinned v0.99.1 oauth/flow.ts, provider.ts, types.ts and errors.ts from commit d86654abb8862e201933517d6f1fce9f88dd117f. The handoff contains their exact hashes and byte counts.

The custody successor transfers a late successful physical response or body stream into the actual cleanup inventory before post-await cancellation is observed. Synchronous stream/response/request disposal is recorded as a direct invocation with no invented Task; cleanup still attempts every acquired resource and retains sibling faults. The held-browser group also invokes a held late-success response control with exact Stop and response-disposal faults. The shared-refresh group additionally checks that an insufficient_scope challenge forwards its exact scope and skips refresh before redirect. Dynamic registration follows original timestamp filtering and missing redirect_uris normalization while preserving unknown fields. These extend the same six authored groups; none are executed.
