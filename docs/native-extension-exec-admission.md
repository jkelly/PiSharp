# Supplied native execution capability

This source-only leaf binds an explicitly supplied separated process runner and one caller admission callback to the actual native extension initializer owner. It is available before session attachment. The callback resolves a requested command to an absolute executable, exact ordered arguments and cwd, explicit environment, one-use spill path, and unchanged positive timeout. It does not create executable authority or search an ambient PATH.

The installer accepts one actual registry and one initializer binder. A future CLI loader factory must verify that exact registry before decorating the original plugin once. Installation and public profile forwarding patches remain separately reviewed proposals. Existing Runtime callback View and original Node pi.exec wiring are not installed by this leaf.

Every acquired supplier/process/initializer/disposal task is directly joined, with its aggregate and direct observation cached once per actual Task reference. Owner retirement revokes new calls, cancels held work, joins ignored mapping returns and actual process originals, then independently joins original plugin cleanup. Mapping tasks are explicitly distinct from process originals. Synchronous unowned cancellation remains a fault; reentrant supplier execution/close is refused.

Results require complete separated output, confirmed cleanup and no infrastructure diagnostics. Natural nonzero exit remains result evidence. Truncated output fails closed. Windows private-job termination, bounded capture, pre-spawn cancellation and whole-buffer UTF8 decoding differ from the original unbounded per-chunk Node implementation; no full pi.exec or JS wire parity is claimed.

Fourteen authored source controls are unexecuted. No process, compiler, Node or network operation has been run for this leaf. Successful private internal pipe task identities are not exported by the underlying runner; its actual joined structured receipt is retained instead.

Cancellation callback safety is bounded explicitly. Supplier ancestry is tracked across A-to-B-to-A calls, but a token callback can restore an unrelated ExecutionContext. Public DisposeAsync therefore refuses calls while cancellation dispatch is active, or while an acquired operation remains pending with an already canceled supplied signal or owner token. This also rejects unrelated concurrent external public close calls during that interval. The trusted installed owner uses its internal retirement path to cancel and join the same stable cached original; it never bypasses the public boundary on behalf of a supplied callback. Outside the rejected interval repeated public closes share that original. Universal public concurrent-close parity is not claimed.

Synchronous admission and runner callbacks additionally carry a thread-local physical ancestry frame around invocation and ValueTask.AsTask conversion, restored on the same thread before awaiting. This survives ExecutionContext.Run with an unrelated captured context. Arbitrary cross-thread callback dependency cycles outside the admitted logical ancestry/canceled-active contract are not claimed detectable; supplied callbacks must not retire an active self or ancestor owner.

Each synchronous frame retains both its logical and physical parents, rather than selecting one. Reentry checks walk both roots/parents iteratively using reference identity and a 1024-frame fail-closed bound; shared ancestry is visited once. The distinct logical-A/physical-C into B unrelated-context control is authored and unexecuted.
