# Registered MCP profile refresh

Registered admission enables one profile refresh operation through the actual replaceable-session reload reservation. Acquisition captures the bridge's current committed metadata and retains the current native profile view. The reservation owns the new runtime before old authority changes, drains old work, publishes the new catalog through the durable session transaction, binds the candidate profile view, and joins previous runtime cleanup. Session close joins the same owned reload original.

Active names retain permitted surviving selections. New default extension tools are selected only under the existing lifetime selection policy. MCP metadata is already committed before this refresh; the catalog transaction introduces no second native-registry mutation. Native extension loading/reloading and durable cross-store atomicity remain separate admitted host workflows.

The new source-only control attaches a genuine profile/session, discovers one admitted direct tool, unregisters its metadata, refreshes to an empty MCP catalog, requires the generation-two registry and active selection to omit the old tool, and checks both generations' retirement plus the session writer close. It uses injected channels and independent per-generation capture registries, with no live service or process.

The ordinary command control now retains its actual command Task and complete original exception inventory when command execution faults. Its explicit registry cleanup preserves the primary failure without an additional outer automatic disposal overwriting it.

All controls remain unexecuted. Genuine codemode discovery identity and loader-composed SDK/MCP initialization controls still require integration and qualification.
