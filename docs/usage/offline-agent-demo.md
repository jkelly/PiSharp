# Offline native agent demo

This executable exercises the native request, streaming, agent, tools and durable session stack without calling a provider. It is a deterministic development milestone, not the full Pi CLI, an upstream differential oracle or a phase acceptance result.

Use a built `PiSharp.Cli.dll` with .NET 10 and explicit new absolute paths:

```powershell
dotnet src/PiSharp.Cli/bin/Release/net10.0/PiSharp.Cli.dll --offline-demo --workspace C:\Temp\pisharp-demo-new --session C:\Temp\pisharp-demo-new\session.jsonl
```

The workspace parent must already exist. The workspace and session must both be absent before the demo starts; rerunning with the same paths is refused. The session must be a direct child of the new workspace and cannot be named `input.txt` or `answer.txt`. Paths are capped at 2,048 UTF-16 characters, require valid Unicode and exclude control characters. Windows UNC, extended and device namespace paths are unsupported in this local demo profile. The demo uses the explicit created workspace as its home path and reads no home configuration, credential store or provider environment key.

The CLI creates synthetic UTF-8 `input.txt` in the owned new directory. An inert explicit key passes through `ResponsesKeyAuthRequestFactory` into an actual `HttpRequestMessage` for `https://offline.invalid/v1/responses`. An injected deterministic `HttpMessageHandler` checks the request and returns authored SSE events; it makes no socket or HTTP network request. The native `ResponsesHttpSseTransport` decodes those events and the stateful agent executes `read`, then `write`, then a final assistant response. The real read result and successful write result must appear in subsequent projected HTTP request bodies. The handler checks actual `answer.txt` bytes before sending the first final answer.

The tool declarations are the native read/write owned declarations persisted as a system-message `toolsAdded` array and projected into actual top-level Responses function tools. The prepared-action policy examines final target and operation. It admits only reading `input.txt` and writing `answer.txt` within the canonical owned demo root; the session log cannot be a model tool target. Fixture input creation and session storage are explicit host setup/persistence operations. This policy and existing-segment path resolution do not provide hostile path-race confinement or a native-code sandbox. The demo expects a trusted local parent directory and no concurrent outside writer; freshness checks do not atomically reserve a directory against hostile races.

`PersistentAgentSession` durably records committed inputs, finalized assistant messages and tool results through `SessionLogStore`. The demo captures its acknowledged byte length and selected leaf after the first completed prompt, closes the coordinator, inspects the settled JSONL bytes and reopens the same latest branch. A second prompt uses the persisted first user message, function calls/results and final answer. The handler rejects the resumed request if this history is absent. Final session bytes must preserve the first committed prefix and match the coordinator's acknowledged byte length. The store's local flush-to-disk acknowledgment is the supported durability profile; this does not prove power-loss or remote filesystem guarantees.

On success, stdout contains one owned JSON report with four actual request payloads, the two final policy actions, actual output text, both final assistant texts, session byte lengths/hashes and reopen/prefix checks. `networkUsed: false` describes the intercepted HTTP transport; no provider network is used. The report explicitly marks the data authored and keeps upstream differential and phase acceptance claims false. It contains no authorization header value. Errors produce one fixed-message JSON diagnostic on stderr: exit 2 for argument/freshness rejection, exit 1 for an admitted run failure/cancellation, exit 0 for success. `--help` prints usage and performs no demo effects.

Failed or canceled admitted runs can leave directories, partial file effects or session bytes in the explicitly created workspace. Owned callbacks and coordinator disposal are awaited; the CLI does not delete or roll back those effects. Inspect the owned files, and use new paths for a new demo. Cancellation is cooperative and supplies no forced background timeout. The production read/write text, size, alias and cancellation limits remain those in [read-write-tools.md](../contracts/read-write-tools.md); images, other encodings, edit/shell tools and broader CLI modes remain unfinished.

`OfflineDemoTests` launches the actual compiled CLI in a hidden child process using explicit absolute .NET host and CLI DLL paths supplied by the root test helper. It verifies real file bytes, all four request payloads/declarations, selected policy targets, session JSONL roles, durable byte hashes/prefix and rejection without writes to existing paths. `Configure(dotnetHost, cliDll)` supplies those paths; `Cases()` returns three groups. `Evidence` is a cloned JSON report from the successful actual child for inclusion in the root-owned structured test report. Tests create and clean only uniquely named owned temporary roots. Source and tests are supplied for isolated root-owned build/execution; this document claims no unexecuted pass.
