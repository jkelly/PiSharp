The application installer maps loaded original configuration and committed extension metadata to explicit named HTTP or stdio capabilities. Its constructor is inert. Every enabled entry's configuration validator runs before channel construction or generation resources are acquired. Disabled entries acquire nothing; unknown names, wrong transport and missing exact server owners fail before publication.

`McpApplicationHostInstallation.CreateRegisteredAdmission()` is accepted by the existing profile registration path. `Bridge` is the same native bridge to use during genuine initializer activation/commit and joined owner retirement; the installer never activates an owner twice. Every acquisition receives that bridge's current committed catalog. Generation resources supply actual empty server registry/scopes, exact argument admission and hook composition, plus independently owned discovery semantics. The installer constructs the genuine `McpPreOpenServerCapture` factories. The existing runtime/profile pipeline performs activation, real final-catalog discovery-identity validation, attachment binding, refresh/withdrawal and joined cleanup. This creates no parallel session lifetime.

Capabilities must explicitly compare the configured command/endpoint/headers with their admitted resources. A channel-factory construction callback is effect-free: it may prepare a delegate, but cannot acquire a connection or allocate an unowned resource. Actual allocation belongs to the returned channel factory, whose exception path joins its own allocations. HTTP can use `AdmittedMcpHttpChannelFactory.Create`; stdio can use `McpRegisteredServerWireAdmission.CreateChannelFactory` over an admitted process-wire callback. The OAuth lane can supply its lifecycle-owned authenticated physical request factory; its owner belongs in generation resources. No clients, child processes, credentials, browser, filesystem configuration or interpreters are obtained from ambient state.

The generation supplier owns all allocations until a successful return. Its returned native owner owns every server registry/scope, and its distinct discovery owner owns the semantic registry/executor. A rejected return joins both independent originals. Each reload must return fresh scopes/resources. Once accepted, existing runtime ownership takes them over and closes channels before their backing generation resources. Callback executors, resource savers and OAuth adapters are separately admitted.

Eight source-only cases are exposed by `McpApplicationHostInstallationTests.Cases()`: pre-acquisition configuration refusal, held acquisition cancellation, held cleanup with both independent faults, faulted source with full sibling inventory, synchronous unowned callback cancellation remaining Faulted, the actual downstream activation's second validator cancellation remaining Faulted, reused owner refusal preserving the live owner, and real public profile generation replacement after joined native metadata withdrawal. `RawCapturedOriginals` exports actual Task references with one cached aggregate and direct observation per Task across aliases. Actual generation suppliers and resource disposal tasks are retained before awaits and individually joined in finally. The new cases are not registered in shared Program.cs and have not been compiled or executed. Their qualified runner must select them explicitly and export the actual originals with the bounded task/fault DAG reporter.

The narrow proposed profile overload is a separate patch artifact until root reviews the leaf API. No canonical or existing profile source was changed by this delivery. The installer completes reusable host composition; a concrete application still supplies its authorized resources and actual initializer host. It does not grant default ambient connection authority or prove full original MCP parity.
