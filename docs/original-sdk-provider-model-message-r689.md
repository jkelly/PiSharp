# Provider, model and message facade continuation

This source candidate extends the frozen flags leaf `b6699684240553ed42a21f768df4d3c83bc06fb2`. It implements native owner-bound provider registration/catalog/stream dispatch and command model/message actions. It does not assert full JavaScript ABI equivalence or completed CLI/session host wiring. Original Pi 0.99.1 is pinned at `d86654abb8862e201933517d6f1fce9f88dd117f`, extension loader `registerProvider`/`unregisterProvider` and action forwarding, and `types.ts` provider and send-message contracts.

`ExtensionProviderRegistrationHost` receives explicit admitted built-in definitions and an admitted configuration adapter. An extension binds its actual `IExtensionRegistry`, stages provider definitions, and the host calls `CommitOwnerProviders` after directly awaiting genuine `ActivateAsync`. Registration after that commit is immediate. The native overload carries an immutable model catalog plus one actual `StreamSimple` implementation. The name/config overload invokes the supplied host admission adapter exactly once and requires its resulting provider identity to match. That adapter must map raw original provider options to genuine admitted protocol/custom-stream/OAuth behavior; it grants no new environment lookup, command execution, credentials, transport acquisition or network capability. A synthetic resolver returning a catalog entry without a real implementation is not API completion.

Replacing a provider replaces its whole model list and stream implementation. Exact model/API/provider identities and metadata identity fields must agree. Definitions are immutable; an already admitted stream keeps its selected old implementation. Replacement within an owner reuses its exact native marker, avoiding a temporary extra registration charge at a quota boundary. Unregister is idempotent, removes only that owner's current provider and restores the admitted built-in models. A shadowed owner's unregister cannot remove a different winning owner. Old shadowed definitions are not resurrected; built-in restoration is explicit. Failed initialization has no public catalog effect. Close retires the owner definitions through its real lifetime token. Catalog order is ordinal provider order and declared model order.

Metadata markers are real native observation entries with no-op callbacks. Their role is no longer merely descriptive during stream invocation: `ExtensionRegistryProviderLease.cs` uses the existing native `AdmitCurrent` and `ReleaseAdmission` to acquire the exact marker's entry/owner leases, including snapshot/generation/state/concurrency checks. The stream runs under a real `CallbackFrame` and actual native UI/session context. Native owner cleanup waits for the provider's original MoveNext task and iterator Dispose task. Removal does not abandon a selected in-flight stream. Enumeration captures every returned ValueTask into its original Task once and directly awaits it, without a cancel-detached wait. Creation/move/disposal/context cleanup failures are retained together with full original task aggregates. A source-faulted OCE remains a fault; only a canceled original with the requested matching owned token becomes cancellation. The consuming host must dispose its enumerator when it stops consuming, as with the existing transport contract.

`ExtensionProviderTransport` is an explicit existing-`IChatTransport` adapter in Extensions.Agent. It forwards the actual `ChatRequest` model/messages/timestamp/thinking level to that leased stream dispatch, with no producer task, channel or queue. It exposes supported thinking levels from the current admitted model metadata. A standalone control constructs the existing `Agent` with this adapter and requires its actual assistant-ended event from the registered provider; this is authored evidence, not a runtime result.

`ExtensionRegistrationCommands` constructs a genuine native command descriptor. It requires an actual executing `ExtensionCommandContext`. Its admitted application host receives `SetModelAsync`, `SendMessageAsync` and `SendUserMessageAsync` calls; the facade never synthesizes selection success or delivery. Model identity must exist in the current admitted catalog before invocation. Message DTOs preserve false, absent options, explicit JSON null details, custom display/type, triggerTurn, steer/followUp/nextTurn and user expandPromptTemplates. Text/image content blocks are bounded and validated before effects. The owning application still decides real queue/turn/session semantics.

Each command action slot is registered before calling the admitted host. Its exact original Task is captured once and directly awaited. Even if extension code ignores its returned ValueTask, command completion closes admission and joins the actual host task before the native callback lease exits. Full fault inventory, a synchronous no-original fault, matching canceled-original status and primary/cleanup collisions are retained. The action view is tied to an active originating command lease and cannot be used afterward or from an unrelated invocation.

Native bounds: at most 128 owners/providers per owner/builtin providers, 256 models per provider, 128-code-unit names/model/API identity, 1 MiB cumulative model metadata/transcript, 4096 transcript messages/content blocks, 65536 stream frames and 128 action originals per command. Existing registry admission quotas remain authoritative. This bounded profile is distinct from permissive malformed JavaScript domains.

The standalone project now has fourteen groups: six frozen flag groups plus eight provider/model/message groups. New groups cover staged catalog/config forwarding/replacement/builtin restoration/foreign owners; the real existing Agent pipeline; held owner close through MoveNext and iterator disposal; original multi faults plus disposal collision and faulted OCE; matching owned cancellation; ignored real host action joins and message option forwarding; validation/stale action views/full ignored-host fault inventory; and rejection of a saved native context during a later same-owner callback before any user/host effect. Held tests release and join originals in finally, and report full reference-indexed original fault DAGs. No compiler, restore, build, test, Node, live API, package acquisition or credentials ran in this source lane.

Remaining real shared integration paths are explicit. The automatic Runtime adapter now resolves the admitted action capability only through `ExtensionCommandContext.GetFacadeHostForAdapter()`, after exact originating-frame validation. The separately admitted explicit-host overload uses the same validation without requiring a configured read host. The public read-only wrapper never exposes raw mutation interfaces. The root-owned `NativeExtensionActivation.cs`/`NativeExtensionContextFacadeHost.cs` composition must install the provider/config/action dependencies, commit after activation, and construct the actual session/Agent with `ExtensionProviderTransport`. Existing `PersistentAgentSession.ConfigureAsync(SessionRuntimeUpdate)` and `SubmitInputAsync(PromptInput, admission, options)` are real model/delivery boundaries. Its `SessionRuntimeRegistry` currently has an immutable model binding map: selecting a newly registered model after session construction needs an explicit admitted dynamic-model resolver or a reviewed reconstruction boundary. Simply forwarding ConfigureAsync cannot close that gap. Original provider OAuth, refreshModels and acquisition/config interpolation must be mapped by real admitted host adapters; no fake completion is claimed here.

Re-entry correction: factory/GetAsyncEnumerator, every actual MoveNext/Current, iterator Dispose and native context disposal each install their own actual owner CallbackFrame for the original await, removed before yielding. The Agent group also drives two synchronous reads and verifies self-close/quiesce refuse in factory, Current, second read and disposal, retaining and joining any unexpected returned originals on regression. Diagnostic fault tables are iterative, capped at 1024 nodes/4096 edges with explicit truncation; all admitted control inventories must fit without truncation. Report write and stream disposal faults retain both exact references.

Synchronous Current failures have a separate current-phase no-original-task wrapper. A Current getter OCE with no requested cancellation remains an outer fault; the multi-fault group now verifies its exact synchronous fault reference and preceding successful MoveNext/disposal original statuses.
