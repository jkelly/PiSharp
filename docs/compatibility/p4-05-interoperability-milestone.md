# Original P4-05 import, migration and export qualification

This milestone follows the original work package in [Phase 4](../plans/04-sessions.md), without changing its dependencies P4-01/02/03 or the original eight phase gates. It builds on independently accepted lifecycle `2759aba53fd9485611de1b769bde1e69186be44d` and history `b3c1942bc5eebc6d73c3157e20e25b797afbecc7`. Source baseline remains Pi v0.99.1 `d86654abb8862e201933517d6f1fce9f88dd117f`.

The actual non-destructive import and export operation is `SessionCopyService.CopyAsync`, also exposed through the shared read-only lifecycle API and compiled `session migrate` / `session copy` commands. Destination selection is explicit; a transcript ID, cwd, image path, extension ID or serialized type never selects a filename or gains execution authority. V1 tree IDs come from the explicit caller plan, making repeated imports deterministic. The pure migration preserves owned source records and enumerates each header, identity, parent, compaction-reference and hook-role transformation. No source file is rewritten.

The new `NativeArchiveExact` format publishes only a complete captured byte sequence to a new explicit destination. It preserves future headers, damaged JSON and invalid UTF-8 as opaque archival data and reports `ArchiveNotRunnable`; it never admits them into the current append store or provider context. A capture lacking observed EOF cannot publish. Existing input/output ceilings, cancellation, no-overwrite rename, temporary ownership and joined cleanup apply unchanged. Native exact current export preserves byte framing; current JSONL export preserves raw record fields while applying explicit migration transforms.

Every clean export includes an explicit retention report: exact source-byte preservation, excluded record/field counts, ordered unknown entry identities retained as inert data, current-format admission and whether general Pi-reader interoperability is guaranteed. Archive identities are read from original captured bytes, including original legacy IDs; an explicit migration plan cannot replace identities in unchanged archive bytes. A missing or nonstring unknown-entry ID reports `ArchiveIdentityInventoryIncomplete` alongside the identities actually present. Unclassifiable records, invalid UTF-8, malformed or duplicate-property JSON, excessive JSON depth, empty input, and inventory resource limits report `ArchiveIdentityInventoryUnavailable` with an empty identity list. These inventory limitations do not exclude archive bytes or grant current admission. Current JSONL output reports identities actually applied by its migration. The compiled receipt's `migration` field remains the inspection proposal; `migrationAppliedToOutput` is false for archives, true for published migrated current JSONL, and null when no output was published. No native-only state is excluded by these formats, so exclusion counts are zero. Future/damaged archival data is never labeled runnable. A bounded fixture comparison does not guarantee arbitrary-file semantics, and all raw numeric tokens remain available even when the JavaScript reader observes binary64 conversion.
