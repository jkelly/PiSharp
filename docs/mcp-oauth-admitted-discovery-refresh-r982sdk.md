# Admitted MCP metadata discovery and refresh-only OAuth flow

This source implements the next protocol seam beyond provider state and bearer challenge retry. McpAdmittedOAuthDiscovery derives and requests the original protected-resource and authorization-server metadata candidates. McpAdmittedOAuthRefreshAdapter uses that metadata and an already admitted client/refresh grant to issue one form-encoded refresh, parse the result and persist it through the existing explicit state-store provider. CreateAuthentication supplies actual token/unauthorized callbacks to the R976 authenticated HTTP operation. No new background owner is created: each returned callback Task must settle and is joined by the HTTP operation. Concurrent unauthorized callbacks share one retained refresh Task; its exchange is anchored to the initiating callback token, as the original adaptation uses that first context's fetch. A later request with a token already replaced skips a redundant rotating-token refresh.

All HTTP effects require the caller-supplied McpAdmittedOAuthExchange. Proposed endpoint/method/headers/body/purpose are data, not authority. The delegate must independently admit each URI and fully own/join its physical response/read/close work before returning its response DTO. There is no default HTTP client, fetch, endpoint permission or network acquisition. An explicit IMcpAdmittedOAuthStateStore and clock are mandatory; configured client information is optional only when the admitted state already supplies it. Request/response/challenge/cached-discovery UTF8 bytes have finite ceilings, and immutable JsonData retains metadata unknown fields within its existing depth64/duplicate-property constraints. Diagnostic DTO ToString methods omit credentials. Default CLI/profile policy is not changed or silently granted access.

The pinned source is Pi v0.99.1 d86654abb8862e201933517d6f1fce9f88dd117f: packages/mcp/src/oauth/discovery.ts, flow.ts, provider.ts, types.ts, errors.ts and auth-provider.ts. Implemented decisions include protected-resource path then root fallback for4xx/502; up to three OAuth/OIDC issuer candidates in original order; issuer equality ignoring a trailing slash; resource origin/path coverage; bearer/dpop challenge resource_metadata/error parsing; cached discovery; selected client_secret_basic/client_secret_post/none; resource field; OAuth coded body errors taking precedence over HTTP status; finite expires_in coercion for JSON primitives/array string coercion; old refresh-token preservation when absent and explicit rotated-token replacement. Expiry uses the existing provider's clock-at-save invocation semantics. Stored state for a different exact normalized server URL remains ignored.

This is refresh-only, rather than full authorizeMcp. Missing configured/stored client information, missing refresh grant or insufficient_scope returns an explicit authorization-required exception; no registration, redirect, PKCE, callback server, browser, authorization-code exchange or token acquisition is invented. Invalid-grant/client recovery and authorization fallback remain unimplemented. Expired token reads are not proactively refreshed, matching the original adapter's token read. Refresh failures do not claim original browser fallback. Native callback failures preserve complete Task.Exception and direct exception references instead of swallowing arbitrary foreign exchange failures during protected-resource discovery. Metadata URL admission is HTTP/HTTPS only and cannot skip issuer validation. Cached opaque JSON is revalidated, unlike the original provider's typed cached assumption. Native JSON/byte bounds and unflattened failure wrappers are explicit ABI adaptations, not JS object or full OAuth parity.

Each admitted ValueTask is materialized once. Actual store/read/update/exchange/shared-refresh originals are directly awaited; synchronous failure has a null original. Faulted OCE remains Faulted, while a genuine original canceled with the requested owned token retains the original Task and cancellation exception in an OCE-derived envelope. A shared active callback frame rejects same-provider token/unauthorized reentry before returning an in-flight task or effects, and deactivates when its actual work settles. There is no independent Close method to create a second owner or a cancellation self-join. HTTP-operation cancellation still joins held exchange/store originals; a callback ignoring cancellation must settle, and already admitted store writes are joined. No token HTTP request or new token write begins after an observed cancellation fence.

Six authored groups in McpOAuthDiscoveryRefreshTests cover exact candidate/header order, issuer/resource refusal before token effects, actual McpServerRuntime initialization over an in-memory HttpMessageHandler with a401 followed by refresh and bearer retry, exact form payload/token persistence/clock expiry, changed-token suppression, concurrent held refresh/reentry, authorization-required/coded error handling, Basic/POST methods and expiry coercion, foreign-state isolation, exact shared store faults/faulted OCE and held canceled exchange settlement. Expected failure controls acknowledge complete bounded carrier/container/leaf graphs and retain observed failures if predicates reject. Subsidiary Task/aggregate/direct references are exposed as CapturedOriginals. All exchange/store tokens are synthetic; no sockets or credential access occur in controls. Six Cases require explicit coordinator registration and native qualification; no shared Program or project edits were made. These controls are unexecuted and provide no runtime credit.
## R993 required cancellation admission and parsing correction

The adapter constructor now requires an affine `McpOAuthCancellationAdmission`, bound only after all constructor validation. The caller must give this same admission to its exchange/store owners. Cancellation effects initiated after awaited callback work that can execute callbacks synchronously must use `Cancel(borrowedSource)` or directly join `CancelAsync(borrowedSource)` before that callback original returns. The latter returns the actual `Task.Run(source.Cancel)` original: it does not catch, detach, normalize or discard any cancellation-handler aggregate. No cancellation source is acquired, created or owned by the hook.

The physical entry frame exists only around actual synchronous dependency invocation or owned cancellation. Its logical and physical ancestry are captured before worker scheduling and restored at the worker's actual cancellation entry. An earlier normal `CancellationToken.Register` can restore a frame-free execution context without removing this physical entry. Own and active ancestor token/challenge reentry is refused before state reads, writes or joining the shared refresh. Unrelated adapters remain available. Shared logical frames are deactivated in `finally`; ancestry is not a permanent descendant prohibition.

This is a REQUIRED caller admission restriction, not a claim that arbitrary unrestricted callbacks are safe. Direct cancellation from an arbitrary callback continuation after an await, bypassing the admitted hooks and restoring a frame-free registered context, is outside this API and remains capable of a self-join. The predecessor R982 unrestricted source is preserved and blocked. Direct cancellation during the actual synchronous admitted dependency entry is guarded separately.

The six existing case names remain. The shared-refresh group now additionally exercises direct entry cancellation, after-await synchronous/asynchronous admitted cancellation in both exchange and pending store write, nested cancellation owner/ancestor refusal, and unrelated adapter success. All rejected and cancellation originals are captured and finally joined. The fault group acknowledges the full cancellation aggregate with a faulted OCE and duplicate nested leaves, and rejects extra wrapper/container/sibling shapes.

Present optional strings must be nonempty as in pinned `optionalString`. Empty refresh token/scope/id token replies fail before token persistence and preserve the old grant. Only URL errors from protected-resource metadata parsing are tolerated as discovery misses; callback faults, cancellation, admission/byte bounds and authorization-server issuer checks remain failures. Malformed resource and authorization-server URL controls prove origin discovery fallback. All controls are authored only; no compiler, test, native, HTTP or browser execution has been performed by this worker.
