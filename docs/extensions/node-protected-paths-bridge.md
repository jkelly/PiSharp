# Protected paths: first real Node hook bridge

This candidate loads the unchanged public `protected-paths.ts` extension from Pi v0.99.1 (`d86654abb8862e201933517d6f1fce9f88dd117f`) in a separately launched, explicitly admitted Node worker. The whole public `loadExtensions` export uses the pinned official Jiti 2.7.0 loader. The returned JavaScript hook remains in Node. An actual native `ExtensionRegistry` publishes its C# proxy atomically, leases each callback, and supplies the real native UI context. This is an authored candidate awaiting compilation, execution and independent qualification; it earns no phase completion or product parity credit.

The prototype uses the explicit read-only oracle, official Jiti root and canonical real-extension reference root already qualified by the parent. It does not install, extract, discover a runtime, alter source or fixtures, execute package scripts, or invoke the upstream Agent engine. The launch profile is closed: fixed entry bytes, exactly three helper files, exact plan bytes, approved Node runtime bytes, explicit qualified dependency roots and generation numbers. The existing fixed probe allowlist and entry digest remain separate. No core or CLI project acquires a Node dependency.

`PiSharp.Compatibility.Node` depends on Contracts, ExtensionHost, Extensions.Abstractions and Extensions.Runtime. `NodeToolCallExtension` implements the existing `IPiSharpExtension`; `NodeExtensionWorkerLaunch.ForProtectedPaths` admits this one worker profile. The native registry owns activation, owner generations, revocation and callback leases. `NodeExtensionUiBroker` owns one opaque protocol handle per extension owner and at most eight active tickets borrowing actual native contexts. It grants `Notify` only where the actual context advertises that capability. JavaScript functions, source runtime objects and closures remain inside Node; no function is serialized or reconstructed in C#.

The hook receives the complete source-shaped tool call and returns a complete owned observation. Undefined remains absent at the native patch boundary; the observation retains its explicit undefined ledger. Null, JSON values, own undefined, numeric bits, negative zero, functions and symbol properties retain the qualified observer's representation. When source input-before and input-after agree, the proxy retains the original native argument JSON, including its raw numeric spelling and whitespace. It does not classify JSON.stringify formatting as a mutation. General numeric materialization, unusual source result shapes and full extension API compatibility remain open obligations.

Source `ctx.ui.notify` remains synchronous. It queues a request to the native broker, whose actual `Ui.PublishAsync` is awaited; the worker joins admitted publications before the native hook settles. Cancellation first detaches the request observer, then an operation fence waits for the actual JavaScript `finally` and nested publications. The native lease is released after that fence. A publication that crosses its real output boundary and then fails retains an unknown outcome; there is no replay. This joined callback boundary is explicitly different from claiming universal original UI/Runner scheduling parity.

The native `ToolInvoker` remains authoritative. A prepared extension hook can block a native write before the final policy or file effect. A source continuation still passes native schema admission, prepared-action construction and final action policy. The tests use a separate real native write adapter for those facts. Several original source hook requests omit native tool-schema fields, so those eight raw requests are dispatched through the actual registry and leased hook rather than being misrepresented as eight executable native tools or eight complete Agent scenarios.

The qualified a667 input has eight whole reference cases. This slice selects its two protected-paths cases, containing eight requests: protected spellings, ordinary/read continuations, Windows separators and headless UI. All eight retain their original request, complete qualified dispatch and trace, actual source input/result ledgers, notification arguments and actual settlement. Only object property enumeration order is ignored when comparing JSON observation objects; array order, field presence, raw numeric values and ledger entries remain checked. No source or golden is changed. The other six whole cases, including hello, input transforms, commands/dialogs and the reference rollback control, remain open for real bridge qualification. The eleven-extension/42-scenario corpus remains mandatory.

The loader audits exactly one unchanged `tool_call` handler before and after every invocation. Other handlers, tool/command/flag/shortcut registration, renderers, markdown transforms, provider/native-provider/virtual-model registrations and MCP are explicitly unsupported in this profile. Shared event-bus operations also fail clearly. Other context and UI getters/functions fail at their boundary. The profile does not establish a permanent compatibility exclusion or a general support matrix: implementing these contracts is later phase work. The one qualified virtual-module replacement is disclosed and remains identical to the reference: the narrow public aliases provide genuine `Type` and `defineTool` identities. Full canonical namespaces, other SDK facades, custom components and loader branches remain open.

There are two authored factory controls. A held async JavaScript factory is supplied directly to the unchanged public `loadExtensionFromFactory`; it registers a staged hook, awaits release and throws the authored string. Its actual source-export rejection and complete thrown observer are retained before native activation rolls back. It does not test an additional failing TypeScript module through `loadExtensions`. A separate factory through that same public export registers an unsupported command and is rejected by the closed profile audit. The real protected-paths factory is synchronous; the metadata saying the public loader call was awaited is not evidence for every async module-loader branch. A separate native initialization hold tests atomic publication and its completion boundary.

Admission and finalization verify the complete qualified read-only identities: 2,093 acquired public source files against the recorded canonical and acquired fingerprints, nine existing repository metadata files, fifteen installed package inventories, the restored receipt, reference plan/input/golden/manifest and all its controls/helpers, official Jiti archive and sixteen publisher files. Native held read handles pin runtime, entry, all three bridge helpers and qualified metadata/control files during execution. Source and installed dependency inventories are rechecked before source loading and after source finalization; the native owner repeats inventory verification after actual process/I/O joins. No historical setup receipt is rewritten. The automatic load/read records begin after bootstrap qualification, so the pinned bootstrap helpers and archive inspector are separately accounted for rather than claimed as an exhaustive automatic load trace.

Runtime source-read rows remain complete for their declared post-bootstrap scope. Existing qualified immutable fingerprints and manifest/receipt entries bind all files, including assets and notices outside the code-read summary's declared extension set.

The original supervisor owns the real child, stdin writes, protocol read pump, stderr, post-protocol stdout drain and exit. Source finalization and its complete inventory checks finish before requesting process shutdown. Shutdown keeps the existing 500 ms grace and real kill/join fallback; the candidate does not extend that grace. All callback outcomes and transport tasks remain joined. The peer ends stdout and releases public stdio references only after handlers, publications, writes and shutdown acknowledgement settle. The owner drains remaining physical stdout only after the actual protocol reader joins; such tail bytes never become authoritative events or replies. This profile exposes no child-spawn capability.

Bounds are separate and explicit in the plan. Native and peer frames are limited to 1 MiB with depth 32 and 65,536 JSON values; connection admission limits encoded retained packets to 8 MiB, 32 pending calls/writes and 16 callbacks. Decoder buffers have their own 4 KiB read and 1 MiB partial-frame bounds. Native source packets are capped at 256 KiB. Each of four retained native last-record slots is capped at 512 KiB; no progress history is retained. Source observation paths are checked before the qualified observer allocates sidecars, with a 262,144-character aggregate path budget. Returned observations/records are byte bounded; source failed operations have an 8 MiB aggregate retained-failure budget and are removed at their actual settlement fence. Source operation counts, notifications, module/read tables and resolution counts also have fixed bounds. These bounds do not claim that encoded-byte accounting measures all V8 or managed heap memory.

Every mutable directory and physical HOME/TEMP/cache/agent identity belongs to the fresh caller-owned run root, outside repository/oracle/Jiti/reference/runtime inputs. A nonoverlapping task-local sibling, Temp or task-3 directory is legitimate. The child environment is cleared before the thirteen fixed profile entries are supplied; inherited secrets, arbitrary arguments and package execution are absent. JavaScript filesystem/process/network denial and admitted-module checks serve this trusted fixed-source prototype; they are not an OS sandbox or a promise to execute hostile extensions safely.
