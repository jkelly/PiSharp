# PiSharp 1.7.0 source preview

PiSharp's 1.7.0 candidate follows Pi and Pi Durable 1.7.0, including changes introduced upstream in 1.6.1. The latest published PiSharp package is [1.6.0.2](1.6.0.2.md).

## Try the candidate from source

From the root of a checkout containing the candidate, use the .NET SDK pinned in `global.json`. Restore once, then run either entry point.

```sh
dotnet restore src/PiSharp.Cli --source https://api.nuget.org/v3/index.json
dotnet run --no-restore --project src/PiSharp.Cli -- --offline --no-session
dotnet run --no-restore --project src/PiSharp.Cli -- durable --help
```

## Changes for CLI users

- Select a profile with `--agent-dir <directory>`. On terminals that implement OSC 7577, the resume command carries the profile and startup restrictions such as tool selection.
- Configure cache misses, cache warming, compaction costs and dropped reasoning separately under `notices`. The CLI no longer sends install telemetry.
- Codemode's `models.generateImages(model, context, options)` accepts `aspectRatio` and `size`. Usage includes reasoning and image output tokens when the provider reports them. The shipped catalog has 43 providers, and Radius can discover image and decision models from its configured endpoint.

## Changes for Durable applications

| When updating a caller | Use in 1.7.0 |
| --- | --- |
| Submitting inside an existing transaction | Rename `conversation.SubmitAsync(tx, draft)` to `conversation.AdmitAsync(tx, draft)`. The regular entry point remains `SubmitAsync(draft, context)`. |
| Returning a tool park | Use `ToolPark.Sleeping(...)` or `ToolPark.Waiting(...)`. Read the flat park fields after checking `Kind` for `sleep` or `wait`. |
| Returning a yield or compaction decision | Construct `OnYieldResult.Continue(...)` or `OnYieldResult.Tasks(...)`. For compaction use `CompactionDecision.Declined` or `CompactionDecision.FromSummary(...)`. |
| Reading a signal or a storage commit result | Switch on `Kind`. Signals use `value` and `expired`. Commits use `stored` and `refused`. A delivered JSON null is a value. |

PiSharp retains its existing Chord v1 peer protocol. For test results, platform limits and the pinned source inventory, see the [compatibility decision](../decisions/0018-pi-1.7.0-sync.md).
