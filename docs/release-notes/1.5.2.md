# PiSharp 1.5.2

PiSharp 1.5.2 ports Pi **v1.5.2**, including v1.5.1, and updates all 28 libraries and the CLI package together. This release includes the native AI, CLI, Durable, Chord and extension-runtime updates below. Package publication is recorded separately in the public release ledger; these notes do not claim complete upstream or provider parity.

## Source and scope

The candidate pins `b4afdddf44e059c67ccf5097e5317d913521b470`. The complete local Git comparison against v1.5.0 records **2,531 changed files** across every package and the repository root, with hashes and rename/deletion endpoints. See [the inventory](../../compatibility/sync-1.5.2-files.json), [file-by-file applicability](../../compatibility/sync-1.5.2-applicability.json), [decision 0014](../decisions/0014-pi-1.5.2-sync.md) and [work plan](../../AI_DOCS/sync-1.5.2.md).

## Changes

- **AI and CLI:** shared session-scoped strict-tool fallback state, model refresh, prompt-cache retention, input/session cleanup, missing-directory session choices, queued-image handling and tool/process corrections. The complete exact 1.5.2 catalog contains **43 providers and 1,773 entries** (1,643 chat, 66 image, 64 classifier), with **82 additions, 21 removals and 104 changes**. Its [package provenance](../../src/PiSharp.AI/Catalogs/Releases/1.5.2.provenance.json) and [catalog report](../../AI_DOCS/agent-reports/sync-1.5.2-catalog.md) preserve hashes; native capability binding and request regressions remain part of final validation.
- **MCP, schema and codemode:** OAuth and transport lifecycle updates, schema/exposure behavior and runtime/declaration corrections.
- **Terminal and Markdown:** updated rendering, Mermaid and Markdown transformer surfaces, selectors and interactive lifecycle behavior.
- **Durable:** read-only JSONL opening/recovery, SQLite batch handling, compaction and scheduling changes. The [candidate Durable overlay](../../compatibility/durable-sync-1.5.2-overlay.json) preserves the previous map and separates current work from old acceptance.
- **Chord:** runtime reload/old-work handling, transport state/trace changes, keyed host data, live queries and sync, telemetry, application files/archives, worker snapshots, HTTP and portable publication contracts. Public legacy native APIs remain separately represented; upstream JavaScript removal does not authorize deleting them.
- **Node extensions:** exact Pi 1.5.2 runtime dependencies and regenerated fallback modules, in a version-isolated cache. Default attribution remains disabled and explicit identities remain effective.

These areas contain new and previously implemented behavior. The applicability map records accepted local source tests as `tested` or `tested-with-limitations`; no-op dispositions and historical evidence remain separate.

## Behavior and migration notes

- Chord HTTP routes and sockets require authentication by default. Intentionally anonymous endpoints must explicitly set `Public = true`; the Chord links endpoint requires a principal.
- Changed live Chord objects restart during reload. Already admitted work retains its original implementation; calls queued with obsolete remote method indexes are rejected rather than dispatched against a new binding. Native `Legacy` APIs remain available separately.
- Chord store schema 3 adds nullable host ownership metadata without assigning existing records to a host. Telemetry SQLite schema 2 migrates stored millisecond timestamps to integer microseconds. Preserve backups when moving persisted stores between versions; older readers may not accept newer schemas.
- Cache warming defaults to `idle`. Explicit warming settings and model/account selections remain effective. Live requests and warming replays use the same captured cache-retention policy; explicitly resolved authentication does not trigger additional legacy or ambient environment reads.
- Native Azure Responses usage now applies the selected model's catalog rates, including long-context pricing tiers, instead of leaving usage costs at zero.
- JSONL viewers must opt into `JsonlStorageOptions.ReadOnly` when opening storage. The option prevents recovery writes and presents the committed state captured at open; setting only the harness's read-only flag does not make a writable storage opener read-only.
- `PiSharp.Chord.Hosting` now directly depends on `PiSharp.Durable.Store` for its application store and `PiSharp.Tui` for native terminal I/O. All sibling package versions remain pinned together. See [package admission](../contracts/gap-package-admission.md).

## Boundaries and history

Upstream standalone apps, examples, fixture assets, build tooling and documentation are recorded with explicit no-op reasons. Browser DOM/React and downloaded-JavaScript terminal adapters require their actual execution platform; native portable services do not claim to execute them. Type-only import relocations have explicit source dispositions rather than invented runtime changes.

The v1.5.0 source lock is preserved byte-for-byte. Earlier captures, fixture manifests, acceptance notes, compatibility maps, release counts and published package versions remain historical evidence. No model/account selection or Anthropic subscription OAuth policy is broadened by the source update. New public APIs retain their experimental qualification.

The existing `AnthropicMessagesRequestOptions` compatibility switches now use `bool?`: `null` inherits model metadata and an explicit `true` or `false` overrides it. This changes public constructor/property signatures, so rebuild native consumers; code reading a switch as `bool` must use `??` with its appropriate established default. These existing APIs are not newly experimental. See the [migration contract and defaults](../contracts/anthropic-compatibility-option-inheritance.md).

The complete legacy fixture checker retains a pre-existing gap: six standalone fixture families need dedicated verification handlers, and its final gate requires the exact historical Node 24.19.0 executable. Dedicated current-source/applicability checks are separate; this update does not claim all historical oracle gates pass.
