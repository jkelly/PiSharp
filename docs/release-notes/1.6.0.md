# PiSharp 1.6.0 — UNRELEASED

This is the source candidate for Pi **v1.6.0** and Pi Durable 1.6.0. The published release remains **1.5.2**, on Pi v1.5.2. No package, installer or website publication is recorded by these notes, and nothing here is available on NuGet. Integrated validation and final acceptance belong to the coordinator; source implementation is not a parity claim.

Each work package wrote a report under [`AI_DOCS/agent-reports`](../../AI_DOCS/agent-reports/) (`sync-1.6.0-<package>.md`). These notes summarize them. Where a statement below says cases ran, the report names the cases and their counts; where a report says something was not run or not verified, these notes say so too.

## Source and scope

The candidate pins `faac585884ae2c013a6b1400f3e9e77f10b34bac`. The complete local Git comparison against v1.5.2 (`b4afdddf44e059c67ccf5097e5317d913521b470`) records **1,311 changed files** across every package and the repository root: 764 modified, 495 added, 37 renamed and 15 deleted, with hashes at both endpoints. 746 of them are under the upstream `apps/` folder, which has no native port. See [the inventory](../../compatibility/sync-1.6.0-files.json), [file-by-file applicability](../../compatibility/sync-1.6.0-applicability.json), [decision 0015](../decisions/0015-pi-1.6.0-sync.md) and the [work plan](../../AI_DOCS/sync-1.6.0.md).

The v1.5.2 source lock is preserved byte-for-byte as `compatibility/target.v1.5.2.lock.json`. The 1.5.2 inventory, applicability table, acceptance record, model catalog, runtime fixture and release evidence keep their original sources.

### Providers

Ported with regression cases ([report](../../AI_DOCS/agent-reports/sync-1.6.0-ai-providers.md)):

- **Retries.** Errors that report only a socket error code (`read ECONNRESET`, `write EPIPE`, `connect ETIMEDOUT`), `Connection closed.` and the Codex WebSocket connection limit are retried. PiSharp also recognizes the same failures as .NET reports them (the Winsock and Unix socket texts, `The response ended prematurely`, and similar).
- **Strict tools.** A tool whose schema has a node without a `type` (such as `items: {}` or a bare `const`) is sent non-strict with `strict: "prefer"` and fails locally with `strict: "require"`; a node with only an `enum` stays strict. Mistral models receive strict tools only when `compat.supportsStrictMode` is set. A non-strict Anthropic schema keeps its root `additionalProperties`. GitHub Copilot models on the Responses API send an explicit `strict` value, and Copilot's Claude models send strict tools.
- **Completions.** Reasoning models' system messages use the `developer` role only for `api.openai.com`; every other host gets `system` unless `compat.supportsDeveloperRole` says otherwise. Top-level `reasoning_tokens` in usage are read.
- **Codex.** The system prompt is the first `developer` input item and no `instructions` field is sent. Thinking level changes are `configuration_update` items with a fixed `reasoning.effort` on models that set `compat.supportsMidConvoEffort`. `maxTokens` is sent as `max_output_tokens` (at least 16) unless the model sets `compat.supportsMaxOutputTokens: false`. A cached WebSocket is not reused after 45 minutes, and the 60-minute limit mid-stream is retried on a fresh connection.
- **Responses diagnostics.** OpenAI Responses, Azure Responses and Codex record `openai_input_transformations` on the assistant message: the replayed reasoning items the API withheld and why. `turn_boundary` removals are not recorded.
- **Anthropic.** Message threads are on by default for any provider whose base URL is on `api.anthropic.com`. Session cleanup (`SessionResources.Cleanup`) now also frees the shared Anthropic thread state.
- **Google.** A `CONTINUATION` finish ends the turn with stop reason `length`.

Deliberate native differences:

- The Anthropic thread default compares the exact host, where Pi tests whether the base URL contains `api.anthropic.com`. `https://api.anthropic.com.gateway.example` does not get threads.
- `ResponsesTranscriptProjectionOptions.IncludeInitialSystemPrompt` stays as a PiSharp-only option. Pi removed its counterpart.
- **The PiSharp-only output-token ceiling is lifted.** The request factories refused any request above 1,000,000 output tokens. The default bound is now the 32-bit range, so every catalog value is sent as it is. Pi 1.6.0 raised `maxTokens` to 1,048,576 on the default models of `fireworks`, `opencode-go` and `together`, which the old ceiling refused. The options remain for a caller that wants a smaller bound.

Not verified:

- The suites that replay captured provider fixtures did not run, because their fixture files are not in the worktree: `PiSharp.CompletionsSimple.Tests`, `CompletionsAnchored`, `CompletionsGrammar`, `CompletionsThinking`, `OpenRouterBinding`, `OpenRouterCacheProfile`, `OpenRouterReasoning`, `PiMessages` and `AnthropicSdkBeta`. Their fixtures were captured from older sources, so rows that send a reasoning model's system prompt to a host other than OpenAI, or a strict tool with an untyped node, may now differ from the fixture.
- Upstream's live conformance test `openai-reasoning-replay-e2e.test.ts` was not ported or run.

Known limitation: **connection failures on four native transports are still not retried.** OpenAI Completions, Anthropic Messages, Google Generative AI and Mistral replace a connection failure with a fixed text (`Completions stream did not complete.` and similar), which the retry classifier does not match. OpenAI Responses and Codex are retried. Azure Responses was not probed. This gap predates 1.6.0 and needs an owner decision, because the fixed texts are an approved sanitization policy.

### Agent, Env and MCP

Ported with regression cases ([report](../../AI_DOCS/agent-reports/sync-1.6.0-core-small.md)):

- **Agent.** Every tool call of a batch that is aborted mid-batch gets an `Operation aborted` result, also the calls that had not started. With a cancelled token the result comes back before the tool lookup and before `beforeToolCall`. In the coding agent this is what pressing Esc during a batch of tool calls does; the case runs through the persistent session, not through interactive mode or the RPC dispatcher.
- **Env.** The remote `ListDirAsync` leaves out an entry removed between enumeration and `lstat`, and names that are not valid UTF-8, instead of failing. The daemon keeps reading a program's output after exit while the link holds a reader up, so the end of the output is no longer lost.
- **MCP.** `McpCatalogPlanner.ServerSummary(description, instructions)` returns a server's one-line summary: the first line of the configured description, else of the server's instructions. Instructions are trimmed first, which differs from 1.5.2 for instructions that start with white space.

Not verified: the Env suites ran on Windows and, from a local WSL run, on Linux; macOS was not run, and the Env suites are in no hosted workflow.

Follow-up: `tools/Env/upstream-android-1.5.2.json` still pins the pi-env 1.5.2 Android daemon archives. The daemon's Rust sources changed in 1.6.0; a 1.6.0 manifest needs the 1.6.0 archives downloaded and inspected, which was not done.

### Tools, exec and HTML export

Ported with regression cases ([report](../../AI_DOCS/agent-reports/sync-1.6.0-cli-tools.md)):

- **find.** A relative path pattern is matched against the path relative to the search directory, `**/x` matches at any depth, a leading `./` works, and a pattern no longer matches through folders above the search path.
- **read.** The result no longer stores a note that the model does not support images. The model is named in `details.imageUnsupportedByModel`, and the terminal UI shows the warning from that detail, also when the result is collapsed. A read cancelled while the file is being opened returns a clean cancelled result.
- **bash.** Output that ends in one line longer than the retained tail shows the end of that line instead of nothing.
- **`pi.exec`.** A command ended by a signal reports 128 plus the signal number instead of 0.
- **HTML export.** OSC 8 terminal hyperlinks become anchors (`http:`, `https:` and `mailto:` only), other escape sequences are dropped, and a click on a link does not toggle expandable output.

Deliberate native differences:

- TypeScript extensions run Pi's own `pi.exec` code and report what Pi reports. For C# extensions, a command stopped by a timeout, an abort or the output cap reads **143 on Windows** (it read 1) and **137 on Linux and macOS**, where Pi reads 143: the native runner kills the process group at once, with no five-second SIGTERM grace period.
- On Windows native, a command that exits with code 1 by itself in the instant a stop is under way reads 143.
- On Windows `find` still lists every entry with `fd` and matches the relative path itself, because `fd` does not match `--full-path` globs there.

Not verified: nothing ran on Linux or macOS. The POSIX `fd` arguments and the POSIX exit code mapping are checked as values; no POSIX process ran. The symlink variant of the linked-search-path case did not run (the junction variant did).

Known limitations:

- The explicit-policy find profile (`FindTool` with `FdFindExecutor`) is not updated: it still prefixes path patterns with `**/` and can match through folders above the search path. No PiSharp host constructs it; the CLI uses `PiFindTool`.
- 14 `exec.*` cases in `NativeExtensionExecHostTests.cs` and two sibling files are not registered in their suite, so no suite runs them.

### CLI sessions, modes and extensions

Ported with regression cases ([report](../../AI_DOCS/agent-reports/sync-1.6.0-cli-session.md)):

- **Diagnostics.** Problems found at startup and when a session is replaced (`/new`, `/resume`, `/fork`, RPC `new_session`, `switch_session`, `fork`) are reported once: in the chat in interactive mode and on stderr in print, JSON and RPC modes. This covers settings file errors, `enabledModels` and `--models` patterns that match nothing, and `Could not restore model <provider>/<model>. Using <fallback>`, which was shown only at interactive startup. SDK hosts read them through the new `AgentSessionRuntimeDiagnostics.TakeUnreported()`.
- **Package installs.** In interactive mode git and npm output is captured, and a failed install reports the end of it. Until the terminal UI starts, each install is announced as `Installing <source>...` on stderr. git and ssh cannot prompt in interactive mode. `/reload` outside interactive mode sends git and npm output to stderr instead of discarding it.
- **Extension event bus.** An exception thrown by a `pi.events` handler is reported like other extension errors, for TypeScript and for native extensions. `ExtensionRegistry.EventBusErrorReporter` is the new host hook; a host that does not set it no longer gets `Event handler error (...)` on stderr for owner listeners.
- **Sessions.** MCP tools loaded by `tool_search` are kept on resume and `/reload` when an extension deactivates only its own tool at `session_start`. `/copy` and RPC `get_last_assistant_text` skip aborted, failed and tool-only replies. The resume command printed on exit is on its own line. The session list accepts a cancellation token.
- **llama.cpp.** The default server URL is `http://127.0.0.1:9931`. Decision classifiers with image input send their images.
- **Other.** An unreadable `CHANGELOG.md` prints nothing. `/share` reports the start error when the GitHub CLI cannot start. `--help` names the four Qwen Token Plan key variables.

Already native, with cases added: RPC session replacement runs `session_start` once and streams its entries; JSON mode streams entries appended by `session_start` handlers; `/reload` emits `session_shutdown` then `session_start` once.

No native counterpart: waiting for queued stdout at exit (native terminal writes are synchronous), `pi update` for managed npm installs, the standalone binary's npm resolution, and an extension load failure after `/resume` into another project (a native replacement keeps the run's extensions).

Not verified: the Unix branches of the new cases, and any real git, npm, ssh, GitHub CLI, llama-server or provider call. Interactive mode was exercised only through the suite's virtual terminal.

Observed and not changed: RPC `fork` after `switch_session` under `--no-session` fails with `Session branch publication failed`; package commands in print, JSON and RPC modes still inherit stdin; `ModelResolver.RestoreModelFromSession`, which Pi removed, remains without a production caller.

### Durable harness

Ported with regression cases ([report](../../AI_DOCS/agent-reports/sync-1.6.0-durable-core.md)):

- **Signals.** `Signals.DefineSignal` defines a typed JSON value delivered to a live task with `IHarness.SignalAsync` or `ITx.SignalAsync`, which answer `delivered`, `duplicate`, `invalid`, `closed` or `not_found`. A value is kept in the task, also one that arrives before the sleep on its key. `ReadSignalAsync` on the task runtime, the hook API and the tool API reads it.
- **Sleeps and waits.** A sleep may wait for signals with an optional `until`, and a wait may use `JoinPolicy.Any`. A woken task reads why in its state's `Wake` (`WakeReason`). Parked work holds no invocation.
- **Tools that park.** A tool returns `ToolPark.Sleeping(...)` or `ToolPark.Waiting(...)` instead of a result and runs again once woken, with `api.Wake` and `api.Checkpoint` set. Its slot shows `sleeping` or `waiting`. `ToolRegistration.Cancel` cleans up the external work of a parked call that is aborted. `IToolExecutionApi.StartToolAsync` starts or finds a nested call without waiting, and `CreateTaskAsync` takes a key.
- **Submissions.** `SubmissionDraft.Input`, `Write` and `Continue` take `notify` (`SubmissionNotify`), which delivers the built-in `Signals.SubmissionSettled` signal to a task in the settling commit. `SubmissionDraft.Input` takes `onAbort` (`InputOnAbort`); `keep` keeps an input queued through an abort.
- **Gates.** A `BeforeTool` hook may return a `GateSleep` to park a call before it runs. Every wake, registry publication and open runs the whole `call` phase again.
- **Hooks that start tasks.** `AfterTools` and `OnYield` hooks may return tasks, which run as the generation's children. `OnYield` tasks decide whether an answer stands while the run's inputs stay open.
- **Records.** `pi.tool` is version 4 and `pi.generation` version 3. A tool result's `durationMs` is the span from the tool task's first run to its result, hooks, parks and reruns included, and results that never executed have one.
- **Fixes.** Closing the harness releases provider session resources. The idle-scope walk no longer costs time proportional to the depth of a long ownership chain.

Deliberate native differences:

- C# has no union types: a park is carried by `ToolExecutionResult.Park`, so `ToolExecute`'s signature is unchanged. Signal values are `JsonValue`, so the signal types are not generic.
- `tx.SignalAsync` throws `ReadAfterWrite` after any other table write of the transaction, but not after the writes of earlier deliveries in the same transaction. Pi throws after any table write and relies on JavaScript's call order.
- A registry publication between a reservation's count and its snapshot gives a gated call one extra pass over its gates, never a missed one.

Not verified:

- The SQL Server-backed groups (`storage.mssql.conformance.*`, `session.mssql.*`, `harness.*.mssql.*` and the SQL Server upgrade cases) did not run: they need `PISHARP_DURABLE_MSSQL_CONNECTION_STRING`. The new storage conformance case therefore did not run against SQL Server.
- `PiSharp.Durable.Web.BrowserTests` and `PiSharp.WebAgent.BrowserTests` were not built or run.
- Weak evidence: the unhandled-rejection case for `Submission.wait()` may pass without the change in .NET, and "a record written before `startedAt` existed keeps the old measure" has no case.

### Chord

Chord's assemblies are `[Experimental("PISHARP_CHORD001")]`. The upstream changelog omits several features that are in the source between the tags; they are in scope and named below.

Ported with regression cases (reports: [foundation](../../AI_DOCS/agent-reports/sync-1.6.0-chord-foundation.md), [edge](../../AI_DOCS/agent-reports/sync-1.6.0-chord-edge.md), [store](../../AI_DOCS/agent-reports/sync-1.6.0-chord-store.md), [remote](../../AI_DOCS/agent-reports/sync-1.6.0-chord-remote.md) and `sync-1.6.0-chord-queries.md`, which lands with its branch; the [discovery report](../../AI_DOCS/agent-reports/sync-1.6.0-chord-discovery.md) is the plan):

- **Contracts and wire.** Event members and `queries` members in contracts, a remote contract's admission schema, `Contract.MemberNames`, and the failure cause kind `FailureKind.Denied`. The wire gains the `event` message, event acks and an optional call window in `hello`. The protocol version stays 1 and every 1.5.2 frame still decodes.
- **Events** (not in the upstream changelog). An implementation supplies an event member with an event source from `ISelf.Events()` and emits through it; a holder subscribes with `IReference.Event(name)`. There are event mappings for older contract versions, over links and through relays.
- **Call windows by trust** (not in the upstream changelog). `HostOptions.CallWindow` (10,000) and `HostOptions.EventWindow` (32). A host announces no call window on a trusted link.
- **Shared holds** (not in the upstream changelog). Remote references of one host to one object share one wire hold.
- **Store.** Column sets (`Tables.DefineColumns`, `TableOptions.Exposes`), `Expressions.Exists` and `ExistsNode`, `Query.Join` and `WhereNode`, read plans, and a read index: a commit runs a live query again only when its writes can change it. `ChordStore.SettledAsync`, `IStore.OnCommitted`, and `DeleteHostDataAsync` limited to one plugin. Counters `chord.query.probes`, `chord.query.skips` and `chord.query.rows`.
- **Named queries and lists.** A local contract lists queries with `Schemas.Queries`; the table's owner implements them with `self.Queries(table, options, builders)`; any object of the store's host reads one with `self.LiveQuery`, `self.Count` or `PageAsync`. `self.List` returns a list a screen loads more of.
- **One frame per commit.** A watched derive read between two changes of one commit, and a list or live query set several times in one commit, publish one frame.
- **App kit and surfaces.** Sign-ins replace sessions (see the breaking changes). `LinksOpened` gets a `close` argument. A client starts without its server, may turn following off (`ClientOptions.Follow`) and takes part limits (`ClientOptions.Limits`). `Variants.LiveIn` and `TerminalScope.Variant` narrow a reference to one variant.
- **Sync.** A store whose outbox was turned off and on again can upload: the upload creates an archive slot after the remote's head. A pull disposes every body it read, also one it refused.

Deliberate native differences:

- There are no microtasks. The host's dispatcher orders an event flush after the state published in the same dispatcher action. Each inbound event message gets its own ack, where Pi sends one ack per JavaScript turn.
- The native store writes each commit in a transaction of its own. Pi writes the commits queued behind a running step as one backend transaction (group commit). That was already so at 1.5.2. The list and tiling cases issue the same commits one after another, and the assertions on the number of groups are left out.
- A `JsonNode` has one parent, so no node is shared between two values. Cases that assert object identity upstream assert equality and the frame natively.
- `Variants.LiveIn` is public; Pi keeps `liveIn` internal.
- `IStore.OnCommitted` runs its listener on a pool thread.

Admission and workers:

- **Admission.** A remote contract may declare an admission schema. Its type is served with `IFacetHost.Serve(Contract, AdmittedHostFactory, ServeOptions)` and `ServeOptions.Admit`: an `Admit` function reads data about the caller through `IAdmitSelf` (`Get`, `Registry`, `Derive`, `LiveQuery`) and returns a watchable of `Admission.Allow(value)` or `Admission.Deny(reason)`, and the factory is handed the admitted value. A denial shows `failed` with the cause kind `FailureKind.Denied` (wire value `denied`): getters reject at once, references keep no value and running calls reject `forbidden` with reason `revoked`. Another value rebuilds the object. `self.Job` is refused in an admitted factory. The decision is recorded as the `chord.admit` span event.
- **Route admission.** `RouteOptions.Admit` (a `RouteAdmit`) asks one decision per principal and address before anything is resolved or forwarded; a path is gated while it is withheld, and a cycle is refused `invalid/cycle`. `ProcessWorkerOptions.Admit` passes it to the workers' route, so no worker starts for a caller who is denied.
- **Workers.** `ProcessWorkerOptions.Store` is required: a worker's exit is published, and `StopAsync` returns, only once the commits queued before the exit settled. The workers close a worker's link when it exits, before they publish the exit, so its inbound calls are aborted first. `ProcessWorkerState.Incarnation` is the running worker's incarnation, set at the link's handshake. `TerminalScope.On(IEventMember, Action<ChordEvent>)` subscribes to an event member.
- **Native differences.** An activation is posted to the host's dispatcher, so `admit` runs in a later dispatcher turn than the flush that sealed the previous attempt; the cases turn upstream's microtask orderings into dispatcher turns. Worker `State` is a polled snapshot, not a watchable.

Not verified: only the Chord suites, the Chord Durable integration suite and, for the store and queries packages, `PiSharp.Durable.Tests` ran. Nothing ran on Linux or macOS. The variant and scope cases that rebind through an admission were adapted to reconnect as another principal until admission lands.

Known limitations:

- **The native Chord store has no group commit.** It is not part of the 1.5.2 to 1.6.0 delta.
- The native provider keeps a restart's hold bound to the old attempt until the successor is live, so a restart shows no `loading` state.
- `Hosting/Terminal/TerminalRuntime.cs` now gets its client before the first script set was applied, so its render callback can run before the server's plugins are loaded.

## Breaking changes and migration

### PiSharp.Tui

- `IComponent.Render` returns `IReadOnlyList<string>`. Change the return type of every component. A component whose output changed must return a new list, not the earlier list with new contents: `Container` compares child output by identity first. Code that changes render output in place, including the result of `base.Render` in a `Container` subclass, must copy it first.
- `ITui` gains `SetSuspendSignalHandler(Action?)`. An `ITui` implementation of your own must add it.
- `LayoutFrame` gains the positional member `RenderCache`. `LayoutBox.Lines` and `LayoutBox.ScrollContentLines` are `IReadOnlyList<string>`. `TuiBase.ResolveFakeCursors` takes `IReadOnlyList<string>`. `LayoutEngine.RenderFrame` gains the optional parameter `reusableOutput`.

### PiSharp.Durable

- `RunEndTask` and `Define.RunEndTask` are renamed `HookTask` and `Define.HookTask`, with no alias. Rename them in `AfterRun` hooks.
- `GenerationHooks.AfterTools` returns `Task<IReadOnlyList<HookTask>?>`. An existing hook returns null.
- `GenerationHooks.OnYield` returns `Task<OnYieldResult?>`. A hook that returns its continuation from an async lambda still compiles, because `JsonValue` and `string` convert implicitly; `Task.FromResult<JsonValue?>(...)` must become `Task.FromResult<OnYieldResult?>(...)`.
- `SleepingTaskState.Until` and `TaskGraphState.Until` are `double?`. Code that reads `Until` of a sleeping task handles its absence.
- `Now()` is declared on `IHookApi`. `ITaskRuntime` inherits it, so callers compile unchanged; an implementer declares it there.
- `Inbox.WithdrawQueuedInputsAsync` has no default reason.
- `IToolExecutionApi`, `IHookApi`, `ITx` and `IHarness` gain members. `ToolExecutionApi` and `DelegatingToolExecutionApi` implement the new tool API members, so a wrapper derived from the latter compiles unchanged.
- **Storage.** `pi.tool` is version 4 and `pi.generation` version 3. A database written by 1.6.0 is not meant to be opened by PiSharp 1.5.2, which would block these tasks (`task_too_old`) and treat a sleep without `until` as due. Keep a copy of a session before you open it with 1.6.0 if you may need to go back.

### PiSharp.Durable.Tools and the Durable hosts

- `CodemodeNamespace` and `CodemodeToolOptions.Namespaces` are removed, with no fallback. Declare `Extension.Namespace = new ToolNamespace(name, description, instructions?)` on the extension that brings the tools. A tool whose name starts with a server prefix belongs to no namespace unless its extension declares one.
- The durable `read` tool no longer adds "The current model does not support images; it sees a placeholder instead." to its `image` diagnostic. A host that showed that text reads `details.imageUnsupportedByModel`.
- `PiSharp.Durable.Client`: `ToolStatus` gains `Sleeping` and `Waiting`, so a `switch` over it without a default no longer covers every value. `TaskNodeState` gains `Until` and `Signals`.
- Agent events (wire, additive): `tool_execution_start` may carry `status`; `tool_execution_update` may carry `status` and `args` and is also sent for a parked call; the snapshot's `run` may carry `yield`; `run_yield` is a new event type. A consumer that treated every `tool_execution_update` as "the call runs" reads a parked call as running.

### PiSharp.Chord and PiSharp.Chord.Hosting

- **Sign-ins, not sessions. Everyone signs in again.** `Sessions` is `SignIns`, `EphemeralSessions` is `EphemeralSignIns`, and `SessionKind`, `SessionInfo` and `IssuedSession` are `SignInKind`, `SignInInfo` and `IssuedSignIn`. `App.Sessions`, `AppServices.Sessions` and `AppLimits.EphemeralSessions` are renamed the same way. Persisted and wire names changed with them, with no migration: the cookie `chord-session` is `chord-sign-in`, and the contract and stored document `chord.app.sessions` are `chord.app.sign-ins` with the field `signIns`. After the update every browser cookie and device token stops authenticating, the owner token file is replaced at the next start, paired devices pair again, and the old `chord.app.sessions` document stays in the store unread.
- `TelemetryIngestOptions.Admit` is required. Pass `_ => true` to keep the old behavior. A page whose principal it refuses fails to hold `chord.telemetry.page` with `forbidden`.
- `ChordHttpOptions.LinksOpened` is `Func<HttpRequestContext, JsonObject, Action, Task<Func<Task>?>>`: the third argument terminates that link.
- `HostError.Table` is `HostError.Query`. `query_failed` names the query: the table's name for `self.Query`, the named query's label for `self.LiveQuery`, `self.Count` and `self.List`.
- `IStore` gains `OnCommitted`, which breaks an implementer of `IStore` outside PiSharp.
- `Client.StartAsync` completes before the scripts object answered. A caller that relied on the server's first script set being applied when it returns no longer can. A failure to follow is reported as `update_failed`, not thrown.
- `ConnectionOptions.CanRetry` is asked beside the next attempt, not before it, and one question at a time. `ConnectionLoop.Stop` reports `ConnectionState.Waiting` for the attempt it ended.
- `UploadOptions.Store` is `ISessionSyncUploader`. `ISessionSyncStore` extends it, so callers compile unchanged; an implementer that wrote `PutBatchAsync` as an explicit `ISessionSyncStore` member names `ISessionSyncUploader` instead.
- `SessionSync.PullSessionAsync` disposes the enumerator of every body a remote returned, also of one it never read.
- An activation whose live query fails to load is `activation_failed` with a `broken` cause. In 1.5.2 it was `transient` and retried with backoff.
- `Self.Query` and staging refuse a table that is not the factory's with an `ArgumentException`; 1.5.2 threw a `ChordError` `invalid/args`. A table handle's `PageAsync` and `CountAsync` refuse a joined query.
- Shared holds change what a provider counts: presence and `Activity.References` count one per hold, not one per reference. A part past the link's limits fails every reference sharing the hold. A revoked principal's running calls on a remote reference reject `forbidden` with reason `revoked`; they rejected `released`.
- Binary-breaking, source-compatible: `FailureKind` gained `Denied`; `ResolvedLink` gained the trailing parameter `Opened`; `ChordHost.DeleteHostDataAsync` and `Tables.EvolveTable` gained an optional trailing parameter; `ISelf`, `IStoreSelf` and `IReference` gained default-implemented members. Rebuild consumers.

- `ProcessWorkerOptions.Store` is required (`required IStore?`, null only for a host without a store; a store not opened by `Tables.OpenStoreAsync` is refused with an `ArgumentException`). `ProcessWorkerState` gained the trailing positional parameter `Incarnation`: source-compatible, binary-breaking.
- A worker's fatal error, a link lost before it was ready and a closed control pipe now show in `State` with the worker's exit, not at once. A worker whose control pipe closes while its process lives on is killed after `CloseTimeout`; it was killed at once. A holder's replacement start waits for the exit to be published.
- A contract that declares an admission schema is served with `ServeOptions.Admit`.

**Wire compatibility.** The protocol version stays 1. A 1.6.0 host announces no call window on a link it was given as trusted (`hello` without `calls`) and its `CallWindow` (10,000 by default, was 256) on the others. A PiSharp 1.5.x peer on a trusted link reads the missing `calls` as a zero window or rejects the `hello`, so **1.5.x and 1.6.0 hosts do not interoperate over trusted links** (workers and host-to-host routes). On an untrusted link a 1.5.x peer still works, but it does not understand `event` messages or event acks; events are only sent for contracts that declare event members.

**Sync remotes.** An archive slot can now follow other slots. A 1.5.x sync client that reads such a remote refuses the archive slot with `HistoryUnavailableError`, so devices sharing a remote should update together.

### Other libraries

- `PiSharp.Tools`: `ReadWriteTools.NonVisionImageNote` is obsolete and nothing writes it. `ReadWriteToolOptions.CurrentModelId` is new and names the model in the detail; without it the detail reads "The current model".
- `PiSharp.Extensions.Runtime`: a host that does not set `ExtensionRegistry.EventBusErrorReporter` no longer gets `Event handler error (...)` on stderr for owner listeners.
- `PiSharp.Agent`: code that counted on tool calls without results after an abort (transcript repair, rendering of pending calls) now sees an `Operation aborted` result for every call of the batch.

## Behavior changes

- **Default model.** `openai`, `azure` and `openai-codex` default to `gpt-6.2-sol` when no model is selected. Explicit model selections are unchanged.
- **find.** `src/*.ts` finds `src/a.ts` and no longer `pkg/src/a.ts`. Use `**/src/*.ts` to match at any depth. A pattern without `/` still matches file names at any depth.
- **`pi.exec` exit codes.** A command ended by a signal reports 128 plus the signal number. For C# extensions on Windows a stopped command reads 143 where it read 1.
- **llama.cpp.** The default server URL offered by `/login llama.cpp` is `http://127.0.0.1:9931`, the current llama-server default port. A URL already saved by `/login` or set in `LLAMA_BASE_URL` is still used. If your server listens on 8080, enter that URL at `/login llama.cpp` or set `LLAMA_BASE_URL`.
- **Output tokens.** The PiSharp-only 1,000,000 ceiling is lifted.
- **Diagnostics on stderr.** Print, JSON and RPC modes write the model fallback and replacement diagnostics to stderr. A client that treats any stderr output as a failure needs to allow them.
- **System role.** OpenAI-compatible hosts other than `api.openai.com` receive reasoning models' system messages with the `system` role.
- **Codex.** Requests carry `max_output_tokens` and no `instructions`.
- **read.** A stored read result no longer contains the note about a model without image input.
- **Qwen Token Plan.** The built-in providers call the new gateways. Provider IDs are unchanged.
