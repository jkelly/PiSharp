# PiSharp 1.1.0.6

A C#-only patch on the Pi **v1.1.0** baseline (commit
`abe508e1b89912adde45528136c3221eb69acdd7`).

The [Parity](https://pisharp.ai/parity/) page lists what still differs from Pi.

## Fixed

- **Timed-out commands on macOS.** PiSharp stops a timed-out or aborted bash command by
  killing its process group, then confirms the group is gone. macOS answers that check
  with `EPERM` while the group's remaining members are zombies waiting to be reaped, where
  Linux answers `ESRCH`; PiSharp treated it as uncertain cleanup and failed the run ("RPC
  host cleanup failed"). It now waits through `EPERM`, up to 5 s. (#10)
- **Prompts during settling.** Pi defers a prompt that arrives while the previous run is
  emitting `agent_settled` and runs it afterwards. PiSharp's RPC host refused it with
  "Session is settling. Wait for agent_settled before prompting again.", which an
  interactive user could hit by sending the next message as a reply finished. The prompt
  now waits for the settling run and is then admitted as usual. (#11)
- **Codemode scripts that never returned.** A worker's exit was awaited twice at once on
  the same process; on Linux one of those waits could miss the exit, and the finished
  script's result was never delivered (about one run in ten). Each worker now has a single
  shared exit wait, and a finished script settles even if stopping its worker stalls. (#12)
- **MCP connections at session end.** A background MCP connection cancelled because the
  session ended was reported as a failed connection. It is dropped, as Pi drops late
  results of a retired session; timeouts are still reported. (#10)
- Cleanup failures of owned processes now say what was uncertain (cleanup, output, exit
  code, diagnostics).

## Performance

- Streaming no longer re-materializes growing snapshots, copies SSE buffers or rebuilds
  presentation and context state for every small delta. In offline benchmarks of 2,000
  deltas, cold peak memory for the OpenAI-compatible and Mistral providers fell by roughly
  40% (to about 63 and 57 MiB, against 64 and 53 MiB for Pi 1.1.0). Memory after many
  repeated streams is still higher than Pi's. Details and the reproduction steps are in
  `tools/PerformanceReview/memory-pass-2/RESULTS.md`. (#11)

## Testing

- A macOS arm64 workflow runs the release test suites on Apple Silicon and installs and runs
  the packed `pisharp` tool. (#10)

## Packages

All library packages and the `PiSharp.Cli` dotnet tool are published as 1.1.0.6:

```powershell
dotnet tool update -g PiSharp.Cli
```
