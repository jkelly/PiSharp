# PiSharp 1.5.0

PiSharp 1.5.0 moves the porting baseline from Pi v1.2.0 to Pi **v1.5.0** (commit
`f9a26365568127461c47a07a37dcb42c140a3ac5`, released 2026-11-02). It covers Pi 1.3.0 and 1.4.0
too: there was no PiSharp release for either. As before, the version names the baseline. It is
not a claim of complete behavioral parity.

Each upstream change has a row, with its evidence, in
[sync-1.5.0-applicability.json](../../compatibility/sync-1.5.0-applicability.json). The
decisions are in [decision 0013](../decisions/0013-pi-1.5.0-sync.md).

This release covers phases 0 to 4 of the sync and its close-out:
- the core areas (ai, schema, agent and coding agent, CLI, TUI, codemode, MCP, tools and the
  Node bridge);
- telemetry, in the new experimental `PiSharp.Telemetry` package;
- the durable re-sync, from `pi-durable` v1.2.0 to v1.5.0.

Of the 283 rows these phases need, 232 are ported, 19 are ported with a deferral (see
[Known gaps](#known-gaps) and [Durable](#durable-experimental)), 9 were already in PiSharp and
23 are no-ops. pi-env, the rest of Chord and pi-evals (phases 5 to 7) follow as experimental
1.5.0.x patches. Their 37 rows are still `port`.

**Durable sessions have no way back.** Once PiSharp 1.5.0 has opened a durable session,
PiSharp 1.2.0.x can't continue it. Copy a session's folder or database first if you may need to
go back. See [Stored formats: no way back](#stored-formats-no-way-back).

**Everything marked experimental may change or be removed in any release, including a patch
release, without a deprecation period.** Each experimental API carries an
`[Experimental("...")]` attribute, and the compiler reports an error until you suppress it. The
experimental parts are `PiSharp.Telemetry` and the APIs listed under
[New experimental ids](#new-experimental-ids), and, as in 1.2.0.x, the durable packages and
`pisharp durable`, custom agents, media, service tiers and the maintained catalog overlay.

## Breaking changes

- **Exact sibling versions.** Each PiSharp NuGet package now depends on the other PiSharp
  packages at exactly its own version (`[1.5.0]`), as Pi pins its own packages since 1.3.0.
  NuGet now reports a conflict for a project that mixes PiSharp versions, where it used to
  resolve one. Reference every PiSharp package at the same version.
- **`SessionSummaryRequest.MaximumOutputTokens`** is `double?`; it was `double`. Like Pi 1.5.0,
  compaction, turn-prefix and branch summaries set no output budget of their own. It is the
  model's limit when you pass one in `SessionSummaryRequestOptions`. Otherwise it is null, and
  the route sizes the output as it sizes a turn.
- **`CompletionsSimpleOptions.TelemetryContext`** (opaque JSON) is replaced by
  `CompletionsSimpleOptions.Telemetry`, an `ITelemetrySpan?` (`PISHARP_TELEMETRY001`). Upstream
  renamed `telemetryContext` to `telemetry` the same way, and there is no alias. See
  [Telemetry](https://pisharp.ai/docs/embed/telemetry/).
- **Tool arguments are validated with pi-schema**, as JSON Schema, not with TypeBox.
  - TypeBox features outside JSON Schema no longer apply: refinements, `BigInt`, `Undefined`
    and `Void`, codecs, `Format.Set()` formats and regular-expression property names.
  - Error texts follow pi-schema's, for example
    `- t: unresolved reference #/definitions/Missing`.
  - Native C# tools keep their JSON Schema parameters.
- **Default models.** These apply only when no model is selected, never in place of your
  choice:
  - `openai` defaults to `gpt-6.1-sol`; it was `gpt-5.5`.
  - `github-copilot` defaults to `gpt-6.1-sol`.
  - `nvidia` defaults to `nvidia/nemotron-3.5-super-vl-120b-a12b`.
  - Xiaomi and the Xiaomi Token Plan providers default to `mimo-v2.6-pro`.
- **The model catalog** is pi-ai 1.5.0's, which upstream now generates from models.dev's v2
  catalog. PiSharp refreshes the 42 provider shards from `@earendil-works/pi-ai@1.5.0`.
  - Realtime and image-only models leave the chat catalog.
  - `openai-codex` drops `gpt-5.5` and `gpt-5.3-codex-spark`, which Codex rejects for ChatGPT
    accounts.
  - `kimi-coding` speaks Chat Completions at `https://api.kimi.com/coding/v1`.
  - OpenCode and OpenCode Go use their protocol-specific `/inference/...` endpoints.
- **Resuming a session restores its active tools.** `--tools +name` and `-name` modify the
  restored set. Only `--tools` with plain names, `--no-tools` and `--no-builtin-tools` replace it.
- **Code mode admits at most two live workers per process.** Other scripts wait for a free
  worker in arrival order, for up to 60 seconds and within their `timeout_ms`.
  `PI_CODEMODE_MAX_WORKERS` changes the limit.
- **The default system prompt is Pi 1.5.0's shorter text.**
- **Durable.** The durable libraries follow `pi-durable` v1.5.0's breaking changes, and their
  stored formats moved on. See [Durable](#durable-experimental).

## What changed

### Providers and models (PiSharp.AI)

- **GPT-6.1 Terra** (`gpt-6.1-terra`) is in the `openai`, `azure` and `openai-codex` catalogs.
  Codex serves it with a 500,000-token context, and gives `gpt-6.1-sol` 500,000 tokens too.
- **Identity.**
  - Requests carry the user agent of the Pi version PiSharp tracks,
    `pi/1.5.0 (<platform>; dotnet/<version>; <arch>)`. Bedrock sends `pi/1.5.0`.
  - MCP `clientInfo`, bug reports and crash logs say 1.5.0. The startup header still shows
    PiSharp's own version.
  - **No attribution.** PiSharp attributes no request to Pi or to itself, whatever install
    telemetry is set to. OpenCode requests keep `x-opencode-client: pisharp`.
  - The API is `ClientIdentity` (`PISHARP_IDENTITY001`). `AgentConfiguration.DefaultIdentity`
    turns attribution off.
- **Providers.**
  - Mid-conversation reasoning effort on OpenAI.
  - Claude Opus 5 and Haiku 5.5 send `thinking: {type: "disabled"}` when thinking is off.
  - Gemini 4 uses thinking levels.
  - MiniMax effort levels; Grok `xhigh`; Xiaomi MiMo's thinking toggle; Kimi K3.1.
  - Workers AI classifiers, with their prices, and image input for System One classifiers.
  - OpenRouter's reported cost replaces the catalog estimate, and `usage.cost.totalFromProvider`
    says so. A final message's `responseModel` names the model a pi-messages provider used.
- **Retries and errors.** More gateway and upstream failures are retried. Status codes match
  only as whole numbers. Any HTTP 413 counts as context overflow, and LiteLLM's "context window
  exceeded" too. Zhipu's usage limit (code 1308) and ChatGPT workspace limits are not retried.
- **Tool calls.**
  - Arguments are parsed incrementally by `StreamingJsonParser` (`PISHARP_AI001`).
  - Final arguments that are not valid JSON keep their raw text for the error the model sees.
  - Replies replayed to a different model drop that model's thinking.
  - Images in Anthropic error tool results move to a user message.
  - Whitespace-only tool output counts as empty.
- **Sign-in.** OAuth flows open only http and https URLs, Radius included. Device-code sign-in
  gains `OpenBrowserOnConfirm` and `CopyCodeOnConfirm` (`PISHARP_AUTH001`).

### pi-schema (PiSharp.Contracts)

`PiSharp.Contracts.Schema` (`PISHARP_SCHEMA001`) ports pi-schema:
- drafts 2020-12 and 7;
- `$ref`, `$dynamicRef` and the `unevaluated*` keywords;
- coercion;
- the standard formats;
- `unresolvedRefs` handling.

It is tested against the JSON-Schema-Test-Suite, with pi-schema's known failures. The agent
validates tool arguments with it. `PiSharp.Agent.TypeBoxJsonSchema` stays for the theme schema,
which Pi 1.5.0 still compiles with TypeBox.

### Agent and coding agent

- **Agent identity.** `AgentOptions.identity` reaches every agent-loop request.
- **Compaction.**
  - `/compact` instructions also focus the summary of a split turn.
  - Branch summaries use the thinking level and the context edits.
  - Extension tools stay active on resume and `/tree`, and setting the same tools in a
    different order keeps their order.
- **`pi.exec()`.**
  - It takes `maxBuffer`, and its result has `truncated` (`PISHARP_EXEC001`).
  - It escalates to SIGKILL.
  - It decodes UTF-8 across chunks, and reports spawn errors on stderr.
- **Packages.**
  - A package that fails to install at startup is skipped with a warning.
  - Temporary `-e` sources refresh.
  - npm gets the real path of a symlinked agent folder, and `--no-audit --no-fund`.
  - A failed `git clean` no longer stops an update.
- **Paths, trust and templates.** Windows paths compare case-insensitively. A saved "Do not
  trust" wins over auto-trust. Empty quoted prompt-template arguments are kept.
- **Extension UI.** Renderers get `keyText()` and `keyHint()`. A custom component can report a
  blocked status. Markdown transformers see entry metadata (`PISHARP_EXTUI001`).

### CLI

- **`pisharp update`** can run your own update command: `PI_SELF_UPDATE_COMMAND`, or the
  `selfUpdateCommand` setting.
  - PiSharp asks NuGet for the newest `PiSharp.Cli`, never pi.dev. It runs the command only when
    NuGet has a newer version, or with `--force`.
  - After an update, a fresh interactive launch shows the extension packages' new changelog
    entries under "Extension Updates".
- **`sessionShareDestination`** (`auto`, `gist` or `radius`) chooses where `/share` uploads.
- **`pisharp mcp login -l` and `pisharp mcp logout -l`** act on a project server. A mistyped
  server name gets a suggestion.
- **Models.**
  - A `--model` reference that several providers offer prefers one with credentials, and
    otherwise reports the ambiguity.
  - Provider ids that contain `/` resolve.
  - `/model` shows distinct model names.
- **`/resume`** searches the session name, id, messages and folder separately.
- **Extension dialogs** stack in the editor slot, and an editor swap keeps an open dialog.
- **The HTML export** renders deep sessions and later system messages, and CJK emphasis.
- **Smaller changes.**
  - The login dialog opens only web URLs.
  - Selectors honour the page keys.
  - `~` replaces only the home folder itself.
  - Startup fails clearly in a deleted folder.
  - The heading `[Skill warnings]` replaces `[Skill conflicts]`.
  - Clipboard helpers leave the process group.
  - WSL helpers start from the root.
  - External editor failures are reported.

### Terminal UI

- **Terminals.** Rex is detected, and Orca when `ORCA_IMAGE_PROTOCOL=kitty` is set.
- **Keys.** Kitty function keys and modified F-keys are decoded. On Windows, Shift+Enter sent as
  ESC+CR is Shift+Enter.
- **Markdown.**
  - Bold and italic next to CJK punctuation, and bare URLs stop at CJK punctuation.
  - Display math is safe at table starts and falls back to raw text when it is too wide.
  - Nested blockquotes render in linear time.
  - Streaming reuses earlier blocks.
- **Exit.** The terminal's modes are restored when the process exits without stopping the TUI.
  Titles and program status drop control characters, and regular mode writes no OSC 133
  markers.
- **Lists and selection.** Lists honour `tui.select.pageUp` and `pageDown`. Fuzzy matching
  prefers contiguous matches. Double-click selects paths.
- **API** (`PISHARP_TUI001`): `GetSelectPageIndex`, `RestoreOnExit`, `ReplaceControlCharacters`
  and `IComponent.CapturesViewportInput`.

### Code mode

- Workers are admitted process-wide (see Breaking changes). The hooks are `AcquireWorker` and
  `OnWorkerStarted` (`PISHARP_CODEMODE001`).
- Aborts, timeouts and close settle at once instead of waiting for the worker to exit.
- Tools with large non-object output types get a short summary in their description.

### MCP

- **OAuth client registration.** `oauth.clientRegistration` defaults to `auto`, as in Pi 1.5.0.
  - PiSharp's `auto` always registers a client dynamically, as Pi does for a rebranded build.
    It never presents a Client ID Metadata Document.
  - A client registered before stays in use while its redirect URI matches.
  - An explicit `oauth.clientRegistration: "cimd"` presents upstream's documents, as upstream
    does for rebranded builds.
- **Already as in Pi 1.5.0:** sign-in opens only http and https authorization URLs, and
  `mcp.json` may start with a byte order mark.

### Tools

- **grep** runs `rg --no-config`, so a `RIPGREP_CONFIG_PATH` file can't change how it searches.
  Context lines keep lone carriage returns.
- **`tool_search`** ranks by the query words a tool matches, with the tool name weighted most.
  It finds non-ASCII words too, segmenting text without spaces through the system's ICU
  (`PISHARP_TOOLSEARCH001`).
- **read** picks the smaller image encoding, and its line-range labels follow Pi's.
- **Shells and processes.**
  - Windows shells are found in their installation folders.
  - On macOS, aborting a bash command stops its process group before killing it.
  - fd and rg are not downloaded for unsupported architectures.
  - SGR mouse reports are stripped from tool output.

### Node bridge

- **Pi's npm packages.** TypeScript extensions still run against the Pi **1.2.0** npm packages.
  - Pi 1.5.0's `pi-agent-core` attributes agent requests to Pi by default, and PiSharp doesn't
    attribute requests to Pi.
  - `undici` is overridden to 8.12.3, the version Pi 1.5.0 moved to for security advisories.
  - A runtime installed by an earlier PiSharp, without the override, is installed again on
    next use.
- **Built-in compatibility modules.** They follow v1.5.0, with the pi-schema module and
  `@earendil-works/pi-ai/models`. Extensions use them when the npm install can't run.

### Telemetry (new, experimental)

`PiSharp.Telemetry` (`PISHARP_TELEMETRY001`) ports Pi's pi-telemetry v1.5.0:
- spans, span links, metrics, propagation and typed schemas;
- `TraceRenderer`;
- a no-op adapter and an in-memory adapter;
- the adapter conformance kit.

It has no dependencies and no exporter, so nothing is sent anywhere.
- **Opt-in.** A `ChatRun` records a `pi.ai.request` span only when `ChatRequest.Telemetry` is
  set. The CLI and the coding agent set none, so they record nothing. Durable runs record their
  own spans, and deferred polls record `pi.ai.poll`.
- **Redaction.** Error messages and response ids are redacted for credential-shaped text and
  capped at 500 characters. Upstream records response ids raw.

See [Telemetry](https://pisharp.ai/docs/embed/telemetry/).

## Durable (experimental)

PiSharp 1.5.0 moves `PiSharp.Durable`, `PiSharp.Durable.Tools` and `PiSharp.Durable.Sqlite` from
`pi-durable` v1.2.0 to v1.5.0 (`DurableUpstream.Commit` `f9a26365`). They stay experimental:
every public type carries `[Experimental("PISHARP_DURABLE001")]`, and the API and stored formats
may change in any release. Read
[Upgrading from 1.2.0.x](https://pisharp.ai/docs/embed/durable/#upgrading-from-120x) before you
open existing sessions.

### Breaking changes for library users

- **Getters became watches.** `ISession.DocumentStateAsync`, `IConversation.ViewStateAsync` and
  `IHarness.TaskGraphAsync` are gone. Use `ISession.WatchDocAsync`,
  `IConversation.WatchAsync(context, window)` and `IHarness.WatchTaskGraphAsync`; a watch's
  `Value` is the current value, and `StopAsync` ends it.
- **Agent events are gone.** `pi-durable` v1.5.0 removed `watchEvents` and its event types, and
  `PiSharp.Durable` drops `WatchEventsAsync` with them. Render the conversation view instead.
  PiSharp keeps a projection of the v1.2.0 events only inside the CLI's device host
  (`PiSharp.Durable.Hosting`, not a package), for the device wire.
- **Watch listeners get tagged calls.** A listener takes a `WatchCall<T>`: a
  `WatchValueCall<T>` (`Value`, `Ops`, `Retired`) or a `WatchFailedCall<T>`, plus a
  `DurableContext`. A document watch follows its address, so a retirement no longer ends it.
- **Custom storages commit batches.** `IStorage.CommitAsync(batches, receive, context)` stores
  several commits in one call, each with its own `seq`, and returns a `CommitResult`.
  `StorageConformance` checks the contract; `CommitWritesAsync` in `PiSharp.Durable.Testing`
  commits a single batch.
- **Renamed and reshaped members.**
  - `SubscribeCommits` is `ObserveCommits(CommitObserver)`.
  - `SessionEnd` is tagged by `Kind` (`Closed`, or `Failed` with its `Error`).
  - A document change in a commit is a `DocumentValueChange` or a `DocumentRetireChange`.
  - `HarnessOptions.OnReport` takes one `Report` tagged by `Kind`: `StorageFailed`,
    `TaskFaulted`, `TaskInterrupted`, `MigrationFailed`, `TaskOutdated`, `TaskError`,
    `ExtensionError`, `HostError` or `ListenerError`.
  - `TaskInspectionKind.Ready` is `Pending`.
- **`checkpointWhen` is required.** Every `Documents.Define*Doc` takes a
  `DocumentCheckpointPredicate` after `initial` and before the optional `migrate`, which must now
  be passed by name. A null predicate throws.
- **The examples were renumbered** to upstream v1.5.0's names (upstream `b9fb2b854`), for
  example `05-watches` to `04-watches` and `24-child-tasks` to `23-child-tasks`. `examples.*`
  prints the new names.

### Stored formats: no way back

Once PiSharp 1.5.0 has opened a session, PiSharp 1.2.0.x can't continue it. Copy a session's
folder or database first if you may need to go back.

- **SQLite.** Opening a file migrates it to schema version 2 (the tasks table gains the
  `sleeping` status). PiSharp 1.2.0.x refuses it: "SQLite schema version 2 is newer than
  supported version 1".
- **SQL Server** (`PiSharp.Durable.MSSQL`, in the repository, not packaged). Migration 2
  replaces the tasks table's unnamed status check with a named `durable_tasks_status` that
  allows `sleeping`. The version is kept once per database schema, so after 1.5.0 opens any
  store in a schema, 1.2.0.x refuses every store in it.
- **Records.** 1.5.0 writes `pi.live` version 3 (each run counts its turns; compactions carry
  their trigger), `pi.tool` version 3 and `pi.generation` version 2. Older records migrate on
  read. PiSharp 1.2.0.x doesn't know the new versions. On JSONL storage, which has no schema
  version, it opens the session but leaves such tasks blocked (`task_too_old`) and fails to load
  a `pi.live` version 3 document.
- **Tested direction.** The new `compat.upgrade-from-v1.2.0.*` cases open every v1.2.0 capture,
  migrate it and continue the resumable ones. They cover SQLite, and SQL Server through a
  version 1 schema.

### One-time effects of the upgrade

- A conversation from 1.2.0.x records its built-in tool declarations once more on its next
  turn, as removed and added again: pi-schema writes them in a different key order than TypeBox
  did. Upstream v1.5.0 does the same, and the model sees the same tools.
- A model request that was in flight when a 1.2.0.x process stopped is no longer sent again. On
  reopen it counts as a failed attempt and is retried after the backoff
  (`HarnessSettings.Retry`). With retries off, the run ends unanswered (`interrupted`).

### Behaviour changes

- **Deferred progress.** Partial answers and tool output are stored within
  `ProgressSettings.PersistWithinMs` (`HarnessSettings.Progress`, default 1,000 ms) instead of
  with each commit. Watches still see each one at once. A crash loses up to about a second of
  streamed text, and a crash in a stream's first second leaves no aborted entry.
  `ProgressSettings.PersistWithinMs = 0` stores each one at once.
- **Restart limit.** A task cut off by five restarts in a row ends instead of running again
  (`HarnessSettings.RestartLimit`; the run ends `restart_limit`).
- **Idleness.** After a run that ended without an answer, `pi.live` keeps `runFailure` until the
  next run, so idleness means no run, not an empty `pi.live`.

### New in the library

- **Group commit.** Commits made while a storage call is in flight go together in the next call,
  and a Harness's line jobs overlap storage instead of waiting for each commit.
- **Read caches.** A writing Session serves hot conversation, task and submission records and
  each conversation's newest entry from memory, so a normal run reads almost nothing from
  storage.
- **Sleep and wake.** `ITaskRuntime.SleepUntilAsync` and `NextTaskState.Sleeping` let a task wait
  for a time between phases, across restarts. `IHarness.Wake()` says when the next sleeping task
  is due; with `HarnessOptions.OnWake` a host arms its own wakeup and calls `Resume`, and
  `HarnessOptions.SetTimer` replaces the built-in timers.
- **Telemetry.** `HarnessOptions.Telemetry` takes an `ITelemetryContext` from the new
  `PiSharp.Telemetry` package (`PISHARP_TELEMETRY001`). It gets `pi.durable.submit` and
  `pi.durable.phase` spans, entry, submission, checkpoint, replay and report events, and
  phase-duration and active-task metrics. Attributes hold IDs and fixed categories, never
  content; `DurableTelemetry.Schema` lists them all. Without a context, nothing is recorded.
- **Work at the end of a run.** `GenerationHooks.AfterRun` returns tasks (`Define.RunEndTask`)
  that run before the run's answer is committed. A handoff round now continues the same run.
- **Provider request bodies.** `GenerationHooks.BeforeProviderRequest` replaces the provider
  request body of one generation request. Hooks chain in extension order, a throwing hook is
  reported and the chain continues, and compaction requests don't use it.
- **Entry reads in hooks.** `IHookApi.EntryAsync` and `EntriesAsync` read the raw history.
- **Turn limit.** `AgentChange.MaxTurns` ends a run unanswered (`turn_limit`) after the round
  that reaches it.
- **Admission and continuation.**
  - `SubmitAsync(tx, draft)` admits a submission inside your own commit.
  - `SubmissionDraft.Continue(requestId)` continues a conversation.
  - `whenIdle: WhenIdle.Reject` refuses input to an idle conversation.
- **Views and observers.**
  - `ConversationView` is a window over the newest entries (`ConversationWindow`), and
    `ConversationTranscript` loads earlier entries.
  - `IHarness.ObserveConversationAsync` and `ObserveTaskGraphAsync` attach synchronous
    observers.
  - Task graph nodes say why a task is blocked (`TaskGraphNode.Blocked`).
- **Deferred commits.** `CommitOptions(CommitPersistence.Deferred(withinMs))` lets your own
  progress commits wait in memory.
- **Options.**
  - `HarnessOptions`: `Identity`, `Env`, `ReadOnly`, `Now` and `ConversationCreated`; per-model
    compaction overrides (`CompactionSettings.ModelOverrides`).
  - `SqliteStorageOptions`: `Prefix`, `WalAutoCheckpointPages` and `BusyTimeoutMs`.
- **Registries from Chord.** `RegistryReader.Create` reads a Chord registry without Chord's
  host. It lives in `PiSharp.Durable.Store`, which is in the repository but not packaged.

### Device wire

The device protocol stays version 1, and `DurableWire.DurableVersion` stays "1.2.0".
`pisharp durable serve`, the web hub, the Web Agent and `pisharp durable attach` keep their
frames, through the Hosting projection of v1.2.0's agent events. It sends one batch per
publication and never folds batches. Past 100 undelivered batches, one snapshot replaces them.
The only additions are optional fields a v1 client ignores:

- the snapshot's `runFailure`;
- `run_end`'s `failure`;
- an agent's `maxTurns`;
- a task node's `blocked`.

### Benchmarks

`docs/durable-benchmarks.md` has the numbers. They come from one machine (AMD Ryzen 9 9950X3D,
Windows 11), one or two runs each, and are machine-local. No parity with upstream is claimed:
upstream's numbers come from a probe that isn't in its repository, or from a different workload.

- **Group commit** (memory storage behind a fixed round trip, 128 conversations).
  - Session changes went from 248 to 16,632 commits per second at 4 ms, with 73 commits per
    call, and from 977 to 57,611 at 1 ms.
  - Harness runs went from 13.8 to about 1,800 per second at 4 ms, with 32 commits per call and
    about one storage read per conversation's first run.
  - Entry appends went from 248 to 17,234 and 20,284 commits per second at 4 ms.
  - Memory storage with no latency costs more CPU per commit: about 200,000 commits per second
    became about 130,000.
- **Idle conversations.** With 4,096 idle conversations kept, one-tool runs went from 132 to 531
  per second, and with 2,048 from 216 to 552. A 4,000-task fan-out went from 923 to 404 ms, and a
  20,000-deep chain from 3,408 to 2,050 ms.
- **Partial commits.** A 500,000-character streamed answer allocates 52 MiB instead of
  6,103 MiB, and a tool call of that size 69 MiB instead of 2,608 MiB. The cost per commit no
  longer grows with the answer.

## Fixes

- **A deferred MCP server reached through `tool_search` no longer hangs a prompt.** The server's
  catalog publication waited for the prompt's run, and the run's `tool_search` waited for the
  server. The catalog is now published during the run once it reaches its provider phase
  (PR #50).
- **Unix processes.** On Linux and macOS, a process whose executable or working directory
  doesn't exist is refused before launch, as on Windows. `pi.exec()` then reports
  `spawn <command> ENOENT` with code 1, as Node does, instead of the shell's exit code 126 or
  127. A relative command name that `PATH` can't resolve still goes through `/bin/sh`.
- **Durable scheduler.** A sleep, such as a retry backoff or a poll delay, that came due between
  a scheduler pass and the wake it scheduled was run by neither, so the task slept forever. It
  now runs. A host that arms its own wakeup (`HarnessOptions.OnWake`) also gets the wake it was
  owed when the session fails.
- **Durable ordered flows.** Nested tool calls abandoned at a restart settle in call order: an
  ordered flow stays in order through a context wait and no longer reads around the line
  through a cached snapshot.
- **`ask_user_question`.** A question retired between the tool's commit and the start of its
  wait ends as retired, instead of failing with "Tool call ... has no interaction document".
- **Chord transactions** (`PiSharp.Chord`, in the repository only) accept a callback that awaits
  its own read, however late it returns. They used to refuse it now and then.

## Known gaps

These rows are ported with a deferral; the table records each one. The durable and Chord rows
with a deferral are under [Durable](#durable-experimental).
- **`ai.client-identity`.** Identity travels on each request; there is no Models-level default
  identity.
- **`ai.transcript-tool-support`.** Responses, Codex and Azure `additional_tools` and tool
  search are not implemented. Azure refuses those flags.
- **`ai.system-one-compat`.** The CLI's classifier registry reads only the built-in catalogs, so
  `models.json` settings don't reach classifier calls.
- **`ai.tool-call-args-incremental`.**
  - Mistral still writes a full message snapshot per frame.
  - pi-messages capture still deep-clones its partials.
  - Anthropic and Completions rebuild their failure-path partials.

  The Mistral and Azure Responses source inventories stay on v1.2.0 until these deferrals
  close.
- **`core.exec-max-buffer`.** Native `pi.exec()` still captures at most 1 MiB per pipe. The
  Node bridge honours `maxBuffer` in full.
- **`core.session-write-failure-rollback`.** After a write that may have reached the file, a
  native session faults and accepts no more writes. Upstream rolls the entry back and keeps
  writing.
- **`cli.custom-overlay-own-handle`.** An overlay's handle (`onHandle`) and
  `overlayOptions.visible` are not forwarded from Node extensions.
- **`tui.native-shift-enter-esc-return`.** PiSharp can't read the Shift state on macOS, so
  native Shift+Enter is not detected there.
- **`tools.tool-search-unicode-words`.** Word splitting follows the system's ICU, which can
  differ from V8's. Without ICU, text without spaces stays one word.
- **`bridge.pi-ai-extension-view`.** Installed extensions keep Pi 1.2.0's `pi-ai`, because the
  installed runtime is Pi 1.2.0.

The [Parity](https://pisharp.ai/parity/) page lists what else still differs from Pi.

## Packages and tool

The 23 library packages and the `PiSharp.Cli` dotnet tool are published as 1.5.0, 24 packages
in all. They are the 22 libraries of 1.2.0.2 and the new **`PiSharp.Telemetry`**, which
`PiSharp.AI` now depends on.

```powershell
dotnet tool update -g PiSharp.Cli
```

- **Not packaged.** `PiSharp.Chord` (Chord v2, `PISHARP_CHORD001`) and `PiSharp.Durable.Store`
  (durable storage on Chord v2's store) are in the repository but not packaged.
  - `PiSharp.Chord` reads PiSharp.Contracts' pi-schema internals, which need a public
    experimental API first, and the rest of Chord is phase 6.
  - No packaged project references either one, and the tool doesn't carry them.
- **Source only.** The Web Agent, Durable Web, SQL Server storage and the libraries under them
  stay source only, as in 1.2.0.2.
