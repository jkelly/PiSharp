# PiSharp 1.1.0.5

A C#-only patch on the Pi **v1.1.0** baseline (commit
`abe508e1b89912adde45528136c3221eb69acdd7`). 1.1.0.4 was tagged but its release run
failed in its tests before publishing, so nothing was published as 1.1.0.4; its changes
ship here.

The [Parity](https://pisharp.ai/parity/) page lists what still differs from Pi.

## Fixed

- **Startup header.** The interactive header showed Pi's package version (`v1.1.0`) next
  to the logo, and the onboarding line named Pi. It now reads **PiSharp v1.1.0.5**, using
  PiSharp's own product version, and the onboarding line names PiSharp. This is listed as
  an intentional difference from Pi.
- **Lone surrogates and auto-compaction.** Auto-compaction's token estimate read message
  text with a .NET JSON string accessor that rejects an escaped lone UTF-16 surrogate. A
  session holding one (from a prompt or a tool result) failed its run when the estimate
  was taken, which happens after every turn since 1.1.0.3 turned auto-compaction on in
  every mode. The estimate now counts UTF-16 code units from the JSON text, as Pi's
  `text.length` does.
- **`agent_settled` order.** Pi awaits the extensions' `agent_settled` handlers before its
  listeners (RPC and JSON output) see the event. PiSharp delivered it to clients first, so
  a client that closed the session on `agent_settled` could race the handlers. Extensions
  now see it first.
- **Settings read during a write.** Settings writes truncate `settings.json` and rewrite it
  under `settings.json.lock`. A reload that landed in between (each manual or automatic
  compaction re-reads the settings) read an empty file and used the defaults. Reads now
  take the same lock.

## Packages

All library packages and the `PiSharp.Cli` dotnet tool are published as 1.1.0.5:

```powershell
dotnet tool update -g PiSharp.Cli
```
