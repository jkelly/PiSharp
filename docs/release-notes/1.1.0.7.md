# PiSharp 1.1.0.7

A C#-only patch on the Pi **v1.1.0** baseline (commit
`abe508e1b89912adde45528136c3221eb69acdd7`).

The [Parity](https://pisharp.ai/parity/) page lists what still differs from Pi.

## Fixed

- **Commands that read standard input on Apple Silicon.** PiSharp marks the pipe ends it
  gives a spawned command close-on-exec, so the command does not inherit the parent's
  copies. It set the flag through a P/Invoke of `fcntl`, which is variadic; on macOS arm64
  variadic arguments are passed on the stack, so the flag was never set. A command given
  standard input (such as `bash -s`) then held the write end of its own input, never saw
  end of input and hung, and output pipes stayed open after a command exited. macOS now
  sets the flag with `ioctl(FIOCLEX)`, and every platform checks that it was set. Linux and
  Windows were not affected. (#14)
- **Settings and project-trust locks.** `settings.json`, the interactive settings and
  `trust.json` are locked as Pi locks them: a `<file>.lock` directory, ten attempts 20 ms
  apart, stale after 10 s. PiSharp checked for the directory and then created it, and the
  create succeeds on an existing directory, so two processes could both take the lock and
  overlap their writes. The lock directory is now created exclusively. The stale takeover
  no longer mistakes a lock released in between for a stale one (Windows reports its time
  as 1601), lock paths longer than `MAX_PATH` work on Windows, and a lock that fails for a
  reason other than being held reports that reason instead of "Lock file is already being
  held". (#15)
