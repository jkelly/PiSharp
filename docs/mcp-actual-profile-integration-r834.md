# Admitted MCP profile and combined initialization

`McpRegisteredProfileAdmission.CreateProfileAdmission()` supplies the existing ordinary session/RPC command admission input. The profile partial also accepts this admission directly while retaining the existing native registry, exact policy, independent resources and runtime-view ownership guards. The optional `OfflineSessionProfile.CreateAsync` parameter is a separately owned provider-file patch and is not included here.

`McpRegisteredServerWireAdmission` creates the actual JSON-RPC channel from one caller-admitted wire. It installs copied incoming handlers and dynamic roots before channel start. Registration metadata does not create a transport, credential or process admission.

`PrepareNativeInitialization` provides a decorated extension for the native SDK registration bridge's single genuine activation. The host passes the decorated extension once to that bridge, then commits MCP against its returned exact scope and activation original. MCP publication stays inert until the native activation completes. Post-activation publication failure closes and joins that exact scope. Aborting preparation does not independently dispose an extension whose ownership belongs to the native host.

The three combined initializer controls exercise the actual native registry, inert staging, one activation, failed initializer cleanup and conflicting publication cleanup. A further ordinary `SessionCommands` create control uses the committed registered catalog and the actual JSON-RPC channel over an injected wire. It requires a durable tool declaration, advertised dynamic roots capability and exact wire/native/discovery retirement counts. These controls are source-only and unexecuted. Genuine discovery identity, refresh/withdrawal, session-close/reload joins and loader call-site composition remain required before host integration can be accepted. This source does not claim cross-store durable atomicity or a live MCP connection.
