# Actual session model catalog publication

This slice extends the existing SessionRuntimeRegistry with an immutable model binding and thinking-capability table. CaptureModelCatalog returns a revision and the actual borrowed bindings. PublishModelCatalog validates all identities, duplicate keys and limits before invoking admitted capability getters, builds the complete prospective table, and publishes with one compare/exchange. A stale or reentrant publisher cannot overwrite the winner. Resolution captures one table for both transport and thinking admission. Captured selections retain their original transport objects.

Tool-catalog, lifetime-selection, invocation-owner and reload copies retain the appropriate catalog holder. Copying does not rerun transport capability getters. Existing PersistentAgentSession factory and ConfigureAsync paths consume the new table without changes to session state, durable commit or core Agent files.

NativeExtensionRegistrationBridge.PublishModelCatalog is an explicit admitted host refresh after genuine provider installation, replacement or unregister. It combines the application's retained baseline bindings with the actual native provider catalog and a real ExtensionProviderTransport. Thinking metadata belongs to the captured catalog; streaming continues through the existing provider host's native callback/iterator ownership. No credential acquisition or executable binding is inferred from configuration.

The six standalone groups exercise a real known session selecting and prompting a newly installed provider, a real factory selecting an already installed late provider, pre-callback validation/cancellation, reentrant compare/exchange refusal with consistent thinking/transport, shared tool/initial-selection copies, and captured selection identity across replacement. Actual asynchronous session and native scope operations are captured once and directly joined. The reporter retains raw original tasks and complete exception inventories before bounded graph metadata and preserves output write/flush/dispose failures. These controls are source-only and have not been compiled or run by this worker.

## Remaining owner integration

NativeExtensionActivation and PluginAssemblyLoader remain allocated to the activation owner. That owner must invoke the single native initializer bridge, then PublishModelCatalog with the application's real runtime and retained baseline bindings. Replacement/unregister and scope retirement must refresh the catalog too. Provider metadata and the session catalog are distinct stores; this API does not claim a global durable transaction or automatic refresh for every facade call. CAS conflict requires explicit owner reconciliation. The existing session reservation and durable ConfigureAsync boundary remain authoritative; this slice does not introduce cross-store serializability.

The MCP initializer decorator can be passed into NativeExtensionRegistrationBridge.ActivateOwnerAsync once. Commit its stage only against the returned exact Scope after ActivationOriginal completes; abort staging on failure and close/join that same scope if the post-activation MCP commit fails. Native scopes own disposal; the bridge borrows the registry and is disposed after the loader/native owners have joined.
