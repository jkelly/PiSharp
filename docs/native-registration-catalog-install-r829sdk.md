# Single activation and configured model refresh

This successor preserves eba7df50 and adds an optional actual runtime binding to the native initializer bridge. ConfigureModelCatalog borrows the application's exact current baseline once. It can run before activation or at the existing runtime binding boundary after activation; in the latter case existing installed owners are immediately reconciled. No model factory, credentials or configuration binding is inferred.

Once configured, genuine native initialization metadata publication refreshes the session catalog before promoting the initializer facade. Active facade provider replacement and unregister refresh automatically. RetireOwnerAsync validates the exact installed scope, captures its actual DisposeAsync Task once and directly awaits it, then reconciles the catalog even after a cleanup fault. Full native fault inventory and a separate reconciliation error remain in the resulting exception graph. Failed post-activation publication closes the same native scope and attempts catalog reconciliation even if cleanup faults.

The original six model groups now exercise automatic install, replacement and unregister refresh through real session operations, and the exact retirement hook. The separate six initializer groups remain unchanged. Both fixtures are source-only and unexecuted.

## Allocated activation-owner callsites

PluginAssemblyLoader's optional activation delegate must default to registry.ActivateAsync. The admitted delegate prepares the MCP decorated extension once, awaits NativeExtensionRegistrationBridge.ActivateOwnerAsync once, and passes returned Scope and ActivationOriginal to the MCP stage commit. On MCP commit failure it must call and directly join bridge.RetireOwnerAsync on that exact scope, retaining both primary and cleanup inventories. It returns the exact scope to the loader; the loader retains the same instance and package/context ownership. LoadedExtension's optional retirement delegate must default to scope.DisposeAsync; the admitted delegate calls bridge.RetireOwnerAsync once. These callsites belong to the loader/activation owner and are not edited here.

NativeExtensionActivation owns the bridge and explicit flag values/configuration adapters. At its actual application runtime bind it supplies the real SessionRuntimeRegistry and retained original model bindings to ConfigureModelCatalog. Dispose loader/native owners first, then bridge. No cancellation registration dispatches unjoined cleanup or model mutation. Catalog refresh is a synchronous admitted operation under the bridge gate, with one actual revision capture and CAS publication. Provider metadata and model catalog remain distinct stores: refresh failures are explicit reconciliation failures, not a globally atomic transaction claim.
