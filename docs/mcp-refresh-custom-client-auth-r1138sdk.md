# Admitted refresh client authentication, source-only

This isolated successor of reviewed c0f2a450 preserves the authorization-code leaf and all public host/registry/core/session/terminal paths. It extends the existing refresh adapter, state provider and borrowed exchange rather than creating another refresh or storage engine. The original pinned Pi0.99.1 packages/mcp/src/oauth/flow.ts tokenRequest branch prepares base Accept/content-type headers, grant/refresh/resource parameters, then awaits addClientAuthentication INSTEAD OF selecting default Basic/Post/none, then exchanges and saves tokens.

The old seven-parameter McpAdmittedOAuthRefreshAdapter constructor, including its defaults and binary signature, remains an overload. A new explicit eight-parameter overload receives an optional borrowed McpAdmittedOAuthRefreshClientAuthentication. Only a configured callback selects the custom branch; it bypasses SelectAuthentication and default credential checks entirely. Absence preserves the original branch. The custom callback receives IMcpOAuthRefreshClientAuthentication with admitted endpoint/client/metadata and bounded header/form methods. No client, HTTP request, endpoint, clock, credential, browser or store is acquired. Native host use is explicit: supply the callback/store/exchange/clock/cancellation admission, then pass CreateAuthentication() to an already admitted HTTP operation/factory. This leaf does not perform that host/profile binding or claim a full host adapter.

The callback's returned ValueTask is materialized once through reviewed McpOAuthAdmittedWork and directly joined before an immutable proposal snapshot can reach Exchange. Its synchronous entry runs under the existing physical owner frame; the active logical frame now also retains captured physical ancestry across awaits, preventing a frame-free normal Register callback in a nested refresh from joining its waiting ancestor. Cancellation after awaited dependency work MUST use the existing affine McpOAuthCancellationAdmission and join the actual returned original before the dependency returns. Saved proposal references retire at Snapshot/finally after join, including fault/cancellation. No detached post-completion callback effects or atomic wall-clock retirement guarantee is claimed. Native header token/byte-string validation, lowercase lookup, trim/comma-space Append, form USVString/ordered duplicate/first-position Set behavior reuse the independently reviewed authorization-code proposal semantics in a separate owned implementation because the frozen code-flow files are not edited. Entry caps256 headers/256 form pairs and maximumBytes are explicit native bounds, not JS object/type identity or full Headers/URLSearchParams iteration/cookie semantics.

The refresh adapter has no new Close/Dispose API. Existing authenticated HTTP operation ownership remains responsible for canceling and joining its actual OnUnauthorized original, which joins the shared refresh and admitted callback. The new held control proves caller cancellation does not settle either shared handler until the held callback original returns, and then fences Exchange/token-save. The existing original save-discovery step precedes the hook and may already commit: this is preserved, not misreported as no store effects or rolled back. No changes are made to the reserved HTTP capture/Stop owner.

Four authored unexecuted groups cover custom overriding a default Basic requirement with no secret, base refresh/resource fields, header/form mutation/default constructor behavior/refresh-token retention/retired references; two callers sharing held refresh, actual cancellation original and no late token effects; exact multi/shared callback faults, synchronous and task-faulted OCE versus a genuinely canceled matching-token original; and A normal Register calling unrelated B refresh, B yielding then invoking another frame-free callback that refuses A Token/OnUnauthorized before state reads. Actual callback/store/exchange/group Tasks and captured AggregateException/direct references are retained and joined; predicate failures retain whole original graphs. Diagnostic signal waits are finite and always release held work in finally, without replacing actual returned operations. The source project is a library with default Runtime reference; no shared Program/project/solution changes, no reporter execution, no builds/tests/Node/network/reflection occur here.

Remaining original OAuth gates include dynamic client registration/client metadata selection, invalid-client/invalid-grant invalidation and whole-flow one-retry orchestration, refresh server-error redirect fallback, browser callback/state/verifier handling, actual application/profile/store integration, full JS mutable object/type surfaces, and original Unicode-token parsing edges in the unchanged discovery/refresh parser. Existing code-flow UTF16 corrections are not silently claimed for that unchanged parser. Source review and genuine changed-producer/meaningful control qualification are required before any acceptance. Older packages,85/87 controls and Node27 results are not inherited.
