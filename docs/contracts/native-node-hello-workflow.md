# Genuine Hello package workflow candidate

This candidate connects the unchanged upstream `hello.ts` factory, live TypeBox schema, whole `validation.ts` preparation and original five-argument execute function to a compiled native package, recorded provider requests and durable CLI/RPC sessions. It is statically authored; root execution and independent review determine acceptance. The earlier C# Hello schema fixture is an authored native control and is not source execution evidence.

The immutable source is Pi v0.99.1 commit `d86654abb8862e201933517d6f1fce9f88dd117f`. Hello's 640 source bytes have SHA-256 `0aa4e9800c2526914d4c1edb00b2cfa9bd9dd6da5218289994cccd5f5bfa4934`. [The closed profile](../../compatibility/node/hello-bridge.plan.json) holds exact helper, whole-source and preparation-reference pins. The existing canonical source/dependency/Jiti verifier is composed read-only; it starts no protected-paths worker and changes no predecessor pin. All fifteen existing dependency inventories, original licenses and official Jiti 2.7.0 artifacts are verified before and after. No installation or network access is part of this workflow.

`NodeHelloWorkerLaunch` requires explicit absolute runtime, repository, oracle, Jiti, canonical-reference, Hello-preparation-reference and fresh invocation paths. Source and metadata streams remain held through joined worker shutdown. The package loads private Compatibility.Node and ExtensionHost assemblies in its approved collectible context, with the shared Abstractions and Contracts assemblies in Default. The existing exact artifact-bound `windows-worker-directory-0` supervisor grant remains necessary; no general native-library permission is added.

The whole public loader registers the actual Hello definition in Node. The canonical single virtual-module replacement exposes the original qualified Type and defineTool aliases; full SDK namespaces remain a mandatory future gate. The descriptor name, label, description and public schema are recorded verbatim. No `additionalProperties` keyword is added. The original schema object remains live for validation, and recursive own descriptors, symbols and TypeBox Settings are observed before and after. Qualified TypeBox 1.3.27 uses the nonenumerable string `~kind` and lacks `Symbol.for('TypeBox.Kind')`; the unchanged validator therefore retains its original fallback behavior.

Initial preparation runs after strict original native JSON admission and before native initial schema validation. It calls the entire upstream `validateToolArguments`, including its clone, optional-null treatment, genuine Value.Convert, Compile and check/fallback path. There is no Value.Clean, schema rewrite, result replay or ported conversion. Preparation receives cancellation and arguments only, with no host/UI context, callback handle or fabricated call ID. Hook replacement validation does not rerun source preparation, so an authored replacement `{ "name": 7 }` fails the final native string schema.

Execution receives the actual provider ID, final authorized parameters, owned AbortSignal, bounded synchronous onUpdate and the fifth argument from genuine `ExtensionRunner.createToolContext`. The original Hello emits no updates. The adapter joins every admitted native update delivery before releasing the execution lease if a future call admits one; this candidate does not claim universal source scheduling parity. The genuine runner has no UI bridge here and unsupported neighboring host operations throw explicitly. Hello uses none of those operations. The source function and its full result shape remain unchanged.

The opt-in [workflow tests](../../tests/PiSharp.CodingAgent.Tests/NodeHelloPackageTests.cs) contain four groups. Each provider family executes original `hello-result` and `hello-unicode` input through real recorded HTTP/model/tool requests and the compiled CLI, acknowledges a flushed durable log, independently reopens RPC with actual numeric42 source preparation, and branches from the earlier CLI ancestor with actual native Hello denial. `--deny-extension-tool hello` retains the declaration and binding while refusing the final executable target. Original `hello-denied` has no source-authored ID; `native-hello-denied` is a separate explicitly authored provider ID. Responses expectations preserve the full authored `call_id|item-id` identity.

The fourth group retains actual upstream missing-name, object-name and array-name failures, a separately authored native adversarial replacement hook, and ungranted native write denial. Rejected calls have no original execute receipt. No original factory or hook is modified to produce those controls. Successful preparation/result serialized JSON and complete observation values are compared against the frozen genuine reference. JSON record whitespace is not observation data; serialized source JSON, IDs, scalar sidecars and array order remain exact. The complete new source errors and raw stacks are retained; reference and bridge instrumentation paths differ and are never normalized to manufacture equality.

Every invocation retains raw CLI/RPC stdout and stderr byte reads, physical process exit, package disposal receipts, actual source operation settlements, immutable before/after inventories, protocol counters and supervisor launch/termination receipts. Successful cases require natural worker exit, joined EOF/owned stream closes, no pending calls, callbacks, writes or handles, and no remaining package snapshots. Watchdog or I/O overflow first stops the actual process tree and then awaits process and admitted reader joins; failures retain their raw bounded evidence.

Only `tools/test-native-hello-package.ps1` opts into this Node process harness. The ordinary native gate never calls these cases or starts Node. Native CLI/core production project graphs do not acquire a Compatibility.Node reference.

All eleven unchanged extensions and all forty-two corpus IDs remain required. This candidate assigns no executed corpus or phase-six/seven closure credit. Other schema families, optional-null/coercion profiles beyond the observed Hello path, full SDK/context support, real progress/UI timing, crash/cancel/restart integration, shipping notices and independent qualification remain open. Protected-paths raw relative tool-call argument fidelity also remains open: native final-action preparation currently supplies its validated absolute arguments. This path-free Hello workflow does not resolve or waive that obligation.
