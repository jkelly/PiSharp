# Read-only edit preview

This native host API implements the read-only orchestration in Pi v0.99.1 `computeEditsDiff`, pinned at `d86654abb8862e201933517d6f1fce9f88dd117f`, in [`edit-diff.ts`, lines 514–543](https://github.com/badlogic/pi-mono/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/edit-diff.ts#L514). It uses the existing native matcher, all-original-content edit plan and display formatter. This candidate supplies executable comparisons; isolated execution and independent acceptance are recorded by the root review, not claimed by this document. P3-06 and the broader phase remain open.

## Host API and authority

```csharp
var preview = new EditPreview(cwd, home, requiredReadPolicy,
    operations: trustedOperations, options: previewOptions,
    accessProbe: trustedAccessProbe, transforms: trustedTransforms);
EditPreviewOutcome outcome = await preview.ComputeAsync(path, edits, cancellationToken);
```

`edits` is an initialized immutable array of `TextEdit`. The source compute helper also receives an already typed array. Model argument variants, including a single object, JSON-string array and appended legacy fields, use the existing `EditTool.PrepareAsync` API separately. An initialized empty array proceeds through read authorization, R_OK and content read, then returns the source plural no-change error. A default array, missing path, unsupported UTF-16/NUL text and configured admission limits produce native invalid-argument failures before content read.

Each compute call constructs an explicit host-authored invocation frame and routes a private adapter through `ToolInvoker`. It does not invoke a provider. The adapter and invoker remain private, and construction requires `IToolActionPolicy`. The final immutable action has tool name `edit-preview`, operation `preview-edit`, kind `Path`, empty command arguments/environment, the configured working directory, and matching absolute `Target` and owned `arguments.path`. Initial preparation resolves the path and calls the trusted filesystem canonicalizer before policy. Canonical resolution can inspect filesystem metadata before policy, as in the accepted file adapters; content access starts only after authorization. The policy receives the exact final action that execution uses.

Trusted action transforms may retarget the action and replacements. A transform must update both target and owned arguments and supply the intended canonical absolute target; final structural validation rejects target/argument disagreement, other operations, command actions or ambient environment/cwd changes. A host policy must inspect the final target and the explicit read operation. A write-only permission is unnecessary for this read authority. Host callbacks, canonical resolution, transforms and policy are trusted native code. This API does not supply hostile-path race confinement, hard-link identity, a native callback sandbox or file locking.

## Source outcomes and native failures

`EditPreviewOutcome.Preview` is owned `JsonData`. Successful matching returns the complete source-shaped body `{diff, firstChangedLine}`. Matching, ambiguity, overlap, empty-old-text and no-change errors return fulfilled `{error}` bodies. A bounded access-probe code returns the exact source wrapper `Could not edit file: <displayPath>. Error code: <code>.` The native invocation has empty `Content`, identical `Details`, `IsError=false`, no typed `Failure`, absent `StructuredContent` and `Terminate=false` for all these fulfilled outcomes. The source preview itself does not return a chat-tool content envelope.

Native structural admission, denied policy, transform/policy failure and cooperative cancellation remain distinct. They return `Preview=null` and the invoker's typed failure in `Invocation`. If the invoker retains a completed body after late cancellation, it remains visible in `Invocation.Details`; `Preview` still remains null. Unknown callback exception messages are private: access failures use `Could not edit file: <displayPath>. Access probe failed.`, unknown read failures use `Cannot read file contents for edit preview.`, and other unknown computation failures use `Cannot compute edit preview.` These fixed native messages are a deliberate profile, rather than reproduction of upstream arbitrary exception payloads or platform-specific read-error strings.

## Read, display and cancellation behavior

Execution performs actual R_OK followed by one bounded content read. It strips one leading BOM, normalizes CRLF and lone CR to LF, matches every replacement against original normalized content, and formats the display diff and first changed line. It never creates directories, writes content, rereads for a commit conflict check, generates a unified patch or registers a mutation reservation. Preview may observe a file while a coordinated writer is active. The display describes the bytes that were read and supplies no later-commit guarantee.

`DiffFormatter.FormatDisplay` shares the existing display implementation with `Format`; it bypasses unified-patch construction and its output limit. Myers work, trace, line and display budgets still apply. The factoring leaves the formatter algorithm, tie selection and unified patch implementation unchanged. A display that fits its budget can succeed when an unused unified patch would exceed the same character budget. Exact jsdiff compatibility beyond the captured overlap remains unqualified.

Reads default to 1 MiB, plan content to 1 Mi UTF-16 characters, arguments to 524,288 serialized characters, paths to 4,096 characters and replacements to 64. Existing formatter defaults bound lines, work, trace cells and display characters. Options enforce finite positive upper bounds. The adapter verifies a trusted read callback's returned byte length and copies its memory before decoding. Strict UTF-8, valid surrogate pairs and the existing text-content profile are supported; invalid UTF-8, NUL/unsupported control content, images, binary and other encodings produce an explicit fulfilled native unsupported-content error. Node's replacement decoding for malformed UTF-8 and unrestricted binary text are outside this implemented profile and require future compatibility work.

Cancellation is checked around canonicalization, access, read and computation. A callback that ignores cancellation is awaited until it settles its own I/O and asynchronous cleanup. A late callback return or failure after cancellation cannot advance to another read/effect boundary. There is no forced timeout or detached background operation. The trusted callback interfaces retain responsibility for awaiting all owned work before returning or throwing; transforms and policy also follow the accepted invoker's cooperative contract.

## Platform profile and immutable evidence

The default access probe is the existing `LocalFileAccessProbe`: Windows uses `GetFileAttributesW` metadata, matching the selected libuv R_OK profile without a substitute open/ACL check. A ReadOnly regular file is allowed for preview; the edit tool's R_OK|W_OK profile rejects it with EPERM. Linux/macOS use libc `access` with real IDs. Error-code mapping is bounded and partial. Other platforms are unsupported by the local probe. Directory content-read failures are sanitized through the native profile. These source-linked platform choices are separate from an executed cross-platform differential claim.
