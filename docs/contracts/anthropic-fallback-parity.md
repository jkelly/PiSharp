# Anthropic fallback parity candidate

This provider-local P2-06 candidate is based on `7452a7b2a355e1f603a31eb693def91a9f565df1` and unchanged Pi v0.99.1 `d86654abb8862e201933517d6f1fce9f88dd117f`. It fixes a concrete request/stream mismatch: the request projector already declares allowed fallback models and selects the server-side fallback beta, while the mapper previously rejected every fallback marker and priced returned models at requested-model rates.

`AnthropicMessagesOptions.AllowedFallbackModels` accepts an immutable array of explicit `AnthropicFallbackModel(Provider, Model, Rates)` records. Selection follows the pinned [complete provider helper](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/anthropic-messages.ts): only a different returned model in `message_start` with an exact model and requested-provider match selects alternative costs. Unmatched models retain requested rates. Marker `from`/`to` fields have no pricing authority. The requested assistant identity stays unchanged and the existing `responseModel` metadata records the returned identity.

Pre-output fallback starts and optional stops are bookkeeping; native content positions stay contiguous. A fallback after any text, thinking or tool content starts fails with existing sanitized MalformedStream classification and retains partial output. Duplicate marker starts/stops, index reuse and marker deltas remain stricter structural admission than the public helper. Configured profiles and retained marker identities are separately bounded by MaximumContentSlots. Existing raw input and event limits remain effective. Native decimal costs, zero rates, one-hour cache writes, exact identity matching and error usage settlement use the selected profile without introducing catalog or credential access.

The pinned [SSE tests](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/test/anthropic-sse-parsing.test.ts) supply the source-informed returned-model pricing and mid-output rejection cases. Two parsed mapper groups and one actual fake-HTTP/SSE group are authored and registered through existing Anthropic test discovery. They cover initial/delta/cache pricing, optional marker stops, sparse content positions, unknown/requested/case/foreign-provider models, zero rates, initial-usage EOF, invalid profiles, marker bounds and strict structural rejection. The HTTP group observes the fallback request and beta, settles via ChatClient, verifies success/EOF/mid-output rejection, and checks response/request cleanup.
