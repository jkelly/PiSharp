# Typed native tool authoring, bounded source successor R594

This is a source-only native equivalent for the generic authoring/conversion portion of Pi v0.99.1 `ToolDefinition<TParams,TDetails>` and `defineTool`, pinned commit `d86654abb8862e201933517d6f1fce9f88dd117f`. The retained R336 SDK inventory marks ToolDefinition parameters/execute partial and the full generic/schema/output/render/options ABI open. This addition does not change those historical classifications or assert full original ABI parity.

`ExtensionTypedTool.Define` takes the canonical raw Parameters schema and explicitly supplied `JsonTypeInfo<TArguments>` / `JsonTypeInfo<TDetails>`. Use source-generated metadata. No schema is inferred, serializer options are not taken from ambient globals, and the helper does not perform host schema validation. It returns the existing `ExtensionToolDescriptor`; descriptor init properties can be set with a record `with` expression. Register and execute it through the existing registry and prepared binding. Final argument authorization and schema validation remain the host's responsibility.

The typed callback receives the same native context and cancellation token as the raw callback. An invocation-aware context preserves its tool call ID, broker and original awaited progress receipt. The helper captures the returned original ValueTask once and directly awaits it once. It does not race or detach callback cancellation, catch user callback faults, or manufacture invocation identities. Explicit converter failures propagate with their identity.

Fault propagation follows normal native `await` semantics, as in the existing raw async callbacks. A Task-backed callback containing multiple separately recorded faults propagates the await-selected exception; the callback Task's full Exception inventory remains distinct. A faulted callback Task containing OperationCanceledException becomes a canceled helper/registry Task even with a clear token. Controls retain and report the original callback's faulted status and complete DAG, and separately record the invocation status. This helper does not establish full original Task-status or fault-inventory preservation at the host dispatch boundary.

`ExtensionTypedToolResult<TDetails>` always writes content and details; null typed details write JSON null. Optional StructuredContent and Usage distinguish absent (C# null) from explicit null (`JsonData.Null`). Nullable IsError and Terminate preserve absent, false and true. Opaque structured numbers pass through `JsonElement.WriteTo` without numeric conversion. The host's existing content and result limits remain authoritative.

Conversion has a separate bounded profile: default 262,144 UTF-8 output bytes, depth 32, accepted ranges 512..16,777,216 bytes and depth 1..64. One fixed buffer reserves the byte limit plus 4,096 writer slack bytes. Buffer requests that exceed this capacity and advances beyond the actual output limit fail with a fixed JsonException before JsonDocument parsing or owned-value cloning. Writer capacity requests can conservatively reject a near-limit value. These limits govern the helper's serialization buffer, not allocations performed inside trusted extension code or user converters. They do not increase registry/pipeline quotas.

Eight standalone source controls in `tests/PiSharp.TypedSdkTool.Tests` cover actual registry activation and prepared binding execution, transformed final arguments/schema preservation, progress and invocation identity, absent/null/false preservation, strict source-generated argument admission before callback, held cancellation/finally/owner close, quiescence/resumption, original aggregate exception DAG identity, single-consumption ValueTask sources and conversion/host update/result quotas. The helper uses the explicitly supplied source-generated metadata. A metadata property-name override proves that typed details follow that supplied contract rather than default/reflection metadata. This guarantee applies to the typed helper, not the whole host: the existing registry snapshot serializer uses the normal host reflection profile. The fixture preserves that profile. Its report records each case's original Task and subsidiary callback/registry/cleanup Tasks, directly joined, plus complete exception DAGs with shared leaf identities. Gate timeouts are observation guards only; `finally` releases and joins admitted work.
