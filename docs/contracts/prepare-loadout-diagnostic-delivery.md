## Bridge and admission

LoadoutDiagnosticDelivery borrows one exact binding snapshot, an explicit async diagnostic delegate and a cancellable generation lifetime owned by the activation. It grants no registry, tool, session, process or UI authority and does not dispose borrowed resources. Capture performs bounded synchronous bookkeeping only: no prepare hook invocation, reporter call, async work or background worker. It maps only registered tools with a prepare hook to event prepare_loadout, owner ID, owner generation and the actual tool registration ID. Existing diagnostic sanitization is preserved: no plugin message, stack or fabricated extension path enters ExtensionEventDiagnostic. The exact original Exception remains in a trusted host capture receipt. Native source-path/error/stack wire parity is still a separate gap.

Each accepted failure occurrence is charged against the configured maximum (default 128, allowed 1..4096) until its original batch reporter completion is joined. Pending plus in-flight captures share that bound. Unknown/non-prepare tools, full capacity and retired generation return explicit declined receipts retaining the original failure; the owner must retain/handle them, not silently discard them or attribute builtin failure to an extension. Declines are never sent to the sink. Repeated occurrences with the same Exception instance are separate captures.

DeliverAsync(currentBinding.Snapshot, admissionToken) admits one immutable pending batch. Current binding identity is reference-exact; do not substitute a fresh registry.CaptureSnapshot even at the same revision. Admission cancellation throws with its original token and leaves pending work intact. Once admitted, reporting is governed by the borrowed generation lifetime, not a later caller cancellation. A current snapshot mismatch permanently invalidates the bridge. Generation retirement/mismatch before a report admission refuses that report with retained capture evidence. Already admitted reporter work is always directly awaited even if retirement occurs while it is held. The activation must retire the generation token before replacing it, and join original returned tasks before releasing its diagnostic sink/resources. The bridge does not infer registry retirement from metadata or implement reload/unload ownership.

Concurrent delivery callers join the same original Task through actual completion. A private start gate prevents trusted reporter execution under the bookkeeping monitor. Reporter self-wait is refused. Captures admitted during delivery remain in a separate next batch; the serialized host owner must drain its capture boundary again rather than assume the first receipt includes new work. The bridge neither schedules nor retries work automatically.

A successful report occurs once per captured item; the completed batch is not redelivered. Reporter failure, including foreign OperationCanceledException, is retained as the exact original instance beside the original preparation failure. Later items in that batch are skipped, preserved in the receipt, and never retried because earlier reporter effects may already have occurred. ThrowIfReporterFailed is an explicit optional host policy that aggregates both exact original causes; ordinary prepare failure alone retains existing fallback and does not throw. Source listeners are synchronous; this bridge's explicit joined async delivery timing remains a native difference.
