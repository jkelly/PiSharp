# Native session shutdown notification

The current Pi v0.99.1 baseline is `d86654abb8862e201933517d6f1fce9f88dd117f`. Actual native source in the supplied `75c18ddda73ce7d82954d701a582511d06a63dd1` manifest already implements quiescence, transactional registration, cooperative unload, session compaction and replacement-start notifications. It does not implement the `session_shutdown` helper. This bounded successor supplies the host API and the shared offline/live RPC quit placement; it does not close the extension lifecycle phase or implement future backlog/Extras.

```csharp
ValueTask<bool> ExtensionRegistry.DispatchSessionShutdownAsync(
    ExtensionRegistrySnapshot captured, JsonData observation,
    Func<ExtensionEventDiagnostic, CancellationToken, ValueTask>? reportDiagnostic = null,
    ExtensionSessionSnapshot? retainedSessionSnapshot = null);
```

The helper validates an immutable JSON object with `type: "session_shutdown"`, required `reason` (`quit`, `reload`, `new`, `resume`, or `fork`) and optional string `targetSessionFile`, then emits that same object to captured `Observation` registrations for that topic. It returns false for an admitted snapshot with no shutdown handlers and true after dispatching a nonempty admitted list. It retains ordinary registry identity, exact entry/generation, active scope and shared concurrency/resource admission. All selected callbacks are leased before the first callback, in owner admission/registration order. Removal during notification affects later captures; the original list remains admitted. A stale snapshot cannot start callbacks after removal or owner replacement, and a participant cannot await its own or another admitted participant's disposal.

Each original callback and reporter is directly awaited. Callback failure, including an `OperationCanceledException`, reports a sanitized `ExtensionEventDiagnostic` with event, owner, generation and registration identity and continues. The report contains no plugin exception text, stack or payload. If the trusted optional reporter itself throws, its original exception propagates and later callbacks are skipped. Every admitted lease and shared dispatch charge is released by the outer finally on either path.

This shutdown notification accepts no borrowed operation/session cancellation token. Its callbacks receive a dedicated token owned by this dispatch, also exposed as `OperationCancellationToken`; `SessionCancellationToken` is None and the existing generation lifetime remains separately owned. After every original callback/reporter has settled, the operation cancels its own lifetime and releases all leases. Throwing cancellation listeners remain cleanup failures; when a reporter also failed, both original causes remain in an aggregate. The callback frame remains active through lifetime cancellation so a listener cannot synchronously await disposal of an admitted participant. External owner disposal still cancels only its generation lifetime and joins admitted callback work. No caller timeout or cancellation detaches these joins. A noncooperating callback or synchronous cancellation listener can prevent settlement. The helper neither disposes the registry/loader nor adds a shared once-only/reload bit.

[`types.ts:785-790`](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/extensions/types.ts#L785) specifies the required reason and optional destination. These source paths were inspected, not executed as a differential oracle.

Pi creates a shared mutable Runner context; native dispatch retains per-generation immutable payload/context admission and cooperative disposal joins. Shutdown uses a dedicated retained read context implementing only IExtensionContext, IExtensionSessionContext and IExtensionUiContext. It exposes no session actions, command, tool, model, catalog, context-edit, compaction or activation interfaces. UI is permanently unavailable; the normal provider is never reopened. The optional final snapshot is validated and copied using existing immutable view budgets and opaque-number policy, without recapturing a canceled attachment. Null explicitly means no retained view. This differs from ordinary callbacks, which open live session action scopes, and from the source shared mutable context. Ending the dedicated lifetime and preserving its listener failures are additional native ownership semantics. Empty native dispatch still validates registry identity, liveness and the shared dispatch budget. Sanitized host diagnostics replace source error messages/stacks; an absent native reporter drops those diagnostics. These are disclosed source differences, not claims of full parity or permanent exclusions.
