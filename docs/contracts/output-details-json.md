# Output details JSON admission

`ToolInvoker` admits `ToolResult.Details` as inert output data. A decoded NUL in `details.truncation.content` survives executor results, awaited progress partials and complete result transforms. Details strings and opaque property names may contain escaped NUL; valid scalar Unicode, owned JSON, finite numbers, strict retained syntax, container depth and the existing ordinary result budget remain required. Input and action admission remain separate.

## Native admission and limits

Normalization obtains the original owned details' raw JSON text and charges its UTF-16 length against `MaximumResultCharacters` before strict reparsing. The strict parse rejects retained permissive `FromElement` comments and root/nested trailing commas. Ownership and traversal reject duplicate decoded property names, undefined values, malformed JSON, nonfinite binary64 numeric values, unpaired Unicode surrogates and excessive container depth. Escaped NUL is admitted in details string values and inert property names; it is never treated as an action, process argument, path or environment value.

Output details and structured output share the same output-data traversal. Structured output keeps its accepted independent raw-size cap, strict retained syntax reparse and ownership rules. Admission validates parsed values without replacing the original `JsonData`, so original whitespace, lexical escapes, property/array order, explicit nulls and tokens such as `1.0`, `9007199254740993` and `-0` remain owned unchanged. `Details` is mandatory: C# null is rejected; `JsonData.Null` is explicit JSON null and remains a valid four-character output value.

The ordinary allowance remains 65,536 characters by default, cumulatively charging raw details, ordinary text, failure-message length and text extra-property names/values. A NUL in raw details typically costs the six characters of `\u0000`; the same decoded NUL in ordinary text costs one UTF-16 character. Exact inclusive boundaries succeed, and one character beyond them fails. This fix raises no allowance or constructor limit. Large tools must still produce a result that fits the host's configured cumulative budget. Strict reparsing temporarily owns a validation value and does not claim a total heap bound.

Executor or partial admission failure becomes the invoker's fixed `ExecutionError`; rejected progress is never published. Invalid complete replacement details becomes `HookError` and preserves the last validated result, including its NUL-bearing details, ordinary content, structured output and termination state. Existing result transforms, scheduler behavior, progress closure/backpressure and whole-result hook replacement semantics remain unchanged. This bounded admission applies to the actual invoker and does not newly validate arbitrary trusted scheduler executors or outer afterhook returns.

Tool-call IDs, tool names, argument JSON, action operations/targets, paths, argv, cwd, environment keys/values, failure messages and ordinary content extra-property keys/values keep their prior NUL exclusion and existing validators. The change is confined to `Details` output admission. It does not widen any executable/input boundary or copy output into one.

## Authored controls

It checks exact raw ownership, unchanged whitespace, ordered opaque/NUL property names, explicit nulls, Unicode, wide numeric tokens, finite numeric bounds, inclusive cumulative budgets, scalar details and exact container depth. Executor and result-transform controls reject retained permissive syntax, duplicates, nonfinite numbers and malformed Unicode without exposing rejected details or replacing the last validated result.

The existing NUL-output flow now uses actual native tail truncation to create NUL-bearing progress, final and transformed details. A typed prepared adapter runs through the actual invoker, bounded scheduler and high-level Agent with an awaited update gate. Assertions follow owned details through progress and final outcomes, final `ToolResultMessage`, canonical JSON and the next native `ChatRequest` captured by an authored transport. This test does not qualify HTTP-wire details retention. Existing identity/action/environment/failure/extra-property NUL controls are retained, with a direct tool-name NUL control added. These expectation changes follow the source output-data contract; they do not remove the remaining input safeguards.
