# Bounded native VT renderer prototype

This is the small owned-renderer experiment for P5-07, using Pi v0.99.1 at `d86654abb8862e201933517d6f1fce9f88dd117f` as the compatibility target. It adds real awaited `IConsoleTerminal.WriteAsync` calls and authored virtual physical-sink tests. The source authoring lane has not run a compiler, tests, performance measurements or terminal experiments. The coordinating gate must attach results to an immutable commit before describing any test as passing. This prototype does not select the production interactive CLI route or close P5-07, P5-08, P5-09, P5B, the OS matrix or native v1 acceptance. Runtime model metadata is unavailable; no model attestation is claimed.

`TerminalTextLayout(ITerminalWidthPolicy, TerminalRenderLimits?)` converts one bounded, complete UTF-16 text value into an immutable `TerminalFrame`. `CreateFrame(text, rows, columns, cursor)` takes explicit viewport dimensions and a zero-based `TerminalCursor`. The caller supplies a trusted display-cell policy with a bounded identity; there is deliberately no guessed Unicode-width default. Tests use an exact, small fixture policy. A policy identity must change when its data or terminal fallback changes.

Layout validates all input UTF-16, including text beyond the visible viewport. CRLF, CR and LF become logical row breaks. A tab becomes exactly three spaces, matching the pinned TUI's declared width treatment without emitting a terminal tab. Other C0 controls, DEL and every C1 control become visible `?` characters before grapheme segmentation. Raw model/tool/paste text never becomes an output control sequence. Characters that resemble the remaining printable part of an escape sequence stay visible data. Frames have no public constructor; renderer text can only enter through this normalization path. Styling and hyperlinks are outside this experiment.

The prototype segments normalized text with the runtime's `StringInfo.GetTextElementEnumerator`. It wraps whole clusters and preserves surrogate pairs and combining/ZWJ clusters recognized by that runtime. Cell width is a separate injected policy. Multi-cell continuation positions cannot become a cursor target. A cluster wider than the requested viewport is omitted as a whole and sets `IsClipped`; overflow below the viewport also sets it. A zero-cell standalone cluster is omitted in this narrow unstyled profile. These are prototype fallback behaviors that still require pinned Unicode and real-terminal qualification; they are not permanent exclusions from P5B. A terminal transport may internally fragment an admitted complete frame into ordered native writes. This renderer does not claim atomic glyph presentation or qualify native fragmentation on every terminal.

`VtRenderer(IConsoleTerminal, TerminalRenderLimits?)` borrows an already acquired, verified VT console lease. The host owns acquisition, actual dimensions, exclusive output access and eventual lease disposal/restoration. The renderer creates no global Console input or output route, detects no capabilities, changes no code pages or system settings and disposes no borrowed terminal. The host must configure the transport write limit at least as large as this renderer's frame limit. The viewport profile assumes ownership of the physical screen; its full redraw includes `CSI 2J`. It cannot share screen regions with unrelated output or serve redirected/non-TTY output. The host must route those modes through their declared text path.

An initial, invalidated, resized or width-policy-changed frame sends an SGR reset, screen clear, absolute positioning and line clear for every bounded row, then its final absolute cursor position and visibility. Subsequent frames send changed whole rows plus the cursor; identical visible rows and cursor send zero bytes. This is a changed-row diff experiment, not a minimum-cell diff optimizer. Data newlines and tabs never reach the transport. Absolute positioning between rows and at the end clears delayed wrap after content fills the right edge, including the last viewport row. Supported output commands are only `CSI 0m`, `CSI 2J`, `CSI 2K`, `CSI row;column H` and cursor visibility `CSI ?25h/l`. Synchronized-update sequences are not yet qualified or emitted.

Admission reserves an explicit, bounded number of render calls. Owned completion gates preserve their admission order. A waiting call applies backpressure until its predecessor's actual transport write settles. Saturation raises a typed resource-limit failure; it does not create an unbounded pending queue or drop a committed frame. A queued cancellation also waits for its predecessor before settling, preserving output order. Callers must await their admitted render operation. Cancellation does not detach an active physical write with a timeout wrapper.

The cache becomes unknown before each actual write and commits only after the awaited transport completes successfully and its token remains live. Exceptions and cancellation invalidate it. `Invalidate()` marks a same-size resize or external host output; a generation check prevents an in-flight pre-invalidation write from restoring an obsolete cache. A successful write whose generation was invalidated reports `CacheCommitted = false`; the next render performs a full redraw. Dimension changes independently require a full redraw. Disposal closes admission, requests cancellation, drains admitted calls and their physical writes, and disposes only its own cancellation source. Concurrent disposal calls share completion. A transport that cannot settle cancellation still requires the host's process watchdog; the renderer cannot safely invent completion.

| Bound | Default | Allowed configured range |
| --- | ---: | ---: |
| Viewport rows | 256 | 1..1,024 |
| Viewport columns | 512 | 1..4,096 |
| Allocated viewport cells, rows × columns | 65,536 | 1..262,144 |
| Original input UTF-16 code units | 65,536 | 1..1,048,576 |
| Retained text and encoded physical-frame UTF-16 code units | 65,536 | 32..1,048,576 |
| One grapheme's UTF-16 code units | 256 | 1..4,096 |
| Active plus waiting render calls | 8 | 1..64 |

Normalization storage is bounded to at most three times the admitted input characters. Row count, column count and total cells are checked before allocation. Retained text is checked before each append; VT overhead is included in the encoded frame budget before any physical write. A frame built with broader layout limits is rechecked against renderer rows, columns, cells, text and retained-grapheme bounds. Width-policy results must be nonnegative and no larger than the configured column bound. Policy execution is trusted host code and must be bounded; this experiment does not sandbox a policy callback.

Nine authored renderer groups are registered alongside the existing native input/lease/ConPTY groups. They cover exact full/diff/cursor bytes and unchanged suppression; an independent ASCII virtual-screen parser with right-edge delayed wrap; held physical writes and cache timing; bounded concurrent order and saturation; partial physical output followed by a fault and full redraw; active, queued and pre-admission cancellation with caller-token recovery; resize during output and same-size invalidation; literal controls, newlines, tabs, combining marks, CJK, emoji and ZWJ boundaries; exact input/cell/row/column/grapheme/frame limits; and disposal while output remains held with borrowed-lease survival. These are authored checks, not upstream differential or all-terminal evidence.

The exact East Asian Width dependency is available locally. The canonical upstream `package-lock.json` pins `get-east-asian-width` 1.6.0 with SHA512 integrity `QRbvDIbx6YklUe6RxeTeleMR0yv3cYH6PsPZHcnVn7xv7zO1BHN8r0XETu8n6Ye3Q+ahtSarc3WgtNWmehIBfA==`. The already admitted `Pi-edit-oracle-v0.99.1/archives/get-east-asian-width-1.6.0.tgz` has observed SHA256 `4451f58e2f5a4ef27ae8b4ba25b64be97d3a8413dc8614a4321a10d418eee6d7`; its inspection receipt records the matching integrity, eight regular members and MIT licensing. Expanded `node_modules/get-east-asian-width/lookup-data.js` contains the inclusive wide/fullwidth/ambiguous/narrow/halfwidth ranges; its observed SHA256 is `f6b40f86c9a2a6808ec808fa8ddcb8da261254cc6121d37ffaeb2bf35dad1d5b`. `index.js` defaults ambiguous characters to one cell. A native table import must preserve the original MIT notice and prove conversion against the admitted package, rather than use unrelated npm width tables. This experiment identifies that source and does not yet import it.

East Asian Width alone cannot establish parity. Pinned `packages/tui/src/utils.ts` uses `Intl.Segmenter` and Unicode-v `Default_Ignorable_Code_Point`, `Control`, `Format`, `Mark`, `Spacing_Mark` and `RGI_Emoji` properties. Its spacing-mark exceptions, regional-indicator fallback and trailing visible codepoint rules can allocate more than two cells within one cluster. The runtime grapheme data, these exact Unicode properties/emoji sequences and their terminal fallback behavior still require versioned source data, licensing/provenance and an upstream differential corpus, including Indic, Thai/Lao and half/fullwidth sequences. No heuristic block list or fixture-only policy closes that requirement.

The maintained .NET comparison candidate is research-only Terminal.Gui v2.5.0, whose [official release](https://github.com/tui-cs/Terminal.Gui/releases/tag/v2.5.0), [tagged project](https://github.com/tui-cs/Terminal.Gui/blob/v2.5.0/Terminal.Gui/Terminal.Gui.csproj) and [tagged README](https://github.com/tui-cs/Terminal.Gui/blob/v2.5.0/README.md) were researched by the coordinating lane. No local candidate package, exact full release-commit qualification, executable comparison or performance measurement is attached here. Consequently this document is not a renderer-choice ADR and neither selects nor rejects that candidate. P5-07 still needs measured comparison of streaming, editor, resize, scrollback, alternate screen, overlays and image fallback behind the intended abstractions.

Mandatory follow-up includes native pinned width/property/grapheme qualification; component/editor and IME cursor behavior; main-screen scrollback and alternate-screen ownership; focus, overlays and selection/copy; Markdown/code/tool views, themes and completion; supported synchronized writes; Kitty/iTerm2 image cleanup and text fallback; keyboard-only accessibility and responsive-streaming measurements; real renderer PTY/ConPTY plus recorded-terminal checks on Windows x64, Linux x64 and macOS arm64; non-TTY, SSH/multiplexer and child-process recovery; and phase 6 plugin-backed terminal reruns. Those rows remain acceptance blockers. Existing terminal transport qualification does not automatically qualify this renderer on those platforms.
