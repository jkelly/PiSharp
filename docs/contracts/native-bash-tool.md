# Explicit native Bash tool adapter

`BashTool` joins the native `IProcessRunner` primitive to the accepted prepared-action invoker and awaited tool progress interface. It supplies a `bash` declaration and definition, source-facing output formatting, and separate programmatic `StructuredContent`. This is a bounded explicit Bash argv profile; whole P3-07, platform and genuine whole-tool parity remain unfinished.

## Configuration and policy

`BashTool(IProcessRunner runner, BashToolOptions options, Func<string>? nextSpillFileName = null)` borrows the trusted runner and explicitly configured Bash executable. Options require an existing normalized absolute executable, working directory, immutable complete environment, and existing normalized absolute spill directory. There is no PATH lookup, shell fallback, implicit home/temp destination, process-environment overlay, credential fallback, installation or global change. The optional filename allocator is trusted native code; its result must be a bounded simple filename. The default creates a fresh `pi-bash-<GUID>.log` name without creating a file.

Use `CreateInvoker(mandatoryPolicy, transforms?, resultTransforms?)`, then `CreateDefinition(invoker)`. The public adapter methods are trusted effect plumbing and do not enforce a policy by themselves; calling ExecuteAsync directly is not an alternative host authorization path. A host must route all model, nested and direct command work through the mandatory final-action invoker.

The closed model input is `{"command":string,"timeout"?:number}`. Empty commands are valid Bash input. Unknown fields, non-string command, NUL, unpaired UTF-16, non-object data, invalid timeout, and configured resource limits are rejected. Raw retained JSON is charged before strict reparse; comments or trailing commas admitted by a permissive external JsonDocument cannot acquire action authority. Timeout is optional with no default; it must be finite, positive and at most Int32.MaxValue milliseconds, including fractional seconds. Its admitted raw JSON token survives preparation; the runner receives the same JavaScript-style binary64 numeric value.

Preparation produces one immutable `PreparedToolAction` with:

- ToolName/Operation `bash` and Kind `Command`.
- Target equal to the configured absolute executable and argv exactly `["-c", command]`.
- Explicit cwd and the complete immutable environment.
- Owned Arguments containing command, optional original timeout token, and generated absolute `outputPath`.

The output path is visible to transforms and final policy, not retained in an out-of-band mutable map. Validation repeats after transforms and immediately before the runner: executable identity, command/argv agreement, existing normalized cwd, environment grammar/limits, timeout and spill path all matter. A transform can replace the command, cwd, complete environment, timeout or filename within the configured spill directory; it must maintain command/argv agreement and pass final policy. It cannot silently switch the executable or escape the configured spill directory. Execution projects the identical authorized fields into ProcessRequest.

The spill destination must not exist at admission. The native runner lazily opens it with CreateNew once truncation requires raw spill, awaits flush/disposal, and never overwrites an existing artifact. Collision, replacement and external filesystem races can still fail execution. Successfully created output is caller-owned and retained; partial/uncertain artifacts remain for inspection without automatic deletion or retry. Lexical path checks, mandatory policy and the process job are not a hostile-code filesystem or arbitrary shell sandbox. Policy must evaluate the complete shell command and full environment; this adapter cannot identify or separately authorize every executable or effect expressed inside Bash.

## Output, progress and failure

The supported completed result follows pinned Bash semantics: empty output becomes `(no output)`; otherwise model text is the merged decoded tail. Nonzero exit appends `Command exited with code N` and sets IsError while retaining a normal structured result. Truncation notices distinguish line limit, 50.0KB byte limit, and partial oversized last line. Details contain the source-shaped truncation object and fullOutputPath when present.

Successful/nonzero programmatic output is a separate owned JSON value containing `output`, `truncated`, `exit_code` and `wall_time_seconds`; `full_output_path` appears only when structured output itself is truncated and an artifact path is acknowledged. The runner retains up to the source's 1-MiB selection budget, preserving both ends around the omission marker. Model truncation alone does not assert structured truncation. StructuredContent is not inserted into model text, Details or durable transcript messages.

Both legacy ExecuteAsync(action, token) and the new three-argument overload remain available. The legacy overload supplies a no-op observer. The callback overload awaits the source's initial empty-content update, then serially awaits each actual runner snapshot with its complete partial result and real work token. Snapshot progress uses empty text rather than `(no output)` and emits raw content/details, without a truncation notice. The runner returns only after callbacks and owned process/output cleanup; the invoker separately closes and joins its progress scope. Native progress is per admitted chunk/final decoder change; upstream's wall-clock throttle and renderer timing are not claimed equivalent.

Abort and timeout preserve bounded known output followed by `Command aborted` or `Command timed out after N seconds`. Missing exit code is distinct. Execution/capture/spawn/progress/cleanup failures use fixed sanitized status text; runner exception payload, environment, command and rejected arguments are not copied into diagnostics. Caller cancellation retains known output after awaited cleanup, with cleanup failure taking precedence. Source abort/timeout throw and do not return normal Bash structured completion; these native errors likewise omit StructuredContent. A canceled command may already have performed effects; cancellation is not rollback.

Two native representation differences remain explicit. ToolResult requires a JsonData Details value, so source undefined details use JsonData.Null; progress with a source details object whose members are undefined uses an empty object. Native ToolFailure classification and fixed infrastructure diagnostics add host semantics rather than claiming source error-object identity. Number formatting outside ordinary timeout profiles and complete raw-result serialization need genuine differential qualification. Raw NUL is retained by the process backend and adapter; ordinary ToolInvoker output admission is a separate root-owned prerequisite, not a reason to sanitize or discard shell bytes here.

## Bounds and authored evidence

Command input defaults to 12,000 UTF-16 characters, downward configurable. The raw and normalized argument JSON cap defaults to 96,000 characters. Paths are at most 4096 characters, generated/transformed filenames at most 128, and full environment at most 1024 Windows-case-insensitive-unique entries and 32,767 characters. Commands and environment cannot contain NUL/unpaired surrogates. The invoker separately bounds final action, ordinary result and structured JSON; the runner retains its fixed output, queue, raw-byte and cleanup limits. These are logical admission/capture limits, not a total heap or shell resource sandbox.

`BashToolTests.Cases()` supplies six authored groups: strict raw/closed admission and no effects; exact final metadata and transformed-action policy denial; completed empty/nonzero/truncation/structured formatting; abort/timeout/foreign/cleanup failures with known output; gated awaited progress/cancellation/cleanup; and actual explicit borrowed Windows Git Bash over owned scratch read/write, Unicode/full environment, nonzero exit, >1-MiB output artifact and progress-triggered cancellation. The real fixture requires `C:\Program Files\Git\usr\bin\bash.exe` and does not substitute or install a shell. Task gates control expected ordering; deadlines are cleanup guards, not sleeps or timing evidence. No tests were executed or built by this authoring lane; root owns registration and immutable validation.
