# Terminal editor component ownership

`TerminalEditorFocusOwner(bool initiallyFocused = true)` represents one editor or an external/null component owner. The terminal caller constructs one owner and passes it explicitly to the input host and view. Old constructors and the two positional draft fields remain available; callers without focus control retain an initially focused editor.

The input consumer attaches its controller lifetime once and captures applied focus lifetime/revision in each immutable draft. `SetEditorFocusAsync(bool, CancellationToken)` admits a focus request into the same FIFO as keyboard events. The existing 32 queued keyboard events and eight queued focus requests have independent bounds, checked before effects. Detached owners, duplicate attachments, admission limits and stale identities use `TerminalEditorFocusException.Failure`. A successful acknowledgement means the consumer applied that request and joined its presentation callback. A blocked physical read does not block focus changes. No second read worker is created.

Cancellation before application prevents the focus effect. Cancellation of the request after application does not detach its admitted paint. Run shutdown still joins owned reads, rendering, submission callbacks and receipts, then detaches the editor and rejects unconsumed requests. The applied focus value survives detachment and reattachment; an explicitly unfocused owner does not gain ownership when an editor is recreated. The attachment belongs to its serialized consumer, which must join admitted work before disposing it.

An inactive editor receives no typing, paste, Enter, Escape or Ctrl+D component binding. Losing ownership does not reset text, cursor, registered paste atoms, pending character jumps, undo or recall history. Existing application Ctrl+C remains in the producer before component dispatch and uses the accepted protocol-aware `ForEditorInput(value, false)` predicate, including MOK lock filtering. Terminal window reports CSI[I/O do not transfer component ownership.

The actual view validates captured owner and layout lifetimes, focus revision and nondecreasing captured editor revisions before publishing a bound draft. Its existing Source frame factory receives the immutable focused flag. Source inverse caret styling remains while unfocused; the cursor marker and trusted position authority are withheld. The intentional Source hardware cursor policy remains hidden. Existing literal callers keep their default visible cursor, and an explicitly unfocused literal draft hides it. Tiny-viewport fallback keeps canonical state intact.

It also exercises held reads/paints/submissions/receipts, cancellation, stale replacement/layout, bounded admission, paste/undo preservation and the injected offline actual caller.
