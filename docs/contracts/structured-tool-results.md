# Structured tool results

This native prerequisite adds optional owned programmatic output to the existing finalized result. It does not implement a shell, tool progress, an output-schema validator, codemode, MCP, or the source's partial after-tool override API. The core remains .NET 10 with no Node requirement. The compatibility target is public Pi v0.99.1 at `d86654abb8862e201933517d6f1fce9f88dd117f`.

## Source boundary

The pinned [AgentToolResult and AgentToolCallOutcome](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/types.ts#L424) carry optional `structuredContent`. A returned error flag retains details and structured output for UI and programmatic callers. [runToolCall](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/agent-loop.ts#L810) returns the finalized execution result, and [emitToolExecutionEnd](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/agent-loop.ts#L912) emits it. [createToolResultMessage](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/agent-loop.ts#L922) deliberately selects message fields without `structuredContent`; the result's programmatic output is excluded from model context and durable message history.

The pinned [Bash result](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/bash.ts#L393) contains `output`, `truncated`, optional `full_output_path`, `exit_code`, and `wall_time_seconds`. The programmatic output limit is [1 MiB](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/bash.ts#L23), independently of the shorter model-facing output. [readFullOutput](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/output-accumulator.ts#L156) may add an omission marker between its head and tail. A nonzero exit result still carries structured output. These facts were checked against the local immutable public source checkout; no source execution or differential oracle is claimed for this slice.

## Native public surface

`ToolResult.StructuredContent` is a nonpositional `JsonData?` init property. Its absence is C# `null`; explicit JSON null is `JsonData.Null`. Object, array and scalar JSON values are accepted. The existing five-argument constructor, named arguments, five-field `Deconstruct`, and factory calls keep their original shapes. `with` copies preserve the property unless a caller explicitly replaces or clears it.

`JsonData` already owns its `JsonElement` by cloning, validates duplicate property names and undefined values, and parses strict JSON without comments or trailing commas. Structured admission retains that owned object directly. It never deserializes JSON into floating-point values or reserializes it. Raw numeric tokens, lexical escapes, property order, array order, explicit nulls and document-lifetime ownership are retained. Numeric admission checks finite binary64 representability without replacing the original token; overflow such as `1e309` is rejected, while a finite wide integer such as `9007199254740993` retains its raw token.

`ToolInvokerOptions.MaximumStructuredContentCharacters` is also a nonpositional init property, preserving the existing nine-argument constructor and deconstruction. Its positive default is `6 * 1024 * 1024 + 65_536`, or 6,356,992 raw JSON UTF-16 characters. One output byte can require six raw characters as a JSON Unicode escape. The extra 65,536 characters leave room for the result envelope, omission marker and other metadata. The invoker's ordinary 65,536-character content/details/failure allowance is unchanged and charged separately; increasing structured capacity never increases the ordinary allowance. The metadata cap is a bounded admission limit rather than a total heap or serialized-byte limit, and the future shell adapter must separately enforce its source output-byte limit.

Structured admission applies the configured `MaximumJsonDepth` container limit, default 32, and requires valid scalar Unicode in strings and property names. Numbers must be finite. Duplicate names, malformed JSON and undefined values are rejected by ownership admission; nested metadata receives the same checks. Valid escaped NUL is accepted as programmatic output data. Ordinary `TextContent.Text` also preserves NUL as decoded output data. Action input, identities, paths, commands, argv, cwd, environment, ordinary details, failure messages, extra property names and extra property values retain their existing NUL exclusion.

## Finalization and projection

`ToolInvoker` admits structured output after execution and after every complete result transform. A non-null failure forces `IsError` using a record copy, preserving metadata. Returned error results keep their structured output. If cancellation or a transform failure occurs after a valid result, the invoker copies the last validated result, appends its fixed diagnostic and preserves structured output, content, details and termination. Invalid executor metadata becomes a sanitized `ExecutionError`; invalid replacement metadata becomes `HookError` while retaining the previous validated result. This is deliberate native hardening and does not assert identical source exception semantics.

Result transforms and `IToolHooks.AfterExecutionAsync` return complete native result values. A `with` update preserves metadata even when replacing content. Returning a new result without metadata or assigning `StructuredContent = null` clears it explicitly; assigning `JsonData.Null` retains explicit JSON null. Successful scheduler afterhooks carry the finalized value unchanged into `ToolOutcome`, `ToolExecutionEnded`, batch outcomes and high-level Agent outcome snapshots. The existing scheduler replaces the entire result if an outer afterhook throws or is canceled, as the source also replaces the result for a thrown after-tool hook. That existing behavior is unchanged. The invoker's bounded admission does not claim validation of arbitrary scheduler executors or the scheduler's outer hook return values.

The source [partial override](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/agent-loop.ts#L853) intentionally clears structured output when overriding content without supplying structured output. Its nullish merge also differs from the native complete-result API. That merge must be implemented at any future source-compatible partial-hook boundary; this slice does not silently apply it to existing C# complete-result hooks.

`ToolResultMessage` has no structured property. The genuine scheduler projects only its existing five native message fields. The existing Agent and AgentLoopRunner canonical wire projections therefore omit structured output, and the next provider request uses that canonical history. Persistence callers receive those projected message bodies. No durable session codec, RPC serializer or event serialization change is included; `ToolExecutionEnded` already contains the finalized `ToolOutcome`.

## NUL text-output admission

The pinned [output accumulator](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/output-accumulator.ts#L45) decodes shell bytes with `TextDecoder`; valid UTF-8 NUL remains a character in both snapshot text and programmatic full output. NUL is output data, while a native process/path/action string uses a different admission boundary. The native invoker now allows NUL only in ordinary `TextContent.Text`, preserving the same UTF-16 scalar checks and exact ordinary result character allowance. No output NUL is removed, replaced or reclassified as an executable input.

The same output-only check applies to executor results, every invoker progress partial, and each complete invoker result transform. The accepted awaited progress scope and scheduler carry that admitted text into observations and finalized tool results. Canonical Agent JSON escapes NUL as `\u0000` and restores it when parsed; the following model request retains the original text value. Structured output remains separate and excluded from that history. The change does not relax strict retained structured syntax, finite-number admission, malformed Unicode, metadata/action NUL checks or output budgets.

The new flow test uses the actual native invoker, scheduler and high-level Agent over an authored scripted provider and trusted prepared adapter. It does not execute a shell, prove whole source execution parity, or qualify every downstream provider's binary-text grammar. Real shell/stdout/backend and durable/RPC encoding tests remain separate required evidence.

## Authored evidence

`StructuredToolResultTests.Cases()` supplies eleven offline test groups: legacy construction/deconstruction, owned raw JSON and absent/null distinctions, normalization and explicit transforms, cancellation/finalization retention, separate exact budgets including one MiB of NUL escaped to six MiB, strict JSON/depth/finite/Unicode admission, executor/transform retained-raw-syntax rejection, gate-controlled actual native scheduler ordering and afterhooks, high-level Agent outcome/event retention with next-request and canonical-history exclusion, and the additional output-only NUL flow. That group holds an actual awaited progress barrier, preserves ordinary/structured NUL through final transforms and events, checks canonical escaping and the subsequent model request, and covers exact progress/final budgets plus malformed Unicode and strict action/identity negatives. Existing finite/raw-number/order controls remain unchanged. Canonical message JSON is parsed again to check its preservation/exclusion contract; this is not a durable store execution or source differential corpus.

The additional output-admission change and new group are authored but **NOT RUN** by this lane. The parent owns registration in the existing console harness, build, execution, final evidence and commit. No existing fixture, source corpus, session store, provider configuration or dependency is changed.
