# Source-compatible tool progress

The public native `Agent` selects `ToolProgressDeliveryMode.SourceCompatible` by default. `AgentOptions.ProgressDelivery` explicitly selects `NativeAwaited` when a caller requires the existing serialized, awaited callback contract. Standalone `ToolBatchScheduler` and `ToolInvoker` calls keep that native contract by default. The scheduler accepts optional fourth-argument `ToolProgressDeliveryOptions`; a prepared invoker inherits the owned scheduler callback mode and delivery receipts.

Source mode follows the unchanged Pi v0.99.1 `executePreparedToolCall` boundary in `packages/agent/src/agent-loop.ts`: reporting starts event delivery immediately and returns an already-completed callback; another update may enter listeners while the previous update is blocked. Each event awaits subscribers in subscription order. Different tool-progress event deliveries can overlap. Parallel tools close, join their own progress receipts, run after hooks, and emit their end independently. Model-facing tool messages still follow assistant call order.

The admission cutoff is execution returning or throwing. Cancellation of the execution token does not close progress by itself. Reports made after abort but before execution settlement are admitted. Reports after settlement are ignored, including invalid partial values and canceled callback tokens. Ignored reports perform no validation, normalization, event delivery, or history mutation. The CLR callback returns a completed `ValueTask`; the captured JavaScript callback returns `undefined`.

All admitted listener work is owned. Execution settlement closes admission and joins the actual delivery receipts before prepared-adapter result transforms, scheduler after hooks, or the final tool event. A prepared adapter receives its own source-facing callback while its scope retains the outer scheduler's actual receipt. It cannot mistake the callback's immediate return for listener settlement. Closing a source scope joins every admitted receipt even when one fails. Failed delivery prevents the tool's after hook/end; a parallel batch joins all admitted executions and cleanup before reporting the original sink failure. Exceptions from cancellation callbacks do not skip remaining settlement work.

The primary `Agent` sink remains an awaited commit barrier and receives the uncanceled settlement token during abort finalization. Subscribers in source mode receive the actual generation work token, including its canceled state after public `Abort` or caller cancellation. The primary commit completes before subscribers enter. Terminal message/history publication and idle/disposal settlement continue to await admitted work. Existing callback self-wait protections remain: a callback cannot wait for its own Agent generation to become idle or dispose itself. A callback cannot recursively publish progress into its own scheduler delivery context.

Source mode bounds admission per batch: 4,096 total reports (completed reports still count), 256 outstanding reports, 8 MiB of retained text/raw JSON characters, and 1,024 content blocks per report by default. Character accounting includes text, owned details, optional structured content, text extra-property names/values, and failure text. Limits are configurable positive values. Parallel invocations share one budget. Nested invoker/scheduler scopes charge each logical report once, retain their own bounded receipts, and release outstanding-character/pending quota only after actual delivery settles. Quota rejection closes no already-admitted work early: the scope joins it before reporting the failure. This is explicit resource hardening beyond the unbounded source promise array. `JsonData` ownership/depth/decoded-duplicate admission and the prepared invoker's strict numeric/Unicode/result limits remain intact.

`SourceProgressDifferentialTests.Cases()` supplies three groups against the immutable whole-source capture at commit `6791a7d7477570a868d8c4237522c5c288894465`. Every input, golden, and lock is SHA-256 checked before parsing. The tests compare complete ordered listener traces (including overlapping active-listener values and actual abort signals), complete control/barrier/late-admission traces, all scalar/array public barrier probes, complete invocation/callback/abort order, tool call correlation and owned partial content/details, independent parallel finalization, source-ordered messages, complete abort canonical history, and generated terminal history. Parallel/sequential canonical and terminal histories enforce their exact remaining difference paths; extra differences fail.

The fixture also captures richer JavaScript representations that this milestone does not qualify: full `Agent.state`, callable tools, pending-call `Set`, `AbortSignal` objects, void prompt/idle return values, result `usage` and arbitrary `opaqueResult`, separately overridden event `isError` versus retained result `isError`, and deliberately untyped null/missing tool content/details/terminate. The test explicitly inventories these remaining rows. Its authored adapter applies source nullish after-hook semantics and converts untyped null/missing content to an empty native content array; missing details becomes the required owned empty object. The absent-details partial and durable message difference remains disclosed. Provider `toolcall_delta` source partial snapshots and typed native delta observations are different representations. There is no whole-fixture JSON equality claim, waiver of these rows, or full P3/provider/session closure.

`SourceProgressOwnershipTests.Cases()` adds five native groups for nested receipt ownership, shared pending/completed/character quotas, listener-fault plus concurrent-disposal cleanup, separate caller-cancellation and protocol-abort controls, and the explicit high-level native backpressure mode. Existing standalone `ToolProgressTests` retain their native awaited/serialized expectations. No source fixtures, capture scripts, shared test registration, tool effects, CLI/session implementation, or source receipts are changed by this slice. Build and execution results belong to the root's immutable review gate; authoring these tests is not evidence that they passed.

The abort differential driver observes the second tool callback's actual return before calling `Abort`. This preserves the captured JavaScript same-stack ordering while retaining the full callback-return signal assertion. The high-level ownership fake emits start/delta/end tool frames before its successful terminal, so the normal authoritative reducer admits it; a fabricated start/terminal-only tool stream would correctly fail before execution. Stage witnesses race actual prompt completion and use a bounded diagnostic deadline, then release every owned gate, abort cooperative work, and await real settlement in `finally`. An early malformed provider completion therefore fails with its actual admission diagnostic rather than waiting for an impossible listener. The existing structured NUL-output test explicitly requests `NativeAwaited` and retains all its original awaited-progress and ownership assertions.

The three existing RPC progress method groups also explicitly select `NativeAwaited` for their strong publication/backpressure and late-rejection controls; their assertions are unchanged. `SourceProgressRpcTests.Cases()` adds a separate group using the default public Agent configuration through a real durable coordinator, prepared invoker, RPC dispatcher, and owned JSONL writer. Its successful case proves a second listener can enter while the first RPC delivery is blocked, both callbacks return immediately, complete frames remain serialized and flushed, and execution/end/durable-message settlement joins real cleanup. Actual write and flush failures then prove shared shutdown waits for owned stream and tool cleanup, preserves accepted queues, emits no normal final acknowledgement, and performs no queued provider/tool continuation. Late invalid/canceled callbacks after successful or failed settlement are ignored without additional frames. This test supplies its own admitted source-shaped model and authoritative fake provider frames; it makes no provider/network/unchanged-whole-RPC oracle claim. Source receipts bound concurrent observer work while the RPC writer continues to serialize complete frames under backpressure.

RPC fault controls observe the actual execution token's canceled state on entry to cleanup and the public Agent's cancellation state. They separately join the registered cancellation observer's own gate while the executor cleanup barrier keeps its registration alive. Entering `finally` through a `WaitAsync` cancellation callback does not imply that an older registered callback has already run. Stream disposal, cancellation-observer completion, executor cleanup, and shared dispatcher shutdown each have their own witnesses and remain awaited.
