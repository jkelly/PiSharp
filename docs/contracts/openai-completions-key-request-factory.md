# OpenAI Completions explicit-key request construction

This is a pure, bounded request-construction slice of P2-08. It creates real independently owned `HttpRequestMessage`/`HttpContent` values for an explicit complete endpoint. It acquires no client, sends nothing, discovers no environment or credentials, reads no clock and starts no retry or tool execution. HTTP/SSE integration, mutable/provisional stream identity and complete provider qualification remain separate mandatory work.

Authority is Pi v0.99.1 `d86654abb8862e201933517d6f1fce9f88dd117f`, the complete public [openai-completions.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-completions.ts), [transcript.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/utils/transcript.ts), [transform-messages.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/transform-messages.ts), [constrained-sampling.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/constrained-sampling.ts) and [openai-prompt-cache.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-prompt-cache.ts). The frozen `fixtures/reference/openai-completions-stream` family observes unchanged public stream execution and real OpenAI SDK 7.19.0 request serialization through an authored offline fetch seam.

## API and owned values

Namespace: `PiSharp.AI.Protocols.OpenAICompletions`.

```csharp
new CompletionsKeyAuthRequestFactory(
    Uri endpoint, ModelDescriptor expectedModel,
    CompletionsTranscriptProjectionOptions? projectionOptions = null,
    CompletionsKeyAuthRequestOptions? options = null);

HttpRequestMessage Create(ChatRequest request, string explicitApiKey,
    CancellationToken cancellationToken = default);
```

The endpoint is the complete resource URI, such as `https://example.invalid/v1/chat/completions`; no resource suffix is inferred. Only absolute HTTP/HTTPS without user information or fragments is admitted. Configuration binds the exact `openai-completions` model descriptor; mismatched requests fail before projection or request/content acquisition. The explicit key must be nonempty printable ASCII without whitespace. Diagnostic messages are fixed and omit keys, rejected fields, URLs and provider payloads.

Factories are immutable and reusable concurrently. Each successful call owns a fresh request, byte content and header collection. Disposing one returned request has no effect on another or on retained transcript/configuration values. The caller owns and disposes every result. Cancellation is checked before projection, throughout traversal and output composition, and before return; request/content acquisition failures dispose the acquired objects.

## Transcript and tool behavior

Canonical `TranscriptEntry.WireBody` values remain untouched, including unknown metadata, explicit null, NUL scalar data and raw numeric spelling. Request projection follows the source's selected fields; it does not forward unrelated assistant/tool-result metadata such as details and usage. Unknown schema properties and signed reasoning-detail properties do remain in their source-defined request positions.

Default system handling collapses all system content into a leading message, appends nonempty content with two newlines, patches sections by name, removes null sections and preserves source enumeration order (integer property keys first). Explicit mid-conversation system support renders updates/removals in place. System messages inside a tool-call/result sequence are held until its results close. Reasoning models use developer instructions when the explicit developer-role capability permits it.

Text user strings and text-block arrays, assistant text/thinking/function calls, and text-only tool results are implemented. Empty user text blocks are filtered. Assistant text blocks are concatenated; empty content with tool calls is explicit null unless the configured compatibility rule requires an empty string. Tool-result text blocks join with LF; empty results use `(no tool output)`. Orphan calls receive source-shaped `No result provided` result projections; their internal synthetic timestamp uses the supplied request timestamp and never reads a clock (timestamps are absent from the provider payload). Failed/aborted assistants are omitted from request replay, while their original history remains owned.

Same-model reasoning fields, complete validated `thinkingSignature` detail arrays, and legacy encrypted `thoughtSignature` details are replayed. Structured details suppress redundant raw reasoning fields. Cross-model thinking becomes plain text, redacted thinking is omitted, and signatures are not forwarded. Function IDs are preserved for the same model; cross-model IDs follow the source's pipe sanitization/hash/length rules and result links use the same mapping. Duplicate/ambiguous call identities are rejected as native admission hardening.

Identity admission covers the entire preserved request history, across assistant and user turns. Each call reserves its original ID and its outgoing wire ID, including unchanged same-model IDs. Reused originals and collisions between preserved and normalized outgoing IDs fail atomically with `InvalidTranscript` before an `HttpRequestMessage` is acquired. A mapping is assigned once; result links are captured in transcript order rather than looked up in a dictionary containing future turns. Actual and synthetic results therefore keep their call's admitted wire identity, while a result preceding a future call cannot be retroactively renamed. Failed/aborted assistants omitted from replay do not reserve identities. The uniqueness rule is native hardening, not a claim that the upstream transformer rejects every ambiguity; ordered result remapping follows the unchanged source transformer.

`CompletionsToolDeclarationProjector` replays system removals before additions. Same-name replacements retain their position; removal followed by readdition moves the name to the end. Standard declarations use `{type:"function",function:{name,description,parameters}}`. Default strict capability is false, matching source compatibility detection: the strict field is absent. An explicitly strict-capable profile emits `strict:false` ordinarily and honors the accepted source-derived JSON-schema preference/require conversion. Required strict schemas that the bounded converter cannot represent fail explicitly. The standard schema/replay implementation reuses the accepted Responses declaration helper and wraps its result in the Completions shape. Source default grammar-incapable behavior falls back to the declared function schema; grammar-enabled custom payloads remain unfinished.

Request argument strings, complete schema output, structured reasoning details and configured numeric options use the accepted pure `EcmaScriptJsonProjection` boundary. It implements binary64 parse/stringify semantics, wide-integer rounding, negative zero, overflow to null, integer-key ordering and exact shortest decimal formatting. This changes only request projections. Raw retained arguments/schemas keep their original bytes; the request projection never becomes execution authority. Native duplicate, strict-syntax, paired-Unicode and resource admission occur before this compatibility conversion. ECMAScript projection's own node/property/number/token budgets also apply.

## Options and headers

Capabilities are explicit configuration, with defaults for the three captured OpenAI cases; compatible-provider support is not inferred from an endpoint. Defaults include stream usage, `store:false`, developer role and reasoning effort support, `max_completion_tokens`, short cache retention, long-cache capability and strict tools disabled.

Direct-stream token behavior omits zero and preserves finite negative/fractional supplied values within the configured magnitude bound. Temperature zero is retained. There is no streamSimple clamp or inferred default token limit. None/short/long cache policies use the source request conditions; long capable caching includes `24h`. Supplied cache keys truncate at 64 Unicode code points. Optional session affinity emits source-defined header names with the supplied original session string. Reasoning effort and standard tool choice are projected when applicable. Empty tools remain present when tool history exists even after every declaration was removed.

Header defaults are `accept:application/json`, native `user-agent:PiSharp` and `x-stainless-retry-count:0`. Model headers precede configured session-affinity headers; per-request option headers apply last. Case-insensitive overrides and explicit null removals are supported, including Authorization and the generated retry-count header. The explicit key is still validated; configured model/caller Authorization then replaces or explicitly removes its generated bearer header, matching the pinned SDK merge order. JSON content owns `content-type:application/json`. Cloudflare auth and Host/content-length/transfer/connection overrides remain unfinished and rejected. Header names require token syntax; values permit printable ASCII/tab and reject CR/LF/NUL. Limits charge both supplied configuration and the final header collection including authentication. Outer retries never increment the source SDK retry-count header; see [explicit auth/retry contract](completions-auth-and-retries.md).

The new genuine-reference test compares **complete parsed bodies for all three cases**, preserving numeric tokens, strings, arrays, null and absence; only object key order is ignored. It does not compare HTTP sends, final serialized wire headers, callbacks, provider DTOs or streams. SDK stainless/OS/runtime headers are not automatically reproduced. Native default metadata, HTTP header serialization/observation and acquisition timing remain independently qualified boundaries. No full HTTP/provider parity follows from parsed-body comparison.

## Admission and bounds

Default transcript/declaration limits include 256 messages, 65,536 raw UTF-16 characters per entry, 1,048,576 aggregate input characters, 1,024 content blocks/declarations, 128 active tools, 1,024 projected messages, depth 32 and 1 MiB output characters/UTF-8 bytes. Returned request payload defaults to 1 MiB, depth 32; projected output budgets are lowered to the factory payload budget. Every source JSON value is strictly reparsed, so retained comments/trailing commas from permissive documents fail. Decoded duplicates and unpaired Unicode fail; inert JSON string NUL is allowed. Scalar numeric tokens are retained at admission and converted at the source JSON boundary rather than being restricted to safe integer spellings.

Each output item is charged cumulatively before entering its retained array. Exact payload field byte counts and depth are checked before UTF-8 materialization/request acquisition. These are logical input/output bounds, not a total heap cap; bounded parsed clones, projection nodes and framework writer buffers coexist.

Mandatory unfinished profiles include image projection/downgrade, grammar-enabled custom tools, anchored mid-conversation tool additions, provider/base-URL compatibility detection, sampling-parameter/routing/template overrides, complete automatic thinking-level maps, source Unicode repair beyond paired native admission, alternate auth/environment/stored credentials, onPayload/onResponse callbacks, real HTTP acquisition/SSE, retries/timeout behavior and all stream/final/error/cancellation differences. None are permanent exclusions or full-phase waivers.
