# Parsed Responses to one explicit turn

The three authored integration groups in [ResponsesTurnTests.cs](../../tests/PiSharp.Agent.Tests/ResponsesTurnTests.cs) compose the actual `ResponsesTextToolTransport` over deterministic immutable DTOs with `ChatClient`, `TurnRunner` and `ToolBatchScheduler`. The production mapper, `ChatClient`, `TurnRunner` and scheduler run through their public injection seams; DTO acquisition, executor and hooks are deterministic fakes.

The successful group supplies an incomplete argument delta, a complete arguments-done checkpoint and a different authoritative item-end object. The executor receives the item-end object, including exact `9007199254740993` and `1.0` number tokens, and the unchanged composite identity `call-turn|fc-turn`. An explicit DTO-disposal gate first prevents successful settlement, assistant commit and tool preflight. After cleanup settles, a separate awaited `AssistantMessageEnded` sink gate prevents preflight and execution. Releasing that barrier admits exactly one invocation and one terminating result; the continuation hint is suppressed without issuing another request.

The failure groups reject malformed authoritative item-end JSON and an unsupported reasoning DTO after a valid tool end. Both wait for gated DTO cleanup, preserve the failed assistant's observed tool identity, emit one normalized error and commit the failed assistant once. Neither admits preflight, executor calls, result hooks or tool lifecycle events. In the unsupported case, the earlier strict tool-end object remains available as partial output while the failed final assistant prevents its execution. A progress tool end alone is not authority to perform effects.

This evidence covers the selected P2-07 final-argument boundary and the P3-02 awaited assistant boundary using the accepted single-turn composition. [The Responses contract](responses-text-tool.md) distinguishes its captured helper overlap from authored envelope/error behavior; [the turn contract](turn-runner.md) describes cleanup and single-request ownership. These new inputs are authored integration cases, not captured upstream traces. No golden is changed, and the tests claim no whole-Agent, partial-preview, provider-wrapper, HTTP/SSE, request projection, JSON Schema or policy-broker parity. Automatic continuation, queues, sessions and host tools remain outside this slice.

Run `./tools/test-native.ps1`. The Agent executable reports these groups as `agent.AuthoritativeArgumentsAfterBarriers`, `agent.MalformedAuthoritativeArgumentsPreventEffects` and `agent.UnsupportedDtoAfterToolEndPreventsEffects` in `artifacts/native/agent-results.json`. The native build uses locked offline restore and the native executables run with Node absent from PATH. Explicit task gates establish ordering; the existing runner timeout only guards a hang. All data is synthetic, with no network, credentials, provider SDK or filesystem/process tool effects.
