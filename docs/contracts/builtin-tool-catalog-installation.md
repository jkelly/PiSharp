# Bounded built-in catalog and explicit edit installation

Baseline: Pi v0.99.1 `d86654abb8862e201933517d6f1fce9f88dd117f`. The inspected [core/tools/index.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/index.ts) defines coding factory order `read,bash,edit,write` and read-only order `read,grep,find,ls`. The native catalog follows those orders when all required capabilities are explicitly provided. Source inspection is not executed differential evidence.

`PiSharp.Tools.BuiltinToolCatalog` constructs the existing bounded read, write, edit and ls adapters. It owns one FileMutationQueue shared by write and edit, retaining the existing canonical-key/Windows-folding behavior. Host-supplied BashTool, IFindExecutor and IGrepExecutor capabilities are optional; the catalog neither discovers nor downloads executables. Borrowed executors keep their original host disposal ownership. The native adapter's operation, cancellation, complete-capture, output and containment constraints remain unchanged.

Registered declaration/adapter pairs are immutable and unannotated. `Select` retains exact caller order and permits an explicitly empty selection. It rejects default arrays, duplicate/case-mismatched/unknown names and unavailable optional capabilities. `CodingTools` and `ReadOnlyTools` select the complete source factory orders and fail if a required capability is absent; they never silently install a partial factory or acquire a capability. Duplicate rejection is a bounded native admission rule, not a claim about every upstream argument-coercion path. There is no native PowerShell factory in this slice.

Selection and registration grant no permission. Hosts must route selected adapters through their existing mandatory ToolInvoker/SessionRuntimeRegistry policy and preserve each adapter's declared resource profile. The catalog provides no default allow policy or invoker with inferred permissions.

The real OfflineSessionProfile now uses that catalog and registers edit inactive alongside ls. Existing startup order/defaults remain read/write plus explicitly admitted Bash, preserving current live/offline fixture composition. Existing persistent `SetActiveToolsAsync` selects edit and persists its order/declaration. Exact final edit actions require both an existing exact read grant and an existing exact write grant for the same target, within the existing workspace and reserved-target guards. Read-only, write-only and missing grants deny edit. The profile does not infer grants from tool selection, grant directories recursively, or admit search executors automatically.

Profile edit input/output bytes and argument characters are capped at 65536. Its native diff output is capped at 4096 characters so edit can coexist with the existing profile invoker/provider result budgets. Oversized input/diff rejects before writing using existing edit limits. The catalog's generic host defaults retain the existing adapter option defaults. Source image/encoding, exact jsdiff output, dynamic cwd and unrestricted resource parity are not established by registration.

Six new deterministic groups in `BuiltinToolInstallationTests` are appended to the existing CodingAgent runner. Its existing `--filter` can select the prefix `builtin installation `. These new groups are directly awaited, including the held-write queue fixture; its finally releases and joins both original operations before deleting its owned scratch directory. They cover complete/incomplete coding/read-only and ordered/empty selections; explicit fake search executors and policy denial; same-key write-before-edit content visibility; actual-profile edit activation with both grants and unchanged startup defaults; three missing-grant denials; and in-process CLI resume restoring durable edit order. No new test framework or actual process/shell launch is authored in these groups. HTTP turns use the existing authored offline handler only.
