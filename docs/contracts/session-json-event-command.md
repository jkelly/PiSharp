# Durable one-shot JSON event output

The native session replacement addition preserves the opening initial-session header and emits bounded additive `session_switched` records with the current session ID, file and attachment generation. Its output subscription then follows the actual new coordinator. Final one-shot verification closes and reopens the current writer, including A→B→A. See [native replacement](native-session-replacement.md) for its transaction, cancellation and cleanup contract; the original adapter evidence below retains its exact historical scope.

This dependency-ready P5-02 slice adds the PiSharp-specific `--output json` selection to existing `session prompt` and `session resume` commands. It runs their actual provider-selectable offline HTTP/SSE profile, shared Agent, prepared tool policy, and durable coordinator. Explicit session/workspace/script/message paths and authorizations remain required. `report` remains the default; `print` retains its final-message behavior. `create`, `inspect`, and `tree` reject every `--output` selection. This spelling is not a claim of upstream CLI parser compatibility.

```text
session resume --session <absolute JSONL> --workspace <existing directory>
  --offline-api openai-responses|anthropic-messages
  --offline-script <absolute authored JSON> --message <text> --output json
```

`--leaf` and `--root` keep their existing branch selection meaning. JSON output observes only this invocation's new run messages; it does not replay prior tool effects, emit old sibling messages, or grant file/Bash authority. Existing explicit authorizations and source-compatible progress defaults, including Bash's bounded actual-delivery receipts, are unchanged.

## Shared wire projection and actual header

After strict durable admission and workspace validation, the command constructs `SessionJsonEventOutput` over its idle session and borrowed `TextWriter`. Construction subscribes **before** prompt submission. `StartAsync` writes the exact owned `session.Snapshot.Log.Header.WireBody` value, including unknown fields, followed by LF, and awaits its flush before submitting the user message. The shared JSONL encoder compacts insignificant whitespace, retaining string/number tokens and all fields. This describes retained header values, not original source-line byte identity or ECMAScript serialization parity.

Every callback passes its native event and the **current actual coordinator snapshot** to `RpcAgentEventProjector`. This is the same implementation RPC dispatch already uses. Its public constructor validates the immutable `RpcDispatchOptions`; each instance owns its usage and pending-tool-start state, requires one sequential consumer, rejects concurrent projection, and borrows snapshots. The output adapter serializes projection and delivery, including overlapping source-compatible progress callbacks. It does not construct a second event mapping.

The admitted native projection emits `agent_start`, `turn_start`, user/assistant/tool `message_start` and authoritative `message_end`, delta-only `message_update`, tool execution start/update/end, `turn_end`, and `agent_end`. Usage remains in each update, and tool starts retain ID/name. Cumulative `message`/`partial` snapshots are omitted from updates by the existing projection. End messages come from the durable primary sink's acknowledged context. The native tool-start DTO has no timestamp, so its retained start position is emitted with its finalized acknowledged body when that tool message ends; this existing RPC behavior is not changed here. Stream start/terminal observations and native absolute argument checkpoints are internal observations rather than extra public delta records.

Opaque content/message/stream fields supported by the common projector remain owned, including explicit null, numeric token spelling, thinking signatures, NUL, supplementary Unicode, and U+2028/U+2029. Tool progress/final result properties use the common complete result codec: `structuredContent`, opaque `usage`, optional/unknown fields and field presence remain observable. Canonical tool transcript messages retain their existing independent materialization contract; programmatic result fields are not silently inserted into LLM history.

`JsonlRecordFormatter` is the narrow public entry into the existing, unchanged `JsonlRecordCodec.Encode`. It validates a borrowed transport configuration and returns that encoder's strict object record with LF. Consequently the CLI shares RPC checks for retained permissive JSON syntax, duplicate decoded names, decoded surrogate validity, depth and byte length. The command's compiled stdout still uses the existing strict, unbuffered `Utf8StreamTextWriter`; this slice introduces no alternate encoding or Node dependency.

## Delivery, budgets, faults and ownership

Default native output limits are:

| Bound | Default |
| --- | ---: |
| One complete UTF-8 record, including LF | 1,048,576 bytes |
| All acknowledged records, including header/LF | 16,777,216 bytes |
| Record count, including header | 16,384 |
| Admitted overlapping observations/waiters | 128 |
| JSON container depth | 32 |
| Returned messages in one event | 1,024 |
| Pending tool-message start identities | 128 |

`SessionJsonEventOutputOptions` and the explicit `SessionCommands.RunAsync` overload let a trusted native host select finite validated limits. Bounds are native hardening, not an upstream unbounded-output promise. Retained input UTF-16 length is also checked before shared strict reparse; whitespace-heavy input cannot allocate an unbounded additional view merely because its compact form is small. Each record is checked before effects, then one actual `WriteAsync` and `FlushAsync` is awaited. Acknowledged byte/count receipts advance only after both return. Cancellation arriving after those acknowledgments does not undo them. A write or flush failure can leave an accepted physical prefix that the receipts do not certify.

There is no payload channel, detached writer task or unbounded queue. Waiters hold admitted native observations, bounded separately; only one record is formatted/delivered at once. Awaited delivery supplies backpressure before final tool messages and the next provider request. Ordinary source progress callbacks still return under their existing source-compatible receipt contract, and the core joins their admitted deliveries before tool finalization; this adapter does not silently switch the Agent to `NativeAwaited` mode.

A projection, framing/quota or physical output fault poisons the adapter, requests synchronous `session.Abort()`, and propagates a payload-free typed exception. Subsequent delivery cannot retry a record, append a settlement report, or report success. `PersistentAgentSession` invokes its durable primary sink before subscribers; native Agent subscribers are awaited and their failures propagate. The command preserves the adapter's first fixed failure if it passes through a tool/Agent wrapper. Abort callback failures cannot replace that first failure. Reentrant delivery and callback self-disposal are rejected, avoiding a wait on the callback's own serialization gate.

Each adapter owns only its subscription, serialization gate and joined lifecycle state. Session and writer remain borrowed. Concurrent `DisposeAsync` calls return the same completion and join every already admitted write/callback before releasing the gate. Disposal unsubscribes and does not retry/flush failed output or close borrowed resources. Trusted writers must eventually settle admitted operations; cancellation is passed to them but is never implemented by abandoning an outstanding write with `Task.WaitAsync`. The command's owned session disposal joins the Agent/provider/tool work and durable lease before a return or fixed diagnostic.

Before a successful JSON command returns, all event writes/flushes and adapter/session disposal have completed. The command compares physical file length to the actual acknowledged snapshot, then exclusively reopens through the strict `SessionLogStore` and checks header, entry bodies/count, physical leaf and committed length against that snapshot. This check does not replay a provider or tool and does not rewrite the source. Failure after a visible `agent_end` still returns failure with stderr diagnostics; this slice does not invent a session-level `agent_settled` acknowledgement.

## Stdout, cancellation and exit behavior

JSON stdout contains only the opening header and admitted shared event records. It never appends the native `session_command_result` report or RPC command responses. Fixed command diagnostics use stderr, with `effectsMayHaveCompleted` once modifying command admission is known. A broken output pipe, output quota failure or projection failure returns exit 1 after cleanup; parser admission failures retain exit 2. Tool/run failure returns exit 1 with fixed `CompletedWithErrors`; a finalized provider error/abort returns exit 1 with fixed `ProviderFailed`/`Canceled`. Provider and tool error values already admitted by native wire contracts remain visible in their actual event records; stderr does not echo exception payloads.

Pre-cancellation produces no header or durable acquisition. Cancellation during an admitted write joins that actual operation and session cleanup. Its accepted JSON prefix may end before terminal records; the command makes no successful-output claim, writes fixed `Canceled` stderr and releases its lease. The existing source-compatible subscriber token can already be canceled during abort settlement, so this slice does not claim upstream abort-event parity. Full source/native cancellation comparison remains required.

The compiled Windows redirect boundary requires `StandardOutputStream.Open()`. The .NET 10 console implementation converts closing, broken and disconnected pipe write errors into success, which prevents the outer strict UTF-8 writer from observing a physical failure. This behavior was verified in the primary [.NET 10 console source](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Console/src/System/ConsolePal.Windows.cs#L1120-L1153). For redirected pipe/file stdout the factory instead duplicates the borrowed standard handle with the same access and noninheritable ownership, then returns an unbuffered `FileStream`. It closes only its duplicate; it never changes standard handles, console encoding/mode or global settings. Character-console devices and other platforms retain their framework stream behavior. Opening failures produce fixed `StandardOutputUnavailable` before command effects.

The safe-handle `FileStream` overload detects the actual handle mode rather than forcing a synchronous/overlapped mismatch. Its Windows write path propagates native write failures; asynchronous calls on synchronous handles use the framework's awaited I/O cancellation path. See the primary [.NET file-stream constructor](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/src/System/IO/FileStream.cs#L95-L106) and [Windows write implementation](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/src/System/IO/RandomAccess.Windows.cs#L120-L142). Program awaits the existing command/host delivery and cleanup, disposes the borrowed UTF-8 writer, then disposes its owned output stream. The factory does not implement concurrent disposal/join on behalf of arbitrary callers: its public Windows duplicate seam requires trusted writable handles, serialized writes, and awaiting admitted I/O before disposal. Partial effects remain possible on cancellation or physical failure; no pending write is abandoned, no partial write is acknowledged as a complete JSON record, and no new output-durability promise is made. Existing borrowed-writer and borrowed RPC-host contracts remain unchanged. Authored fixtures cover actual inherited synchronous stdout pipes and a synchronous local file duplicate; existing externally bound overlapped handles, unusual pipe modes, interactive consoles and other platform combinations retain mandatory future qualification.
