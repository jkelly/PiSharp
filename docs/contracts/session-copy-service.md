# Non-destructive explicit session copy

`PiSharp.Sessions.Import.SessionCopyService` implements a bounded explicit file-copy/import/export slice of [P4-05](../plans/04-sessions.md). It reads an explicitly supplied source, retains its captured original bytes and SHA-256, validates records and the complete forest, and publishes only to an explicitly supplied new destination. It owns no default Pi/PiSharp home, ID/clock authoring, extension restoration, image loader, provider, process or tool execution. IDs, cwd/header metadata, paths embedded in transcript bodies and CLR-looking strings remain data and never select a filename or authorize an effect.

The source baseline is public Pi v0.99.1 at `d86654abb8862e201933517d6f1fce9f88dd117f`, complete [session-manager.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/session-manager.ts). Its `migrateV1ToV2`, `migrateV2ToV3`, `migrateToCurrentVersion`, `parseSessionEntries`, `loadEntriesFromFile` and `SessionManager.forkFrom` establish migration and copy behavior. Pi's reader can skip malformed lines and rewrite migrated sources; this service deliberately performs strict non-destructive native admission. Copying an existing identity/history is distinct from Pi's fork operation, which authors a new header ID, timestamp, cwd and parent-session link. This service does not claim fork semantics.

Public calls are `InspectAsync(sourcePath, v1EntryIds, token)` and `CopyAsync(SessionCopyRequest, token)`. Source/destination paths are trusted explicit inputs, absolute and lexically normalized, with a filename and a 4,096-character bound. Relative, UNC/device and normalization-changing paths are rejected. The destination's parent must already exist; this service creates no directories. Existing file/directory destinations and source/destination equality are rejected before I/O. A new destination alias that resolves to an existing source is also protected by existence checks and no-overwrite publication. This is not physical file-identity certification, adversarial reparse-point protection or a policy boundary. External path replacement races, network storage and cross-platform filesystem guarantees require further qualification.

Inspection returns the existing reader's immutable original capture, validated prefix, recovery/UTF-8/header diagnostics and source-completeness flag; `CapturedSha256` names exactly that bounded capture. `SourceSha256` is present only after EOF was observed. Resource-limited inspection may retain only the first configured bytes plus the reader's single overflow byte; it never implies that those are the full source. Full strict JSONL parsing also validates legacy/future tails that the current reader cannot admit. LF, CRLF, ASCII blank lines and valid nonterminated final records follow the reader profile; BOM, invalid UTF-8, malformed middle/final data, duplicate fields, unsupported Unicode and bounds failures block current publication.

`SessionEntryMigration` supplies the existing pure v1/v2-to-v3 transforms, version detection/defaulting, current records, transformation receipts and warnings. V1 requires an explicit unique ID for each nonheader record; no generator runs in the copy service. V1 physical relationships/compaction full-array references and v2 hook-role conversion retain their existing strict migration profile. There are no guessed replacements for incomplete old message schemas or unsupported references. Unknown entry kinds, numeric tokens, nested opaque fields, missing versus null and inert custom/native-looking data remain owned JSON. All receipts and source records are explicit inspection payload; diagnostics contain only fixed codes/indexes and optional graph failure enums, without exception text or transcript secrets.

Whole-forest validation reuses `SessionContextProjector.Project(entries, null)`, including disconnected branches, duplicates, missing parents and cycles. The service additionally requires parents to precede children in physical order so the published file can reopen under the existing append store's admission contract. A structurally valid forward-parent forest receives `UnsupportedEntryOrder`, not a guessed reordering. Copy validation does not parse opaque timestamps or demand that every branch can already convert to provider context. Imported data gains no extension execution authority.

`NativeExact` accepts only valid current-v3 data and preserves every source byte, including whitespace, CRLF/blank framing and a missing final newline. `CompatibleCurrentJsonl` serializes strict current/migrated records as UTF-8 JSONL with LF after each record. It preserves every unrelated record field and carries full migration receipts/warnings; property-name escaping/whitespace can change during migration and formatting. Known migration changes, including replacement/removal of `firstKeptEntryIndex`, are separately receipted and original bytes remain in inspection. `OmittedRecords`/`OmittedFields` count unsupported-data export exclusions, not those explicit known transformations; both are zero because this service excludes no opaque/native-looking state. Results also report `SemanticCompatibilityUnverified`. That zero-exclusion data-retention claim is not verified Pi-reader/model-context interoperability. No native-only schema is invented and no field is silently discarded. Selected-branch and lossy export projections remain separate operations. The additive archival route and actual native-file reader comparison are described below and in the P4-05 milestone. Future/damaged sources can be inspected with their owned capture and blockers but cannot publish a purported runnable current session.

Defaults are the reader's 16-MiB input, 4-MiB line, 100,000 physical lines/records, 8-KiB read buffer and strict codec bounds, plus a 16-MiB output bound. Input/output cannot exceed the native 64-MiB hard ceiling. Output is also capped by the reader's input bound so it can reopen under the same profile. The planned output is reread through the strict reader before any temp is created. These bounds constrain admitted captures/records/output; they are not a total heap cap. Original bytes, parsed JSON, migration receipts and graph indexes can coexist.

The default filesystem opens the source read-only with `FileShare.Read` and keeps that source handle through validation/publication/cleanup. It exclusively creates a GUID-named `.pisharp-copy-*.tmp` in the destination's existing parent, writes and asynchronously flushes it, awaits stream disposal, then calls `File.Move(..., overwrite:false)`. Neither source nor existing destination is ever truncated, deleted or rewritten. Parent/filename selection comes exclusively from the explicit destination, not header IDs. Same-directory temp/no-overwrite rename is a practical local publication boundary, not a durable-directory, network, power-loss or universal atomicity guarantee. There is no `Flush(flushToDisk:true)` checkpoint claim.

`ISessionCopyFileSystem` is a trusted I/O/fault seam. Open returns an owned readable stream. Temp creation is shielded from caller cancellation until ownership is returned; an implementation must settle and clean resources it acquires if it throws before returning. On generic preownership create failure, the service conservatively reports `TemporaryMayRemain` and does not delete an unacknowledged path. It never deletes a destination as fault recovery. Once a stream is owned, write/read/flush cancellation is awaited, temp disposal/deletion and source disposal use no canceled token, and all acquired work is joined before return. A failed deletion or disposal remains explicit; primary read/write/flush/publication failure is retained with additive cleanup failures.

Caller cancellation before publication throws `SessionCopyCanceledException` with the actual caller token and cleanup/possible-temp information. Foreign cancellation from trusted I/O is a fixed storage failure. Publication has no caller token: success returns the known published receipt even if cancellation arrives afterward. A publication callback that may move the file then throw produces `SessionCopyException` with `Publication.Uncertain`; it does not report rollback or successful publication. Source cleanup failure after known publication returns `PublishedWithCleanupFailure`, retaining the output hash/size and `Published=true`. Only clean publication has `Status.Published`; there is no false clean success or cancellation hiding an acknowledged destination.

The original file/fault groups cover exact original hashes/immutable captures/all branches/new append-store reopen; compatibility raw-number/null/native-looking retention; copied v1 identity/compaction and v2 hook receipts; future/damaged/UTF-8/forest blockers with no temp; read-only source/repeated imports/collisions/normalization/traversal-like IDs; exact and exceeded budgets; cancel-before-I/O and read/write cancellation joined through gated source disposal; partial write/flush/disposal/foreign cancellation faults, cleanup-secondary errors, no-overwrite publish races, uncertain post-effect publication and known late-cancellation receipts. The additive archive groups exercise complete opaque preservation and held cancellation cleanup. Seven actual native-export groups compare the complete current production records and views with frozen unchanged Pi-reader observations, retaining numerical and own-undefined differences explicitly. Fixtures operate only in unique owned temporary directories and do not dereference stored image/path data. Full milestone gates and independent review remain required; these controls do not establish a stronger filesystem durability guarantee.

The additive `NativeArchiveExact` export preserves a complete captured source byte-for-byte, including future formats, malformed JSON and invalid UTF-8. It is explicitly inert archival data and does not require or imply current-session admission. Missing EOF or exceeded output bound blocks publication. This format uses the same exclusive temporary, joined write/flush/dispose and no-overwrite publication path; source and destination protections remain unchanged. Its command spelling is `native-archive-exact`. Current and legacy runnable copy behavior above remains unchanged.

`SessionCopyResult.Retention` discloses exact byte retention, zero excluded records/fields, unknown entries retained inertly, current-format admission and a false general interoperability guarantee. Archive results always mark current admission false and emit `ArchivedSourceExact`/`ArchiveNotRunnable`; they preserve reader/migration blockers for inspection. Source-linked native and actual Pi-reader qualification is tracked in [P4-05](../compatibility/p4-05-interoperability-milestone.md).
