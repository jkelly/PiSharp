# Explicit Completions body results

`ICompletionsResponseBodyResultReader` supplies the actual immutable result used by the HTTP/SSE decoder. `CompletionsBodyReadResult.FromBytes` owns its bytes and accepts an empty nonterminal chunk. `EndOfInput` is physical EOF; `Closed` is logical closure without physical EOF. Closed results have absent-value presence. An empty chunk has an owned empty value and `done=false`. These states do not follow from byte length alone.

`CompletionsBodyReader.FromResultReader` enforces the actual requested byte bound, single active read, shared joined cancellation and single release. An invalid/null/oversized result fails before observer or decoder admission. Pending noncooperative results and faults remain joined. Cancellation closure grants no physical EOF authority. Result release borrows the physical stream and retains the response owner's disposal authority. Existing count readers and their constructor remain supported; count0 retains its existing physical EOF interpretation.

`CompletionsHttpSseOptions.BodyResultReaderFactory` creates a result executor after the awaited response hook and Start, over the same borrowed input as the count factory. Selecting both factories is rejected before HTTP effects. Source preparation keeps its real bounded prefetch; canonical preparation keeps zero early acquisition. Each actual result is passed to `OnBodyRead` and then the decoder. Empty nonterminal chunks cause another result read without flushing partial UTF-8, dispatching pending SSE or completing the provider. Physical EOF still flushes the existing decoder policy. Exact DONE still ends consumption, ignores tail and joins cancellation/physical cleanup.

`MaximumConsecutiveEmptyBodyReads` defaults to4096 with inclusive1..65,536 admission. It bounds injected producer work between nonempty decoder reads. The next empty result above the bound fails the stream after its actual observation and joins cleanup. Cancellation is checked before every additional result. This resource limit is explicit native hardening, not an invented upstream limit or a source parity exception.

Native tests qualify empty chunks between UTF-8 bytes, within incomplete frames, before DONE/EOF, and at held abort/fault/budget boundaries. They are authored behavior evidence, not regenerated source captures. All fourteen strict schedules/assertions and pinned offline files remain unchanged.
