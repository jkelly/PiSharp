# Native message contract, first executable slice

This contract targets public Pi v0.99.1 source at `d86654abb8862e201933517d6f1fce9f88dd117f`. It documents implemented native values and the current adapter boundary; it does not freeze the complete P1 contract or claim provider/session compatibility.

`PiSharp.Contracts.AssistantMessage` is an immutable record with requested API, provider and model, Unix millisecond timestamp, immutable ordered content, usage, stop reason and retained JSON fields. Content consists of typed `TextContent`, `ThinkingContent` and `ToolCallContent` records. Their positions are meaningful. The current assistant shape matches the pinned chat-assistant content variants; images in other transcript roles remain raw wire data in `TranscriptEntry` until those native contracts are implemented.

`PiWireJson` explicitly translates native records to Pi property names and discriminators. Serializing CLR records with default `JsonSerializer` options is not the wire contract. Stop reasons are `pending`, `stop`, `length`, `toolUse`, `error`, `aborted` and `deferred`. Recognized assistant wire fields are `role`, `api`, `provider`, `model`, `timestamp`, `content`, `usage` and `stopReason`.

Optional provider fields and unknown JSON are owned immutable `JsonData` values in `JsonFields`. A field absent from the dictionary stays absent on serialization; a present JSON null stays null. Response IDs, actual model, raw finish reason, reasoning signatures, redaction flags, deferred handles and diagnostic metadata survive round trips as retained fields. Reading retained unknown data gives it no executable meaning. `JsonData` clones the source element, so disposing the caller's `JsonDocument` cannot invalidate a contract value.

Usage token counts are integer values. Costs are decimals and are not rounded by the adapter. Optional `reasoning` and `cacheWrite1h` fields remain present or absent exactly as supplied, including a reported zero. This slice does not calculate model pricing or validate the full provider-specific usage taxonomy.

Tool calls retain string IDs, names, object arguments and opaque optional fields such as `thoughtSignature` and `namespace`. The reducer rejects empty identities, duplicate call IDs within a message, and identity changes at block end. Raw incremental tool JSON has a separate preview surface and does not replace final arguments. `FinalToolArguments.ParseStrict` accepts only complete JSON objects, rejects duplicate object keys, trailing input and malformed escapes, and uses a maximum JSON nesting depth of 64. This type establishes JSON syntax and object shape only. P3 must resolve the tool, validate its schema, apply transformations, revalidate and authorize the final action before executing it.

JSON repair and incomplete-object display parsing from upstream `partial-json` are deferred. Native strict final parsing is an explicit first-slice design choice awaiting compatibility qualification. The compact replay fixtures supply authoritative parsed end arguments, so matching those fixtures does not prove provider wire parsing or repair parity.

All public `PiWireJson` readers validate their entire JSON input, including recognized keys, before interpretation. Duplicate object keys and excessive nesting are rejected even when the caller supplies an ordinary `JsonDocument` element. This is native hardening; upstream `JSON.parse` uses the last duplicate key and no parity claim is made for hostile duplicate-key inputs. Callers do not have to prevalidate through `JsonData` to obtain this behavior.
