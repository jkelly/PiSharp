# Pure immutable session tree queries

PiSharp.Sessions.Tree.SessionTreeQueries builds immutable navigation and global metadata views from an initialized ImmutableArray of validated SessionEntry values, excluding the session header. It has no filesystem, mutable active-leaf pointer, ID generation, clock, provider, tool, import/export or extension execution authority. This is a portion of [P4-03](../plans/04-sessions.md), suitable for consuming admitted history alongside storage/context APIs. Full branch switching, fork persistence, summaries, exports, lifecycle management and phase acceptance remain separate work.

The behavior comes from the unchanged complete public [session-manager.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/session-manager.ts) at Pi v0.99.1, SHA d86654abb8862e201933517d6f1fce9f88dd117f: _buildIndex, getLeafId/getLeafEntry/getEntry, getChildren, getLabel, getBranch, getTree and getSessionName. The pinned [tree traversal tests](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/test/session-manager/tree-traversal.test.ts) and [label tests](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/test/session-manager/labels.test.ts) supply authored semantic controls. No independent unchanged whole-module tree execution comparison is claimed here.

The API is:

    new SessionTreeQueries(options).Build(entries, cancellationToken)
    snapshot.GetEntry(id)
    snapshot.GetChildren(parentId, cancellationToken)
    snapshot.GetBranch(entryId, cancellationToken)
    snapshot.GetLatestBranch(cancellationToken)
    snapshot.GetLabel(id)
    snapshot.GetChronologicalChildren(parentId, cancellationToken)

Build reuses SessionContextProjector.Project(entries, selectedLeafId: null) for complete forest admission. There is no duplicated graph validator or selected message/date conversion. The existing projector's fixed InvalidEntries, DuplicateId, MissingParent, Cycle and ResourceLimit exceptions remain the graph diagnostic authority, including unselected sibling validation, forward parent references and multiple roots. Native admission rejects orphan/missing/self/cyclic graphs rather than applying upstream's permissive orphan-root, self-root, last-write identity or truncated-parent behavior. No malformed graph becomes an apparently complete forest.

SessionTreeSnapshot has a nonpublic constructor and exposes immutable Entries, ById node views, RootIds, StructuralLeafIds, BranchPointIds and PhysicalLeafId. Each flat SessionTreeNodeView has the original owned Entry, immutable direct ChildIds and optional ResolvedLabel. Root IDs, child IDs, structural leaves and branch points retain physical input order. A structural leaf has no children; a branch point has more than one direct child. PhysicalLeafId is the last physical record, matching _buildIndex's rebuilt pointer; it can differ from structural leaves when parents occur later in the supplied array. It is not a persisted or mutable selected branch pointer.

GetEntry returns null for an unknown identity. GetChildren returns direct entries in physical order, matching byId insertion order for a validated unique forest, and returns an empty array for an unknown parent. GetBranch returns all raw entry kinds in root-to-selected-entry order with no sibling leakage, compaction filtering or context replacement. Explicit null selects empty ancestry; GetLatestBranch explicitly selects PhysicalLeafId. Missing non-null selections fail fixed MissingEntry rather than silently selecting another branch. Entries are already owned immutable codec values, so retaining their identity and raw WireBody creates no mutable sharing.

Global labels replay the full physical history, independent of selected branch. For each label target, the latest nonempty string sets label and its exact raw entry timestamp; absent, explicit-null or empty strings clear both value and timestamp. Whitespace labels remain nonempty and are not trimmed. Raw entries preserve absent versus explicit-null fields even though both resolve to a cleared label. Targets absent from the forest stay in the label map, matching _buildIndex; no target entry is synthesized. Labels are real tree entries and remain in children/ancestry. The snapshot's Labels and GetLabel return SessionResolvedLabel values with Label and Timestamp; node views attach the same resolved metadata for existing targets.

Optional label fields are not fully schema-certified by the codec. A final non-string/non-null value for any target marks LabelsAvailable false, returns an empty resolved Labels map, removes node resolved labels and supplies fixed InvalidLabel diagnostics. GetLabel then fails MetadataUnavailable; raw graph/ancestry queries still work. A later valid set or clear for that same target supersedes the malformed value. This is explicit native metadata capability handling, narrower than upstream's JavaScript truthiness behavior on malformed imported records, without discarding their raw data.

SessionName uses only the last physical session_info entry, matching getSessionName even when it is on another branch. An absent/null name or a string empty after trimming clears the title, with no fallback to an older name. Trimming uses the explicit ECMAScript whitespace/line-terminator character set, including U+FEFF and excluding U+0085, rather than culture or .NET whitespace classification. Original fields remain unchanged. A latest non-string/non-null name marks SessionNameAvailable false, supplies fixed InvalidSessionName and exposes no resolved SessionName. Earlier malformed names superseded by a later session_info do not block current metadata. A null resolved name with SessionNameAvailable true is an actual clear/no-title result.

Flat and ancestry queries keep entry timestamps opaque. GetChronologicalChildren is a separate capability query corresponding to getTree's timestamp-sorted child arrays. Supported timestamp strings use ISO seconds, optional one-to-seven fractional digits, and Z or an explicit numeric timezone offset within native DateTimeOffset range. Keys use Unix milliseconds and stable physical ties, matching the public comparator's millisecond resolution for this profile. Root order stays physical; no clock or locale is consulted.

For two or more children, an unsupported timestamp returns UnsupportedTimestamp status, no partially sorted Entries and one fixed diagnostic with the first affected physical record index. It neither prevents Build/flat queries nor rewrites the timestamp. Zero/one children complete without interpreting a date, because the pinned sort performs no comparisons. JavaScript's general Date parsing, invalid-date/NaN comparator behavior and wider date range remain unqualified. Flat ChildIds/GetChildren always retain physical order even after a successful chronological query. The flat snapshot is the immutable graph representation; recursive nested getTree objects are not materialized.

SessionTreeQueryOptions reuses the existing projector GraphOptions admission limits, defaulting to 100,000 entries and 16,777,216 raw UTF-16 input characters. The null-leaf call emits no context messages and does not traverse selected ancestry; MaximumQueryEntries separately defaults to 100,000 children/ancestor entries per query. MaximumMetadataDiagnostics defaults to 256; exceeding it fails ResourceLimit before publishing a snapshot rather than silently hiding malformed metadata. Chronological sorting is bounded by admitted query length. All limits must be positive. These are logical limits, not a total heap cap; callers already own input/query strings and can issue multiple concurrent pure queries.

Build and traversal queries check caller cancellation before work, during record/child/ancestor/date traversal and before returning. Sorting has no caller callbacks and checks cancellation after its bounded synchronous operation. GetEntry/GetLabel are direct immutable index lookups. No partial build/query snapshot is published after failure or cancellation. Metadata and query failures use fixed messages/codes/indexes, without rejected IDs, raw dates, content, paths or inner exceptions.

Eight authored groups cover forward parents/multiple roots/leaves/branch points; sibling-isolated ancestry and physical versus chronological children with offset/millisecond ties; global labels and missing/null/empty/unknown-target semantics; global latest names and exact trimming/clearing/capability controls; opaque-date navigation and explicit chronological failure; reused whole-forest graph diagnostics; inclusive graph/query/diagnostic limits and cancellation with retained snapshots; and a deep iterative unknown-record chain with exact raw ownership checks. Root owns registration, isolated execution and review. The helper does not append labels/names, branch a live store, reconstruct model context, plan compaction or close any phase gate.
