# Explicit MCP prepared publication boundary

Source-only coordinator slice. No builds, tests, process starts or HTTP requests were performed for this source.

`McpPreparedServer` borrows one explicitly admitted semantic channel factory, extension registration scope, actual replaceable-session attachment, mandatory final-action policy and schema validator. Construction validates the native invocation generation and policy identity. It acquires no client, subprocess, credential or activation authority.

Catalog preparation holds the actual owner's existing mutation reservation, directly joins idle session work, and captures the current registry. The extension registry prepares an inert, opaque replacement plan. A prospective native catalog retains unrelated adapters and validates new declarations through the existing prepared pipeline. The actual session appends and acknowledges a declaration replacement before the synchronous, already-prepared registry commit and native configuration update. A matching generation/revision receipt is returned only afterward. Post-ack failure faults the session; it does not claim rollback or replay publication.

Same-name schema/description changes produce declaration replacement. Newly added Direct/default-active tools activate; a manually inactive existing name stays inactive on refresh. Registration callbacks require the actual native invocation owner, session generation and call identity. The existing invoker runs argument preparation and final authorization before the admitted tools/call. Owning callback reentry fails explicitly.

The required `McpPreparedHookComposer` is host-owned: it must preserve unrelated native prepared hooks and replace retired registry hooks. The boundary does not silently drop a preexisting hook pipeline. It receives the actual current registry and prospective extension binding; it must return synchronously without external effects.

Six new Coding groups cover actual durable catalog/call identity, malformed input and final denial, same-name refresh/manual inactivity, close withdrawal/stable original close task, held reporter cancellation and original failure, and post-ack commit uncertainty. Six registry publication groups cover inert prepare, stable commit receipt, stale ownership, collisions, retired callback charges and late leases. Both families are registered once and directly awaited. All twelve are authored and unexecuted.

R284 corrects the reviewed close defect: the prepared-server owner now owns a stable original close task and admission fence. It first closes and joins the runtime and host operation originals, then removes its last actually committed registration subset through the same durable session boundary while the captured attachment remains admitted. Channel cleanup failure does not skip withdrawal. A single original failure is retained; multiple cleanup/withdrawal failures are retained together. Failed withdrawal retains catalog ownership and does not report success. `CatalogWithdrawalAcknowledged` is set only after an actual withdrawal acknowledgment, or if no subset was ever committed. It can be true when withdrawal succeeded but channel cleanup failed; the close task still faults in that case.

Four additional Coding groups cover unrelated native adapters/hooks, held refresh racing close, combined original cleanup/withdrawal failures with retained catalog, and retirement refusing mutation while still joining channel cleanup. The Coding publication family now has ten groups; registry publication has six. All sixteen are unexecuted. Caller/factory dependencies must not synchronously await their owning server operation. Automatic host lifecycle integration remains pending: `BeforeRetirement` already holds the owner/session reservations and cannot simply reenter the current publisher.

Remaining gates: independent source review; exact native allocation and execution; ordinary CLI/profile connection admission; genuine tool-search/codemode/resource discovery identities; register/get-server host APIs; automatic close/reload coordination. The caller must close this server before retiring its captured attachment. Retired attachment admission is rejected, but this slice does not install the missing owning host lifecycle joins.
