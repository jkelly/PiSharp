# Registered input admission in durable sessions

This experimental integration admits owned source-style input through actual registered reducers, the existing `PersistentAgentSession`, Agent, queues, and durable commit barriers. It supplies a named `SubmitInputAsync` path; it does not redefine the accepted canonical-message `PromptAsync` overloads, `ContinueAsync`, tools, or registered tool hooks. Applications choose the source-input path explicitly. Completing the source Agent/session API, all event families, and SDK qualification remains required work.

## Public composition

`PromptInput` carries text, `PromptInputSource` (`Interactive`, `Rpc`, or `Extension`), optional owned image JSON, and optional `PromptInputStreamingBehavior` (`Steer` or `FollowUp`). A neutral `IPromptInputAdmission.ReduceAsync` returns `Continue`, `Transform`, or `Handled`. Transforms may change text/images only; they cannot change source, delivery mode, role, model, declarations, identifiers, or timestamps. Nullish replacement images retain the input images. The completed user message always starts with one text block, including empty text, followed by admitted images.

The host creates `RegisteredExtensionInputAdmission(registry, binding.Snapshot, ...)` from the actual `ExtensionAgentBinding` snapshot used for tools. The adapter borrows registry/session lifetime and retains one long-lived registered dispatcher with configured concurrent/depth/handler limits. Every dispatch acquires all participating owner/generation callback leases through the registry before the first callback. The private reducer projection is not a mirror registration store. Removal preserves callbacks already admitted for this dispatch, excludes future snapshots, and makes a later dispatch through a removed captured entry stale. A host must explicitly create a new captured binding/adapter at an appropriate idle boundary to use subsequent revisions.

`PersistentAgentSession.SubmitInputAsync(input, admission = null, options = null, cancellationToken = default)` returns `SubmittedInputResult`:

| Disposition | Actual behavior |
|---|---|
| `Handled` | No Agent generation, canonical message, queued message, trusted clock/ID call, durable append, or provider request. `Run` is null. Existing queues/history remain intact. |
| `Queued` | The effective canonical user message enters the existing Agent steering or follow-up FIFO. No second queue is created and this result acknowledges no durable append. `Run` is null. The actual loop commits the message when it consumes that queue. |
| `Started` | The effective canonical user message starts the existing Agent through the accepted coordinator execution path. Submission awaits the real run and returns its `AgentLoopResult`. Durable input/end checkpoints and awaited listeners remain prerequisites for subsequent provider/tool work. |

Without an admission adapter, the new method continues through that same native path. Existing canonical `PromptAsync` signatures/default behavior are unchanged and do not pretend to represent handled source input. Supplying a typed reducer does not grant effect authority; final tool validation/policy and accepted result materialization remain unchanged.

## Admission lifecycle and real queue behavior

One coordinator lifecycle reservation serializes input callbacks. It contains cancellation/settlement state only, not messages, executable actions, or another queue. Concurrent canonical prompt, continuation, configuration, and second input admission reject while callbacks are being admitted; snapshots and the existing queue interfaces retain their ordinary roles. Input callbacks and diagnostics are awaited outside coordinator/registry locks. A callback cannot wait for its own coordinator idle/disposal or recursively admit another input. The trusted message clock receives the same self-wait protection.

Handlers see no streaming behavior while the coordinator is idle, matching the source prompt path. During an active coordinator generation they see the explicitly supplied steering/follow-up mode. `Handled` works even during a generation without a mode. After a nonhandled reduction, active input needs an explicit mode and enters the real queue; idle input starts the real Agent. The choice is sampled again after callbacks, so an existing generation that finishes while a callback is held does not create a stale queued run. The reservation prevents a competing generation/configuration from starting between final validation and admission.

The active coordinator lease includes awaited end-event listeners and durable settlement. Input submitted at a held end barrier is queued and remains pending after that generation settles; an explicit accepted continuation consumes it. This is deliberately tested. The source Agent session samples `isStreaming` after hooks and has additional prompt/settled/session continuation machinery. Exact races across those source flags and the native coordinator's end lease remain mandatory qualification work. This integration does not hide that difference, start automatic late-queue continuations, or claim that a queued disposition means a provider request completed.

`Abort` requests cancellation of the held input reservation and actual Agent work. Cancellation callbacks run outside locks; a guarded cancellation-user count prevents disposing their source before they finish. `WaitForIdleAsync` joins input and generation settlement. Concurrent `DisposeAsync` callers share cleanup and join both reservations before closing Agent/storage. A throwing cancellation callback is recorded in the nonpositional snapshot property `InputCancellationCallbackFailed` and never skips callback or storage joins. `IsAdmittingInput` describes the actual reservation independently of `Agent.IsRunning`. Registered owner disposal independently cancels/join its leased callbacks and extension cleanup. Cancellation remains cooperative; a callback that never settles can hold its lease.

## Owned values, errors, and durability

`PromptInputValue` performs pure admission/materialization. Default bounds are 65,536 text UTF-16 characters, 16 images, 262,144 retained image JSON characters, 1,048,576 image UTF-8 bytes, JSON depth 32, 1,048,576 completed message characters, and 4,194,304 completed message UTF-8 bytes. The raw image budget is charged before strict reparse. Scalar Unicode, strict JSON, unique properties, finite numbers, image envelopes (`type`, `data`, `mimeType`), and complete final-envelope depth/size are required. NUL remains inert string data. Unknown image fields and numeric token spelling are retained; no numeric normalization is performed.

Final canonical user-message admission occurs before Agent or queue mutation. A pure inert record probe additionally checks the selected session codec's message grammar, outer-record depth, and size limits. The probe is never appended/projected and calls no trusted ID/clock function. Actual generated IDs, selected parent, graph projection, record metadata, store budgets, and acknowledged checkpoints still pass the accepted durable pipeline; the probe cannot promise that a future trusted ID generator or storage operation will succeed. The independently bounded materialization buffer and admitted JSON are logical resource bounds, not a total heap guarantee. Queue and session bounds remain independently applicable and never silently clamp or drop input.

Registered input callback failure/invalid output produces sanitized diagnostics and continues in source owner/insertion order; first `Handled` stops later callbacks. The optional trusted diagnostic observer is strongly awaited. Its failure rejects preflight with fixed `HandlerFailed` text, joins cleanup, and starts no Agent work. No plugin message, stack, payload, image data, or secret is inserted into failures. Requested operation/session/owner cancellation propagates after actual callback cleanup. Rejected preflight cannot poison acknowledged session history; actual uncertain append failure retains the existing coordinator fault and blocks continuation without retry/recovery or a fabricated success.
