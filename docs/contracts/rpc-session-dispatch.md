# Durable fixed-session RPC dispatch

`PiSharp.Rpc.Protocol.RpcSessionDispatcher` implements a bounded initial command/lifecycle slice over one actual `PersistentAgentSession`. It uses the pinned [rpc-mode.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/rpc/rpc-mode.ts), [rpc-types.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/rpc/rpc-types.ts), [agent-session.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/agent-session.ts) and [json-event.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/json-event.ts), plus [RPC commands](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/docs/rpc-commands.md). It supplies functional P5-04/P5-05 foundations; complete RPC command parity, unchanged-client qualification and P5A remain mandatory unfinished work.

Construct with `RpcSessionDispatcher(session, output, clock, models, options: null, sessionOwnership: RpcSessionOwnership.Owned)`. The session must be idle, available and exclusively operated through this dispatcher for its lifetime. Each `RpcModelDefinition(ModelDescriptor Model, JsonData WireBody)` supplies explicit full model metadata matching id/api/provider. Name, baseUrl, reasoning, input, contextWindow, maxTokens and the four model cost fields must have their source value kinds. Strict owned JSON admission preserves all opaque fields and raw numeric/string tokens; the dispatcher does not invent provider metadata, acquire authentication or select executable runtime bindings. The current coordinator admits thinking `off`. Model/thinking changes through this RPC layer remain unfinished.

`SubmitAsync(JsonData command, cancellationToken)` admits one command and awaits its response/event-output obligations. A successful `prompt` response reports actual generation admission, rather than run completion. `RunAsync(JsonlReader input, cancellationToken)` admits bounded concurrent commands while continuing to read during a running prompt or awaited abort. It uses [recoverable frame admission](rpc-jsonl-recoverable-admission.md) for one no-ID `command: "parse"` response per complete malformed/blank/nonobject frame, then processes later valid records. It has one input-loop claim. `WaitForIdleAsync` joins actual coordinator cleanup and protocol settlement. `Completion` and repeated `DisposeAsync` share shutdown completion, including owned session and output cleanup. Neither a session header nor a handshake is emitted.

| Commands | Implemented behavior |
| --- | --- |
| `prompt` | Create the source-shaped user message with injected timestamp, text block and optional owned image blocks. Reply once with `started` after the coordinator/Agent generation actually advances. A running prompt requires `streamingBehavior: "steer"` or `"followUp"` and replies `queued`. A rejection before generation admission produces one failure response. |
| `steer`, `follow_up` | Use the coordinator's real independent FIFO queues, including while idle. Reply `queued`; no run is started just by these commands. |
| `abort` | Mark run-level abort intent, request actual cancellation and await provider/tool/coordinator/protocol settlement before the no-data response. Preserve pending queues. |
| `clear_queue` | Atomically return and remove both complete queue arrays irrespective of delivery mode. Return their text and emit the actual current queue state. Receipt/output budget checks precede removal. |
| `set_steering_mode`, `set_follow_up_mode` | Apply actual `all` or `one-at-a-time` mode through the coordinator; return no-data success. |
| `get_state` | Return explicit full configured model JSON, actual streaming state, restored thinking, actual queue modes/counts, durable session path/id, latest physical session name when present, and acknowledged message count. `isCompacting:false` and `autoCompactionEnabled:false` describe the current coordinator with no installed summarization workflow. |
| `get_messages` | Return acknowledged selected-context raw runtime messages, preserving custom/summary bodies and opaque values. This read never exposes received-but-unacknowledged Agent message state. |
| `get_entries` | Return acknowledged physical records in append order, excluding the header, plus the selected leaf/null. A present `since` is an exclusive durable cursor, including an empty string; an unmatched cursor fails. Sibling/pre-compaction history is included in this command, while `get_messages` stays selected-context-only. |
| `get_last_assistant_text` | Follow the actual pinned helper: skip empty aborted assistants, concatenate text, apply ECMAScript trimming, and omit `data.text` if the helper would return undefined. The pinned docs/types describe null here, but unchanged `rpc-mode.ts` plus JSON.stringify actually omit the property. |

Optional string command IDs echo verbatim, including empty strings, escaped newlines and valid Unicode. Absence stays absent; explicit null/nonstring IDs fail bounded native admission without being echoed. Ordinary commands receive one response each; responses may complete out of submission order. A stale `extension_ui_response` produces no ordinary response, matching the source's separate response family; native dialogs are not yet registered or functional. Unknown command types return `Unknown command`, while every known pinned command outside the implemented table returns an explicit unfinished-workflow error. No arbitrary permanent subset or replacement protocol is declared.

Accepted provider errors/aborts settle through ordinary authoritative messages/events and never generate a second prompt response. Fatal durable-commit, event-projection, output or continuation-budget failure closes admission and signals a sanitized `RpcDispatchException` through shared cleanup. It does not invent an acknowledged final message or normal settlement after a failed durable barrier. The host owns stderr/exit-code reporting. Caller cancellation before command admission has no wire response; cancellation while awaiting a short admission transition rejects the command before effects. Once started, a prompt is owned by the dispatcher, so cancellation of an embedding submission wait is not a substitute for `abort` or host shutdown.

The event subscription exists before any submission. Actual agent/turn/message/tool events use their source wire field names; `agent_end.messages` contains only this low-level generation's newly generated messages, never the prior transcript. `willRetry:false` reflects the absence of a native automatic retry workflow. Streaming `message_update` emits usage plus compact nested deltas, omitting cumulative message/partial snapshots. The accepted native stream profile reports usage in its start/terminal values; terminal values are translated to final messages, and native absolute tool-argument checkpoints remain internal display state while authoritative toolcall ends remain emitted. Native tool progress and direct RPC bash streaming remain unfinished.

The coordinator's primary sink completes the durable checkpoint and publishes acknowledged context before the dispatcher can emit `message_end`. Tool results expose a native timing difference: `ToolResultMessageStarted` has no timestamp, so the projector retains each bounded pending start by tool-call ID and emits its start/end pair at the acknowledged end using the exact durable raw body. Duplicate starts, missing/mismatched ends and leftover starts at a generation boundary fail closed. This preserves complete wire ordering/body identity without inventing a clock value. Exact source start timing needs a future native timestamp seam and is not claimed here. Tool execution-end results preserve optional `structuredContent`, including explicit JSON null and raw opaque values; model-facing durable tool-result messages intentionally exclude that field. Runtime-only terminate/failure fields are excluded from the execution result.

Queued work normally drains through the existing Agent loop. A message queued late by an `agent_end` observer can require a new actual `ContinueAsync` generation before one session-level `agent_settled`. Automatic continuation is bounded and checks abort/shutdown intent. The actual pinned `_runAgentPrompt` and `_handlePostAgentRun` suppress further continuation after `_agentRunAbortRequested`; pending text remains available for later prompts or `clear_queue`. This source behavior explains the RPC documentation's ambiguous statement that abort "continues queued messages": abort never clears them, but this slice does not start a new generation after run-level abort or EOF. A prompt submitted during the short post-run settlement boundary fails until `agent_settled`; it cannot overlap a still-owned cleanup generation.

All protocol output uses the same transferred `JsonlWriter` wrapper and an awaited publication gate. The gate has no background output queue: waiting records are bounded by admitted commands plus one sequential Agent observer/settlement. Cumulative composed UTF-8 output is charged by a bounded buffer writer; backing storage is limited to `MaximumOutputBytes` plus a fixed 4,096-byte writer reservation, with committed bytes checked before wire output. Message and entry arrays are traversed directly, and generated-only event slicing creates no additional history array. Oversized read replies return bounded failures before any record write; prospective queue receipts and prompt acceptance responses are budgeted before queue/run effects. Inputs/models/output still require temporary per-value JSON ownership; these logical caps do not claim a total heap bound or constrain data owned by a caller before submission.

Defaults: eight admitted concurrent commands, 1 MiB command/output/model-definition bytes, JSON depth 32, ID length 256, command-type length 128, prompt text length 65,536, sixteen images, 128 models, 1,024 returned messages, 4,096 returned entries, sixteen extra continuation runs and 128 pending tool-message starts. Direct excess `SubmitAsync` calls fail before admission; the input loop backpressures at capacity and retains at most one extra pulled admission. Definitions are charged cumulatively. Native reader UTF-8/Unicode/duplicate/depth/frame failures remain terminal hardening. Images are carried unchanged to an explicitly supporting transport; image resizing/input interception/template/skill expansion and Responses image projection are unfinished, with no capability claim inferred from metadata.

Shutdown closes admission, stops input, joins the short submission transition before aborting the actual generation, awaits admitted command/run/provider/storage work and authoritative output, then releases subscriptions and disposes owned session/output. The dispatcher owns its output wrapper; the wrapper's stream-ownership setting decides whether stdout itself remains borrowed. `Owned` session is appropriate for subprocess EOF; explicit `Borrowed` embedding still aborts/joins submitted work but leaves the coordinator lifetime to the host. Repeated concurrent disposal shares one task. A callback output failure initiates internal cleanup without awaiting its own event callback, and public callback self-waits/disposal reject before changing state. Supplied streams/work must cooperate with cancellation or complete; backpressure is awaited rather than bypassed or dropped.

`RpcSessionDispatcherTests.Cases()` exposes four authored groups against actual durable sessions, injected fake transports/tools and real local-file checkpoint wrappers: asynchronous acceptance/reads/raw output/generated-only events/accepted failures; real queues/modes/abort retention/clear/late continuation; gated input/assistant/tool durability and structured result presence; malformed recovery, ID/null grammar, unfinished inventory, prewire cumulative budgets, bounded slow output, callback broken output and shared awaited owned cleanup. Root registers/runs them. This source freeze changes no reference fixture or oracle and makes no native execution or unchanged-source RPC differential claim.

Existing-session switch now has a bounded native generation-checked implementation described in [native replacement](native-session-replacement.md), with an additive `session_switched` event and fresh command context. The prior evidence above does not independently qualify that addition. Remaining mandatory command/workflow dependencies include new/fork/clone replacement, tree/fork-message/name/stats/export operations, full model/thinking workflows, compaction/auto-compaction/retry, direct bash/progress, wider commands/resources/input handlers/extensions, dialogs and rich UI capability negotiation. Their absence is an explicit implementation dependency, not a waiver of P5 acceptance.
