# CLI-owned Windows pipe input cancellation

This correction addresses Astra R3 on immutable candidate `b062defb82dc553b6ce51230072688ca59fbfe28`. The private hidden-console reproduction delivered an actual CTRL_C_EVENT to exactly the owned helper and compiled CLI. Its cancellation token was canceled, but the framework standard-input pipe read remained pending until an unrelated frame arrived. No-wake cancellation failed; that evidence remains sealed under task-3. This change has not yet been built or executed by the authoring lane.

`Program` uses `CancellableStandardInput.Open()` for RPC input and awaits its disposal after the borrowed public `RpcSessionCommand.RunAsync` host settles. Windows pipe input uses a noninheritable `DuplicateHandle` of `GetStdHandle(STD_INPUT_HANDLE)`. The CLI closes only its duplicate, never the original standard handle. No standard handle, console mode, pipe mode, process error mode, control-handler setting, global signal, or user-console attachment is changed. Factory failures produce fixed `StandardInputUnavailable` JSON on stderr. An owned-input disposal failure prevents a successful exit and produces fixed `RpcHostFailed` JSON. The host's caller-cancellation catch, protocol abort/EOF behavior, durable writer cleanup, and borrowed-stream contract are unchanged.

The supported profile is a readable synchronous Windows named/anonymous pipe with this stream as its sole read consumer. `DuplicateSynchronousPipe(SafeHandle)` also permits trusted hosts/tests to supply that explicit profile. A synchronous readable handle is a caller precondition: this method checks pipe type and duplication, but does not detect overlapped mode or certify arbitrary asynchronous handles. `Open()` selects the native path for inherited Windows pipe handles; its supported target is the synchronous pipe used by the R3 helper/framework child profile. Differently configured inherited handles remain unqualified. Duplication grants no authority. It protects source-handle lifetime during duplication and does not take source ownership. Concurrent calls to read the same wrapper are rejected. Other readers using the original or another duplicate are outside this contract: they could consume bytes between inspection and read. Microsoft warns that [PeekNamedPipe](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-peeknamedpipe) can block on a synchronous handle with competing I/O. The CLI creates no competing pipe read.

One read inspects available bytes and reads at most the minimum of that count, caller buffer size, and 8 KiB. It never issues a synchronous read against an empty live pipe. Empty-pipe waiting uses `Task.Delay(10, linkedToken)` and rechecks caller/disposal cancellation on each iteration. There is no detached `ReadAsync`, abandoned `WaitAsync`, or background blocked read. This polling interval is a native host choice, not upstream timing parity. Data is returned as original bytes without Unicode decoding, NUL stripping, newline conversion, or JSON processing; existing JSONL framing remains authoritative.

Broken/disconnected/closing-pipe errors return EOF. Buffered bytes are consumed before EOF. A message-mode partial read accepts the byte count returned with `ERROR_MORE_DATA`; it preserves remaining bytes for later reads. Other native input failures use a fixed IOException without path, payload, native error number, or inner exception. Cancellation before consumption throws with the actual caller token. Bytes already consumed are returned if cancellation occurs during the bounded native call; the next read observes cancellation. An empty destination returns zero after normal admission/token checks.

Disposal has one shared completion. It closes admission, cancels internal polling outside the coordination lock, awaits active read settlement, then closes the duplicate and releases cancellation resources. Disposal-triggered pending reads throw ObjectDisposedException; caller cancellation takes precedence when both tokens are canceled. Synchronous Dispose joins the same completion as DisposeAsync. Read callbacks/user delegates are not part of this stream.

Microsoft documents shared-object duplicate ownership in [DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle), synchronous reads, pipe EOF and partial messages in [ReadFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile). This implementation does not claim arbitrary OS/filesystem calls are interruptible. Windows interactive character devices, ConPTY, legacy input configurations, asynchronous pipe handles, non-Windows standard input, keyboard Ctrl-C behavior, and full native CLI/platform parity remain required unfinished qualification. `Open()` preserves framework input for nonpipe/non-Windows profiles; it does not silently claim cancellation support for them.

`StandardInputCancellationTests.Cases()` provides five authored actual-pipe groups: empty-live-pipe cancellation before any frame/EOF and later reuse; competing-read rejection/shared concurrent disposal/original endpoint survival; bounded raw Unicode/NUL chunks plus buffered EOF; actual message partial reads; invalid/disposed handle diagnostics. Root must register these cases. The original sealed private-console no-wake helper remains the compiled-CLI signal regression and must be run against the corrected candidate in a separate owned task-2 copy. Existing compiled RPC abort/active EOF/output failure/durable-prefix/lease tests must remain passing. Authoring adds no production test switch, build, package, or signal operation, and claims no passed gate or R3 closure.
