## Resulting behavior

Pinned Pi merges `event.toolCall` into the existing block on `toolcall_end` with `Object.assign`, making the final ID, name, arguments and extra properties authoritative. The native mapper now merges into a detached candidate, admits its JSON and type, then validates the complete final call with its reducer before replacing its source partial. It preserves started/delta/end/done progress order and immutable earlier owned snapshots. Arguments remain a strict complete object; empty identities, duplicate final IDs, wrong content type/index, repeated ends and configured bounds remain rejected.

`AssistantStreamReducer` has an explicit `allowPiMessagesIdentityReplacement` opt-in, default false. Opt-in construction requires Pi Messages fallback API, and identity replacement also requires Pi Messages start API. The mapper and outer `ChatRun` opt in for that API. Default reducers and every other API preserve started ID/name equality. Final identity/argument validation, duplicate detection, live block validation, bounds and successful terminal content agreement still apply.

`ToolCallEnded` already contains the complete final `ToolCallContent`; its contract documentation now describes Pi replacement and the absence of execution authority in progress. Its CLR event shape, native PiWireJson codec and source projection shape remain unchanged. Existing serialization carries the full final identity and unknown tool fields without an added native flag. Authored controls replay native serialized ends through an opted-in reducer and verify final source emission snapshots.

## Execution authority and joins

Neither mapper nor reducer invokes tools. Existing Agent/TurnRunner obtains the successfully settled assistant, joins chat disposal, and schedules that final call. The existing ToolInvoker requires `toolUse`, membership of the same call in the finalized message, valid final identity/arguments, registered and exposed final tool name, preparation and validation, transforms, final revalidation and final-action policy before execution. No Agent/SDK production change is required.

The outer Pi `ChatRun` revokes a tool-use or completed-call-bearing terminal if its owned iterator cleanup fails, and revokes successful terminals if cancellation arrives during the final join. Completed calls with `stop` can reach direct `IToolExecutor` implementations; the prepared `ToolInvoker` path's additional `toolUse` requirement does not protect those executors. A native error/abort with empty tool content replaces that executable success; primary failure and cleanup diagnostics remain separate. Ordinary text-only `stop`/`length` terminals retain their outcome and report a postterminal iterator release failure through the secondary cleanup diagnostic. Existing error/abort terminals retain their primary failure on cleanup faults. Real Pi Messages HTTP cleanup completes before terminal publication and still reports cleanup failure as a primary error. Other API settlement behavior is unchanged.

## Authored controls and retained criteria

Seven separately reported control groups cover ID-only/name-only/both replacement and unchanged identity; native codec/source projection and immutable progress; default/other API admission; malformed identity/arguments/JSON, duplicate IDs against active and ended blocks, mismatched type/index, repeated ends and payload/content/slot limits; actual Agent prepared-action success and schema/exposure/policy denial; partial cancellation before and after end plus cleanup-time cancellation/failure; malformed actual SSE with zero authority; and outer iterator joins after a mapped successful tool terminal.

Agent schedules use actual Pi POST/SSE handling through an inert local handler with one-byte body reads. Held cleanup must finish before any tool prepare/policy/effect occurs. The successful case verifies final ID/name and exact final arguments, twice-validated transformed action, identical policy/execution action instance, and final tool-result transcript identity. Failure/cancellation cases verify no preparation, policy or execution. Separate direct ToolInvoker checks reject pending/error/aborted provisional messages.

The frozen `authored-cases-r2.json`, dependency file, both SHA constants, original domainGap marker, and original 12db report/outcome files are retained byte-for-byte. The historical `PM-TOOL-IDENTITY-REPLACEMENT` row encodes the predecessor native rejection expectation; the implemented successor changes that behavior. Its original comparison therefore remains a predecessor limitation check and is not rewritten into a passing fixture. Fresh successor control receipts plus independent review and a separately admitted criterion/expectation successor are required before qualification closure. `PM-NATIVE-TOOL-CONTINUATION/3` and all original source/phase gates remain OPEN; these authored orchestration controls do not retroactively complete them.
