# Pure Anthropic Messages request projection

PiSharp.AI.Protocols.AnthropicMessages.AnthropicMessagesRequestProjector produces an actual complete owned request body for the selected static-tool/native-system-message/native-tool-change Anthropic Messages profiles. It consumes ChatRequest's canonical owned wire transcript and explicit AnthropicMessagesRequestOptions. It has no network, credential lookup, OAuth grant, clock, ID callback, provider execution, filesystem or extension authority. This is a portion of [P2-02/P2-06](../plans/02-provider-layer.md); it does not close provider, numeric-format, transport or phase acceptance.

Behavior is derived from the unchanged complete public [anthropic-messages.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/anthropic-messages.ts), [transform-messages.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/transform-messages.ts), [transcript.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/utils/transcript.ts), [text.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/utils/text.ts), [constrained-sampling.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/constrained-sampling.ts), [sanitize-unicode.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/utils/sanitize-unicode.ts) and [types.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/types.ts), pinned to public Pi v0.99.1 SHA d86654abb8862e201933517d6f1fce9f88dd117f. Tests are authored native source-informed scenarios. No unchanged whole-SDK helper capture or independent request oracle execution is claimed.

The API is:

    new AnthropicMessagesRequestProjector(options).Project(chatRequest, cancellationToken)

MaximumTokens is an explicit positive Int32 authoring parameter. Options explicitly supply model reasoning/image support, thinking enabled/off/adaptive/budget/display/effort controls, temperature capability, empty-thinking-signature compatibility, cache retention/long-cache/tool-cache capabilities, eager/strict tools, key versus OAuth body projection, mid-conversation system/tool-change support, permitted fallback model declarations, resolved configured beta tokens, tool choice and user ID. No catalog, environment default, API key inspection or implied provider capability is consulted. Default cache retention is Short, matching the source when no environment override applies; callers resolve any environment/catalog profile outside this pure helper.

The request includes model, messages, max_tokens and stream true. Optional system, tools, betas, temperature, thinking, output_config, metadata, tool_choice and fallbacks are emitted only under their selected source conditions. The result is JsonData owned independently of all intermediate mutable JSON builders. Canonical entry bodies, timestamps, argument tokens, signatures, namespace metadata and unknown fields stay unchanged.

Default system handling replays every system entry into the current leading prompt and static tool state. Nonempty content text is appended with two line breaks. Section updates set/replace/remove by name; null removes a section. Section values and text retain exact whitespace. Integer-index section keys follow ECMAScript enumeration order; other keys retain first insertion order, with removal/readdition moving a key. Tool removals precede additions in each system record. Redefinition keeps current insertion position, while removal/readdition moves a name to the end. The complete current tool list is projected even when declarations changed later in the transcript.

With SupportsMidConversationSystemMessages true, only an actual leading system record supplies the top-level system prompt. Later system text/section changes use the pinned update/removal framing and are held until immediately before the next retained assistant or transcript end. They do not interrupt tool/result accounting. With SupportsMidConversationToolChanges true as well, a nonempty leading toolsAdded array and no changed same-name declaration enable native tool changes. Initial tools stay active; their last declaration carries the tool cache breakpoint. The exact source deferred placeholder follows them, and every later uniquely named declaration is retained with defer_loading true, including removed tools. Later system records emit text followed by tool_removal references and tool_addition references, with OAuth canonical names when selected. These updates share the existing delayed system-message placement, preserving immediate tool/result adjacency. A missing capability, missing initial anchor or changed declaration falls back to the complete current static tool list without native references or automatic tool-change beta. See [candidate evidence](anthropic-native-tool-changes.md).

User string content is skipped only when empty under the explicit ECMAScript trim character set. User text-array blocks are likewise filtered for empty text; supported image blocks become base64 image source objects with media_type and data. Image media types are jpeg/png/gif/webp. Base64 strings are forwarded as strings without claiming image decoding or content certification. The ModelSupportsImages false profile replaces consecutive images with the exact source user/tool placeholder, coalescing adjacent images and existing equal placeholders.

Assistant input is admitted through the shared PiWireJson typed contract. Pending/deferred input is rejected; source Error/Aborted turns are skipped. Same-model identity requires API, provider and requested model ID all to match. Same-model signed thinking is retained even when its text is empty; redacted thinking becomes redacted_thinking with opaque data. Unsigned nonempty thinking becomes plain text unless the empty-signature compatibility profile preserves a thinking block with signature empty. Cross-model nonempty thinking becomes text, empty thinking is removed and redacted thinking is removed. Opaque reasoning signatures never cross model identity.

Assistant tool blocks become tool_use with ID, name and object input. Cross-model IDs replace each non-ASCII-letter/digit/underscore/hyphen UTF-16 code unit with underscore and truncate to 64 code units, matching the pinned normalizer. Associated real tool results receive the same mapping. Same-model IDs are retained. The canonical namespace/thoughtSignature and other metadata stay owned in the input; the Anthropic source's wire tool_use shape contains only ID/name/input, so these unsupported wire fields are not invented. This helper does not authorize namespaced execution or prove a cross-provider execution round trip.

Consecutive real and synthetic tool results are grouped into one user message. Text-only results join blocks with a line break, preserving empty strings; mixed results use text/image arrays. Image-only results gain the exact "(see attached image)" text. Missing results are projected as source "No result provided" with is_error true before the next assistant/user or transcript end. System messages are transparent to this accounting. No synthetic canonical transcript record or timestamp is authored: the source synthetic timestamp is not observable in final request JSON. Unmatched/duplicate real results and globally duplicate/colliding emitted call IDs fail explicitly instead of sending ambiguous links; those are native structural hardening differences from the permissive helper.

Static tools follow convertTools. Legacy input_schema contains type object, properties and required defaults; unrelated root schema fields are omitted as in the source. Grammar constrained-sampling declarations fall back to ordinary Anthropic JSON tool schemas. JSON-schema strict prefer/require obey the supplied capability: the pinned supported strict subset closes object properties, requires all properties and makes previously optional values nullable. Root metadata is retained for successful strict schemas. Unsupported strict schemas fall back for prefer and fail for require. OAuth canonical tool names that collide fail IdentityCollision. Tool declarations never carry delegates, CLR type tags or executable objects.

OAuthProjection inserts the exact public Claude Code identity system text and applies the pinned canonical casing table to declared/called tool names. It projects body behavior only, without authenticating or transmitting an OAuth token. Automatic betas include OAuth, legacy fine-grained tool input, interleaved budget thinking, permitted server fallback and eligible native tool-change features under their source conditions. A default BetaFeatures array requests automatic selection; an initialized array supplies already-resolved configured tokens, trimmed/deduplicated in first order, and an empty array suppresses betas.

Cache retention None omits cache_control. Short uses ephemeral; Long adds ttl 1h only if compatible. Cache control is attached to top-level system blocks, the last compatible conversation user/system block and the last current tool when supported, or the last initial active tool for native tool changes. Deferred declarations and the placeholder do not acquire tool cache breakpoints; final tool addition/removal conversation blocks can acquire message cache control as in the source. Budget thinking uses an explicit positive budget or source default 1024 for zero; adaptive thinking uses selected display and optional effort. Off thinking emits disabled only when compatible. Thinking enabled suppresses temperature. String tool choices auto/any/none become objects; explicit forced-tool objects are retained as owned JSON. Metadata forwards only selected user_id. Permitted fallback declarations emit fallbacks model objects and the associated automatic beta; this does not qualify returned fallback stream pricing.

Forwarded argument/schema/tool-choice numbers are converted to finite IEEE-754 values before emission, matching the source's JavaScript numeric value boundary. Native shortest round-trip formatting uses .NET's invariant representation with the source fixed/exponent thresholds: negative zero becomes 0, 1.0 becomes 1, 1e-6 stays fixed, 1e-7 is exponential, 1e20 stays fixed, 1e21 becomes 1e+21 and 9007199254740993 rounds to 9007199254740992. Original canonical raw numbers remain untouched. Exhaustive ECMAScript shortest-digit/tie behavior is not independently qualified and remains a required oracle gate. Nonfinite overflow fails UnsupportedNumber; the source's JSON serialization can turn nonfinite numbers into null, which is an explicit native hardening difference.

Inputs are strictly reparsed, including caller JsonData cloned from permissively parsed JsonElements. Duplicate properties, trailing commas, comments, invalid typed content and unsupported shapes fail with fixed payload-free diagnostics. Decoded Unicode must be valid UTF-16. The source sanitizes unpaired surrogate text; rejecting it while retaining original caller data is explicit native hardening. Supported text uses the full explicit ECMAScript trim set, including U+FEFF and excluding U+0085.

Bounds cover message count, per-entry and total raw UTF-16 input characters, original/projected content blocks, tool declarations/current active tools, projected message count, JSON depth, final serialized UTF-16 characters and UTF-8 bytes. The aggregate input allowance includes model/provider strings, selected user ID, configured beta/fallback tokens and tool-choice raw JSON alongside transcript bodies. Retained projected message/tool/result payloads are charged before they are added; final root framing, cache and option fields are checked before an owned result is returned. Arrays and opaque source fields remain covered by raw input/depth limits. These are logical data bounds, not a total heap cap; callers already own their input strings and JsonData.

Cancellation is checked before work, throughout admission, conversion, strict schema traversal and publication. Failure or cancellation publishes no partial request and changes no canonical input. AnthropicRequestException exposes a fixed AnthropicRequestFailure code with no rejected payload, tool name, schema, ID, credential or inner exception.

Eight authored groups cover complete static payloads; ordered section/tool updates and native system framing; same/cross-model reasoning and signatures; real/synthetic grouped results and ID guards; image replay/downgrade controls; OAuth body projection/cache/thinking/beta choices; strict schemas and numeric projection; and inclusive UTF-8/UTF-16 bounds, ownership, strict syntax and cancellation. Root owns registration, isolated testing and independent review.

Managed mid-conversation effort/binding controls, endpoint/auth/catalog/environment resolution, metadata compatibility selection, request retries, HTTP/SSE integration, complete numeric-format differential qualification and live/whole-helper validation remain required. Request fallback declarations and OAuth body identity do not imply corresponding stream/auth acceptance. No phase gate or complete provider acceptance is claimed.
