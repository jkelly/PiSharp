# Anthropic owned emission snapshots

`AnthropicMessagesOptions.CaptureSourceEmissionSnapshots` defaults to false. When enabled, the DTO mapper places an owned **whole source event object** on `StreamEvent.SourceEmissionSnapshot`. The emitted compact event and its payload remain unchanged. This format is specific to this mapper; other providers' sidecar formats are not interchangeable.

The source basis is Pi d86654 `packages/ai/src/api/anthropic-messages.ts`: `message_start` updates response identity and usage; content starts retain wire `index`; tool deltas accumulate `partialJson` and call `parseStreamingJson`; signature deltas mutate state without a push; content stops remove scratch properties before pushing. The helper observes the mapper after each DTO (each emits at most one progress frame), copies current usage/properties/signatures, and uses the existing source-derived bounded `StreamingJsonPreview` for display arguments. An initial nonempty tool input survives until the first delta, including an empty delta. End arguments still come exclusively from unchanged strict final parsing.

Source starts are projected from their actual captured slot, including source scratch metadata, to satisfy the explicit writer's consistency checks. These temporary source-shaped start values never replace native emitted frames. Snapshots own their JSON and cannot acquire later mutations. Terminal snapshots describe the actual sanitized native terminal; HTTP hook-generated replacement terminals may have no snapshot. They must be encoded separately from the finalized terminal if a caller needs a source-shaped observation.

Unsupported bounded preview (including nonobject arguments) or source-shape admission leaves `SourceEmissionSnapshot` null. This absence is a visible coverage failure, not a fabricated empty partial, compact-wire fallback, or new native failure. Future differential captures must record presence per event and fail their source-coverage assertion when absent. Unrecoverable process failures are not swallowed.

No HTTP callbacks, cancellation checks, awaits, disposal, diagnostic redaction, native tool execution authority, or default compact route are changed. Captured JSON adds memory/serialization work when opted in; downstream reducers already charge sidecar size against their own limits. Qualification should use the direct transport emission boundary and explicit budgets, not assume that enabling observations is resource-free.

The original three authored regression groups exercise owned usage/timestamp/identity/signature snapshots, scratch lifetime and partial tool JSON, unchanged compact payloads, and explicit unsupported-preview absence with unchanged strict failure. At that initial source freeze no compiler or native test had run.

This is not a complete original-provider projection: source costs use binary64 projection while native costs remain decimal; unknown native DTO metadata retention and sanitized errors remain native behavior; strict final-tool parsing, cancellation timing and immutable alias semantics remain intentional boundaries. The separately reviewed internal binary64 helper is composed only after ordinary source-event serialization, replacing the owned JSON cost node. No native UsageCost or SourceBinary64Cost is changed. Caller-selected fallback rates remain the existing native selection; absent rates remain zero and model price tiers are not newly resolved. The later isolated capture opts in and records the sidecar separately from compact wire; coverage and remaining comparisons are scoped in the evidence summary. Other callers are not thereby migrated.

The capture switch is an init-only property, outside the original twelve-parameter options primary constructor and Deconstruct. A fourth authored reflection/construction group checks that shape and default-false opt-in. No binary compatibility execution has been performed.

A fifth authored end-to-end group retains the 36-token source golden and exact native decimal checks, but that vector does not distinguish the arithmetic: at input rate 1, both `(1 / 1000000) * 36` and the JSON number `0.000036` have bits `3f02dfd694ccab3f`.
