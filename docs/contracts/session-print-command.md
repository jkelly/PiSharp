# Durable session final-text print command

The native `session prompt` and `session resume` commands accept `--output print`. They still use the actual selected offline Responses or Anthropic HTTP/SSE profile, prepared-action policy, registered tools, Agent loop and PersistentAgentSession durable append pipeline. This is a usable final-output option on explicit-path commands, not a replacement provider, memory-only session or progress scaffold.

Omitting `--output` preserves the existing single JSONL settlement report. `--output report` explicitly selects that same report. Both values are accepted only for prompt/resume; create, inspect and tree reject any output option before durable acquisition. Unknown values, case variants, missing values and duplicate options fail with the existing fixed InvalidArguments diagnostic. Command routes, credentials, profiles, tool authority, session format, import/repair behavior and permanent configuration remain unchanged. The process entrypoint supplies an explicit UTF-8 writer for one-shot stdout; RPC retains its existing binary shared-writer path.

Example, with all paths explicitly supplied:

    PiSharp.Cli session prompt --session <absolute JSONL> --workspace <existing absolute directory> \
      --offline-script <absolute authored JSON> --message <text> --output print
    PiSharp.Cli session resume --session <absolute JSONL> --workspace <existing absolute directory> \
      --offline-api anthropic-messages --offline-script <absolute authored JSON> --message <text> --output print \
      --leaf <existing selected ancestor>

Existing explicit file/Bash authorizations remain opt-in with their unchanged mandatory final-action policy. Print does not add tool permission. The shell line continuation above is illustrative; use the host shell's ordinary argument syntax.

## Source-informed projection

The complete pinned public [print-mode.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/print-mode.ts), [output-guard.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/output-guard.ts), [CLI argument parser](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/cli/args.ts), [json-event.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/json-event.ts) and [JSON mode documentation](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/docs/json.md) were read at public Pi v0.99.1 SHA `d86654abb8862e201933517d6f1fce9f88dd117f`. This candidate contains native authored fixtures, not unchanged upstream print execution or a qualified whole-CLI differential capture.

Print uses the final actual committed Agent message, not a backward search for an earlier assistant. When that message is a successful finalized assistant, it writes each text block in content order followed by one literal LF. Empty text blocks produce LF. Existing CR/LF and trailing LF remain untouched, so a text block already ending in LF produces an additional LF. Thinking and tool-call blocks are omitted. A non-assistant tail produces no text. Pending and deferred assistants cannot be presented as completed print output.

Well-formed Unicode, CR, tab, U+2028/U+2029 and ordinary text NUL bytes are preserved. No BOM, JSON report, event record, header, color sequence or explanatory prefix is authored onto print stdout. Provider-authored text is not trimmed or control-stripped; this raw final-text profile follows the pinned projection and does not claim terminal-control sanitization. Cross-platform process verification and genuine source byte qualification remain required.

An Error or Aborted final assistant emits no text, including any known partial text. Print writes a fixed LF JSON diagnostic to stderr and returns 1, with ProviderFailed or Canceled respectively. Actual provider exception text, rejected script values and output-writer messages are not copied into that diagnostic. Known provider data remains in the durable transcript according to the existing provider/coordinator contract.

The native command's existing nonzero status for completed tool errors, exhausted scripts or a non-completed loop is retained. If a final successful assistant follows an earlier tool error, print emits its text, returns 1 and emits a fixed CompletedWithErrors diagnostic. The upstream print function checks only the final assistant reason and may return zero for that same earlier tool failure; this existing native command exit difference is disclosed, not called source parity. Default/explicit report behavior remains unchanged.

## Durable and output barriers

Print begins only after PromptAsync and WaitForIdleAsync settle, the owned PersistentAgentSession writer/coordinator have been disposed, the offline profile has been closed, and physical file length equals the acknowledged committed byte length with no session fault. Selected-leaf ancestry and append parenting use the existing registry-backed coordinator. Prior physical session/script/source bytes are preserved; no sibling history is flattened or repaired.

`SessionPrintOutput.WriteAsync(TextWriter, TranscriptEntry?)` implements the small reusable final-message projection. The caller owns durable admission and settlement. The writer is borrowed. Every WriteAsync and the final FlushAsync are awaited; a held writer keeps command completion pending. The output stage does not use the cancelled work token to skip the final delivery/flush after owned settlement. There is no retry on a broken writer, no background output task, and no success return after write/flush failure. A writer may already have accepted a prefix before a later failure, and prior tool effects or durable records may already be complete; the fixed CommandFailed diagnostic explicitly retains effectsMayHaveCompleted.

The complete final text is preflighted before any text prefix is written: at most 1048576 UTF-16 characters and 1048576 strict UTF-8 bytes, including one added LF per text block. The byte ceiling is a deliberate native output limit; there is no implicit truncation or newline/Unicode substitution. Oversize text returns the existing ResourceLimit failure after owned durable cleanup. Borrowed custom writers must settle their own WriteAsync/FlushAsync operations; this adapter cannot detach an indefinitely blocked writer. Stderr is also borrowed; an unusable stderr propagates failure rather than fabricating a successful diagnostic.

`Utf8StreamTextWriter` encodes complete string/memory writes with strict UTF-8 and no BOM, then directly awaits `Console.OpenStandardOutput()` writes and flushes. It does not use Console.Out, set Console.OutputEncoding, change the Windows console code page or alter global encoding state. Its stream is borrowed. It has no text buffer, and both synchronous and asynchronous disposal only close writer admission: they do not flush, retry or dispose stdout. Actual stream write/flush failure poisons later writer operations; already accepted bytes remain known partial output. Callers must await and serialize their operations; concurrent operations are rejected, and disposal does not detach or cancel an already admitted stream operation. Each encoding allocation is bounded by the configured per-write UTF-8 ceiling (default 8388608 bytes for the existing one-shot report commands); print's stricter whole-output preflight still applies. Unpaired UTF-16 is rejected before stream delivery, rather than replaced. A surrogate pair must be contained in a complete write; the adapter does not join split UTF-16 writes through a hidden buffer.
