# Session behavior adapter custody

This leaf supplies four adapters: a callback on the actual returned session context, compaction completion/error callbacks, native thinking configuration, and signal-only abort. It does not yet expose them from the registered facade. Root must bind each originating command's actual invocation validator and enroll the stable `ExtensionSessionBehaviorOperationOwner.CloseAsync` once in that command's existing settlement. Calling the kernel with an arbitrary validator does not constitute native admission.

The kernel retains each exact supplier task and callback `ValueTask.AsTask()` original before awaiting it. Closing fences admission and joins all admitted composites, including ignored public returns. Evidence caches the original Task, its aggregate and direct await error; faulted OCE originals remain faults. Callback and synchronous cancellation-registration self-waits fail before returning settlement. Abort's thread-bound marker covers normal Register and UnsafeRegister callbacks irrespective of ExecutionContext flow.

`WithSessionAsync` takes the existing replacement original and the actual fresh broker context mapper. Root must use the real returned command context and its fresh operation token, never reconstruct an old snapshot. `CompactAsync` accepts the actual engine original with a completed-result reader; completion runs only for an acknowledged non-null result, error callbacks receive the original direct error, and both engine/callback failures survive settlement.

The CLI host captures the exact attached owner through the existing read host, checks generation and session identity, then returns the existing ConfigureAsync original or signals the actual captured session Abort. Thinking uses the pinned Pi upward-first model-supported clamp. ConfigureAsync requires command-idle state; active-session parity and default settings persistence are not claimed. Compaction requires an explicitly captured existing typed checkpoint supplier; no provider is acquired by this leaf.

Eleven control groups are authored, unregistered and UNEXECUTED: ten synthetic custody controls and one real registered command/native thinking-clamp and abort control. They cover separately held replacement/callback and compaction/callback originals, reference-distinct failures, external Register/UnsafeRegister self-wait, faulted/synchronous OCE, and exact configuration task/admission. Nested A→B→A controls reject Close and Dispose for either ancestor, retain separately held originals, and preserve stable external settlement/fault identity. Each immutable frame captures both logical and same-thread physical ancestry; Close traverses both reference graphs with a visited set. Mixed logical→physical and physical→logical controls retain outer owners after await and across externally registered cancellation handlers. A finally custody collector releases every held task, closes every kernel, joins every captured original and native create/activate/invoke/cleanup task, caches full aggregate/direct evidence, and preserves unexpected faults alongside assertions. The actual registered control is also unexecuted; no registered-host qualification is claimed. Root must separately add actual facade/engine integration controls when composing the hooks.

The cancellation guarantee applies to cancellation initiated through the admitted `Abort` scope. Arbitrary user CTS.Cancel calls outside that scope can invoke frame-free Register handlers with neither logical nor physical ancestry; this leaf does not detect those unrelated calls and grants no universal cancellation-hook guarantee.

Fixture-only successor: observing `Error(task)` records terminal raw evidence without acknowledging it. Acknowledgements are keyed by the exact Task reference and occur only after full cached graph/status predicates; canceled originals additionally require the exact token. Unacknowledged faults retain the entire original aggregate, including unknown empty aggregates, alongside the primary assertion. Three negative subcontrols prove that one acknowledged cancellation cannot hide a sibling, an empty aggregate survives the failure carrier, and a callback fault before a gate still reaches finally release/join. The eleven group roster is unchanged. Nested negative evidence is retained only after its originals have joined and the carrier's full graph has been checked.

Held entry gates race their actual operation terminals and a ten-second diagnostic Task. The timer is canceled and joined by its own finally; the operation originals remain owned by the outer finally collector and are never abandoned or replaced with canceled timeout wrappers. Diagnostic failure is an assertion followed by release/join, rather than evidence of original settlement. These controls remain UNEXECUTED.

Empty-aggregate production successor: settlement treats an AggregateException with zero children as its own unknown original fault leaf. Only nonempty aggregates are flattened. A subcontrol in the existing fault-status group checks the actual faulted supplier Task, mapped Task, stable close and settlement original, requiring the exact empty exception reference and full cached aggregate/direct evidence. It is UNEXECUTED; the eleven group roster remains unchanged.

Exact-graph fixture successor: acknowledgements compare every nonaggregate node by reference and traverse its actual InnerException. Generic wrappers are never transparent; nonempty aggregate containers alone are traversed without becoming an expected leaf. The owned faulted-OCE envelope and synchronous-OCE carrier must pass exact original-task or type/message/inner-reference predicates before their own node is acknowledged. A fourth negative subcontrol proves that an unrelated InvalidOperationException over an expected OCE is refused and survives the full failure carrier. Accepted production kernel bytes remain unchanged by this fixture-only successor.

Five original API rows need externally owned seams: immutable getSystemPromptOptions construction data; reservation-scoped newSession.setup writing; atomic navigateTree summary/options ownership; post-origin shutdown handoff; and post-origin reload handoff. Existing engines remain authoritative. Task7 thinking/settings getters and R594 typed settings publication are reserved. Core, Agent, Sessions, terminal and shared runner files are unchanged.
