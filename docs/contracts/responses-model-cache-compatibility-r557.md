# Responses model cache compatibility (R557)

The existing `NativeProviderFactory.CreateResponses(..., modelMetadata)` path now reads `compat.supportsLongCacheRetention` and `compat.supportsExplicitPromptCacheMode` from the full caller-supplied model. This follows Pi v0.99.1 [getCompat and cache helpers](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-responses.ts). Previously only thinking metadata was consumed, so model-level cache restrictions did not affect actual native HTTP requests.

When metadata is supplied, its flags are authoritative. Missing or null flags use original defaults: long retention supported and explicit mode disabled. Metadata-free calls retain the existing caller's explicit compatibility profile. Request retention preference, session identity, captured environment, limits and other options remain owned and preserved by immutable copies. Both direct transport and per-request thinking transport use the same resolved profile. Existing metadata identity/reasoning/context admission completes before the client is bound.

Native metadata requires boolean flag values. Strings, numbers, arrays and objects fail with a fixed `ArgumentException` before HTTP acquisition; arbitrary JavaScript truthiness is outside this typed boundary. Other model compatibility capabilities, host/CLI preference forwarding, ChatGPT sign-in suppression and full provider/SDK parity remain open.

Four authored, uncompiled and unexecuted test families cover the retention/flag matrix with deliberately conflicting direct flags, reasoning and nonreasoning direct/off/high requests, absent/null metadata defaults, metadata-free profiles, null request options, malformed typed flags, identity/reasoning mismatch, captured environment and pre-cancel. The existing owned cache runner captures original task status and full fault graphs for the new prefix. This isolated successor does not change the frozen f229 combined candidate or establish new runtime/package acceptance.
