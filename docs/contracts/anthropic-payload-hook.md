# Anthropic awaited payload callback

The original authored slice followed Pi d86654 `types.ts` onPayload and `api/anthropic-messages.ts` ordering: build parameters, await payload callback, retain unchanged payload on no replacement, force `stream:true` on replacement, then send and invoke response/provider callbacks. It preserves native immutable JSON, bounded admission and sanitized failures rather than emulating arbitrary JavaScript object spreading or in-place mutation.

`AnthropicMessagesHooks.OnPayload` is an init-only `Func<JsonData, ModelDescriptor, CancellationToken, Task<JsonData?>>`. It does not change the existing hooks constructor/deconstruction signature. Null return keeps the owned payload; `JsonData.Null` is an invalid replacement. Replacement must be an owned JSON object. The original callback Task is directly registered and awaited; faulted OCE remains a faulted original, canceled Tasks remain canceled, and synchronous OCE retains the existing invocation wrapper and original cause without fabricating a Task. Cancellation does not abandon a pending callback. Native cancellation policy still determines the sanitized terminal after the join.

Use `AnthropicMessagesHttpSseTransport.FromPrepared(client, (request, token) => factory.Prepare(request, explicitKey, token), hooks: hooks)` for a key factory, or `authenticatedFactory.Prepare` for an already injected authenticated factory. The prepared owner exposes an owned payload, but only that payload reaches the hook. No request, response, auth binding or secret is given to the callback. Preparation claims once before invoking the callback, including replay/concurrent-use refusal. HTTP request/content allocation happens only after successful callback settlement, cancellation check and replacement admission. Failed callbacks therefore have no HTTP owner to leak. Existing HTTP send/body/response/request cleanup remains unchanged.

Preparation resolves the configured `max_tokens` before the callback. Replacement values are not overwritten by old options afterward. Beta values remain in the callback payload, then follow existing beta-header extraction and are omitted from the body. The fixed endpoint, authentication/header policy and request/content transfer stay with the factory. Object/UTF-8-byte/depth/finite-number/Unicode/token-magnitude admission runs before send; the prepared route also bounds the full payload including beta metadata before callback, which can be stricter than the legacy body-only byte count. Replacements cannot relax these limits. The prepared path never rereads arbitrary `HttpContent`.

The legacy synchronous `Create` methods and ordinary transport constructor retain their existing route. Supplying OnPayload to that constructor fails explicitly: an arbitrary caller-owned request cannot establish the pre-encoding payload contract. Simple configuration has an init-only `Hooks` property and forwards through the structured route; Simple also exposes Prepare after its existing resolution. Higher-level resolved-provider convenience APIs that do not accept hooks remain unchanged; callers needing this hook must explicitly compose an authenticated prepared factory. No Agent/session/registry wiring is implied.

Seven source-only groups cover inspect-only body/order, replacement/stream/beta/override/ownership, held callback and cancellation join, original task/fault inventory, invalid replacement and prior admission, Simple/authenticated forwarding, and legacy/multicast/replay/ABI admission. They use inert local handlers and no live provider. At initial source freeze these groups were authored and registered but unexecuted. Existing robust CRLF parsing, diagnostic redaction, source snapshots and numeric projection are untouched. The subsequently composed isolated capture is described in the bounded evidence summary; no provider parity is claimed from this API alone.
