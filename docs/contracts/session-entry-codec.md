# Current-version session entry codec

`PiSharp.Sessions.Serialization.SessionEntryCodec` is a pure codec for one current CLI session JSON record. It is a dependency-ready portion of P4-01 in [the phase 4 plan](../plans/04-sessions.md). It preserves wire records without supplying storage, import copies, migrations, tree validation, context projection, compaction execution, session lifecycle or tool effects. It does not establish complete P4-01 or phase 4 compatibility.

The schema inventory comes from public Pi v0.99.1 at `d86654abb8862e201933517d6f1fce9f88dd117f`: [session-manager.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/session-manager.ts), [session-format.md](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/docs/session-format.md), [base message types](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/types.ts), [extended coding-agent messages](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/messages.ts) and the [extensible AgentMessage union](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/types.ts). The native validation and resource policies below are PiSharp decisions. Upstream's `parseSessionEntries` skips malformed lines; this standalone codec reports a failure for its rejected record and never silently returns a partial value.

`Parse(string)` accepts one strict complete JSON object with ordinary JSON whitespace, including LF/CRLF and interior formatting whitespace. `ParseUtf8(ReadOnlySpan<byte>)` additionally requires well-formed UTF-8 with no BOM. Empty/blank input, comments, trailing commas and multiple values fail. The codec does not split a JSONL stream, distinguish an interrupted tail from a malformed middle line, or own line numbers and byte offsets. `Read(JsonElement)` reparses the live caller-owned element's retained JSON text through the same strict parser. Comments and trailing commas fail even when a permissive source document admitted them, including inside nested opaque data. Successful reads clone the complete body into immutable `JsonData`; disposing the caller's document leaves the returned entry usable. A disposed source document is a caller-lifetime error.

`SessionEntry` exposes immutable `Kind`, `Type`, `Id`, `ParentId`, `Timestamp`, `IsHeader` and `WireBody`. The body remains authoritative for optional fields and all nested data. A header exposes `ParentId == null` because it is separate from the entry tree; its retained body still distinguishes any actual property presence. There is no public mutable constructor, dictionary, DTO serializer or CLR type tag. This API returns no executable instructions or provider-ready messages.

All records require string `type`, `id` and `timestamp`; `type` must be nonempty. Tree entries also require `parentId`, whose value is a string or explicit null. A `session` header requires the integer token `version: 3` and string `cwd`. Missing, legacy or future header versions produce `UnsupportedVersion`; no migration is attempted. The header is parsed independently, so this primitive does not enforce its position in a file or confirm that another entry belongs to it.

Known message roles are `system`, `user`, `assistant`, `toolResult`, `bashExecution`, `custom`, `branchSummary` and `compactionSummary`. Their required wire fields follow the pinned interfaces, including a nested integer timestamp. System content accepts strings or text arrays; user/custom content accepts strings or text/image arrays; assistant content is an array of text/thinking/tool-call blocks; tool-result content is a text/image array. Known blocks require their text, thinking, image data/MIME type, or tool-call identity/name/object arguments. Assistant messages also require API/provider/model strings, usage and one of the seven pinned stop reasons. Shell records require command/output strings and cancelled/truncated booleans; absent or null exit codes are preserved, and a non-null exit code uses the native integer profile. Summary roles retain their required summary and boundary fields.

Required usage has nonnegative integer `input`, `output`, `cacheRead`, `cacheWrite`, `totalTokens` and an object `cost` with JSON-number `input`, `output`, `cacheRead`, `cacheWrite`, `total`. Unknown usage categories are ordinary retained strings. Usage relationships, billing calculations, pricing and optional token breakdowns are outside this codec.

A context edit retains null omission or the exact `{ content: ... }` replacement shape. Replacement content can be a string or an array with all current editable block variants. This codec has no target record, so it does not validate target existence, role compatibility or tool-call/result pairing, nor normalize string replacements to blocks. Those responsibilities belong to the later projection boundary.

Optional properties are retained as opaque JSON, including explicit null and absent fields, even when the pinned TypeScript optional declaration would permit only a specific non-null type. This applies to names, labels, `details`, optional summary usage, `fromHook`, compaction `systemMessage`, system sections/tools, signatures, diagnostics, deferred handles, tool metadata and future fields at any level. Required fields remain subject to the checks above. Optional preservation therefore does not certify full message-schema validity or safe provider projection. Unknown message roles and content block discriminators likewise remain inert and exportable, without being interpreted or upgraded into a native operational type.

Strings preserve their decoded values and original JSON tokens. Identifiers, providers, APIs, model IDs, thinking levels and usage kinds are compatible strings rather than GUIDs or closed enums. No path is resolved, base64 payload decoded, signature parsed or entry/header timestamp converted to a date. The pinned format describes entry/header timestamps as ISO strings and nested message timestamps as Unix milliseconds; the codec checks the former's string shape and the latter's native integer shape. It does not validate date syntax, clock range, nonempty identity or parent relationships. Raw CLR input and decoded JSON strings/property names require paired UTF-16 surrogates. Lone raw or escaped surrogates fail with `UnsupportedUnicode` rather than being replaced. This is a narrower native string policy than JavaScript.

The native integer profile follows the existing signed `Int64` message timestamp/count representation in [the native message contract](messages.md): integer JSON tokens in `[-9223372036854775808, 9223372036854775807]`, with nonnegative counts and `tokensBefore`. Decimal and exponent forms, including `1.0` and `1e3`, fail integer validation. Integer `-0` is accepted and retains its token. Exact integers beyond JavaScript's safe-integer range are preserved, not rounded to match `JSON.parse`; this is a native representational decision, not JavaScript numeric parity. Costs, optional metadata and arbitrary opaque JSON numbers retain their strict JSON tokens without conversion to double, decimal or Int64. Large integers, long decimals, negative zero and `1e400` therefore remain exportable in those opaque positions. A preserved token conveys no claim that a consumer can represent it as a finite JavaScript number or bill it safely.

Defaults are 1,048,576 UTF-16 input characters, 4,194,304 UTF-8 input bytes and 32 JSON container levels; configured depth is restricted to 1–64. The root object has depth one. Character charging includes formatting whitespace and escapes. The byte limit applies to the UTF-8 input overload; string/element/serialization operations have no byte input to charge. Character and depth checks apply to every read path and to serialization of an entry from another codec. All nested JSON, including unknown fields, is checked for duplicate decoded property names and paired Unicode. Duplicate names fail even when their spellings differ through escapes; matching is ordinal and case-sensitive. These are intentional native hardening rules, not upstream duplicate-key behavior. Limits are per operation and bound input, not total CLR heap use, retained entry counts or concurrent callers.

`Serialize(SessionEntry)` returns one compact record without a line terminator. It removes JSON whitespace only outside strings from the owned validated body, preserving property order, string escapes, numeric token spelling, unknown data and null/missing distinctions. It does not reserialize through native message DTOs or calculate usage. This does not preserve a file's surrounding whitespace, encoding or original bytes: a later importer must retain the untouched source copy for that guarantee.

Failures expose the fixed, payload-free `SessionEntryCodecException.Failure` categories `CharacterLimit`, `Utf8ByteLimit`, `DepthLimit`, `MalformedJson`, `InvalidRecord`, `UnsupportedVersion`, `DuplicateProperty`, `UnsupportedUnicode` and `UnsupportedInteger`. They contain no rejected text, property names or inner parser exception. Null API arguments and invalid options are conventional argument errors. The API is stateless and has no shared mutable parse state.

Eight authored offline test groups in `tests/PiSharp.Sessions.Tests/SessionEntryCodecTests.cs` cover the header and complete entry inventory, all current message/content variants and stop reasons, opaque future records/roles/blocks, cloned document ownership, absent versus explicit-null fields, context replacement shapes, malformed input, permissive source-document trailing commas/comments at the root and in opaque nested data, duplicates through the string and element paths, exact integer/opaque number policies, inclusive character/byte/depth boundaries including depth 64, cross-codec serialization limits, escaped quotes/brackets, UTF-8 rejection/BOM handling and paired Unicode. Actual non-ASCII string probes use C# Unicode escapes in ASCII source, verify decoded values and prove that exact UTF-8 byte bounds differ from UTF-16 character bounds. These are synthetic native regressions linked to inspected public source. They are not unchanged upstream execution, a session corpus interoperability result, a durability result or full phase closure. The root native harness records execution separately.
