# Write-content NUL admission

The native `ReadWriteTools` write adapter admits decoded NUL in the required `content` string. NUL is file data and becomes the exact UTF-8 byte `00`. The optional private parsing flag `allowNulData` is enabled only for write content, in both initial preparation and final transformed-action validation. Path and normalized `displayPath` strings retain their NUL denial. This refines the earlier general NUL-argument statement in the read/write contract; it does not extend the read content profile.

The public source basis is unchanged Pi v0.99.1 at `d86654abb8862e201933517d6f1fce9f88dd117f`, [`packages/coding-agent/src/core/tools/write.ts`](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/write.ts). Its schema accepts string `content`; execution forwards that string to `ops.writeFile(absolutePath, content)`, and default operations use `fsWriteFile(path, content, "utf-8")`. Content is not passed to path resolution or executable argv/environment validation. The native adapter now preserves the same data distinction within its bounded UTF-8 profile.

The strict UTF-8 encoder continues to reject malformed UTF-16. The retained raw-argument-character limit, path-character limit, maximum encoded write bytes, initial/final action validation, mandatory policy, canonical target, mutation queue and failure/cleanup behavior remain active. Write bytes are checked against the same inclusive configured maximum after content decoding, both before and after action transforms. Above-limit content fails before policy authorization, directory creation or file write. Escaped JSON NUL contributes to the raw argument budget; decoded NUL contributes one encoded byte to the write budget. No BOM or terminator is added.

Preparation owns the submitted JSON and creates separately owned normalized arguments. A trusted action transform may replace content and retarget the complete final action. Final adapter validation checks the replacement content and target/display strings again; policy receives that exact final immutable action, and the executor writes its owned UTF-8 bytes. Original invocation/prepared arguments remain unchanged. Admitting content data does not admit NUL action targets, normalized paths, displayed paths, cwd, argv or environment strings.

Three additional `ReadWriteToolsTests` groups exercise the actual invoker, mandatory policy and real local filesystem:

- Ten exact bytes containing ASCII, NUL, Greek text, a supplementary character and CRLF succeed at `MaximumWriteBytes=10`; eleven bytes reject without changing an existing file or creating an absent parent. Malformed UTF-16 and oversized retained raw arguments still reject without effects.
- Original JSON remains valid after its source document is disposed. Initial and transformed content each contain NUL; the exact seven-byte final transformed output reaches policy and the real file while original/prepared JSON remain unchanged. An eight-byte final replacement rejects before authorization or effects.
- Initial read/write paths and transformed path/display values containing NUL reject, with no file/directory operations, no policy calls and an empty owned filesystem root. The previous NUL-content negative is replaced by a path-NUL negative, retaining a data-independent denial control.
