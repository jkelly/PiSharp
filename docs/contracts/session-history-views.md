# Session history, state and accounting views

`SessionHistoryProjector.Project(entries, selectedLeafId, cancellationToken)` supplies independent immutable views of one admitted session forest. It owns no writer, provider, tool, extension, clock, identifier generator or file. `ProjectLatest` explicitly selects the last physical record; null selects empty ancestry. It reuses the complete native graph admission and existing tree/context projectors, including rejection of duplicates, missing parents and cycles anywhere in the forest. Those native hardening rules differ from the permissive pinned reader on malformed graphs.

`FullHistory` retains every original physical entry. `BranchHistory` retains the complete selected ancestry. `Context` retains the existing selected, compacted and edited runtime/model projection. `HistoryContributions` and `HistoryMessages` convert original selected records before applying context edits or compaction selection, including older summary and system checkpoints. All source record bodies, opaque fields and numeric tokens remain unchanged. Unknown state entries retain identity but acquire no executable behavior.

`DisplayMessages` is the native read-only inspector policy: known user, assistant, tool result, shell-execution and summary messages are displayable; custom messages with `display:false` are hidden, while custom messages with an absent flag or `true` are displayed. System messages and unknown runtime roles remain in original history without becoming display messages. A malformed custom display flag cannot acquire display authority. This policy describes the inspector and does not claim upstream TUI layout compatibility. Hidden custom messages still follow their existing model-context rules.

`SystemHistory` preserves ordered original system/tool-declaration messages and stored compaction system checkpoints. `SystemState` uses the pinned `transcript.ts` replay helpers' semantics over the selected context: append nonempty instruction content, replace/remove named sections, and remove/add/replace complete tool declarations in insertion order. Removing and later re-adding a section/tool gives it a new position. JavaScript integer-index property enumeration is preserved for sections. `EffectiveSystemMessage` is the composed current state with the first surviving system timestamp, optional sections and optional `toolsAdded`; `SystemState.Prompt` renders content followed by the active sections. `SystemState.Tools` remains inert JSON and grants no execution authority. A compaction checkpoint replaces earlier system history for this current-state calculation while original history remains available. Unsupported optional section/tool shapes fail explicitly. Model/thinking settings continue to replay the full selected ancestry. Unselected sibling state does not change these values. Global labels and session names deliberately replay physical history through the existing `SessionTreeQueries` contract.

`SessionStatistics` accounts over every physical entry, including abandoned siblings and compacted or omitted messages. `BranchStatistics` separately accounts over the original selected ancestry. Counts include original message records, user/assistant/tool-result records and assistant tool-call blocks. Usage contributions include assistant messages, tool results with usage, standalone usage entries of any kind, compactions with usage and branch summaries with usage. Failed and aborted assistant usage remains included. Each contribution retains its original source entry and complete raw usage object; unknown metadata is retained.

The numeric aggregation follows pinned `agent-session.ts:getSessionStats` and `usage-totals.ts:addUsageToTotals`: accumulate input, output, cache read, cache write and `cost.total` in physical order, using finite binary64 values. Total tokens is the sum of those four categories; the supplied `totalTokens` field and cost subtotals are not substituted. This is stored billing history, not a provider price calculation or a model context-window estimate. If an optional usage object has an unsupported shape, a numeric value is nonfinite, or any sum overflows, statistics return `UnsupportedUsage`, null totals and affected record indexes. They retain counts and every raw usage contribution. Partial or nonfinite totals never become authoritative; the numeric tokens in source records are not rewritten.

History message count and raw output-character admission use the existing positive context limits, independently of the shortened model context. Full forest, ancestor and tree query limits remain in force. Cancellation is observed through graph, history, content and accounting traversals and before publishing a snapshot. Logical admission bounds are not a general heap guarantee.

`SessionLifecycleReadOnly.ProjectHistory(view, token)` projects captured data without acquiring the borrowed owner's lifetime. `session history --session <absolute JSONL> [--leaf <id>|--root]` exposes the same API without provider or extension activation. It reports original/selected history, display/model/system views, global metadata and both accounting scopes. The existing 8 MiB read admission, 10,000-record bound and 1 MiB JSON delivery cap apply. Oversized delivery fails rather than truncating a supposedly complete history. Damaged, future-format or unavailable projections retain the existing read-only `recovery_required` disposition; they do not produce successful prefix accounting. History projection failures additionally report the typed `historyProjectionFailure`, including `UnsupportedMessage` or `ResourceLimit`, and return exit code 1. A complete source read can remain `sourceComplete:true` when its history view is unavailable. Existing inspect/tree reports retain their prior shape. The source is never repaired or rewritten by this command.

Original P4-03 reference, malformed-graph, all-leaf and reopen obligations remain review criteria. P4-05 migrations/reader interoperability, P4-07 automatic recovery/settlement and all eight phase gates remain open. No completion percentage is assigned.
