# Registry-owned input and tool reducers

This experimental native bridge connects the three typed reducer families to actual `ExtensionRegistry` registrations. It does not connect hooks to Agent input admission, prepared tool execution, provider requests, or durable session storage yet. Those integrations, the remaining extension event families, and full source behavior qualification remain required work. No public extension SDK freeze is claimed.

An extension uses its initialization `IExtensionRegistry` to call `RegisterInputHandler`, `RegisterToolCallHandler`, or `RegisterToolResultHandler`. Each descriptor contains an owner-local registration ID and the corresponding typed `ExtensionReducerCallback`. The same ID cannot identify a tool, command, observation, and hook within one owner generation. Multiple callbacks for a family are allowed, including across owners. Existing tool/command name reservations remain independent of event names. The advertised experimental feature is `registered-input-tool-reducers`.

Initialization stages tools and hooks in the same transaction. Successful initialization publishes one `ExtensionRegistrySnapshot` containing `Tools`, `InputHandlers`, `ToolCallHandlers`, `ToolResultHandlers`, and their complete registration metadata at one `Revision`. A failed or canceled initialization rolls back all its staged registrations and awaits owner cleanup. Active add/remove operations each publish a new immutable snapshot. No callback is exposed in public snapshot metadata.

The host constructs one long-lived `RegisteredExtensionEventDispatcher(registry, admitToolResult, options, maximumHandlersPerDispatch)`. The registry is borrowed. `admitToolResult` must be a trusted, pure, complete result admission function, such as the native `ToolResultValueCodec.Read` boundary; it is called for the initial result and every prospective replacement. The host calls `DispatchInputAsync`, `DispatchToolCallAsync`, or `DispatchToolResultAsync` with the actual captured registry snapshot and explicit operation/session cancellation tokens. Dispatch returns the existing typed reduction, not an executable tool authorization or durable commit.

## Snapshot admission and lifetime

Admission checks the snapshot's registry identity and every participating registration's current owner generation, active scope, and exact registration-entry identity under the registry gate. All selected callback leases are acquired together before the first callback. A removed entry's retained charge lasts until its last admitted callback lease settles. Removal cannot reclaim that charged capacity or replace the callback in an admitted projection. Reusing an ID creates a distinct entry when remaining capacity permits. An old handle cannot remove that newly registered entry.

Once admitted, removing a registration affects future snapshots and leaves this dispatch's ordered callbacks intact. A snapshot captured before removal cannot start a new dispatch through the removed entry: it fails with `StaleSnapshot`, rather than treating its retained delegate as lifetime authority. Unrelated snapshot entries are not invoked or leased. An empty selected family is a valid reduction with no callbacks. This is stronger generation admission than the standalone reducer handler sets' capture-only lifetime behavior.

Callbacks run in owner activation admission order, then each owner's registration insertion order. Completion order of concurrent initializers does not reorder owners. The dispatcher constructs an ephemeral reducer projection directly from the admitted registry entries. It never registers callbacks into a second handler store. One private long-lived reducer engine preserves its concurrency and recursive-depth accounting across all calls and families; creating the projection does not reset those counters. The registry also retains its shared dispatch cap across dispatcher instances, observations, commands, and tools.

No extension callback, pure result admission function, cancellation listener, or cleanup runs under the registry lock. Disposal of any participating owner or its registry from inside the dispatch is rejected with `ReentrantDisposal`, including a later participant that has not executed yet. This prevents a callback from awaiting cleanup that requires its own dispatch to release a lease. External owner disposal closes admission, cancels its lifetime, and joins all admitted callbacks and extension cleanup. Concurrent disposal callers share the same settlement. A throwing lifetime-cancellation listener is collected as cleanup failure; it does not skip callback joins or extension disposal. Cancellation remains cooperative: a trusted callback that does not settle can hold its lease indefinitely.

## Reduction and bounds

The bridge preserves the accepted reducers' family policies. Input handler failure produces a sanitized diagnostic and continues; `Handled` stops later callbacks. Input transform images use the source nullish rule. Tool-call failure blocks dispatch with a sanitized typed exception, complete patches are validated before replacement, each non-null decision replaces the previous decision, and the first `block:true` stops the chain. Tool-result failure or invalid replacement produces a diagnostic and continues. Only `content`, `details`, `structuredContent`, `isError`, and `usage` reduce state. A content replacement without a structured-content property clears the old structured value; explicit null remains distinct from omission. Original result properties and numeric token spelling are retained. Execution outcome error status remains separate from a patched raw `isError` property.

Existing registry bounds cover all typed descriptors, including staged and leased retired registrations. Metadata charges the owned registration ID plus its fixed event name; owner ID storage is also charged. Existing JSON/image/text/concurrency/depth bounds apply through the reducer engine and mandatory result admission. `maximumHandlersPerDispatch` defaults to 256, accepts 1 through 4096, and rejects excess selected callbacks before any lease or callback. A smaller configured registry cap still applies. These are logical admission limits, not total process heap limits. Tool-result `ReturnedPatches` retain independently admitted patches, so retained payload limits multiply by the selected handler count and concurrent dispatch count; the host should choose those settings together. Captured snapshots retained by the host are caller-owned immutable views and do not themselves grant callback admission.

## Source evidence and mandatory differences

The design uses the unchanged public `packages/coding-agent/src/core/extensions/runner.ts` at upstream commit `d86654abb8862e201933517d6f1fce9f88dd117f`. Genuine whole-Runner evidence was committed separately as `9314b373b0fac99bd5fc6cc02a873c0fde1ac0f4`: its `fixtures/reference/extension-reducers/expected.json` has SHA256 `ef3fd54d53cb846a9337640316cdcc90e22f5862938fd031473fd58008aaa34d`. That capture exercised the entire unchanged exported Runner, 85 source files and 786 dependency files, with two initial and two default fresh-child runs. It observed owner-grouped order, current-dispatch removal retention, next-dispatch additions, first-block stopping, later whole-decision replacement, content clearing, and explicit null properties. The native tests reproduce those overlapping rules using actual registry registrations and callback leases; they do not claim a full golden trace match.

The genuine source also mutates shared input objects and shallow tool-result content aliases, returns raw handled objects with opaque fields, and represents some returned properties as JavaScript `undefined`. Native typed immutable events instead require explicit argument/result replacements, return the typed handled reduction, and keep absent CLR patch fields separate from explicit `JsonData.Null`. The source's context abort flag permits later input/result callbacks and retains their error-reporting traces. Requested native operation/session/lifetime cancellation stops the reducer after awaited callback cleanup. Source error payloads and stacks are not copied into native diagnostics. These measured differences remain mandatory compatibility and authority-design work; this bridge does not normalize them away, claim alias/abort/undefined parity, or treat them as permanent scope exclusions.
