Source-only implementation against 0ac59c6. No builds, tests, transport calls or native execution. Thirteen synthetic/registered groups are unexecuted and not registered in Program. This is not whole extension SDK parity.

The callback receives the actual staged coordinator's reservation-affine manager, while both source and target remain reserved. Identity, parent and timestamps come from that coordinator; inert fields go through the existing strict codec/projector/explicit registry. Typed message/config/custom/name/label methods and native entry drafts are available; branch/reset and acknowledged reads use the staged state. The manager supplies no file relocation, new-session recursion, disposal, process or tool authority. Original SessionManager file-relocation/recursive lifecycle operations are not exposed through this staged capability.

Each append returns an owned actual native operation task; storage checkpoint originals and callback originals are captured separately. At callback completion, new admission is fenced and all dropped append originals are joined before target publication. Escaped managers reject mutation. Capacity is 128 appends and 512 reference-unique boundary originals. Fault graphs and await exceptions are cached once per exact task. Faulted cancellation is kept distinct from canceled originals; unknown empty aggregates remain errors. Target validation and the existing replacement transaction retain responsibility for final lifecycle publication and rollback.

User/custom targets retain their original parent/editor-text semantics. Summary parent is the resolved target; summary and label use one acknowledged append batch, and the final label entry becomes the selected native leaf, matching original manager append behavior. Label-only navigation labels the requested target. The existing no-summary/no-label operation remains an in-memory selection.

The actual generator, policy callback, checkpoint and observation tasks are retained. Owned Abort waits for the generator original to settle before clearing compaction/idle ownership. Only the actual canceled task's matching work-token cancellation is acknowledged; a faulted OCE remains a fault. Checkpoint publication and post-tree observation failures carry explicit checkpoint/committed receipt evidence. After an acknowledged append there is no late token check that erases that receipt. Queue/stale checks and native prospective state validation occur before effects.
