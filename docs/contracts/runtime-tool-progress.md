# Runtime registration preserves prepared-tool progress

`SessionRuntimeRegistry` captures a trusted adapter's registered name in its private `NamedAdapter`, then creates the accepted `ToolInvoker` and tool definitions from the source-ordered active durable declarations. The wrapper must forward both prepared execution overloads.

The legacy `ExecuteAsync(action, token)` remains unchanged. The progress overload now delegates `ExecuteAsync(action, onProgress, token)` directly to the inner adapter with the same immutable action, callback and work token. An inner adapter that implements only the legacy method still uses the interface's existing fallback, producing no synthetic updates. Forwarding changes no registration/declaration checks, captured name, preparation, validation, transforms, mandatory final-action policy, result admission limits or lifetime ownership.

The original wrapper omitted the progress overload. Consequently, its interface default called the wrapper's legacy method, which called Bash's legacy method with a no-op observer. Actual process output and final results survived, while every progress update disappeared before the scheduler. This was identified from the immutable corrected Bash CLI gate `db04813355dd182ce52442f97e275b48552a3247`: zero build warnings/errors, 52/54 CodingAgent groups passing, exact large-output final/metadata/spill assertions passing, but no actual nonempty `tool_execution_update`; the abort fixture timed out waiting for real progress before it ever submitted abort. The preserved evidence is `artifacts/offline-bash-corrected-phase-native.log`. No cancellation-settlement defect is inferred from that pre-abort timeout.

The corrected wrapper restores the real path: adapter -> invoker progress admission -> scheduler -> Agent/coordinator subscription -> RPC projection/writer. It does not substitute the final result for progress or synthesize callback data. Existing progress scope receipt/closure and awaited delivery behavior remain owned by the accepted Agent components. The independent source-compatible progress policy work is separate; this wrapper forwards whatever policy those components supply.

`RuntimeToolProgressTests.Cases()` adds three authored, framework-only groups:

- Actual registry and durable coordinator: exact partial content, raw number tokens, explicit null and StructuredContent survive a held awaited subscription. The actual tool cannot finish or acquire its next provider request while that listener is held. Once released, final content/details are acknowledged on disk and observed in the next request; separate programmatic/partial data never enters canonical history. A changed trusted Name getter still uses the name captured at registration.
- Actual registry, Agent and coordinator failure/cancel: already admitted listener and trusted executor cleanup gates hold settlement. Failure remains an actual fault; abort retains cancellation identity. Both wait for owned work, preserve previously acknowledged assistant/input state, avoid another provider request and close the real session lease.
- Actual registry and invoker/scheduler: a legacy adapter produces no invented updates and retains final owned metadata; mandatory policy denial prevents either execution overload; a narrow ordinary result cap rejects invalid progress before publication.

The tests use a trusted inert prepared action and deterministic fake native transport/adapter, with actual temporary durable storage. They do not spawn a shell, call a provider or infer full upstream parity. Six-second guards bound failed test cleanup; gates control expected ordering. Registration is root-owned: append `RuntimeToolProgressTests.Cases()` to the CodingAgent console harness. No existing test registration or shared source was edited by this lane.

This authoring handoff has not built or executed the correction. Root owns compilation, the full retained suite including actual Bash subprocess regressions, and immutable independent review. The minimal forwarder does not close the full runtime/plugin/tool or P3/P4 compatibility gates.
