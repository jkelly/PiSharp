# Native loadout preparation successor

Source-only successor of activation `267323ac3ac88c9f80d0763240905322ecd25c9c`. No native build, tests, SDK execution, source execution or provider call was performed. Four new authored groups join the seven activation groups and use their directly awaited runner prefix. Independent review and coordinator-owned bounded qualification remain required.

The synchronous `ExtensionToolDescriptor.PrepareLoadout` receives one immutable metadata-only `ToolLoadout`: original declared tools in active order, the callable tools, every registered tool, and exposure lookup. It has no callback context or executable delegate. `ExtensionRegistry.PrepareToolLoadout` admits the captured registration owner, holds its callback lease without holding the registry gate, checks cancellation/lifetime, and releases the lease in `finally`. Metadata snapshots expose only `HasLoadoutPreparation`; `ExtensionAgentBinding.GetLoadoutPreparation` supplies a borrowed, owner-checked host bridge.

Only active callbacks run, in active order. Every callback sees the same original descriptions. Later callbacks win description keys; hidden declaration names accumulate. The whole result is validated before merging, with bounded counts, aggregate presentation characters and scalar Unicode checks. Failed preparation contributes no partial changes and allows later callbacks to run. Bounded `ToolLoadoutDiagnostic` facts are retained by the binding/selection, with an optional synchronous host diagnostic observer. Native async extension-error event delivery is not connected by this increment.

The native CLI copies the bridge into `SessionRegisteredTool`. Registry resolution prepares a new presentation on installation, activation and reopen; validation-only replay does not invoke callbacks. No-op activation does not reprepare. Hosts composing a session registry must use `ExtensionAgentBinding.ContextHooks`, which omits the binding's fixed initial presentation. Standalone binding consumers use `Hooks`. This separation prevents an old hidden set from filtering a later session loadout.

`AgentHooks.FinalTransformRequestMessages` runs after context handlers and a run's forced-system projection. The loadout presentation filters hidden names from every system message's additions and removals, and applies model-facing descriptions. Empty tool delta properties are omitted. Canonical history, durable declarations, root/nested execution admission, final-action policy and usage accounting are unchanged. A hidden declaration remains active and executable. Restored activation is reconstructed from canonical declarations, then preparation is rerun for the new runtime installation.
