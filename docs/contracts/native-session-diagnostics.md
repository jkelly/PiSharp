The primary session sink appends `customType: pisharp.native-chat-diagnostic.v1` at the actual `AgentLoopTurnEnded` barrier after assistant/tool message acknowledgments. Data carries schema version 1, the exact acknowledged assistant entry ID, accepted public SDK operation generation, and separate optional semantic and cleanup diagnostics. Retries share that accepted operation generation; their actual assistant entry IDs remain distinct. RPC correlates against the same public generation. Adapter/code values are closed. No exception text or callback payload is stored. The data bound is 4096 UTF-16 characters and IDs are at most 256 UTF-16 characters. A persistence failure faults the writer and prevents successful settlement.

`NativeSessionDiagnosticProjector` reads selected **raw** ancestry, so an omitted assistant remains inspectable and billable. A record must reference a preceding assistant in that ancestry. Malformed or unresolved declared records appear as bounded read issues. A recognized historical `openAICompletionsFailure` field appears as an `unverified-legacy-observation`. Original bytes and opaque fields are retained. A recognized custom record has `declared-native-record` provenance; the name does not authenticate origin or grant execution/retry authority. Reads retain the newest 1024 combined observations/issues. After truncation, one slot is reserved for an explicit `ResourceLimit` issue; the newest association stays available to a live RPC event. An imported identity beyond 256 characters is reported as an invalid record with an empty issue identity, without rewriting its original entry. Public view writers validate closed enums, provenance-specific identity/generation shapes and a 4 MiB output bound.

RPC emits the separate native `pisharp_chat_diagnostic` event only after the matching diagnostic entry is durably acknowledged. Its versioned `data` envelope preserves the assistant association and provenance. Source Pi `message`, `message_update`, `turn_end` and transcript bodies receive no diagnostic fields from this consumer. Native CLI report and inspect/history modes expose the same versioned `nativeDiagnostics` read view. Print/JSON message bodies retain their existing source-compatible purpose.
