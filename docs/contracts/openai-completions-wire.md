# OpenAI Completions parsed chunk source

`PiSharp.AI.Providers.OpenAICompletionsWireSource` is a standalone `IChatTransport` over a trusted caller's asynchronous source of owned `JsonData` chunks. This is the first native parsed-wire portion of P2-08, not a complete Completions provider. It sends no request, resolves no credential or environment variable, installs no SDK, reads no clock and executes no tool. Requested identity and timestamp come from the supplied `ChatRequest`. No accepted reducer, message contract, transport, tool executor or other provider has been changed.

The authority is public Pi v0.99.1 commit `d86654abb8862e201933517d6f1fce9f88dd117f`: the complete [api/openai-completions.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-completions.ts), [types.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/types.ts), [transform-messages.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/transform-messages.ts), [transcript.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/utils/transcript.ts) and [json-parse.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/utils/json-parse.ts). The canonical Completions implementation is under `api/`; it is not an inferred Responses adapter. The native tests contain authored inline chunks informed by these sources. No unchanged upstream Completions stream execution or independent provider-family qualification is claimed here.

## API and ownership

The constructor accepts:

    OpenAICompletionsWireSource(
        Func<ChatRequest, CancellationToken, IAsyncEnumerable<JsonData>> source,
        OpenAICompletionsWireOptions? options = null)

Options and synthetic per-million-token rates are immutable public records in the same new source file. The request API must be exactly `openai-completions`, with nonblank well-formed provider and model strings. Bad constructor limits/rates, an invalid requested identity, or a pre-cancelled token fail before source acquisition. The original request and actual work token are passed to the source factory once per run; messages are borrowed and are not projected or consumed by this mapper.

The returned enumerator is owned for that run. Native Start follows successful acquisition, before the first pull, with empty content, pending reason and zero usage. Acquisition/factory failure produces one sanitized Error without Start. This envelope is an authored integration boundary: the upstream wrapper pushes Start after SDK acquisition and response hooks, which this component does not implement.

Pulls occur only as normalized enumeration advances. There is no background queue, hidden retry, prefetch of another chunk, or replacement run. A bounded per-chunk list holds that chunk's normalized operations; the mapper yields those operations before another pull. Valid operations already admitted before a later malformed tool field are retained before the error terminal. Whole-DTO structural/unknown-feature admission may reject a chunk before its content is mapped.

Normal exhaustion, source faults, malformed input and cancellation await actual enumerator disposal before terminal delivery. Early consumer disposal awaits the same owned cleanup and does not pull unread data. Read, Current getter, factory/acquisition and cleanup are separate failure boundaries; a source Current exception is SourceFailed rather than being misclassified as malformed provider JSON. An earlier source/protocol failure wins over cleanup failure; cleanup failure alone prevents successful settlement. Actual caller cancellation takes priority after cleanup, while a foreign OperationCanceledException is a source failure. An early-disposal cleanup exception is thrown with a fixed payload-free message. A trusted source that does not settle its own cancellation/disposal can hold the run; this implementation does not detach that work behind a timeout proxy.

Cancellation is checked around source pulls, Current access, progress delivery, cleanup and final event delivery. A cancellation observed during EOF block-end delivery produces Aborted, never a later successful Done. Known content and strict finals already calculated remain in the aborted message but confer no tool permission. The high-level `ChatClient.StartWithAbortSettlementAsync` path can retain the bounded authoritative aborted terminal while draining without a cancelled reader token; the legacy ChatRun path retains its existing cancellation policy.

## Supported field mapping

Only the first array-position choice is consumed, matching the pinned loop; the choice's numeric `index` is not a content position. Empty/missing choices and null first choice permit ID/model/usage bookkeeping. Extra choices and unrelated chunk/choice metadata are inert after bounded strict admission. Optional `object` must be `chat.completion.chunk` when nonempty. Present content-bearing fields require the declared native types; the source is more permissive about some unexpected values.

| Wire field | Native mapping |
| --- | --- |
| First nonempty chunk id | Owned responseId metadata; later IDs do not overwrite it |
| First nonempty chunk model different from the requested model | Owned responseModel; requested model/provider/API stay unchanged |
| First-choice delta.content string | One text block; starts on its first nonempty delta |
| reasoning_content, reasoning, reasoning_text | First nonempty string in that priority order per chunk; one thinking block |
| First selected reasoning field | Exact thinkingSignature field name, retained across subsequent field changes; opencode-go reasoning aliases to reasoning_content |
| Function tool call index and/or id | Stable correlation map; native content indices are contiguous first-appearance positions |
| Function.arguments fragments | Exact bounded raw preview; empty tool deltas remain observable |
| Last nonempty finish_reason | Owned rawStopReason and mapped terminal reason; reading continues through EOF for trailing usage |
| Top-level usage, otherwise first-choice usage | Source precedence, with an empty top-level object still suppressing the fallback |

Text, thinking and multiple tool calls can interleave. Block starts and deltas follow source processing order: text, selected thinking, then tool_calls array order. On supported success every block ends at EOF in first-appearance order, followed by one Done. Finish reasons `stop/end` map to Stop, `length` to Length and `function_call/tool_calls` to ToolUse. Content-filter, network-error and unknown reasons preserve rawStopReason and produce a sanitized ProviderError. A missing finish reason is UnexpectedEof unless the caller explicitly selects `SupportsFinishReason:false`; that capability infers ToolUse when tools exist, otherwise Stop. Compatibility detection from provider/base URL is not invented here.

A tool's first admitted occurrence needs a nonblank ID and function name. Its wire index is optional if its ID supplies correlation; a later index can attach to that same identified call. Conflicting index/ID aliases, a changed established ID/name/index, or a continuation with neither index nor ID fail. These stricter correlation checks are native hardening, not proven wrapper parity.

**Delayed tool identity is an open contract dependency.** The source creates a toolcall_start immediately with an empty ID and/or name and fills them later, retaining argument fragments in between. The accepted native reducer requires nonempty immutable tool identity at start and forbids changing it at end. This initial mapper returns UnsupportedFeature rather than inventing IDs. Bounded staging could preserve the argument bytes but would postpone Start, change first-appearance/event timing and possibly reorder interleaved blocks. It cannot be called full trace parity. A provisional wire-content identity contract or a deliberately qualified staging projection is required before closing this capability; no core change is hidden in this slice.

## Tool arguments and partials

Before any successful block ends are exposed, every accumulated function-argument buffer is parsed by the existing `FinalToolArguments.ParseStrict` and validated for depth, finite numbers and decoded Unicode. Empty scratch becomes an empty object. Truncated JSON, trailing repair, arrays/scalars/null, duplicate decoded keys, malformed escapes, nonfinite numbers and lone surrogates fail without ToolCallEnded or Done. Final content retains exact ID/name and owned complete object arguments. Scratch fields are absent from replayable content.

**Whole-prefix and repaired-final parity remain open.** Upstream parseStreamingJson repairs partial JSON and also finalizes from its repaired result. The accepted native reducer exposes the accumulated raw preview separately and keeps started tool arguments empty until strict finalization. This mapper does not integrate the standalone preview helper. Refusing a repaired executable final is deliberate native hardening. Raw argument numeric lexemes such as `1.00` remain owned JSON tokens rather than being rewritten to JavaScript JSON.stringify's `1`; the authored exact-final test does not mislabel that token retention as a captured JavaScript final.

On malformed/unsupported/faulted/aborted input the mapper retains known partial content without synthesizing balanced successful block ends. The upstream loop does emit block ends before checking an EOF missing finish reason, error finish reason or its final abort check. That error-path event-timing difference is explicit; genuine differential capture and cancellation qualification remain mandatory. No Error/Aborted terminal authorizes tool execution. This assembly has no executor dependency.

## Usage, metadata and diagnostics

Cache read uses nullish, short-circuited precedence: prompt_tokens_details.cached_tokens, prompt_cache_hit_tokens, cached_tokens, then zero. Explicit zero wins; null falls through; an ignored lower-priority field is not coerced into a count. Cache write is prompt_tokens_details.cache_write_tokens or zero. Input is max(0, prompt_tokens - cacheRead - cacheWrite). Output is completion_tokens, already including reasoning. Reasoning is completion_tokens_details.reasoning_tokens or zero. totalTokens is the checked sum of input, output, cacheRead and cacheWrite; incoming total_tokens does not replace it. Reported usage has reasoning:0 when its breakdown is absent; an entirely absent usage object retains the initial omission.

This initial numeric profile admits selected count/index values using nonnegative Int64 integer JSON tokens bounded by JavaScript's maximum safe integer; function indices additionally fit Int32. Fraction/exponent count tokens, strings, negative counts and wider values fail instead of being silently coerced. General JavaScript double rounding, unsafe aggregate totals, model catalogs and tier pricing are not qualified. Reasoning above output fails under the existing native reasoning-subset contract even though the public parseChunkUsage helper does not enforce it.

Explicit nonnegative decimal rates are authored configuration, with zero rates by default. Costs use checked decimal arithmetic per million tokens; computed cost scales are canonicalized with G29 only for these calculated decimals. Raw argument, signature or opaque numeric tokens are never cost-normalized. Overflow fails with a fixed diagnostic. Requested identity, reported response identity/raw reason, thinking signature and reasoning usage metadata are owned immutable fields.

The failure enum is SourceFailed, MalformedStream, UnexpectedEof, ResourceLimit, ProviderError, Cancelled, CleanupFailed or UnsupportedFeature. Error terminals carry the corresponding [typed native diagnostic](native-chat-diagnostics.md), separately from message data, and fixed errorMessage; Cancelled uses Aborted and all other failures use Error. Actual exception messages, rejected argument strings and provider error bodies are not copied into diagnostics. Known content and bounded rawStopReason are intentionally retained provider data, not sanitized diagnostic prose. A nonnull top-level error object is an explicit native parsed-source rejection cue. ChatRun still maps admitted error terminals to its existing Provider/Cancelled categories; the owned enum metadata distinguishes the mapper cause.

## Bounds and remaining required work

Defaults: 4096 chunks, 65536 raw UTF-16 characters per chunk, 1048576 aggregate raw input characters, 64 content slots, 1048576 logical content characters and JSON depth 32. Limits are positive, with depth at most 64. Every DTO is reparsed strictly, including retained caller elements originally parsed with comments/trailing commas. All decoded strings/property names need paired UTF-16; all JSON numbers must be finite, including ignored fields. Tool-call array entries per chunk are separately limited by MaximumContentSlots, even when several refer to one existing slot.

Logical content charging includes requested identity, accumulated text/thinking, tool IDs/names and initial empty objects, raw tool fragments, selected signature and owned response/raw-stop/usage metadata. Replaced metadata is charged by retained size difference. It does not double-charge parsed final arguments derived from already charged fragments. The private reducer has a derived `min(Int32.MaxValue, 2 * MaximumContentCharacters + 1024)` cap because it retains preview and parsed argument representations separately, with a fixed diagnostic reserve. Fixed native failure tags/messages are outside the producer logical payload budget. Incoming JSON buffers, parsed clones, lists, StringBuilder capacity and caller-owned request/history/source data are separate memory; these limits are not a total heap or network-byte cap. A caller's ChatRun reducer can impose a lower independent limit.

Nonempty reasoning_details, encrypted/detail merge replay, custom grammar tools, audio/refusal/legacy function_call content, nonstring multimodal content and unknown delta content features fail UnsupportedFeature. Empty/null reasoning_details and null audio/refusal/function_call are inert. These are temporary unimplemented mandatory profiles, not permanent exclusions. Full transcript/system/tool projection, cross-model signatures/IDs, payload/tool schemas/choice, images, provider compatibility detection, authentication/header precedence, scoped environment/stored credentials, SDK/HTTP/SSE composition, retry/hook behavior, model-family/catalog/tier costs and complete cancellation/error trace parity all remain required under [P2](../plans/02-provider-layer.md). No general compatible-endpoint or full provider claim follows from this component.

## Authored verification handoff

`OpenAICompletionsWireTests.Cases()` supplies six groups for root registration: exact interleaved operations/finals and native reducer/ChatRun composition; stop/EOF/usage priority and number controls; strict finals/unsupported identity and valid-prefix failure; raw/depth/Unicode/slot/payload bounds; gated source ownership and distinct failure boundaries; and actual cancellation with cleanup/final-event races plus opt-in ChatRun abort settlement. The exact structural comparator ignores object key order only, preserving array order, strings, null versus missing and numeric raw tokens, with mutation controls.

The groups were authored without execution in this delegated slice. Root owns Program registration, isolated build/test execution, immutable review and later genuine unchanged-source oracle capture. No fixture, golden, dependency lock, provider credential or accepted core file was changed.
