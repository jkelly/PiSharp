## Complete capture and ownership domain

This slice deliberately uses the existing original separated completion receipt. Pi streams match events and kills its child when the requested limit is reached. The reviewed runner exposes completed separated stdout/stderr, not an owned typed match-event streaming-stop contract. This patch therefore does not approximate stop/kill receipts or weaken joins: rg must finish naturally with complete bounded stdout/stderr, and the tool then formats the first limit events. At most 10000 match events and 1 MiB aggregate path/text characters are admitted; per-pipe clipping, incomplete cleanup/capture, malformed/unknown JSON events, encoded-byte-only text, unsupported line numbers, oversize/NUL/surrogate/multiline data and status/exit inconsistencies reject explicitly. Begin/end/summary metadata is ignored. Malformed JSON differs from source's silent ignore, by explicit refusal. The parser accepts only absolute canonical-form BMP paths emitted by an absolute search target; relative path events reject. Regex syntax is not preinterpreted. Source unlimited output, fractional/nonpositive limit coercion and malformed event behavior are not parity claims.

The executor's search type/existence checks occur before lease/process acquisition. After acquisition every canonical-launch, original-runner, receipt, parser and containment outcome reaches awaited original lease disposal. The runner directly joins original process exit/termination, stdout/stderr pumps, drain, collector, output and physical process lifetime before settlement, as documented in the fd contract. No new WaitAsync, timeout, Task.Run, wrapper process, shell or detached work is introduced. Original operation failure alone is rethrown unchanged via ExceptionDispatchInfo; cleanup failure alone is retained unchanged; both retain original exception objects in operation/cleanup order. Failure precedence survives caller cancellation during cleanup. Otherwise-successful paths recheck the original caller token after spill disposal. The retained binary image scope is await-disposed on every subsequent exit. As in the fd correction, this is a post-spill check, not atomic cancellation settlement after that check or during image disposal.

Real rg streaming limit termination, process and separated pipe behavior, stderr diagnostics, Unicode/encoding/platform/glob/repository/environment/configuration semantics, physical image/parent immutability and spill qualification require an admitted binary and coordinator receipts. Positive context requires a separately designed bounded policy-mediated file-read/cache capability. No real rg invocation is authored in these tests, no CLI registration/default authority expands, and no provider/terminal files change.
