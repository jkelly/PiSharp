# Owned source tool-result values

This slice implements the serializable result rules in pinned Pi v0.99.1 `packages/agent/src/agent-loop.ts` (`d86654abb8862e201933517d6f1fce9f88dd117f`): `executePreparedToolCall`, `finalizeExecutedToolCall`, `createErrorToolResult`, `emitToolExecutionEnd`, and `createToolResultMessage`. It changes production result admission, scheduler hooks, Agent history, and RPC projection. It does not qualify the entire JavaScript Agent API or tool-result grammar.

`ToolResult.FromJson` / `ToolResultValueCodec.Read` admit an owned strict object. Its immutable property map is authoritative. Unknown result properties, arbitrary usage, explicit null, and raw finite number lexemes are retained. Missing content stays missing in execution/progress results; null content stays null. The typed `Content` view is an empty array for either, and an absent `Details` has the existing empty-object compatibility view without creating a property. `HasProperty` and `Property` expose actual presence. `Usage` and `StructuredContent` use CLR null for absence and `JsonData.Null` for explicit JSON null.

The five-argument typed constructor, deconstruction, and record updates remain available. Typed updates replace the corresponding property in the same map; a content/details/flag update cannot leave an old raw result attached. `WithProperty(name, null)` removes a property. `Failure` is native runtime classification and is never automatically a source result property. The typed `IsError` compatibility view includes a native failure; the actual owned `isError` property remains available separately. `ToolOutcome.IsError` carries the execution/after-hook disposition and is used for events, canonical messages, and CLI completion. A source patch can set outcome error true while the result object's own `isError` remains false or absent.

The typed constructor cannot distinguish omitted optional arguments from explicit false. Its false defaults omit `isError` / `terminate`; true arguments create those fields. Use the raw source factory when their exact presence matters. `Success` produces content/details plus terminate only when true. `Error` and scheduler exception/hook-error construction produce content/details, with a separate native `Failure` and effective outcome error. Their raw object does not acquire `failure` or an own `isError`. A blocked terminating result additionally owns terminate true, matching source preflight behavior. Default CLR record serialization is not the Pi wire format; use the explicit codec.

`ISourceToolHooks` selects the actual source patch hook; ordinary `IToolHooks.AfterExecutionAsync` remains a complete-result replacement hook. A null/no patch leaves the result unchanged. The production source helper copies only non-null content/details/usage/terminate replacements; other patch fields are not copied. Null retains the original value. A non-null structured replacement wins. Otherwise a non-null replacement content array, including an empty array, removes structured content; absent/null content preserves it. A non-null boolean `isError` patch changes only the outcome disposition. Unknown patch fields are still admitted and charged before being ignored. Arbitrary untyped patch error-disposition types remain unfinished source grammar, rather than being silently coerced.

One materializer supplies both high-level Agent and loop history. It normalizes missing/null result content to `[]`, copies details/usage only when present (including explicit null), uses the outcome error, and adds canonical identity/timestamp. Structured content, terminate, arbitrary result fields, and native failure classification stay outside canonical/durable/model messages. The durable coordinator already stores the complete acknowledged message body, and selected-branch projection/reopen preserves it. Provider request projectors continue to apply their source-defined tool-result projection; they do not copy result metadata into provider payloads.

RPC progress and execution end now emit the complete owned result object; execution-end error remains an independent envelope field. The same shared bounded writer, checkpoint barriers, asynchronous prompt acceptance, and awaited cleanup remain in force. Existing authored RPC assertions which stripped owned terminate/isError were corrected to match this implemented behavior. Their former direct-executor `1e400` positive was preserved as an explicit negative on the actual durable/RPC path; a wide finite `1e300` control preserves the positive raw-token assertion. No source capture or golden is modified.

Admission validates every retained property, including usage and unknown metadata. It rejects permissive comments/trailing commas, decoded duplicate keys, unpaired Unicode, nonfinite binary64 numbers, excessive container depth, excessive content blocks, and resource limits with a sanitized result error. Finite wide/decimal/exponent/negative-zero tokens are retained, without assistant token/cost coercion. Output NUL is inert JSON data. The existing prepared-adapter action and text-extra validation rules still apply. The raw factory/standalone codec defaults to 65,536 ordinary retained characters, 6,356,992 structured raw characters, 128 content blocks, depth 32 per metadata value, 7 MiB complete serialized characters, and 28 MiB complete UTF-8 bytes. Content's fixed array/block envelopes do not consume the metadata depth budget. Known typed content uses its existing decoded text/extra budget; additional result property names and raw values consume ordinary budget. Complete serialization, including syntax and escaping, is separately capped.

The outer execution/`ToolResult.ToJson` profile accommodates existing configured prepared adapters: 512 KiB ordinary characters, 8 MiB structured characters, 1,024 blocks, metadata depth 32, 12 MiB complete serialized characters, and 48 MiB complete UTF-8 bytes. `AgentOptions.ResultValues` and the appended optional scheduler `resultOptions` select explicit execution limits. The materialized message carries those admitted limits to the common history serializer. The invoker retains its own configured lower ordinary/structured/block/depth limits and adds configurable complete raw character/byte caps (12/48 MiB defaults), preserving its existing positional constructor/deconstruction. RPC applies its own configured output byte/depth bounds while composing the complete result. This prevents an accidental new 64 KiB outer limit from rejecting the existing CLI's 128/512 KiB prepared-output profiles. A 70,000-character authored control verifies that path without a giant allocation; an explicit lower outer budget still rejects it.

Batch progress charges usage and arbitrary properties along with completed/admitted receipt counts and existing pending/retained limits. Admission rejects exhausted count/pending quotas before JSON validation, and validation runs under the shared budget gate to bound its concurrent allocation. No listener or caller code runs under that gate. Rejected metadata cannot reach listeners or acquire a final acknowledgement. Existing stronger awaited progress behavior and source-compatible settlement/late-callback behavior remain selected by their existing modes.

Serializable result corrections do not close those requirements.
