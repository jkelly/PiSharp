# Concrete admitted MCP adapters

This CURRENT v0.99.1 independent leaf implements actual UTF-8 JSONL stdio and JSON/SSE HTTP wire paths under the R270 supplied-capability seams. Parent is refresh correction `f3045b557dc20fce146be8d7f8c832c94821b877`; earlier runtime/config prerequisites remain required. Source baseline is Pi `d86654abb8862e201933517d6f1fce9f88dd117f`. This is authored source, not compiled or executed transport qualification and not complete MCP integration.

## Host wiring API

Contracts live in `PiSharp.Extensions.Mcp.Transport`. `IMcpAdmittedDuplexLease.Input` writes server stdin; `.Output` reads stdout. The coordinator supplies one fresh independently closeable lease. Its StartAsync and stable CloseAsync own original process, pipe and stderr settlement; CloseAsync requests stop/unblocks readers before it waits. Adapters borrow streams and never spawn, kill or dispose those streams. The existing whole-command ProcessRunner has no invented duplex mode.

`McpHttpExchange(HttpRequestMessage, CancellationToken)` wraps the host's already admitted HttpClient. Delegate completion/failure joins its original send and transfers response ownership. The adapter creates no client, handler, credentials or ambient endpoint. `McpHttpBinding` captures absolute HTTP(S) endpoint, immutable explicit headers and mandatory explicit `McpHttpProfile`. Host retains URI/header/network authorization and redirects/auth policy. No default credential resolution or OAuth retry exists here.

Implementations live in `PiSharp.Extensions.Runtime.Mcp.Transport`:

- `McpStdioTransport(lease, limits?)`: bounded LF JSON-RPC read pump and serialized writes/flush over supplied streams.
- `McpStreamableHttpTransport(binding, exchange, limits?, clock?)`: POST JSON or SSE responses; opt-in GET after initialized, bounded GET resumption and opt-in close DELETE.
- `McpJsonRpcRequestChannel(wire, limits?, notification?, clock?)`: implements the existing admitted runtime request channel. A host factory wraps either wire transport in this channel and supplies it to McpServerRuntime.

`McpNotificationHandler` receives method, owned optional params and lifetime token. Wire Receive is quick dispatch. Notifications use bounded, tracked, serialized callback originals outside the reader, so an awaited tools/list refresh can receive its response without blocking its own reader. Channel Close reentry from notification/progress/incoming callbacks rejects before mutation. Coordinator must additionally fence host/runtime close or reload reentry before host state mutation; this channel cannot install that fence on an unrelated runtime. Independent callers may close.

Host owns executable/environment/workdir acquisition, job/process-tree/stdin/stdout/stderr lifecycle, admitted HttpClient closure, prepared registered callbacks, atomic catalog generation admission, resources and lifecycle withdrawal, CLI/session activation and test registration. No shared owner files are changed.

## Implemented protocol behavior

Stdio uses replacement UTF-8, bounded LF frames, one preceding CR stripped, blank lines ignored and nonblank partial EOF rejected. JSON-RPC validates version, string/finite-number IDs, method/response shape, and exclusive result/error. Writes include newline and join write plus flush originals. Reader or framing failure marks the channel disconnected.

Channel generates monotonically increasing safe numeric IDs, bounds inflight requests and callbacks, correlates response/error/progress by typed ID, preserves remote error code/message/data, and independently bounds result bytes. Progress merges _meta.progressToken while retaining other supplied metadata, resets the request deadline, and serializes/joins borrowed progress deliveries. Cancellation/deadline completion stops and joins the physical send, timer/cancellation callback originals and progress before returning; notifications/cancelled is written and joined for cancellable requests. Initialize never receives a cancellation notification. No uncertain request replay occurs. Ping, supplied immutable roots/list and method-not-found server requests are answered through the same wire owner. Unknown/late response IDs are dropped. No arbitrary local tool invocation or new callable authority is introduced.

HTTP sends JSON POST with JSON/SSE accept headers, captures a printable session header and sends the negotiated protocol header. JSON accepts a message or bounded body batch. Requests reject 202/204 without a result; notification/response bodies are disposed without unnecessary reads. SSE handles LF/CRLF, comments, empty/missing/message event names, data-line joins, priming IDs including empty IDs, digit retry fields, replacement UTF-8/BOM and pending EOF dispatch. Event and line bytes are bounded. A POST SSE reader ends after a matching reply and the remainder of that acquired chunk, then disposes its body; request completion does not leave an unjoined response pump. Subsequent future data on that response body is not consumed.

The SSE failure-receipt successor distinguishes cleanup from resumable exchange/read failures without changing the external exception objects. Response/body cleanup faults never resume and never become successful results after an acknowledged reply. Terminal read exhaustion rethrows the retained original read exception, including when a later resumed stream merely ends without answering. Original read and cleanup faults aggregate once by reference; no POST replay or owner abandonment is introduced.

GET opens only if explicitly enabled after initialized; 405 means no GET stream. GET and response-stream resumptions are opt-in, bounded total attempts with capped delays and Last-Event-ID. No POST is replayed. Status errors retain code and session-expired metadata, excluding server error bodies. Auth, session and protocol errors do not resume. Explicit DELETE close has a supplied finite deadline, owns its response and retains cleanup failure rather than silently discarding it.

Close returns one original Task and terminal failure across repeats. Each owner fences admission and requests cancellation/lease stop before draining original start/send/read/body/callback work. Stdio joins transferred lease close and reader; HTTP joins sends, bodies, GET and optional DELETE; channel joins request timers/cancel writes/progress and host callbacks. Held originals are directly awaited, never replaced by a canceled WaitAsync proxy. Completed invocation faults remain with their invocation; background reader/host-notification and owner-close faults remain observable on close. Dispatched callbacks are tracked before scheduling and canceled before new effects if they have not started.

## Bounds and fidelity limits

Defaults are 16 MiB frames, 4096-byte read chunks, 64 inflight requests, 64 pending callbacks and safe numeric IDs up to 9007199254740991. Existing JsonData adds depth 64 and duplicate-member rejection. TimeProvider is injectable; positive finite request deadlines are capped to native timer range; nonpositive/nonfinite deadlines disable the timer as in pinned client. GET reconnect count is capped at 1000 and delays are finite profile values. Host must cap external invocation concurrency and require finite settlement from its supplied leases/exchanges/callbacks.

The wire frame ceiling bounds allocation before JSON materialization; per-request MaximumResponseBytes additionally bounds the decoded result. These are separate ceilings. Coordinator must pass a wire MaximumFrameBytes no greater than its runtime response ceiling when that profile requires the same pre-materialization cap; a smaller per-request override alone does not retroactively lower the shared reader's allocation ceiling. No unbounded wire accumulation is permitted.

Native restrictions/differences requiring qualification: malformed stdio/SSE frames fail their reader rather than emit a recoverable error and continue; duplicate members/depth/Unicode whitespace and replacement decoding are not full JavaScript differentials; unknown response IDs have no upstream diagnostic event; server-side generic request handlers/cancellation/elicitation/sampling are not implemented beyond ping and immutable roots; SSE numeric retry values outside int range are ignored and profile-clamped; GET retries are a total bound, not upstream healthy-stream retry resets; HTTP status error bodies/auth challenges are not projected; DELETE faults are retained; POST SSE stops on reply rather than consuming future trailing notifications. Session-expired recovery and any approved replay policy remain host work. These are not claimed as full pinned transport parity.
