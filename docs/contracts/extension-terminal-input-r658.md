The existing native UI supplies dialogs and text publication. Existing PiSharp.Tui leaves supply text, select-list, raw console transport, decoding, keybindings and the text editor; this lane changes none of them. The pinned source `packages/coding-agent/src/core/extensions/types.ts` declares TerminalInputHandler as `(data: string) => { consume?: boolean; data?: string } | undefined` and onTerminalInput as an unsubscribe-returning interactive-only operation. `packages/tui/src/tui.ts` applies listeners in registration order, stops on consume, transforms provided data (including empty strings), and suppresses an empty final string.

`IExtensionTerminalInput.OnTerminalInput` maps that synchronous shape to a nullable native result and disposable unsubscribe handle. The same synchronous delegate object within one scope is registered once. `OnTerminalInputAsync` is an explicit native extension of the source ABI for task-bearing callbacks, with the original IExtensionContext and linked caller/context/retirement cancellation. It captures and observes the actual returned Task. Scope and hub disposal cancel admission and join admitted callbacks, retaining fault task identity and exception DAG membership/multiplicity. Faulted and synchronously thrown OperationCanceledException remain faults; a genuinely canceled task returns a no-input Cancelled outcome. Callback output arriving after scope retirement or connection close cannot be forwarded. Unsubscribe is idempotent and excludes callbacks not yet admitted, while an already admitted callback is joined by its owner.

`ExtensionTerminalInputHub` is an actual callable host admission seam for a single connection/session generation. The trusted host must construct it only for a connected interactive terminal, open and own scopes for admitted callback contexts, and expose the optional IExtensionTerminalInputContext feature. It must dispatch raw input after consuming protocol responses, before decoding/focused-component delivery. It forwards only a Forward outcome's Data. The hub itself acquires no terminal reader/writer and grants no renderer, editor, or session action. The synchronous API preserves source data transformation; owner scoping, a fixed subscription snapshot per admitted input, asynchronous callbacks, and bounded admission are explicit native adaptations. New subscriptions during an in-flight dispatch start with the next input. Source JavaScript Set iteration can visit newly inserted listeners during that same dispatch. This is not unchanged TypeScript plugin compatibility.

The host owns serialization of real terminal events and connection/session replacement. Closing the old hub before publishing a new hub rejects old generation input and waits for old callback originals. Generation numbers are supplied by the admitted host; a matching number alone is not a credential or a new host capability. The facade accepts at most 256 scopes per connection lifetime, 256 registered subscriptions, 256 concurrent input dispatches and 256 pending-plus-retained faulted callback originals per scope. These bounds fail explicitly, rather than detach work. Closed scopes remain bounded historical ownership records until hub retirement.
