## SDK and host path

An actual native extension context supports optional `IExtensionToolActivationContext.GetActiveTools()` and synchronous `SetActiveTools(ImmutableArray<string>)`. Hosts advertise `callback-tool-activation` only when an `IExtensionSessionToolActivationProvider` is installed. Native CLI's existing session provider installs the scope; generic native callback contexts forward through it. The base context ABI remains unchanged. The returned revision and ordered names acknowledge a logical selection, not a disk checkpoint. `PersistentAgentSession.GetActiveTools()` reports that selection immediately; its Agent snapshot still reports the current request's scheduler until a boundary publishes the replacement.

Names use existing descriptor/runtime limits and ordered de-duplication; unknown and Hidden names are ignored. Registered metadata and callable/model exposure remain distinct. Preparation uses leased synchronous callbacks outside session/registry gates, rejects reentrant activation, and retains only immutable presentation metadata. No provider transport, terminal, RPC, Node facade, settings refresh or registry-refresh behavior is added.

The setter does not change the invoker captured by a running tool batch. At the next request boundary the Agent validates configuration, pending input projection, transcript budget, and constructs its replacement scheduler before admitting the host publication. The session compares captured selection, context/log, and actual run identities before append admission. A stale boundary retries at most 16 times without admitting its staged checkpoint. Once append admission begins, the original append is joined with an uncanceled settlement token; the actual acknowledgment is retained and the session and Agent publish matching selection before returning. Calls admitted through the new scheduler retain final argument preparation, mandatory policy authorization, owner generation, exposure filters, nested invocation tracking, and cleanup joins.

Cancellation before append admission leaves the prior acknowledged configuration and accepted logical selection available to a later prompt. Cancellation after acknowledgment retains the actual checkpoint and matching scheduler. Retained callback scopes, extension cancellation and retired attachments reject effects; synchronous scope actions are tracked by the existing scope disposal join. Concurrent prepared proposals compare the selection epoch and cannot overwrite a newer accepted selection.

An activation setter rejects the short admitted append/publication transaction, just as it rejects other selected-state transactions. This prevents a revert to the old raw selection from discarding a proposal while an already admitted checkpoint is completing. Before admission, newer accepted logical proposals cause the staged boundary to retry.

## Selected-state reconciliation

Host durable configuration supersedes pending logical selection, including an explicit active-name setter whose raw durable selection is already current. Opaque tree revisions include the logical epoch. Successful no-summary navigation prevalidates restoration bounds and checked epoch arithmetic before publishing Agent/context state, clears the pending selection, and returns a revision containing the post-restoration epoch. Veto, owned abort, and current-leaf no-op retain the logical selection. The public navigation signatures are unchanged. The terminal caller can keep its existing capture/select contract; no frontend edit is required for this seam.
