## Exact caller boundary

The core owners add `Task StopAdmissionAndJoinAsync()` on PersistentAgentSession and ReplaceableAgentSession. The call closes admission irreversibly, cancels cooperative original work and directly joins it. Repeated calls share the original task; self-wait guards run before lifecycle mutation. Caller cancellation cannot detach this task. Stop does not release the current Agent, store or SessionRuntimeLease. Existing DisposeAsync remains the final resource release and reuses this first phase. Failed cancellation callbacks stay failures; all final closes are attempted and actual exception causes are retained. Previously recorded boolean cancellation-failure facts remain failures even where their original cause was not retained by the old abort path.

The native host caller extension is internal, in the existing CLI assembly:

```csharp
RpcSessionCommand.RunWithPresentationAsync(
    args, input, output, diagnostics, presentation, hostCancellation,
    userShutdown: IsExplicitUserShutdown,
    stopTerminalAndJoin: async stopped =>
    {
        // Trusted terminal owner closes its input/paint admissions and directly joins
        // its original drain, read, render and leave/restore tasks here.
        // Aggregate cleanup failures instead of skipping later original joins.
        return stopped.AcknowledgeTerminalStopped(terminalCleanupFailures);
    });
```

`stopTerminalAndJoin` has type `Func<RpcSessionShutdownSettlement, ValueTask<RpcTerminalStoppedAcknowledgment>>?`, appended to the existing signature. The settlement provides phase-one `Failures`, optional actual `Session` snapshot, and compact `ChildCleanup` receipts. Only its own first acknowledgment is accepted; identical repeated acknowledgment returns that receipt. Foreign acknowledgments and a repeat attempting to replace/discard failure facts fail. The callback itself is awaited with no caller token. The terminal owner must return only after its original terminal operations have joined, including failure paths. It must not await `RuntimeCleanup` or `Completion` inside this callback: those tasks complete after it returns.

After the acknowledgment, the command joins profile/session resource release. `RuntimeCleanup` reports runtime-release failures; `Completion` retains all operation/first-phase, terminal acknowledgment, runtime-release and final checkpoint failure facts. The caller must still directly await the original host task, including its final borrowed diagnostic write. Invalid/throwing acknowledgments retain failure and still attempt every resource close; disconnected/retired UI scopes have no repaint or input authority during that cleanup. A failed acknowledgment never yields user-intent success.

Terminal caller files are unchanged in this successor. Existing callers compile against the optional argument; the assigned terminal worker must wire the actual drain/restore acknowledgment before claiming the complete interactive ordering. The plain nonterminal RPC entry point uses the same joins and immediately performs final resource release because it owns no terminal to acknowledge. A terminal caller which omits the new argument retains its historical disposal ordering and gets no two-phase terminal qualification.

Specific existing caller dependency: TerminalSessionCommand currently completes its acknowledgment receipts in RunHostAsync's final block, after the original host returns. The new callback must complete those receipts at phase one before joining the original terminal input task, and must not await the original host inside the callback. Its currently post-host connection/select-list/view/read/resize cleanup must be moved into the callback's owned terminal stop, with idempotent fallback for failure paths. This avoids a host/input/receipt cycle and supplies the real drain/render/leave acknowledgment. The callback identity is the actual settlement object; it is not an extension UI presentation identity.

No additional plugin activation, source loading, trust policy or executable launch path is introduced.

Replaceable stop closes attachment/catalog/mutation admission and cancels lifetimes, joins original discovery and mutation work, then stops every adopted session. Previously admitted staged rollback and historical session retirement may already be disposing their rejected/retired resources; stop joins those originals and does not invent a second lifetime. Current resources are retained for the second phase. The existing SessionRuntimeLease owns any host-provided child supervisor and its DisposeAsync is still directly awaited in the second phase. No independent PID discovery or frontend child kill operation is added.

After the original mutation joins, stop captures and cancels any final adopted lifetime as well. No gate is held across those cancellation callbacks or resource disposal. Shutdown execution frames reject recursive waits on their own stop/disposal; synchronous cancellation also tracks its owning thread because CancellationToken.Register may restore an older ExecutionContext. Independent repeat callers still share the original task. These checks do not remove or delay any original join.

NativeProcessRunner already returns only after its owned job termination/confirmation, root exit, actual stdout/stderr pumps, drain/collector, output storage and process lifetime cleanup. The adapter directly awaits the actual runner and retains compact owner-scoped ordinal/process/exit/cleanup/capture/diagnostic facts, without retaining large output or command arguments. Incomplete cleanup/capture, output I/O, lifecycle/progress failures, or an uncompleted original runner stay host shutdown failures. Clean canceled or ordinary nonzero-exit outcomes retain their actual cleanup status and are not mislabeled as uncertain cleanup. Bash tool work joins this receipt before phase one returns.

NodeWorkerSupervisor already supplies `Termination` and `NodeWorkerSupervisorException.Termination` after joining its actual protocol/input close, root/tracked child exit, post-protocol stdout and stderr tasks, and owned stream/resource closes. ## Cancellation and source relationship

Dispatcher input cancellation is recognized through the actual JsonlReader linked read token (internal `OwnsCancellation`) or the dispatcher input token. Startup cancellation uses its actual admission token. Native observation callbacks normalize cancellation from their known private linked/admitted tokens to the known admission origin after original callback/context cleanup; foreign OCEs retain their identity and remain failures. Independent cancellation, I/O errors, failed terminal restoration, native cleanup failures and uncertain child settlement cannot be suppressed by the user-intent flag. Only clean joined shutdown allows explicit terminal user intent to succeed.
