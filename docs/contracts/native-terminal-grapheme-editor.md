## Source-compatible controller

`PiSharp.Tui.Input.TerminalTextEditorController` owns immutable `TerminalTextEditorSnapshot(Text, CursorUtf16Offset)` draft snapshots in one input consumer. The host owns rendering, focus, submission, cancellation and console lifetime. The default and maximum draft limit is 65,536 UTF-16 units; smaller positive constructor limits are supported. The controller has no Node or process dependency.

| Operation | Behavior |
| --- | --- |
| `SetText(text)` / `Clear()` | Normalize CRLF/CR to LF and tabs to four spaces; commit with the cursor at the end. Notify even when unchanged. |
| `InsertText(text)` | Programmatic insertion uses the same normalization. Nonempty insertion emits one notification. |
| `SetCursor(offset)` | Admit a valid UTF-16 scalar boundary, including a source cursor inside a newly joined grapheme. Emit no notification. |
| `HandleInput(TerminalText)` | Insert decoded literal text at the current cursor, then notify for nonempty text. |
| `HandleInput(TerminalPaste)` | Decode source-style letter CSI-u control encodings, normalize CR/LF/tab, remove characters below U+0020 except LF, apply the source ASCII-word/path-prefix space rule, then insert and notify. DEL and C1 characters remain data. |
| Backspace / Delete | Segment the logical line prefix/suffix at the current seam, remove the adjacent cluster or line break, retain the source edit seam and notify even for an empty deletion. |
| Left / Right / Home / End | Move through prefix/suffix clusters or to LF-delimited logical line boundaries; emit no notification. |
| Shift+Enter | Insert LF and notify. Submission, other bindings and release/protocol/unknown events remain host concerns. |

Successful insertion/deletion retains the nominal UTF-16 seam. For example, inserting ZWJ between two women emoji leaves the cursor after the ZWJ inside the resulting cluster; subsequent Backspace segments the prefix at that seam. This is also required for regional-indicator joining and joining a line with a leading combining mark. Surrogate-pair interior cursors are rejected.

`TextChanged` is a synchronous native event emitted after a successful operation. No-op SetText/Backspace/Delete callbacks are part of this contract. Size, Unicode and cursor rejection preserve the prior snapshot identity and emit no callback. A subscriber exception propagates after the mutation has committed; the trusted host owns subscriber reentrancy. Normalization intermediates are bounded by the input limit, and admission checks the final expanded draft atomically.

This existing controller keeps its literal large-paste behavior: a prepared paste exceeding 1,000 UTF-16 units or containing at least ten LF characters stays literal within its native bound and returns `LiteralLargePaste`; `PasteMarkerExpansionSupported` remains false. Opt-in marker storage, expansion and undo use the separate controller below. The literal controller has no undo. Command history, autocomplete, focus/keymaps and complete visual navigation remain open.

## Opt-in bounded paste marker controller

`TerminalTextEditorPasteController` is a separate single-consumer type with the same Snapshot/SetText/Clear/InsertText/SetCursor/HandleInput/TextChanged operations, plus `GetExpandedText()`, `RegisteredPasteCount` and `RetainedPasteCharacters`. The existing controller's public API and defaults are unchanged. Internal shared helpers reuse its text/paste preparation and validated snapshot commit without subscribing an underlying observer; this controller emits its own actual notifications after draft and registry state commit.

`Snapshot.Text` contains marker display data. A host must explicitly use `GetExpandedText()` for submission or external-editor content. Submission, trimming, render scheduling, console ownership and cleanup remain host responsibilities. Boolean method results describe changes to the logical text/cursor snapshot; SetText can reset a registry and notify while retaining an identical display snapshot.

After the existing ordered paste preparation, content with more than 1,000 UTF-16 units or more than ten lines is stored under a sequential ID. Its marker is `[paste #1 1001 chars]` or `[paste #1 +11 lines]`; line count includes the final empty line after LF. The line form takes precedence. Callbacks contain marker text, not expanded content. Small paste remains literal.

Expansion follows the source's registry insertion order, making one replacement pass per canonical ID. Each pass replaces all matching aliases with literal stored content; `$&`, `$1` and similar content are data. This is not recursive expansion: a later pass can expand a forward reference introduced by an earlier one, while an earlier/self reference introduced after its pass remains literal. Leading-zero IDs can be atomic for segmentation but do not match canonical expansion IDs.

Only markers with registered numeric IDs become atomic segments for Left/Right and adjacent deletion. Programmatic scalar seam cursors can remain inside marker text, in which case prefix/suffix segmentation follows the source slice. Forward Delete removes display text but retains the registry and counter. Backspace on a registered marker removes its entry, decrements the counter and shifts higher IDs in ascending order, then renumbers matching text throughout the draft. The source's bare-alias renumbering quirk is preserved: an absent suffix becomes the literal `undefined`. SetText/Clear reset registry and counter even when display text is unchanged.

Native resource admission is stricter than upstream's unbounded storage. Logical draft, cached expanded output at every ordered pass, and total retained paste content are each bounded by the configured 1–65,536 UTF-16 units. The constructor also admits 1–64 registry entries. Forward-deleted entries still count toward retention until Backspace or SetText/Clear removes them. Expansion multiplicity, normalization growth, marker-label size and entry overflow reject before any snapshot/registry/counter/cache change or callback. Subscriber errors propagate after all state has committed.

These bounds are disclosed native admission policy, not an approved global source deviation. Numeric alias renumbering is implemented for positive Int32 IDs; formatting/renumbering of larger unknown source-number aliases is unqualified. Source behavior at rare renumbering/cursor combinations, command history, visual marker wrapping, keymaps and the complete Editor contract remain outside the accepted corpus. No whole-marker, editor or package parity claim follows.

## Bounded undo in the paste-aware controller

The existing two-parameter constructor is unchanged. `HandleInput` accepts the upstream default Control+minus binding for press/repeat and ignores release. The incremental decoder correction maps raw U+001F to `TerminalKey("-", Control)`; CSI-u `45;5u` has the same identity. CSI-u `95;5u` remains Control+underscore and is not an undo binding. Control+Z remains ignored. Other keybindings and complete protocol equivalence are unqualified.

An undo frame retains the immutable draft/cursor, ordered paste entries, ID counter, retained content and expanded cache. Undo restores the complete state and emits one actual marker-text callback; an empty stack emits none. There is no redo. A source cursor inside a joined grapheme remains at its saved scalar seam. Marker Backspace/renumbering, forward Delete retention and programmatic registry reset are undoable.

Typing coalesces non-whitespace text, including punctuation, until another action ends the group. Any ECMAScript `/\s/` character in a decoded text operation begins another undo frame; BOM is whitespace and U+0085 is not. Movement and no-op deletion end typing groups without adding a deletion frame. Nonempty programmatic insertion, Shift+Enter and raw nonempty paste are atomic undo actions. A nonempty paste filtered entirely away still pushes a frame without an insertion callback; undo emits the unchanged draft. Truly empty paste/insertion leaves grouping and history untouched. SetText/Clear push only when normalized display text changes, while still resetting registry/counter and notifying when unchanged.

`UndoDepth` and `RetainedUndoCharacters` report bounded history. `MaximumUndoEntries` is 64; `MaximumRetainedUndoCharacters` is 1,048,576 UTF-16 units. Each frame conservatively counts draft text, all retained paste content and its expanded cache, including shared strings. Oldest frames are evicted on either limit. Fixed entry/registry bounds also bound metadata. Upstream storage is unbounded; this retention policy is disclosed native behavior and is not a global parity exception. Candidate rejection preserves history, grouping, draft, registry and cache and emits no callback. Subscriber exceptions occur after the complete edit or undo has committed.

`Reset()` is the host boundary after accepted submission, cancellation or teardown: it empties draft/registry/counter/undo, ends action grouping and then notifies once. The bounded kill ring persists, as it does across source submissions. `Clear()` remains an undoable programmatic SetText. Hosts must choose Reset at prompt boundaries so older drafts cannot be recovered through undo. Killed content remains subject to the separate ring limits below. Submission and trimming remain host-owned; this standalone contribution does not simulate either.

## Default control editing and line kill/yank

This unit completes the logical-line delete/recover/cycle workflow within the existing paste-aware type; it adds no editor/helper type and leaves the two constructor parameters unchanged. The default alias profile is:

| Binding | Native editor action |
| --- | --- |
| Control+A/E, Control+Home/End | Logical line start/end |
| Control+B/F | Previous/next source-seam grapheme or line break |
| Control+D, Shift+Delete | Forward character deletion; the host intercepts empty-draft Control+D for quit |
| Shift+Backspace | Backward character deletion |
| Control+J, Shift+Enter, Alt+Enter | Insert an undoable LF |
| Control+U/K | Kill the prefix/suffix of the logical line; at a boundary, kill the adjacent LF |
| Control+Y | Insert the most recent killed text |
| Alt+Y | Replace the most recent yank with the next older ring entry, rotating the ring |

The decoder maps raw U+000A to Control+J and raw CR to Enter. CSI-u 57349 is literal U+E005 text in pinned Pi, while source keypad Delete codepoint 57426 is Delete; the native decoder corrects that specific earlier conflation. None/Shift-modified decoded single printable scalars use the same literal typing/grouping path as TerminalText. Releases remain ignored. Broader Kitty function, shifted/base-layout/lock, modifyOtherKeys and terminal-specific identities remain unqualified. The correction is necessary to match a frozen public source schedule; its expectation is not rewritten to agree with the earlier native mapping.

Consecutive line kills prepend for backward deletion and append for forward deletion. Successful movement, typing, programmatic changes, paste and undo end kill accumulation; a no-op line kill emits an unchanged callback while preserving the prior action. Line kills retain paste registry/counter entries, so yanking a marker can still expand its stored content until SetText/Clear/Reset removes the registry. Kill entries contain literal display text, including marker aliases and LF. Each destructive kill and yank pushes one ordinary undo frame. Undo restores draft/paste state without restoring or clearing the source's independent kill ring.

Yank-pop works only directly after a successful yank/yank-pop with at least two entries. It preflights both intermediate and final logical/expanded drafts against native limits before modifying anything. It then commits removal and emits its actual intermediate notification, rotates and inserts the replacement, then emits the final notification. One undo frame covers both phases. Observers see Snapshot.Text equal to each callback's text. If the first observer throws, deletion and its undo frame stay committed; rotation/insertion do not run. If the final observer throws, replacement and rotation stay committed. This preserves source sequencing; subscriber reentrancy remains a trusted-host concern.

`KillRingCount` and `RetainedKillCharacters` expose resource accounting. At most 64 entries and 1,048,576 conservative UTF-16 units are retained, evicting oldest entries. Each accumulated entry is also bounded by the configured 1-65,536 draft limit. Reset keeps this bounded ring while clearing prompt/undo/action state; SetText/Clear also keep the ring and end actions. Native admission failure preserves ring, action, snapshot, registry, expansion, history and notifications. These logical retention limits are disclosed native policy, not upstream heap or global parity claims.
