# Experimental Completions source run

This candidate introduces `CompletionsHttpSseTransport.StartAsync(request, cancellationToken)` and the invocation-owned `CompletionsRun`. The default `IChatTransport.StreamAsync` uses the same run, HTTP source, decoder, reader executor and mapper. Its consumer reads canonical events. Public `StartAsync` selects source DTO observation and bounded emission retention; it does not select a different abort, reader-cancellation or cleanup policy. Direct parsed `OpenAICompletionsWireSource.StreamAsync` retains its existing joined contract.

`SourceResult` is the actual semantic producer task. Normal exact `[DONE]` waits for real reader Cancel and Release before that producer finishes. Natural EOF releases without Cancel. An observed abort or source error can finish the producer while actual pending read/decoder work, reader cancellation or physical disposal remain held. The message handle returned by that task is the same producer-owned handle retained by queued source events. Its `Snapshot` returns an immutable owned revision; `Emission` remains the immutable revision captured at publication. No final-message copy is substituted into earlier emission snapshots.

`CleanupCompletion` joins admitted decoder/read work, independently executed cancellation/release, physical body/response/request cleanup, and the retained discard drain when the consumer returns. `CanonicalCompletion` then provides the joined native result. A source Stop followed by physical cleanup failure remains source Stop and produces canonical Error. An already failed/aborted native result keeps its primary failure while the separate typed cleanup outcome exposes the additional failure. Source result or source terminal publication grants no tool, session or durable-write authority. The default transport withholds the successful final batch and terminal until physical ownership has settled and publishes a terminal consistent with its canonical result.

The existing CLI, TurnRunner, session and RPC callers consume the default canonical transport through their existing joined ChatRun path. This patch edits none of those callers or stores. Actual integrated CLI and durable tool continuation remain root-run validation obligations; this document does not claim those executions happened.

`NextAsync` performs the actual outer reader operation and returns `CompletionsIteratorResult`. `ReturnAsync` closes that consumer, joins any admitted read/next operation, returns the actual `{done:true}` DTO with `/value` recorded as own undefined, and transfers the queue to one owned discard drain. It continues the provider. One event reader and one active read/next operation are admitted. Read-token cancellation and explicit run cancellation cancel owned production; disposal shares the actual settlement and joins remaining work. Canonical early iterator disposal also transfers and joins its retained queue. Unconsumed bounded events require reading, return or disposal before a canonical completion waiting on queue ownership can settle. Producer-context disposal is rejected before mutating ownership to avoid self-join deadlock.

The independent internal reader release closes actual lease authority once the admitted read has settled. Its cancellation task and CTS remain owned until cancellation settles. Public strict `ICompletionsResponseBodyReader.Release` still rejects active read/cancellation. An injected executor that refuses independent release is joined and released after its own cancellation settles; this native executor policy remains visible in diagnostics. Noncooperative late reads are joined before decoder buffers or the physical body are disposed, and canceled late bytes gain no provider events. Reader Cancel/Release failures after exact DONE retain the previously approved narrow nonfatal policy only when physical disposal succeeds. Physical disposal and EOF/pre-DONE ownership failures remain fatal.

Source snapshots retain strict owned raw JSON and explicit own-undefined paths, plus `SerializedJson` produced by the accepted production `EcmaScriptJsonProjection` over the actual DTO value. The serializer never changes original native numbers, raw tokens, messages or durable JSON. Per-value character/UTF-8 budgets default to 8 MiB and are configurable only within 2..8,388,608. The event channel defaults to 32 and admits 1..4096 capacity with awaited backpressure. Public source emission retention is separately limited to 4096 entries and 4,194,304 cumulative raw-plus-serialized UTF-16 characters. Existing HTTP, mapper, Unicode, unique-key, retained raw-syntax and depth controls remain; projection also keeps its own node/property/number/token bounds. Bounds fail closed. Initial pending message and Start DTO admission precede linked CTS/reader resources and HTTP effects; later snapshot/budget failures close the channel and settle source, cleanup and canonical ownership.

`CompletionsPublicFailure` admits only explicitly supplied public failure data: 1..8192 UTF-16 characters, at most 8192 UTF-8 bytes, valid Unicode and no NUL. `CompletionsPublicFailureException` carries that admitted value with a constant exception message. Arbitrary acquisition/callback/cleanup `Exception.Message` is never copied. Abort uses the proven source literal `Request was aborted`; malformed SSE JSON and the empty provider-error case use known bounded SDK literals. Broader SDK APIError formatting remains mandatory work rather than an implicit unsafe exception-message bridge.

The added seven behavior groups use actual owned HTTP handlers, content streams and reader executors: held abort versus cleanup; normal DONE versus EOF; default tool-final and early canonical-close barriers; bounded return/drain and exclusivity; live alias plus explicit/unknown failure admission; noncooperative cancellation, throwing callbacks, shared disposal and self-join denial; and initial/progress budgets, exact public-data bounds, acquisition cancellation, numeric ownership and fatal physical cleanup.

The original 14 strict lifecycle comparisons remain complete. Each case additionally executes a separately labeled actual public-source invocation with its own request, reader, source task, cleanup task and canonical result. Its receipt retains source emission/drain snapshots, real return DTO, held checkpoints, native headers/reader effects and a separate complete compatibility comparison. Abort's additional held checkpoint awaits its actual source task while cancellation remains held; it does not rewrite the earlier canonical checkpoint or source golden. The source run's emission ledger captures real producer snapshots but does not expose a timestamped producer callback trace, so no emission milestone is invented. A source reader checkpoint/WHATWG DTO, enqueue count, SDK host identity, callback representation or ordering gap remains a diagnostic gap wherever the actual native API differs. The old canonical ledger is retained separately; two invocations are never represented as one cleanup owner.

The diagnostic request-header observation uses actual `Headers.UserAgent.ToString()` rather than comma-joining parsed product tokens. It retains actual computed Content-Length and native runtime headers and never fabricates SDK Node/lang/arch metadata. The root-owned existing cancellation test changes only two token identity assertions: the shared run now supplies its own cancellable linked token; factory and body acquisition observe that same owned token and both observe external cancellation.
