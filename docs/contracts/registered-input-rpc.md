# Registered input admission in RPC

`RpcSessionDispatcher` accepts a last optional borrowed `IPromptInputAdmission? inputAdmission = null` constructor argument. A native CLI composition supplies `RegisteredExtensionInputAdmission` built from its actual `ExtensionRegistry` and `ExtensionAgentBinding.Snapshot`. The dispatcher does not discover, activate, mirror, or dispose extensions. The composing host closes the registry/profile after dispatcher cleanup. Omitting the argument preserves the existing canonical RPC prompt and queue path.

When configured, `prompt`, `steer`, and `follow_up` submit `PromptInputSource.Rpc` through `PersistentAgentSession.SubmitInputAsync`. Registered reduction is awaited outside RPC transitions and coordinator state locks. It receives original owned text/images; transforms compose in actual registered owner/insertion order, null images retain prior images, continue retains input, and handled stops reduction. The authoritative coordinator owns final message admission, its trusted timestamp, actual Agent invocation or existing queue mutation, and durable checkpoints. Neither RPC nor the admission adapter owns another input queue.

The supplied binding snapshot retains its captured handlers when another owner is added; the added handler appears only in a newly captured binding. Removing a captured owner revokes future admission through that old binding before callbacks or input effects. Hosts select a new binding and admission adapter explicitly at an appropriate idle boundary.

An idle ordinary prompt clears the streaming mode before hooks, matching the accepted source-input coordinator behavior. An active prompt exposes its supplied `steer` or `followUp` mode. A handled active prompt succeeds without a delivery mode; nonhandled active input requires one. Explicit `steer` and `follow_up` use the nonpositional `PromptInputAdmissionOptions.QueueOnly` flag: they retain their explicit mode for hooks while idle, enqueue through the same coordinator/Agent queue, and never start a generation themselves. Handled explicit queue commands reply `handled` and leave both queues untouched. This is an explicit native integration choice requiring unchanged-source comparison; the existing source evidence establishes prompt interception but does not establish identical registered-hook dispatch for every explicit RPC queue command. It is not a permanent exclusion from qualification.

All three dispositions are budgeted before hooks. A started coordinator submission completes after run settlement, so RPC does not await that completion to acknowledge admission. The actual `AgentLoopStarted` event sink first publishes a private entered witness, then waits behind the existing `Ready` barrier. RPC writes and flushes one `started` response before opening that barrier. This protects agent events, input durable commits, and provider work even with a synchronous provider. Queued and handled responses instead await completed coordinator admission. Preflight failures emit one sanitized failure response and start no run; failures after actual entry retain the existing fatal/settlement policy and do not create a second prompt response.

One bounded input-command semaphore serializes source admission while leaving read commands, mode changes, clear, abort, and EOF able to proceed. It is not an output queue or state lock. Recursive input submission from an active RPC input callback rejects before command admission. The actual coordinator retains its callback self-wait protection. Once reduction accepts a generation, dispatcher abort/EOF owns cancellation; cancellation of a caller's already returned prompt wait does not cancel that generation. Cancellation while a registered callback is awaited requests that callback's actual token and joins cleanup before the failure response.

`PromptInputAdmissionOptions.BeforeQueueCommit` is a synchronous trusted host preflight over the final canonical message, a captured actual queue snapshot, and its selected mode. RPC uses it to budget the prospective `queue_update` containing transformed text before mutation. It runs outside coordinator locks with the input self-wait guard; reentrant queue/mode mutation from that validation callback rejects. The coordinator then checks the actual queues again under its short commit boundary. Drain/clear leave suffixes of the validated queues and cannot enlarge their receipt. Growth/replacement triggers recapture and revalidation, bounded to eight attempts; continued contention rejects without appending the submitted input. Delivery modes remain authoritative and do not alter receipt size. Native per-message/per-queue limits, final session schema admission, policy/loadout checks, and acknowledged storage barriers remain independently enforced.

RPC input materialization uses its configured text, image count, JSON depth and command-byte limits for original and transformed values. Zero allowed images is supported; a transform cannot add an image through that boundary. A rejected transformed queue receipt changes neither queue nor durable history and emits no fabricated queue update. Actual accepted queue updates and later durable input messages are observations of the same queue records, including image bodies and raw opaque number tokens.

Monitor continuation joins input admission before starting another generation. If a held input hook spans the previous generation's completion and the coordinator admits a new generation, its actual start adopts a new run state and history offset. The superseded monitor joins and releases its own settlement gate without emitting an extra `agent_settled`. Existing abort intent, bounded automatic continuation, acknowledged message-end barriers, generated-only `agent_end` slices, one output writer, and shared EOF/output cleanup remain in force.

`RegisteredInputRpcTests.Cases()` supplies six offline behavioral groups: actual registered two-hook transforms/continue/images/durable reopen; handled and failed/stale admission without effects; actual entered/flush/durable/provider barriers; idle and busy delivery modes using the same queues and durable drain, including a held hook across actual prior-generation settlement; transformed receipt/image bounds plus clear/mode/growth races, validation self-wait/mutation rejection and eight-attempt contention exhaustion; caller cancellation before and after acceptance, RPC input reentrancy/read controls, EOF cancellation and output-failure joins. Providers are injected parsed event streams, storage is actual temporary-file `SessionLogStore` storage with checkpoint gates, and JSONL output is the real owned writer. Tests use explicit gates and deadlines. They do not replace or weaken existing dispatcher tests or change reference fixtures.
