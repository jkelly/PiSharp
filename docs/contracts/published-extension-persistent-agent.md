# Published native extension and persistent Agent integration

`PublishedPersistentAgentTests.Cases()` supplies three behavioral groups for the experimental native binding. Root must publish the existing repo-owned `fixture.one` project for Windows win-x64, provide the test project's CodingAgent/Sessions references, and register the cases. The tests consume those actual managed artifacts through `PluginAssemblyLoader`; they do not build or publish packages, discover executable plugins, or substitute an in-memory extension implementation.

Each temporary package has an authored manifest with exact artifact hashes. Metadata inspection and execution use separate explicit trust decisions bound to that package, manifest, scope, policy and host generation. The registry snapshot supplies `ExtensionAgentBinding`. Its required validator implements the entire fixture schema `{}`, which imposes no JSON member restrictions; the prepared-tool contract additionally requires object arguments. The final-action policy observes the identical owned arguments and virtual Extension action, without granting file or shell authority. Missing validators, rejected argument admission and final policy denial prevent the actual published callback.

The durable group traverses real request construction, an injected closed `HttpMessageHandler`, fragmented UTF-8/SSE, strict Responses DTO mapping, the public Agent, the prepared invoker, registry lease and published callback. Only the authored inert key and `.invalid` endpoint are configured; the injected handler acquires no network or credential source. The fixture's existing echo callback returns a complete owned result with text, NUL/Unicode, details, arbitrary usage, explicit null, ordered arrays and opaque/programmatic properties. The full execution observation is compared field-for-field, with numeric tokens and array order exact. Canonical tool messages retain the source content/details/usage/error shape; arbitrary result and structured-content properties are not invented as durable tool-message fields. The original complete echo arguments remain in the durable assistant tool call.

An audited wrapper delegates every write, asynchronous flush, flush-to-disk and checkpoint to the actual file store. Live-reader checks use explicit `FileShare.ReadWrite` while the coordinator holds its writer lease. A held tool-message-end subscriber proves acknowledgement precedes the external event and the next provider request; exact physical length, parsed records and flush/checkpoint counts agree with the acknowledged snapshot. Disposal releases the writer. Reopening restores exact records and history without callback execution; a later real HTTP prompt projects the prior function call/result and sees the published text. Provider projection remains its own source-defined shape rather than carrying programmatic result metadata.

The lifetime group holds the published fixture's existing synchronous `HostAction` probe on a worker. This trusted authored probe observes the real execution cancellation token admitted by final policy and releases cooperatively; it is not a claim that the fixture has an asynchronous callback ABI. Concurrent coordinator and loader disposal each share settlement. Cancellation cannot overtake the admitted callback, final tool/message events, actual storage close or published shutdown. The test holds the actual fixture shutdown as a second barrier, verifies registration revocation, zero post-cancellation effects and zero next-provider acquisitions, then checks the durable cancellation record and released artifact snapshot.

These are authored native integration tests, not unchanged-source oracle qualification or independent acceptance. The corpus uses canonical safe integer arguments because the accepted Responses argument serializer still has an unresolved wider numeric compatibility boundary; no numeric rewriting or filtered comparison is introduced. General JSON Schema evaluation, namespaces, nested extension calls, callable/Set/AbortSignal representation, full SDK behavior, CLI/session activation and other provider/authentication families remain mandatory unfinished work. Root owns compilation, execution, immutable receipts and review of this slice.

The first native gate compiled with zero warnings/errors and passed the preceding 27 extension groups, then failed these three integration groups; its original receipt is preserved as `artifacts/published-persistent-agent-first-native.log`. The prepared invoker rejected the echo input's nested NUL string before schema validation or final policy, so the successful callback and cancellation gate were never reached. The dedicated correction admits inert owned argument string values at initial/final admission while retaining executable-string checks, raw budgets, schema and policy. The original complete integration input, callback-effect expectations, denied-policy expectation and durable/lifecycle barriers remain intact. Separate invocation regressions migrate the exact earlier inert-data negative into a positive ownership control while retaining NUL identities and executable fields as negatives. The corrected root gate remains pending.
