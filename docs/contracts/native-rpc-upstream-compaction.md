# Native RPC compact and set_auto_compaction aliases

Source-only implementation based on 68878a0e246110a915c494cd9733412dd28d8208/tree a2bf8399ea2946e94c28c993aeb06ea1a84e2178. The two command names were recognized but unsupported. Existing pisharp_compact, pisharp_set_auto_compaction and branch-summary transactions were inspected and their dispatch moved into one shared partial; no second compaction transaction or provider transport is introduced. Builds, tests, upstream execution and API calls are zero in this lane. Authored expectations remain distinct from qualified observations and accepted parity.

## Pinned wire mapping

Pi v0.99.1 d86654abb8862e201933517d6f1fce9f88dd117f sources were read locally: [RPC dispatch](https://github.com/badlogic/pi-mono/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/rpc/rpc-mode.ts), [typed commands](https://github.com/badlogic/pi-mono/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/rpc/rpc-types.ts), [manual compaction and toggle](https://github.com/badlogic/pi-mono/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/agent-session.ts). No source runtime or differential capture was executed.

compact accepts optional bounded string customInstructions and retains correlated response identity. It calls the existing owning session's CompactAsync with the planner-selected retained boundary and existing default settings. Success data is the result in pinned order: summary, firstKeptEntryId, tokensBefore, estimatedTokensAfter, optional usage and details. These values come from the actual prospective/acknowledged compaction entry and rebuilt context. estimatedTokensAfter sums existing per-message estimates, rather than reporting old provider usage or native checkpoint identifiers. No native generation/checkpoint/skipped fields are added to this alias result.

The manual lifecycle uses compaction_start {reason:"manual"} and compaction_end {reason:"manual",result,aborted:false,willRetry:false} before the command success response. An optional trusted start-delivery hook on the existing persistent/replaceable compaction API runs under the real session reservation and commit ownership, before planning/inference/durable effects; start observers see IsCompacting=true. Existing callers retain null defaults. End follows return of the original CompactAsync transaction, so observers see the released reservation. Generated result, complete success envelope and success end frame are preflighted against the output budget before append. Startup/caller cancellation, explicit abort and EOF retain the existing tracked ContextEditCommand and original session abort/checkpoint semantics.

A cancelled precommit manual operation emits end with aborted:true, willRetry:false, with result/errorMessage omitted, followed by a Compaction cancelled command error. Other started failures emit aborted:false, omit result, and include errorMessage prefixed with Compaction failed:. The native null-plan result becomes an error, never a successful skipped result: Already compacted for a last selected compaction entry, otherwise Nothing to compact (session too small). No end is synthesized for a command refused before start admission. Once physical append is admitted, late abort joins and accepts the actual checkpoint, producing successful end/response. Errors from postcommit observation/output are not promises of rollback; existing acknowledged state remains authoritative.

set_auto_compaction requires a boolean enabled and has no success data property. It applies to the validated captured attachment without requiring a client generation. Enabling requires an explicitly installed summary generator; disabling can operate without one. The admitted model's positive finite contextWindow supplies the native automatic threshold configuration; existing reserve/keep defaults are retained. Enabling itself performs no generation, provider request or transcript append. get_state exposes actual AutoCompactionEnabled. Subsequent ordinary turns use the existing configured automatic compaction service and acknowledged session_compact observation path. Native pisharp_* generation grammar and checkpoint response shapes remain separate and unchanged.

## Explicit unsupported behavior

- Upstream compact first aborts the active response. This alias preserves native idle admission and refuses active/settling runs, input reservations and pending input. Clients can explicitly abort/join first. No implicit global owner abort is introduced.
- Upstream toggles settings-manager persistence. This implementation toggles the current native runtime only, resets default compaction options on configuration, and resets on session replacement. It adds no settings file, per-model settings override or CLI persistence. Existing native automatic admission remains idle-only.
- Automatic threshold execution works through existing services, but upstream auto_compaction_start/auto_compaction_end frames are not published by this slice. It does not relabel native automatic execution as manual events. Overflow retry/source error notification parity remains outside these aliases.
- Hosts without the native owning-session/summary-generator seam cannot compact or enable automatic compaction. Existing native codec/planner bounds, summary options, extension handling, file-operation details and provider qualifications remain. Failure diagnostics outside the mapped cancellation/null-plan cases retain bounded native messages. No broad source, byte-serialization or live-provider parity is claimed.
