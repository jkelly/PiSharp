# Bounded Responses transcript projection

`PiSharp.AI.Protocols.OpenAIResponses.ResponsesTranscriptProjector` is a synchronous, stateless projection of `ChatRequest.Messages` to an owned `JsonData` Responses **input array**. It neither sends a request nor executes a tool. Canonical `TranscriptEntry.WireBody` values remain unchanged. The accepted stream mapper, HTTP/SSE composition, Agent runner and existing contracts are not modified or automatically connected by this slice.

The input is an already normalized transcript with system/user/assistant/toolResult entries. Legacy `Context.systemPrompt` and `Context.tools` normalization is outside this API. Every native entry role must agree with its raw body's role. Assistant bodies use the existing `PiWireJson.ReadMessage` contract; other roles remain raw immutable JSON. Invalid or unfinished assistant histories cannot acquire execution authority through projection.

## Explicit policy and supported items

Construct the projector with immutable `ResponsesTranscriptProjectionOptions`. `Reasoning` is required; developer-role compatibility, mid-conversation system support and inclusion of the initial prompt are explicit options. Default instruction role is developer for a reasoning target unless developer-role support is disabled; otherwise it is system. Mid-conversation system support defaults to false and initial prompt inclusion defaults to true. The composite-call provider allowlist defaults to the pinned wrapper's openai/openai-codex/opencode set; synthetic or alternate policies must supply their own immutable set. `ModelDescriptor` provides identity only. Options are caller declarations, not a qualified model catalog or capability discovery.

The slice supports text-only system/user/tool-result content and typed assistant text/thinking/function-call content. Empty tool output uses `(no tool output)`; multiple text parts join with one newline. User strings, including an empty string, become input_text items; empty user arrays are omitted. Error/aborted assistants are skipped. Pending/deferred assistants are rejected. Complete length-stopped history can be projected, but projection does not grant tool execution permission.

Same-model identity requires provider, API and model to match. Same-model signed thinking, including empty encrypted reasoning, parses its signature into a bounded reasoning object and retains opaque fields such as encrypted_content and explicit future:null. Malformed/non-reasoning signature shapes fail with a sanitized diagnostic. Cross-model redacted thinking is dropped; nonempty visible thinking becomes plain text; empty or unsigned whitespace-only thinking is dropped. Same-model unsigned thinking does not produce a Responses item, following this converter's source behavior. Redacted same-model thinking without a usable signature is rejected as native hardening.

Same-model text uses v1 signature ids and commentary/final_answer phase, or legacy plain-string ids. Missing ids receive msg_pi_<messageIndex> and a suffix for later text blocks. Long ids receive msg_<shortHash>. Cross-model text drops signature/phase and receives fallback ids. Empty projected assistant/user arrays do not advance the fallback message index; a leading system entry also does not advance it.

Function calls preserve their names, strictly object-shaped arguments and matched result links. Cross-model call parts use the pinned ASCII sanitization, 64 UTF-16-unit truncation and trailing-underscore removal. Foreign provider/API item ids use fc_<shortHash>; the hash uses the pinned unchecked 32-bit arithmetic over UTF-16 units and unsigned base-36 output. Same-provider/API different-model function item ids are omitted to avoid reasoning pairing validation. Namespace is sent only for the same model. The canonical call and result IDs remain untouched in the original transcript.

## Systems and complete tool pairs

When mid-conversation systems are unsupported, all system content folds into one leading instruction. Nonempty content joins with two newlines. Named sections retain their position on replacement, disappear on null deletion and move to the end when re-added after deletion. JavaScript array-index key ordering is applied before insertion-ordered other keys. With mid-system support, later sections render the exact pinned update/removal text. A system arriving between tool calls and matched results is held until the pending group closes, preserving result order before the instruction update.

Every tool group must have exactly one matching result per call before a new assistant/user boundary or transcript EOF. Tool name must also match. Missing, duplicate or unknown results fail. Duplicate projected call ids across the admitted transcript, normalized collisions, empty normalized call ids and composite ids with more than two parts fail explicitly. These stricter admission rules are native hardening.

Upstream inserts `No result provided` tool results with `Date.now()` for orphan calls. This initial slice rejects that path and contains no clock shim or synthetic orphan result. Images, unknown roles/content, custom/grammar tool calls and nonempty tool declarations/removals are also rejected. Additional-tools, tool search, complete payload fields, authentication, catalog policy and provider invocation remain outside this input-array contract.

## Argument serialization and numeric boundary

The Responses function argument is an opaque JSON **string**, generated according to the supported `JSON.stringify` profile. Object array-index keys sort numerically, followed by other keys in insertion order; arrays retain order. Quotes, backslashes and controls are escaped, while valid Unicode including U+2028/U+2029, private-use characters and supplementary pairs remains literal inside the argument string. The enclosing wire JSON may escape those characters without changing the decoded opaque string. Nulls and booleans retain their values.

The initial argument-number profile accepts only canonical signed integer tokens from -9,007,199,254,740,991 through 9,007,199,254,740,991. Fractional forms, exponent notation, negative zero, trailing scale such as 1.0 and larger integers fail with UnsupportedNumber. Exact 2^53 is deliberately excluded even though JavaScript can represent that particular value; this is a narrower profile, not evidence of its precision loss. No general JavaScript number formatting/rounding is claimed. The three genuine captures contain no argument numbers; accepted integer boundaries are separate authored checks. The projector does not apply computed-cost normalization or rewrite raw transcript numeric tokens.

All admitted strings and property names must contain paired UTF-16 surrogates. Unpaired values fail rather than being replaced or silently removed; upstream sanitizeSurrogates removal/JSON.stringify escaping for those values is outside the supported native profile. Duplicate-key rejection comes from the existing owned JsonData/PiWireJson contracts, including parsed signatures, and is native hardening.

## Bounds, cancellation and failure taxonomy

Defaults are 256 entries, 65,536 serialized UTF-16 characters per entry, 1,048,576 serialized input characters, 1,024 total content blocks, 32 JSON container levels, 1,024 output items and 1,048,576 serialized output characters. Depth may be configured from 1 through 64. Other limits must be positive; output-character capacity must allow the two-character empty array. Options are validated at construction.

Input bounds apply before interpretation. Parsed reasoning/text signatures also receive depth validation. Output bounds include the containing array, separators, all serialized item fields and the extra output-array depth level. Argument strings and folded instructions derive from the admitted input. Caller-owned parsed values, intermediate lists, JSON nodes, string builders and serialization buffers allocate additional temporary memory; these are logical admission/state bounds, not a total heap cap.

Cancellation is checked at entry, during each projection pass and JSON traversal, during argument generation and item admission, and before return. The synchronous projector has no asynchronous work or disposal lifetime. The deterministic native check verifies already-cancelled admission and that cancellation does not corrupt a prior or later projection. It does not claim a timing-based mid-computation cancellation test.

`ResponsesProjectionException.Failure` distinguishes InvalidTranscript, UnsupportedContent, UnsupportedNumber, UnsupportedUnicode, UnsupportedSignature, UnmatchedToolResult, IdentityCollision and ResourceLimit. Messages are fixed and contain no rejected text, signature, arguments or identity. Caller cancellation remains OperationCanceledException. Tool schema validation/authorization and execution are still separate Agent responsibilities.
