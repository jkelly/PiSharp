# Completions source abort reader release

Pinned Pi v0.99.1 (`d86654abb8862e201933517d6f1fce9f88dd117f`) uses OpenAI SDK 7.19.0. Its `createAbortableSSESource` starts cancellation on abort and calls the actual reader's `releaseLock()` before propagating source completion. Abort does not await the pending cancellation promise. A genuine source probe with a held ReadableStream pull and held/rejected cancellation confirms release before Error/result, while the physical pull remains held. Normal exact DONE instead awaits cancellation before release and normal completion.

Previously, native interrupted close started a background release worker that first awaited `CompletionsResponseInput.CancelAsync()`. That task joins physical input ownership. Thus Error/result could precede logical release, deterministically with a held physical pull and intermittently with a cooperative one. The original strict `abort-pending-read-cancel-gate-rejects` public milestone ordering exposed the latter race.

The source-facing prefetched-input path now attempts actual logical reader release synchronously after starting cancellation and before publishing source Error. The default stream reader over `CompletionsResponseInput`, including actual delegates that wrap it, closes its lease authority at that point. Admitted read/cancel tasks retain their cancellation resource until settlement. Their body input, bytes, decoder operation and physical response remain owned by the same invocation. New reads are rejected after release; no EOF, DTO, bytes or cancellation settlement is fabricated.

An executor that refuses release while its own read is active retains the existing deferred release and independent source-abort behavior. Its actual admitted work is joined before release and physical disposal. The transport does not force an arbitrary executor's release policy. A release exception is retained as native cleanup failure without copying private text into source or canonical messages.

Canonical physical-body operation retains its joined read/cancel/release policy. Every path still joins decoder work, cancellation, input disposal, physical body/response/request disposal and retained cancellation resources before canonical completion. Earlier logical source release grants no assistant-commit, tool, durability or canonical authority. Exact DONE, EOF, reader DTOs, enqueue behavior, detached consumption and auth/retry preparation retain their existing contracts.

The focused tests hold both physical read and cancel settlement, assert release before the actual Error publication, then prove cleanup and canonical completion remain pending. They cover rejected cancellation, release faults/private-data suppression, refusal by a noncooperative custom executor, late-call rejection and canonical joined controls. Existing noncooperative physical/result-reader controls now assert the source-supported early logical release while strengthening their physical ownership checks. The original strict comparator, fixtures, source lock and golden captures remain unchanged.
