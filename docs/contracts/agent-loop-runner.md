# Bounded append-only Agent loop

RunWithContextAndAbortSettlementAsync separately opts into the [high-level aborted-work contract](abort-settlement.md). Authoritative events use an uncanceled settlement token; finish callbacks retain actual canceled work. Its genuine case-seven comparison includes the real thinking default and aborted signal. Existing RunAsync/RunWithContextAsync and the original default differential projection below retain their accepted propagation contracts.

`AgentLoopRunner` composes the accepted `TurnRunner` and tool scheduler into sequential requests. Its fixed `ModelDescriptor`, injected clock, prepared system/user messages, required asynchronous request callback and awaited `IAgentEventSink` are caller-supplied. Each run owns an immutable `TranscriptEntry` array; every append creates a new array, so retained request/turn snapshots cannot change. Provisional stream observations remain outside canonical history. The accepted assistant-end barrier commits the final assistant before tool preflight; finalized source-ordered tool results append after the batch settles.

`RunAsync(initialMessages, callbacks, sink, cancellationToken)` retains its existing initial system/user admission, including an empty batch. `RunWithContextAsync(canonicalHistory, newInputMessages, callbacks, sink, cancellationToken)` admits prior history separately, appends the new system/user inputs once, and includes that complete combined history in every request and returned transcript. Only the new inputs emit `AgentLoopInputMessageStarted`/`Ended`; prior messages emit no replayed input, assistant or tool events. Turn indices and the turn bound restart for each run. Prior tool calls, including calls retained in error/aborted assistants, never enter the scheduler or execute again. Retained histories and request/turn snapshots remain immutable across multiple runs.

Canonical history must be an initialized immutable array of owned entries whose role matches the raw object. System/user entries retain the existing raw-message admission. Assistant history must read through the current `PiWireJson.ReadMessage` grammar, have a finalized stop reason (not Pending/Deferred), nonempty API/provider/model and unique nonempty call IDs/names within each assistant. Tool-result history uses the current native text-only result grammar: nonempty `toolCallId`/`toolName`, integer timestamp, boolean `isError`, present `details` and an array of text content. Unknown retained JSON fields, numeric tokens and null/missing distinctions are kept untouched. Custom roles, unfinished assistants and other tool-result content fail with `ArgumentException` before any event, callback, clock, transport or tool effect. History admission checks message shape; provider-specific conversion and tool-call/result pairing remain the caller's request-boundary responsibility.

An empty `newInputMessages` batch selects context-only continuation when history is nonempty and ends in `user` or `toolResult`. Empty, system-tailed and assistant-tailed histories are rejected before effects or queue polling; an assistant-tailed context can instead supply newly selected queued input. This native role restriction is explicit: pinned [low-level continuation](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/agent-loop.ts#L128-L153) rejects empty and assistant-tailed histories and delegates converted-role eligibility to `convertToLlm`; the pinned [high-level Agent](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/agent.ts) also rejects system-only continuation. This seam supplies no custom-role conversion or queued-input selection of its own.

`PrepareRequest` receives the turn index, fixed model and current transcript. It must return a request with that model and every canonical message in unchanged order, roles and exact raw JSON. Omitted, rewritten or reordered history and model changes fail before transport acquisition. This explicit seam permits caller-owned request construction while keeping this slice's history invariant. General transcript transforms, context replacement, compaction, model/reasoning changes and provider-payload projection are outside the contract. Callers supply any initial tool declaration; the loop does not implement upstream `declareToolChanges`.

The optional `PrepareNextTurn` callback receives the completed turn and returns append-only system/user messages. Steering and follow-up callbacks return immutable message batches; they own queue admission and draining. The loop preserves the captured low-level order: one initial steering poll, a steering poll after each completed turn, and another steering poll after next-turn preparation only when the earlier poll was empty. Prepared messages precede pending messages. Follow-up is polled after tool continuation and steering have stopped. Non-terminating tool results select another request automatically; unanimous termination suppresses that tool-continuation hint while queued input may still select a request. A failed/aborted chat exits without another queue poll or provider request.

`FinishTurn` remains an awaited observer of the completed immutable assistant/tool/transcript snapshot. The optional `FinishTurnDecision` receives the same snapshot and returns `AgentLoopFinishAction.Default`, `End` or `Continue`. When both callbacks are present, the observer runs before the decision callback; this two-callback composition is an explicit native policy, while upstream has one `finishTurn` hook. Both callbacks settle before `AgentLoopTurnEnded`, post-turn queue polling and any later request. The genuine decision projection uses the decision callback alone.

`Default` preserves normal scheduling. `End` emits the completed turn and loop end, then returns without polling steering or follow-up; messages still owned by those caller queues remain there. `Continue` ensures one subsequent request unless the run fails or reaches an admission limit. A non-terminating tool batch, steering delivery or follow-up delivery satisfies that decision without adding another request. If none selects a request, the loop starts exactly one context-only turn with the existing transcript and normal next-turn preparation. The next completed turn must make a new decision to request further explicit continuation. A failed/error/aborted assistant still awaits the callbacks, ignores their returned decision, emits its completed turn and exits as `ChatFailure` without polling queues. These rules follow pinned [runLoop](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/agent-loop.ts#L238-L331) and [FinishTurn](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/agent/src/types.ts#L147-L158).

Loop/input/turn/end records supplement the accepted assistant/tool events. Every callback and sink call is awaited without a state lock. Each owned chat run has settled cleanup before its assistant barrier and before any subsequent request. Callback, sink and cancellation faults propagate after the active accepted turn has settled owned resources; the loop does not synthesize successful end events after those faults. A finish-decision fault leaves the completed immutable assistant/results available in its callback snapshot, with no later request or success end event. Callbacks must cooperate with cancellation. There is no forced cancellation of arbitrary callback code or cleanup timeout.

An out-of-range native decision enum on a successful turn throws a fixed `InvalidOperationException` before turn-end delivery. Failed turns ignore the returned value. This enum admission is native hardening, not JavaScript unknown-decision-object parity.

The clock is sampled once before each chat/effect turn. All that turn's tool-result transcript messages use the sample as their timestamp; accepted content, IDs, names, details and error flags are preserved. The clock is sampled before effects so a thrown clock callback cannot discard a successful batch. This is an authored timestamp policy matching the capture's fixed clock, not general upstream per-result clock timing parity. Runtime-only termination/failure metadata stays in the native outcomes and is excluded from the tool-result wire entry.

Default admission is 16 turns and 1,024 transcript messages. Initial input, or combined canonical history plus new input, above the message limit throws `ArgumentException` before any loop/input event, queue poll, request callback, clock sample, transport acquisition or tool admission. It emits no `AgentLoopStarted` or `AgentLoopEnded`. An admitted context that already fills the limit returns `TranscriptLimit` before preparing another request, retaining its complete history. A turn limit prevents another request and returns completed history, turns and already-drained pending messages. A final assistant reserves room for itself and every potential tool result before scheduler admission. Insufficient room returns `TranscriptLimit` with the rejected assistant and admits no tools. Completed batches retain all source-ordered results; capacity cannot reject them after successful execution. An oversized pending batch is returned uncommitted in `PendingMessages`. These cardinality limits are not payload/heap caps, timeout budgets or high-level queue backpressure.

This is selected-field scheduling comparison, with an explicit unmatched aborted-signal requirement. The seventh source observation both returns an Aborted assistant and aborts its controller; its retained controls and `finalSignalAborted: true` remain visible in the golden and are asserted as source facts. The native terminal-state projection supplies that Aborted assistant with an **uncanceled caller token**. It does not reproduce the source's aborted-signal lifecycle. Actual native caller cancellation instead propagates after owned cleanup and prevents later requests/end events; separate deterministic cancellation tests enforce that accepted contract. Signal/control metadata, provider emissions and full scenario-object equality are outside this named profile, so matching selected fields cannot close the unmatched lifecycle requirement or full P3 parity.

The comparison is a **bounded native projection**, not full event or Agent parity. It preserves every shared message field, string, timestamp, raw number token, array order and missing/null distinction, allowing only object-key order changes. The one root assistant metadata difference is checked explicitly: the oracle's `thinkingLevel` must be `"off"` and the native value must omit that field; the field is outside equality after that check. Nested opaque objects receive no such exemption. Native `ModelDescriptor` comparison covers ID/API/provider only. Mutable upstream assistant-start/update snapshots, full model catalogs/options, reasoning-level stamping, automatic tool declarations, convert-to-LLM transforms and schema validation are outside the projection. Prepared declarations in the test input are authored at the public seam. Genuine capture provenance and repeatability remain separate from native assertions and independent acceptance.
