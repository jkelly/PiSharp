# Native process runner: bounded Windows backend

This slice implements an actual Windows process primitive in `PiSharp.Tools.Processes`, targeting the repository's .NET 10 toolchain. It uses framework libraries and Windows APIs, with no Node runtime, provider connection, package installation, global PATH change, or administrator operation. It does not implement a complete Bash tool, authorize executable actions, confine arbitrary native code, or complete P3-07. The eventual tool adapter must prepare and revalidate its final executable/argv/cwd/environment/spill action and pass it through mandatory `IToolActionPolicy` before invoking this trusted effect primitive.

## API and ownership

`IProcessRunner.RunAsync(ProcessRequest, ProcessOutputCallback?, CancellationToken)` returns an immutable `ProcessRunResult`. `ProcessRequest` holds an explicit absolute executable, immutable argument array, absolute working directory, copied immutable full environment, explicit absolute spill filename, and optional timeout in seconds. No PATH discovery, shell substitution, environment fallback, or default home/temp destination occurs. Paths must already be fully qualified and lexically normalized; UNC/device paths are rejected. This is not symlink identity validation or protection against external executable/cwd replacement.

`NativeProcessRunner` accepts validated `ProcessRunnerOptions`, a trusted `TimeProvider`, a trusted `IProcessOutputStorage`, and an optional awaited `ProcessLifecycleCallback`. The storage must return a writable owned stream for exclusive creation at the requested path. `LocalProcessOutputStorage` uses an asynchronous `FileStream` with `FileMode.CreateNew`; it never truncates an existing artifact. Injected storage/clock/observers are trusted host code, not serialized authorizations or restored delegates. Concurrent calls own separate jobs, streams, queues, decoder state, timers, and output artifacts.

`ProcessRunResult` distinguishes `Exited`, `NonZeroExit`, `Canceled`, `TimedOut`, and `Failed`; it carries nullable native exit code/PID, `ProcessStarted`, `CleanupConfirmed`, `CapturedOutputComplete`, model snapshot, separate structured output, rounded elapsed seconds, and enum-only diagnostics. `ProcessStarted` means the child was successfully resumed; a canceled suspended launch can have allocated an OS PID observed by the lifecycle callback while returning false and no result PID. No exception text, command, cwd, environment values, inner exception, or stack trace is copied into diagnostics. Captured child output is intentional bounded payload. `CapturedOutputComplete` means the admitted emitted stream was captured; it does not mean the command completed, future descendant output was preserved, or shell side effects rolled back. A failed write can leave a partial artifact shorter than `RawBytes`, which counts admitted observed bytes.

## Admission and process lifetime

Admission rejects null/default values, NUL or malformed UTF-16 in executable inputs, duplicate environment keys under Windows case-insensitive comparison, `=` in environment keys, oversized argv/environment, nonnormalized paths, unavailable executable/cwd/spill parent, and existing spill targets. Limits are 256 arguments, 1,024 environment entries, 4,096 characters per path, and conservative 32,767-character command/environment bounds. Invalid path parsing yields `InvalidRequest`. An already canceled token starts no process and creates no artifact.

Timeout follows the pinned Bash input profile: optional finite positive seconds, fractions allowed, maximum `Int32.MaxValue` milliseconds, no default timeout. The trusted timer is acquired disarmed before launch and armed after successful resume. Caller cancellation requests settlement; cleanup is awaited without the canceled caller token. Actual caller cancellation takes precedence over timeout once cleanup settles, while cleanup failure forces `Failed`. Unrelated `OperationCanceledException` from progress/lifecycle/storage is a sanitized failure, not caller cancellation.

`WindowsProcessLifetime` creates asynchronous stdout/stderr named pipes, an explicitly inheritable read-only Windows `NUL` handle for stdin, and a private unnamed job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and no breakaway flags. It calls `CreateProcessW` with an explicit application name, quoted argv, Unicode environment, exact cwd, `CREATE_SUSPENDED`, `CREATE_NO_WINDOW`, and a restricted inherited-handle list containing only child stdin/stdout/stderr. The null-device input provides EOF without depending on closure of a connected named-pipe server before child resume; the host's console input and unrelated inheritable handles are not offered. The process is assigned to the job before resume. Assignment/observer/resume failures terminate and dispose the suspended launch; there is no fallback that runs outside the job.

The synchronous native creation call runs on an awaited worker task. Cancellation before that worker starts prevents creation; cancellation during creation still joins the call, assigns any resulting suspended process to the job, and performs owned cleanup before returning. The worker sets and restores its thread-local error mode around `CreateProcessW`, preserving existing flags while adding `SEM_FAILCRITICALERRORS`, `SEM_NOGPFAULTERRORBOX`, and `SEM_NOOPENFILEERRORBOX`. No await occurs while that mode is changed, and the host process-wide mode is untouched. This is native headless-launch hardening; it does not make the Windows API forcibly cancelable or promise a bound against an arbitrary stalled OS/filesystem call. Microsoft documents thread-local error handling and prevention of critical-error UI hangs in [SetThreadErrorMode](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-setthreaderrormode).

Root exit is observed through a registered process wait. After exit, the runner awaits pipe EOF or 100 ms of output inactivity, rearming on each observed chunk rather than using a fixed exit deadline. At settlement it terminates the job, awaits root exit, queries job accounting until zero active processes, settles pipe readers and the collector, finishes the decoder, awaits final output callbacks and owned stream disposal, and disposes process/job/pipe/wait handles. Internal lifetime termination/disposal calls share completion tasks. Five-second cleanup bounds detect failure; they are not a command timeout. If pipe settlement needs forced cancellation, capture is marked incomplete. All callbacks are awaited outside coordination locks; a trusted callback that does not complete can delay settlement and is not forcibly interrupted.

The supported containment shape is ordinary Windows `CreateProcess` descendant inheritance, including grandchildren and an exited parent whose descendants retain stdio. WMI/service-mediated outside-job creation and arbitrary native escape behaviors are not sandboxed. Job assignment under the host's existing job must be tested on the actual environment. Killing surviving descendants before normal return, bounded cleanup, and hard resource limits are native hardening beyond upstream's background-process behavior. Microsoft documents job inheritance, exceptions, nested jobs, accounting, and kill-on-close in [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) and suspended process transport in [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw).

## Bounded output

Two pipe pumps feed a bounded queue, and one consumer merges observed chunks. Cross-pipe scheduling order is not deterministic chronological ordering. Default read chunks are 8 KiB and the queue holds eight chunks. Incremental replacement UTF-8 decoding strips an initial BOM, retains CR/LF and NUL, and flushes an incomplete final sequence at settlement. Raw bytes are preserved independently. This is the native .NET decoding profile; authored split/invalid-byte cases do not establish exhaustive WHATWG decoder parity.

The model snapshot uses the accepted `ToolOutputTruncator.Tail` with default 2,000-line/50-KiB limits and global line/decoded-byte counters. Rolling decoded text is reduced from more than four model byte budgets to approximately two, at a UTF-8 boundary. A partial first retained line is omitted when later complete lines exist; an oversized sole line retains its bounded partial tail. Snapshots also expose raw byte count, final line byte count, and provisional full-output path.

Once raw bytes, decoded bytes, or lines require truncation, the collector exclusively creates the requested artifact, writes the retained original raw prefix, and then streams subsequent raw chunks. It flushes and awaits asynchronous disposal before returning. Successfully created artifacts remain caller-owned; no automatic deletion or repair is performed. Filesystem failure can leave a partial artifact, including an uncertain create whose storage callback never returned a stream/path acknowledgement. Output failure disables creation retries during decoder finalization. The default raw-output ceiling is 64 MiB, configurable downward; only the remaining budget is admitted from a crossing chunk. Exceeding the ceiling stops the job, discards further queued output, reports `OutputLimitExceeded`, and marks capture incomplete.

Structured output is a separate immutable string/flag result, never disguised as model-facing `Details`. It selects up to a 1-MiB raw-byte budget: full output below the limit, otherwise first/last halves with an omission marker. The head holds back an incomplete trailing character, the tail skips leading UTF-8 continuation bytes, and each selected segment strips its initial BOM as upstream's fresh `TextDecoder` does. The omission marker adds a small amount beyond the selection budget; replacement decoding of invalid bytes can expand UTF-8 text size. This raw selection profile does not promise a strict 1-MiB decoded JSON serialization bound. Full raw spill bytes remain unmodified. Output options cannot increase source model/structured budgets or the native total budget.

Progress callbacks are per-run, serialized by the collector, and may observe every admitted chunk plus a decoder-flush change. Callback failures stop execution and disable further ordinary updates. There is no source throttle/initial frame, tool-execution event integration, or callback after terminal completion in this primitive. A Bash adapter and shared progress scope remain necessary. Elapsed seconds use the supplied monotonic clock rounded to one decimal; Windows exit codes are represented as native signed 32-bit values.

The public reference is Pi v0.99.1 commit `d86654abb8862e201933517d6f1fce9f88dd117f`: complete [Bash implementation](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/bash.ts), [shell configuration and cancellation](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/utils/shell.ts), [post-exit drainage](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/utils/child-process.ts), [output accumulator](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/output-accumulator.ts), and [truncation](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/core/tools/truncate.ts). The raw ceiling, strict admission, jobs, awaited termination, and return-time descendant termination are explicit native choices rather than claims about upstream guarantees.

`NativeProcessRunnerTests.Cases()` supplies eight authored groups covering admission/prelaunch cancellation; actual borrowed Git Bash Unicode/cwd/environment/owned scratch effects/exit; exact Windows argv and stdin EOF; one-byte UTF-8/BOM/invalid/NUL capture; line/byte tails and >1-MiB raw artifact/source hashes; budget/partial-write/flush/dispose/foreign-cancellation/progress faults; suspended/running cancellation, controlled timeout and awaited output disposal; and real child/grandchild cancellation plus controlled late inherited-pipe output. Named-pipe handshakes and a manual test clock establish order; delays only implement production cleanup polling or bounded test guards. Every fixture run uses a five-second guard whose `finally` requests cancellation and joins the actual run; controlled callback gates are also released in fixture `finally` blocks. Generated fixtures live solely in unique owned temporary directories.

Descendant fixtures redirect and immediately close stdin. This makes .NET's Windows launcher explicitly set `STARTF_USESTDHANDLES`, preserving inherited stdout/stderr directly rather than forwarding through an ancestor that exits. The .NET 10 [Windows process implementation](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Diagnostics.Process/src/System/Diagnostics/Process.Windows.cs) sets those startup fields only when at least one standard stream is redirected. The late-output callback and rearmed-timer waits have distinct failure messages so a fixture transport fault cannot masquerade as a timer assertion.

Root must register `Cases()` and dispatch `--native-process-test-child` to `await NativeProcessRunnerTests.RunChildAsync(args[1..])` before ordinary report argument handling. Worker modes run only the test assembly and operate on supplied owned scratch paths/control pipes. The `exact-argv-probe` worker mode runs the complete exact-argv group, including failed-image cleanup; its fixed stderr phase markers contain no argv/environment/output payload. Git Bash is explicitly borrowed from `C:\Program Files\Git\usr\bin\bash.exe`; missing shell is a fixture failure, not a silent substitute. Runtime version evidence is collected only by the actual root-run tests.
