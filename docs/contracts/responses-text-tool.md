# Parsed Responses text/function transport

`PiSharp.AI.Protocols.OpenAIResponses.ResponsesTextToolTransport` implements `IChatTransport` over a caller-injected `Func<ChatRequest, CancellationToken, IAsyncEnumerable<JsonData>>`. Each enumeration supplies the original request once to the delegate and owns the returned async enumerator. DTOs are immutable, caller-parsed JSON values. This slice performs no HTTP, SSE decoding, SDK calls, request projection, authentication, retry, catalog lookup or tool execution. It does not select an endpoint or model.

The implemented subset is assistant text/refusal and function-call progress ending in `response.completed` with status `completed`. Sparse provider `output_index` values map to contiguous native content indices in first-creation order. A function call's identity is `call_id + "|" + item.id`; its name and namespace are retained. Authoritative message ends concatenate output-text/refusal parts and supply the exact compact text-signature string with `v`, `id` and optional `phase`. Authoritative tool ends replace accumulated arguments and update namespace. A supported item end without a prior added item creates its slot first, matching the helper's observed creation rule.

EOF and unfinished-tool cases compare their two progress operations each and verify failure without any successful terminal. Failed native messages and diagnostics are authored behavior; they are not compared as equivalent to the helper's provisional mutable output or exception text.

The source helper emits **no Start, Done or Error envelope**. This adapter emits an authored empty/pending `StreamStarted` before acquiring the source, and a single `StreamDone` after EOF, completed-response validation and owned cleanup. That envelope permits the existing `ChatRun` reducer/lifecycle integration. It is not provider-wrapper parity. Final `responseId`, `rawStopReason: "completed"`, usage and stop reason are retained in the terminal message. Successful completed function content yields `ToolUse`; otherwise it yields `Stop`. Earlier compact progress snapshots do not mirror the helper's response metadata or phase-driven provisional stop reason.

The helper calls `parseStreamingJson` during progress. The standalone native display-preview helper is not integrated here. Tests compare raw delta operations and completed arguments, never normalize partial repaired objects into a passing whole-prefix claim.

The adapter forwards an arguments-done suffix when the authoritative string extends the accumulated prefix. A replacement that is not a prefix emits an authored `ToolCallCheckpoint`; nonempty added-item argument seeds also use a checkpoint. These bridge events preserve raw accumulation for the native reducer and have no claimed one-to-one helper-emission parity outside the captured prefix-extension case.

## Strict final authority and unsupported input

Final tool JSON is `parseStreamingJson(item.arguments || partialJson || "{}")` (`StreamingJson.Parse`), as openai-responses-shared.ts does: truncated JSON, repaired escapes, arrays, scalars, null and duplicate properties are kept as upstream returns them. Schema validation and actual authorization remain the tool pipeline's responsibility.

EOF before a supported completed response and completion with any unfinished content throw fixed `StreamProtocolException` diagnostics. Through `ChatRun`, these become `MalformedStream` and an error message, never a successful `ToolUse` terminal. This is an authored classification. All unfinished text is rejected as well as unfinished tools; it does not inherit the helper's narrower tool-use check.

Custom tool calls, failed/cancelled responses, provider error DTOs, unknown event types and unsupported terminal output types fail explicitly with a fixed protocol diagnostic. The `response.in_progress` and `response.queued` lifecycle bookkeeping requires an object response with absent or empty output. Reasoning summary-part-added, summary-text-done and reasoning-text-done bookkeeping is ignored, matching the pinned mapper. Annotations and arbitrary DTO metadata are not projected into assistant content. Terminal supported output items are not reconstructed; they cannot replace missing item-end events. This subset does not claim those unsupported provider paths.

Slot events follow openai-responses-shared.ts processResponsesStream: a text, refusal, reasoning, function-argument or custom-input event whose `output_index` has no open slot of its type (missing or non-integer index, no slot, another type, or a slot already ended by `output_item.done`) is ignored (`if (!slot) continue;`), and slots are matched by `output_index` alone (`item_id` is not consulted). `output_item.added` for an index replaces its open slot with a new content block; `output_item.done` with no open slot creates one; an item end of another type than the open slot does nothing; the slot keeps the identity, call id and name it opened with. Items of other types (for example `web_search_call`) open no slot. Native admission still rejects a negative or non-integer `output_index` on `output_item.added`/`output_item.done`, duplicate terminal responses and events following a completed response, which the upstream helper does not. Unknown DTO fields are inspected for bounds. Completed reasoning items retain their full owned JSON as replay signatures; other unknown DTO fields are not retained as unknown message fields.

## Usage and synthetic rates

`ResponsesTokenRates` contains caller-authored decimal rates per million tokens; defaults are zero. The completed usage mapping retains output tokens, cached reads, cache writes, total tokens and the `reasoning` usage field. Uncached input is `max(0, input_tokens - cached_tokens - cache_write_tokens)`. Missing counts default to zero. Present counts must be nonnegative signed 64-bit integers. Arithmetic overflow is a sanitized protocol failure. The service-tier successor below applies the pinned multiplier policy. No cache-write-duration or provider-catalog policy is implemented.

The capture's synthetic rates produce input 15, output 7, cache read 2, cache write 3, reasoning 1 and total 27; cost fields are 15, 14, 1, 4.5 and total 34.5. Computed cost decimals drop insignificant trailing zeroes before being assigned to `UsageCost`, using invariant `G29` formatting and a decimal parse. This removes retained arithmetic scale such as `0.5 * 2` producing a serialized `1.0` instead of the captured `1`. The boundary applies only to these derived cost fields and their total; it never rewrites opaque signatures, final argument numeric tokens, raw DTOs or expected fixtures. Focused checks retain zero and fractional costs and verify raw argument `1.0` and `9007199254740993` remain exact. Framework decimal arithmetic does not establish general JavaScript floating-point rounding, exponent formatting or current provider price parity.

The native comparison ignores only object-key order. Number tokens use exact `GetRawText()` equality, arrays retain order, decoded strings retain their exact characters, and null differs from a missing property. Mutation controls reject `1` versus `1.0`, adjacent large integers, opaque signature-string reordering, missing nulls, reordered arrays, changed line endings and Unicode normalization. No expected numeric tokens are normalized.

## Bounds, cancellation and ownership

Default bounds are 4,096 DTOs, 65,536 UTF-16 serialized characters per DTO, 1,048,576 serialized characters across DTOs, 64 total content slots, 1,048,576 accumulated native content/envelope characters and 32 container nesting levels. Options are validated at construction; depth is restricted to 1-64 and rates must be nonnegative. DTO object/array nesting and parsed final-argument nesting use the configured depth. Partial raw argument strings are character-bounded and receive JSON-depth validation when they become final objects. Unpaired UTF-16 surrogates in DTO names/strings or final JSON are rejected instead of silently replaced. Limit and adapter protocol messages contain no rejected payload or property name.

The DTO character bounds charge `JsonElement.GetRawText()`. `MaximumContentCharacters` is the accepted reducer's logical payload/envelope budget: it charges content, signatures, tool identity/namespace and message metadata when projected into reducer events. Separate slot identity strings and pending `responseId`/`rawStopReason` fields are not charged immediately to that budget; total incoming DTO characters and the slot count bound them while pending. Terminal projection charges final message metadata before successful settlement. A regression admits long pending text-slot/response identities under a small reducer budget, then verifies that long completed response metadata fails that budget. The caller already owns parsed DTO allocations before admission. Parsing, concatenation, serialization, a small per-DTO progress list and framework buffers allocate temporary storage. These are logical admission/state bounds, not a total heap cap.

Inner signature quoting follows the pinned `JSON.stringify` formula for valid Unicode: U+2028, U+2029, private-use characters and supplementary pairs stay literal; quotes, backslashes and control characters are escaped. A framework `UnsafeRelaxedJsonEscaping` serializer was observed to escape U+2028 within that opaque string and was replaced. The focused regression checks those characters against the source formula; it is authored algorithm evidence beyond the ASCII-ID genuine capture, not another captured provider trace.

There is no adapter queue or prefetch loop. It asks for another source DTO only when the consumer requests further progress; a single DTO can produce multiple local progress events. The injected delegate and source enumerator receive the cancellation token, and cancellation is checked before acquisition, after every source pull and before emitting progress/terminal. The source must honor cancellation for blocked pulls. Direct enumeration does not promise concurrent `MoveNextAsync`/`DisposeAsync` support.

Early enumerator disposal awaits the owned source's `DisposeAsync`. EOF and source/read faults also await cleanup. Successful Done is exposed only after source cleanup completes, so a source cleanup failure prevents successful settlement in this adapter. Source cleanup receives no cancellation token and must finish independently. If it throws while unwinding another failure, standard async-disposal exception precedence applies. External delegate/read/disposal exceptions retain their types for direct consumers; the existing `ChatRun` provides its sanitized external-provider failure classification. The adapter never disposes the caller's delegate or request and never invokes tools.

## Source-only reasoning successor

The parsed adapter and its actual HTTP/SSE binding now accept reasoning output items. Reasoning summary and raw-text deltas produce ThinkingDelta; summary-part completion appends two newlines. At output_item.done, nonempty joined summary text takes precedence over nonempty joined raw content, then accumulated deltas. A done-only reasoning item creates its own slot. The full owned item is serialized through the existing bounded ECMAScript JSON projector into thinkingSignature for the existing transcript replay path. Interleaved text/tool slots retain their original content indices.

At response.completed, terminal reasoning entries backfill missing, null or empty encrypted_content for matching completed reasoning IDs. Existing nonempty encryption wins. Other terminal item fields do not replace the stored item or displayed text; unknown IDs do not create blocks. This follows the pinned openai-responses-shared.ts createSlot, reasoning event branches and backfillReasoningSignatures at d86654abb8862e201933517d6f1fce9f88dd117f.

Native timing qualification: ThinkingEnded is emitted at output_item.done when encrypted_content is already nonempty, because pinned Source never replaces that ciphertext. With missing, null or empty encryption, ThinkingEnded is deferred until a supported terminal resolves encryption backfill. The existing immutable reducer requires authoritative ended metadata to agree with the final message and disallows a second end. Thinking deltas still stream immediately; the final thinking ends precede physical cleanup, while successful settlement waits for cleanup. This deliberately does not claim identical source thinking-end timing or mutable event snapshots. The unique output-index admission, strict malformed-input checks, content limits, and unsupported custom-tool event boundaries remain in force. The later incomplete-response unit below extends the terminal profile. No shared reducer, Agent or session code changed.

Six authored test families cover request resolution/admission, final-text selection and signatures, actual fake-HTTP backfill with a second request replay, interleaved/done-only slots, malformed/oversized reasoning, and held-cleanup success/cancellation. All are UNCOMPILED and UNEXECUTED. Existing nonreasoning request goldens are preserved; the obsolete reasoning-model rejection test is replaced by unknown-effort rejection. Runtime window authorization, locked restore/build, inherited Responses and full companion regressions, and independent review remain required.

## Bounded incomplete-response successor

The adapter accepts response.incomplete only with response.status equal to incomplete. It preserves terminal responseId, usage including cached/write/reasoning tokens, existing configured cost rates, and rawStopReason. A max_output_tokens reason yields Length when every content item has ended; finished tool calls do not change Length to ToolUse. A content_filter reason yields a provider StreamError with the fixed source message `Response incomplete: content_filter`. Missing/null incomplete_details, an empty object, and missing/null/empty reason yield `Response incomplete without a provider reason`. Only these documented branches are admitted; unknown reason strings, non-string reasons, malformed details, and event/status mismatches remain fixed protocol errors.

Incomplete terminals share reasoning encryption backfill with completed terminals. Error results retain partial content and terminal usage. A token-limit terminal with any unfinished content yields a provider error `Response incomplete with unfinished content.` while retaining raw incomplete.max_output_tokens and usage. This is an explicit native boundary: no text/thinking/tool end is fabricated, and unfinished tool arguments cannot gain successful authority. Ordinary completed responses with unfinished content keep their previous MalformedStream rejection. Nonterminal EOF, repeated terminals, and trailing events or parse faults still cannot succeed. Source permissive terminal/status combinations and arbitrary untyped reasons are not claimed.

The stream still joins its original HTTP body and source cleanup before exposing either a Length or provider-error terminal. Cancellation and late read/release faults prevent successful completion. The inherited cancellation/fault fallback is unchanged and does not promise retention of terminal usage when it overrides an unpublished terminal. No shared reducer, cancellation machinery or Agent behavior changed.

Four additional authored families cover reason/error/usage/cost channels, finished and unfinished tool boundaries, incomplete reasoning backfill, malformed/trailing data, and held-cleanup cancellation/read/release faults. They remain UNCOMPILED_UNEXECUTED. Default mapper bounds remain 4096 events, 65536 characters per event, 1048576 cumulative input characters, 64 content slots, 1048576 retained content characters, and JSON depth 32; caller-configured stricter limits still apply.

A separate timing correction adds four gated preterminal schedules (missing/null/empty/final encryption), checking early end only for final encryption, exactly one end, preserved ciphertext and final backfill. These tests are authored, UNCOMPILED and UNEXECUTED.

A further preterminal-interruption correction finalizes valid pending reasoning done items when the source exhausts or a source/DTO read fails, before propagating the original exception. This preserves authoritative final text and the full done-item signature in ChatRun partial results, including done-only reasoning. It does not synthesize successful settlement, alter exception classification, or skip owned cleanup. Bounds still apply to this final projection; a bounds failure can supersede the source failure. Cleanup faults retain normal disposal precedence. Unsupported response.failed events remain malformed rather than a newly supported provider-failure wire profile.

The subsequent cancellation-partial successor introduces a native ThinkingCheckpoint for missing/null/empty encryption at output_item.done. It stores authoritative text and the entire current signature before the next source pull, while keeping the block open for terminal ciphertext backfill. ChatRun cancellation admission and owned task joins are unchanged: an already admitted checkpoint survives cancellation through ordinary reducer partial-message semantics; a checkpoint not admitted before cancellation does not. Nonempty final encryption still produces an immediate ThinkingEnded. A 32-schedule authored family covers EOF, read failure, malformed provider-failure events and preterminal cancellation, crossed with missing/null/empty/final encryption and streamed/done-only content. These schedules are UNCOMPILED and UNEXECUTED.

Pending-signature limit correction: reasoning signature projection translates ECMAScript projection failures at its own shared boundary, including finalization after EOF or read failure outside Process. Resource-limit failures retain ResourceLimit classification rather than becoming generic Provider failures. Three authored, unexecuted schedules use an opaque object with 4097 short properties inside a DTO smaller than 65536 characters, and hold original cleanup for EOF, read failure and completed terminal paths. With checkpoint emission enabled, the oversized signature is rejected earlier at output_item.done. Existing projection/admission bounds are unchanged.

The RPC companion suppresses the internal thinking checkpoint without suppressing subsequent public thinking ends or final/aborted message bodies. Mapper-to-ChatClient-to-projector regressions cover completed/incomplete/EOF/cancellation. No new public RPC event is introduced; dispatcher and frontend behavior are unchanged. This completes the source-only checkpoint integration, not runtime qualification.


The service-tier pricing successor follows pinned openai-responses-shared.ts finalizeResponse and openai-responses.ts applyServiceTierPricing. On completed/incomplete responses, a non-null service_tier string overrides the requested fallback in ResponsesTextToolOptions.ServiceTier; an empty or unknown returned string is retained for resolution and selects the default multiplier 1. Missing/null returned tiers use the requested fallback. flex scales each of the four cost components by 0.5; priority/fast scale by 2, except exact model ID gpt-5.5 uses 2.5. Other tiers use 1. Scaled totals are recomputed; token counts, reasoning usage and terminal reasons are unchanged. Missing usage remains zero. Malformed non-string tiers and arithmetic overflow use the existing sanitized protocol failure. Native decimal cost normalization remains; general JavaScript binary64 bit-for-bit equivalence is not claimed.

Three authored service-tier families cover 126 combinations (three model IDs, three terminal outcomes and fourteen request/response precedence cases), missing usage, all request-tier options, exact payload budgets, invalid configuration and malformed response tiers, overflow, and real fake-HTTP request/returned-tier precedence with held original cleanup. These tests remain UNCOMPILED_UNEXECUTED. Provider-local files only changed; shared streaming/RPC/Agent/session/SDK files are untouched.
