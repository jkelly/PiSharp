# Completions user and tool image transcript projection

This implements the bounded provider request-image criterion in original P2-08/P2-02/P2-10. It uses the existing provider-local `ModelSupportsImages` setting and adds no public API. All 79 original package scopes and eight phase gates remain open. Shared Agent/CLI capability wiring still needs coordinated implementation; this provider unit does not qualify native image-producing tools or durable image persistence.

Pinned [Pi `transformMessages`](https://github.com/badlogic/pi-mono/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/transform-messages.ts#L12) replaces unsupported user/tool images with their respective exact text placeholders. Consecutive images collapse. A literal text block equal to the respective placeholder suppresses a following image; empty text breaks the run before user empty-text filtering or tool text joining. This closes a literal-placeholder edge beyond the earlier 25-profile user-image unit, whose immutable observations remain unchanged.

For image-capable models, pinned [Completions `convertMessages`](https://github.com/badlogic/pi-mono/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-completions.ts#L1397) scans a whole consecutive tool-result group. Each tool message retains joined text, or `(see attached image)` when only images, or `(no tool output)` when empty. Configured names and paired/normalized call IDs remain bound. All group images are collected in message/block order into one following user message beginning `Attached image(s) from tool result:`. A configured assistant bridge is inserted before this attachment user message. Later user input sees the attachment's user role and does not acquire a duplicate bridge. Nonvision tool results carry the downgraded text and remain in tool-result role for later bridging.

Empty user arrays and empty assistant projections retain the prior role, matching the source's skipped-message `continue`. Native legacy string tool content remains admitted as before, outside the typed-array source qualification. Strict typed fields, Unicode, JSON/depth/input/block/message/output-character/output-byte/payload bounds and cancellation remain enforced before HTTP effects. Canonical tool/user images, details and opaque fields stay retained; provider payloads omit source-omitted metadata. No image decoding, MIME inference or external image retrieval occurs.
