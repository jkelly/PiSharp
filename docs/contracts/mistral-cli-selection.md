# Mistral CLI catalog admission

This source-only successor connects the existing CLI `LiveSessionSelection.Parse` / `Connect` / `LiveSessionConnection.CreateTransport` path to the Mistral factory APIs in prerequisite `df2a97d7fe4b1be62b459f588bb12c44504d4c45`. No factory or protocol source is changed.

`Models/mistral.json` is the complete byte-identical `package/dist/providers/data/mistral.json` shard of `@earendil-works/pi-ai@1.1.0` (package SHA256 `6caab33cec57480ed02c57fe37428a030a77cc2a0662814b435a5cf8932ad829`; provenance in native-live-terminal-composition.md): 40 chat models, 16,483 bytes, SHA256 `fcd37c7b178416f86954efdacbb45726d10f102fd1211062792691e62fcf327c`, matching the package's `providers/data/.manifest.json`. Until the Pi 1.1.0 sync it was the released v0.99.1 source catalog (32 chat models, 12,596 bytes, SHA256 `10f33bff9adf1248f7e6848e5890c265399f1f94e5b42cfdc28c109d547af98d`), copied from the admitted `Pi-typescript-semantic-released-catalog-v0.99.1/upstream/packages/ai/src/providers/data/mistral.json` pinned in `compatibility/semantic-released-catalog.plan.json` (source commit `d86654abb8862e201933517d6f1fce9f88dd117f`, publisher source archive SHA256 `4d99d3c9ed6db41f88ce7ba36d478b06a9386f4e81fa0c1ea3f93e681c99e83b`); that historical pin stays as v0.99.1 evidence. The existing embedded-resource glob includes this file without a project change. Catalog bytes, model identity, capability fields, limits and prices are not regenerated or rewritten.

CLI selection now admits provider `mistral` only with the pinned `mistral-conversations` API. It retains existing explicit model selection, default 1,024 output tokens, CLI 1–8,192 limit, selected-model output limit, catalog hash check and error states. `Connect` selects `MISTRAL_API_KEY` through the existing injectable runtime only when a live connection is requested; parsing does not read credentials or create HTTP handlers. No credentials were read during this work.

Normal turns use `NativeProviderFactory.CreateMistralSimple` with the entire selected metadata row, exact endpoint, selected output maximum and catalog prices. Thus the existing Simple resolver applies context-budget clamping and model reasoning/header semantics. Summary turns use `CreateMistral` with their explicit output maximum, no reasoning advertisement and cache disabled, matching the CLI's existing distinction between normal Simple and summary direct calls. Both providers enter the existing connection-owned disposal list; injected handlers remain caller-owned. No alternate activation or HTTP transport was introduced.

The original `api/mistral-conversations.ts`, `api/simple-options.ts`, `utils/estimate.ts` and `models.ts` sources supporting those factory semantics are pinned in the prerequisite's `MISTRAL_FACTORY_SIMPLE_COMPLETION_HANDOFF.json`. This leaf does not extend the prerequisite's bounded protocol feature coverage: model image capability metadata stays faithful to the catalog, but image transport support, full cross-provider repair and mid-conversation update behavior remain protocol-owner work. Selecting a model that also supports images does not establish image request parity.

Three `MistralLiveSelectionTests.Cases()` groups cover all catalog rows (40 since the 1.1.0 shard), actual selection-to-factory synthetic HTTP for normal/summary budgets, catalog cost use and reasoning, connection disposal with borrowed handler ownership, unknown/model-limit refusal and missing-credential zero-handler effects. Parent registration in the CodingAgent test Program remains necessary. No build, compiler, test, Node, HTTP request, package, credential or native execution occurred.
# Direct summary image capability correction

Both normal Simple and direct summary factories receive the selected catalog row's declared image capability. The pinned original `packages/ai/src/api/mistral-conversations.ts:522` passes `model.input.includes("image")` to message conversion for the direct request too. Previously the summary route inherited the native option's false default and downgraded images from a vision row. The existing Routes group now checks actual normal and summary HTTP bodies for a vision and a text-only row, user/tool images, downgrade placeholders, model output budget, reasoning-off behavior and transcript immutability. These controls are source-authored and unexecuted; the registered count remains three CLI groups.
