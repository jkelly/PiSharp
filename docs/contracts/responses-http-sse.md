# Injected HTTP/SSE to parsed Responses

`ResponsesHttpSseTransport` implements `IChatTransport` by composing the accepted `HttpSseTransport` with `ResponsesTextToolTransport`. Its caller supplies a borrowed `HttpClient` and a synchronous `Func<ChatRequest, HttpRequestMessage>` that returns a fresh owned request per enumeration. Method, endpoint, headers, authentication, body projection and model selection belong to that factory. This slice adds no provider SDK, catalog, retry, WebSocket mode or live provider operation.

The mapper retains its authored empty `StreamStarted` before DTO acquisition. Merely obtaining the enumerable, or disposing immediately after that start, does not invoke the request factory. Once the factory returns, the composition owns the request and its content. HTTP sends once and owns its response/body through the accepted primitive. On EOF, exact sentinel, failure, cancellation or early disposal, it awaits HTTP enumerator cleanup before disposing the request. Successful mapper Done is exposed after all those stages settle. The borrowed client/handler are never disposed. A factory that throws before returning remains responsible for anything it allocated without transferring ownership.

Cleanup follows normal asynchronous-iterator/finally exception precedence. The outer request-disposal stage still runs when body/response cleanup throws. Request disposal itself is synchronous and can replace an earlier failure. No cleanup timeout is added; reads must cooperate with cancellation, and source disposal must finish independently. Consumers must drain or dispose the enumerator and must not overlap MoveNext/Dispose. The existing `ChatRun` supplies sanitized external-provider failure and cancellation outcomes.

Each dispatched SSE data string must be one complete JSON object. The JSON parser rejects comments, trailing commas and malformed syntax; owned `JsonData` rejects duplicate decoded property names at every depth. Property names and string values reject unpaired UTF-16 surrogates. Number tokens remain exact through parsing/cloning. Framing requires strict UTF-8; a caller-supplied framing configuration with replacement decoding is rejected at construction. Invalid UTF-8 and JSON produce the fixed `StreamProtocolException` message `Invalid Responses SSE JSON data.` without payloads or property names. Framing size failures and configured admission limits produce a fixed `StreamLimitException`. Through `ChatRun`, those become `MalformedStream` and `ResourceLimit` respectively. External factory, HTTP send/read and disposal faults retain their direct types and receive the existing generic Provider classification through `ChatRun`.

| Bridge limit | Default | Charge |
|---|---:|---|
| Data events | 4,096 | Every dispatched data event, including sentinel |
| Data characters/event | 65,536 | Exact SSE data string, in UTF-16 code units |
| Total data characters | 1,048,576 | Sum of admitted data strings, including sentinel |
| JSON container depth | 32 | Root object counts as depth one |

Configured limits must be positive; depth is restricted to 1–64. The JSON parser independently caps depth at 64 before configured-depth validation and cloning; input exceeding that parser cap is a malformed-JSON failure. The accepted mapper applies its separate DTO/content limits afterward. SSE line/event/read-buffer limits remain separate and configurable; their defaults retain blank-line dispatch and discard pending data at EOF. Parsed JSON documents, immutable clones, framework buffers and consumer-held values allocate additional storage. These admission limits do not establish a total heap cap. SSE event names, IDs and retry metadata are not projected into DTOs; the JSON `type` drives Responses mapping. Control-only SSE blocks do not consume data-event admission.

The exact data string `[DONE]` ends DTO acquisition and disposes the HTTP stream; later bytes/events are not interpreted. Whitespace-padded or extended sentinel strings are ordinary invalid JSON. EOF is also an input end. Neither end supplies assistant success: the mapper must already have admitted supported `response.completed` and authoritative ends for every content slot. Sentinel/EOF before completion fails, including when a valid tool-end progress event has already been observed.

This sentinel rule is **authored**, not a captured SDK equivalence claim. The [pinned public package lock](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/package-lock.json) records OpenAI SDK 7.19.0 for the AI package, but that SDK's streaming source is absent from the approved local oracle dependency tree. No new dependency was installed. The existing parsed Responses capture qualifies its mapper overlap; these new byte streams are synthetic inputs and do not qualify full provider-wrapper/wire behavior.

Run `./tests/PiSharp.Transport.Tests/test.ps1` or `./tools/test-native.ps1`. Six `responses-http.*` groups exercise actual UTF-8-fragmented SSE mapping and strict final arguments; gated body/response/request cleanup; invalid JSON/UTF-8, duplicate keys, Unicode, incomplete completion and HTTP rejection; admission boundaries; cooperative cancellation and early disposal; factory/send/read/cleanup faults and fresh requests across enumerations. The harness uses deterministic fake HTTP handlers and task gates, with a timeout only as a hang guard. No DNS, sockets, credentials, provider calls, Node runtime or filesystem/process tools are used. Results are recorded in `artifacts/transports/results.json` with an authored-composition scope. Full P2, provider, cross-platform and phase acceptance remain open; see [the HTTP contract](http-transport.md) and [the parsed Responses contract](responses-text-tool.md).

## Cohesive request/pricing binding (source-only successor)

Use `new ResponsesHttpSseTransport(client, factory, explicitApiKey, options, responsesOptions)` to bind a ResponsesKeyAuthRequestFactory. Its immutable ServiceTier supplies both the request body and mapper fallback; a non-null conflicting ServiceTier in responsesOptions fails with the fixed InvalidConfiguration exception. Other mapper options, including rates and limits, are copied unchanged. Caller options are never mutated. The client remains borrowed and requests remain fresh and owned per enumeration.

Factory-produced requests also carry a non-wire, non-null local options marker containing the requested tier (including an absent tier). The existing delegate overload validates that marker against its configured mapper fallback before HTTP acquisition. Conflicts dispose the newly created request/content and fail without sending. This covers production CLI delegates that decorate the original request. The marker contains no credential and is not an HTTP header or payload field. Arbitrary caller-authored requests without the factory marker retain the low-level explicit-policy contract; request clones/body rewrites are not inferred or inspected for tier policy.

Static production inspection found three Responses compositions in OfflineSessionProfile and OfflineDemo. All use the key-auth factory, retain its original request and currently omit both requested/fallback tiers; the validation preserves those paths without modifying CLI/frontend code. New fake-HTTP tests exercise twelve request/response tier combinations twice each, pre-cancel zero acquisition, absent/requested tier mismatches, early conflicting override rejection and request disposal. The original tier pricing held-cleanup test now uses the cohesive overload. All tests remain UNCOMPILED_UNEXECUTED. Decimal versus JavaScript binary64 qualification remains open; this binding does not change arithmetic.
