# Admitted MCP runtime leaf

This independent CURRENT v0.99.1 leaf implements MCP session methods over an explicitly supplied `IMcpAdmittedRequestChannel`. It depends on config/catalog commit `525100d214e35330b08b3586cda0668235d0ea3f` (verified-main ancestor `754251be28928b24eaae5895b744c423450c91a3`). Source reference is Pi `d86654abb8862e201933517d6f1fce9f88dd117f`. R267 approves these isolated paths. No full MCP parity or integration acceptance is claimed.

## API and ownership

`McpServerRuntime(entry, options, factory, publisher)` lazily shares one original startup. The factory transfers a fresh independently closeable lease. Initialize uses client name `pi`, the supplied version and latest pinned protocol `2025-11-25`; supported negotiated versions also include `2025-06-18`, `2025-03-26`, and `2024-11-05`. Supplied roots require the channel to install its roots/list handler before start. Initialization validation and the initialized notification precede paged tools/list. Tool rows retain owned raw JSON, with names and object input schemas validated before projection.

`CallToolAsync(originalName, arguments, actualInvocationContext, token)` is for the host's prepared and final-authorized callback. It captures owner/session generations and actual call/parent IDs before awaiting. The exact original remote name is passed in tools/call, with object arguments. It does not route calls through the local tool broker. Content defaults to an empty array when absent; structured content must be an object; remote isError and unknown fields remain raw JSON. Definite disconnected requests retire their lease without replay; a later independent operation may reconnect. No request with uncertain effects is retried.

Native progress deliveries are serialized and joined on success, cancellation and failure, including when a channel swallows a callback failure. Each admitted callback receives the linked invocation token. The runtime refuses owning connect/refresh/call/close reentry from publication or native progress callbacks before effects. Detached callback work is outside the contract and is forbidden. Independent callers may close and await originals.

`HandleNotificationAsync("notifications/tools/list_changed")` performs and joins a serialized refresh. The host notification pump must await this original. `Snapshot` returns immutable generation/revision/catalog/initialize/original-tool metadata; it grants no invocation authority.

The publisher receives immutable current/planned/withdrawn tools. It must validate host generation and admission at the atomic commit, use the existing registry/tool pipeline, join actual publication/reporting originals, then return an exact generation/revision published receipt. Only that receipt advances local acknowledged state. A callback failure or mismatched receipt retains the prior state and latches an uncertain outcome; the runtime will not automatically republish. Withdrawals use the last acknowledged catalog. A matching receipt for an already committed publication is retained even when close arrives during that callback. The host owns withdrawal on lifecycle close.

Close fences new admissions, cancels lifetime, closes the transferred lease once, and joins admitted startup/request/progress/publication operations. A lease acquired after the fence is closed by its startup original before settlement. Repeated CloseAsync calls return the same Task and terminal exception; DisposeAsync wraps that Task. Cancellation never uses an abandoned WaitAsync proxy. Operation faults remain on their original tasks; close does not duplicate every invocation failure. Close reports the captured lease-close/cancellation failure; a late acquisition's cleanup failure remains on its joined startup task.

## Bounds and remaining integration

Default limits: 1000 pages, 4096 tools, 262144 UTF-8 bytes per input schema, 1048576 bytes per response, and 8388608 retained catalog bytes. All are finite and positive; page cap cannot exceed the pinned 1000. Empty cursor strings continue paging and duplicate cursors reject. These configured additional bounds are a native profile restriction, not upstream unlimited-count parity. The channel must enforce response limits before materializing frames; the runtime additionally checks returned JSON. Output schemas are preserved raw, not separately interpreted or size-validated beyond response/catalog bounds.

The channel adapter owns actual JSON-RPC framing, ID correlation, incoming request dispatch, physical sends, cancellation writes, progress-reset timeouts, notification ordering and original joins. No concrete HTTP/stdio adapter, transport acquisition, environment/config-value expansion, auth/OAuth, session-expired retry, resources/read/catalog, MCP-app/resource rendering, output-schema conversion, CLI persistence, registered tool callback or host/session activation is implemented here. Native install remains Node-free. Existing provider/chat transports are not claimed to be MCP adapters. Instruction trimming, native floating-point progress formatting, the existing JsonData depth and duplicate-member rejection and inherited config leaf limitations are not differential-qualified against JavaScript.

Coordinator exclusively owns shared registry, activation, resources, publication admission, generation fencing, test registration and concrete transport/session integration. Reserved shared files are untouched.
