# Fixed Node worker process supervision slice

This is an early optional [P7-04/P7-09](../plans/07-node-bridge.md) process slice around the accepted [worker protocol](node-worker-protocol.md). It runs one fixed authored peer, not upstream Pi, an extension loader or arbitrary JavaScript. Native core/CLI dependency graphs remain Node free. The existing injected-I/O protocol suite remains independently runnable with Node absent; root owns a separate explicitly invoked process-test project and gate.

The author did not execute Node, .NET, source captures, network, installations or Git commands. Root's three frozen process gates built with zero warnings/errors and reached all ten groups: six passed/four failed, then seven/three, then seven/three again. The stage evidence now identifies the stalled stdout end await; the bounded owner-drain correction awaits a fresh root gate. These authored-peer results carry no real extension/corpus, support-matrix or phase completion credit. The unchanged `87d169` real-extension reference remains separate evidence; its original loader/controlled-map disclosures and remaining branches are not repaired or closed by this peer.

## Fixed admission and ownership

`PiSharp.ExtensionHost.Supervision.NodeWorkerLaunch.ForProbe` requires explicit local absolute runtime, repository and fresh run-root paths, worker/session generations, one declared probe mode and bounded options. The only entry is `tools/NodeWorker/protocol-probe-worker.mjs`, admitted by its measured SHA256 constant and matching [launch plan](../../fixtures/native/node-worker-supervision/launch.plan.json). Runtime admission is the existing approved Windows x64 Node v24.19.0 binary SHA256, `3602f2bb1a10f2cbab4c36886218a33c1ab3db87290e73b033c46c77147d0237`. Different binary bytes, entry bytes, links, missing inputs, relative/UNC paths, existing roots and overlapping source/runtime roots are rejected.

This profile accepts a copy of the exact approved executable only when its caller-supplied absolute path and measured bytes qualify. It performs no PATH lookup, runtime discovery, installation, package loading, arbitrary arguments or shell launch. Generations and the closed probe mode are the entire argument set. The native owner holds read handles denying write/delete sharing on the admitted executable and entry through process exit and cleanup, then rechecks their complete hashes. This Windows profile is an initial tested target, not a permanent exclusion or broader platform claim.

All input validation precedes output creation and process start. A private `CreateDirectoryW` call atomically creates a new run directory; an existing directory is never adopted. This uses the OS filesystem API without a separately compiled native helper or package dependency. Reparse-point ancestry is rejected. As with the native extension design, same-user execution is trusted OS access, not containment against another process changing unrelated ancestors or interfering with the host.

The supervisor clears inherited environment variables. The child receives only HOME/USERPROFILE, APPDATA, LOCALAPPDATA and TMP/TEMP/TMPDIR under its owned root, plus SystemRoot/WINDIR derived from the actual OS system directory. It inherits no PATH, NODE_OPTIONS, NODE_PATH, provider credentials or package-cache configuration. Its cwd is the owned root. The script imports only `node:fs`, `node:path`, `node:child_process` and `node:url`; no npm dependency, source module, fetch or network API is used.

The fixed peer can create only its declared effect/child receipts beneath cwd and can spawn only one copy of the same pinned Node executable and same entry in its private owned-child mode. Native generic requests cannot launch that child: `SpawnOwnedProbeChildAsync` owns its admission, validates the immutable parent/generation receipt and runtime path, holds a process handle and joins its actual exit. Tree termination is always rooted at the owned worker process, never a PID supplied as a kill target over the wire.

## API and lifecycle

`NodeWorkerSupervisor.StartProbeAsync` starts the admitted process, redirects all three standard streams, awaits protocol handshake and checks the real worker's runtime version/platform/architecture/PID. The object exposes bounded `StartRequest`/`RequestAsync`, owner-scoped callback registration/revocation, protocol snapshots, `SpawnOwnedProbeChildAsync`, on-demand `ProbeLivenessAsync`, session invalidation, `Termination`, faulting `Completion` and shared `DisposeAsync`.

The accepted `WorkerProtocolConnection` privately borrows stdout/stdin byte streams. Its framing, exact identity checks, pending/write/callback budgets, cancellation uncertainty and shared joined cleanup are unchanged. The supervisor owns the process and streams; the borrowed connection does not acquire ownership of them. No public operation authorizes a host tool or session mutation. A future native composition must supply the brokered handler, policy, schema, recursion and generation-checked commit path.

The fixed peer keeps reading while its bounded handlers await nested native requests. Progress from native callbacks is forwarded in order to the original peer call; it is not discarded. Tagged absent/undefined/JSON-null values remain distinct. Its payload codec is ordinary JavaScript JSON.parse/JSON.stringify: it does not promise preservation of raw numeric lexemes through JS, nor supply a general hostile-input JS parser or arbitrary object/function/cycle conversion. Native wire admission remains the strict accepted codec. Full source-owned undefined/numeric/function observations for actual extensions belong to the separate genuine reference/facade lane.

Default startup timeout is 5 seconds, shutdown grace 500 ms, on-demand liveness deadline 2 seconds, retained stderr cap 65,536 bytes and stderr read chunk 4,096 bytes. Options have fixed upper bounds. Native protocol caps cannot be enlarged beyond the fixed peer's frame/call/callback/write/progress/wire limits. There is no periodic heartbeat policy in this slice; the on-demand probe uses an ordinary bounded call and retains uncertainty if its deadline expires. Discovery/runtime selection, continuous heartbeat policy and real compatibility-session attachment remain later P7-04 integration.

Stdout is exclusively protocol. Stderr drains independently from process start until EOF, including while protocol requests, writes or shutdown wait. Captured stderr is a bounded exact prefix; the owner also retains total observed bytes and a streaming SHA256 over every byte actually read. Exceeding the cap records `StderrLimit`, kills the owned process and faults completion. Overflow is explicit; a truncated prefix is never reported as complete successful diagnostics. The logical stderr cap/read buffer and accepted connection budgets remain separate from total CLR or OS pipe allocation.

Stop fences new admission and starts one shared cleanup task. Owned shutdown attempts the real shutdown write/flush and protocol cleanup within grace. A tracked task waits for the accepted protocol snapshot to be stopped with zero pending writes, then closes the owning stdin wrapper. That barrier guarantees no new write admission and actual settlement of every prior write, including shutdown; the borrowed connection's stream-ownership contract is unchanged. Closing the pipe supplies peer EOF before awaiting exit, but did not by itself resolve the three failing positive paths. Startup/protocol/exit faults allow the same bounded interval for a natural process exit, since pipe EOF can precede the OS exit signal; resource/liveness/generation faults force termination directly. A fault or grace expiry terminates a still-live owned process tree, then awaits actual root exit, child admission/actual child exit, input closure, actual protocol write/callback settlement and stderr EOF. IO observation failures remain recorded while actual exits are still awaited; a timer never releases a live process or reports joined success. The remaining stream and pin handles are disposed after those joins. Repeated Dispose calls return the same completion task.

The peer judges stdin EOF only after its already-delivered asynchronous frame consumption settles. A valid final shutdown frame is processed before EOF classification; unexpected/partial EOF still faults in normal modes. The declared uncooperative `ignore-shutdown` fixture also survives pipe EOF, preserving the actual grace-expiry/tree-kill control rather than exiting when its input closes. Its held-call release waiter exists before admitted progress is published, so an immediate native release cannot cross that progress write callback and disappear.

The second peer correction awaits every active handler and output task, the shutdown acknowledgement and `probe-stop` callback, then clears the keep-alive, dispatches stdin destruction and awaits the stdout end callback. Only after those real output completions does it call the public stdio `unref` methods. It does not force successful exit with `process.exit(0)` or extend grace. Teardown exceptions remain faults even after shutdown has begun. Whether this resolves the retained runtime references requires the fresh actual gate.

The owner now starts one physical stdout-drain task that first awaits the actual `WorkerProtocolConnection.Completion`. Its cleanup awaits `ReadPump`; a stopped snapshot alone is insufficient to transfer reading ownership. After that join, the owner exclusively reads stdout to EOF with a fixed 4,096-byte buffer, an independent default 65,536-byte prefix/cap, total observed byte count and streaming SHA256. The drain runs alongside process exit, is included in the same unchanged grace deadline and final IO joins, and leaves the stream open until actual settlement. Overflow or a read fault records a fixed failure code and forces owned termination; overflow retains its bounded prefix while continuing to physical EOF after termination. There are no concurrent protocol/raw readers, early stdout disposal or unbounded queues.

Post-protocol bytes have no response, event or callback authority. They are raw physical cleanup observations, not evidence that a late protocol message was admitted. The decoder may already own buffered bytes when its read pump joins, so the raw prefix/count/hash describe only bytes actually read by the owner after that transfer. Complete wire history is not claimed. Keeping the physical pipe drained lets the peer's real stdout end operation complete after the protocol reader has stopped; natural exit zero/no kill and actual IO joins remain the acceptance checks.

Unexpected exit, protocol faults, stderr faults/overflow, liveness expiry, startup failure, generation invalidation and failed shutdown remain observable through `NodeWorkerSupervisorException`, which owns the complete terminal facts and retains the first underlying cause. `Termination` exposes those facts even when `Completion` faults. Nonzero natural shutdown exit is a failure. Intentional tree-kill exit codes remain recorded alongside their actual initiating fault. There is no retry or restart after a lost reply.

Caller cancellation preserves the accepted protocol distinction: an unsent queued frame can be skipped with `NotSent`; a write attempt or lost reply is `Unknown`. Pending and write slots remain held until actual settlement. The authored effect-before-exit case writes one receipt before exiting without a reply; native callers must retain uncertainty, not infer no effect from an error. Generation invalidation fences and joins the old process; a replacement requires a fresh root, process and handshake. Old handles cannot become registrations in the replacement.

Killing Node forces its OS pipes to settle but cannot kill an uncooperative in-process native callback or a blocking synchronous cancellation registration. Those still have to cooperate; cleanup remains pending until they join. The fixed child test observes the actual admitted child exit. This does not establish a universal guarantee over arbitrary descendants launched by future trusted extensions; broader supervisor/platform recovery remains mandatory.
