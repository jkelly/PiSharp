# Completions grammar tools: bounded original provider profile

This unit implements Pi v0.99.1's explicit `supportsOpenAIGrammarTools` Completions profile, pinned to upstream `d86654abb8862e201933517d6f1fce9f88dd117f`. It composes grammar declarations and custom tool input with the previously accepted model binding, cache markers, ordered declaration replay and anchored tool additions. It does not close original package P2-08 or any phase gate.

The existing provider-local tool projection and wire option records gain a nonpositional `SupportsOpenAIGrammarTools` property. Model metadata binds both properties; explicit projection configuration exposes the same resolved wire option. Existing positional constructors and shared canonical tool/Agent contracts are unchanged. Custom and `allowed_tools` choices use the existing bounded `JsonData` carrier when grammar is enabled.

Grammar resolution prefers nonempty Lark over nonempty regex and preserves definition whitespace. The schema must describe an object with exactly one required string property; optional properties are permitted. Disabled grammar retains the existing function-schema fallback. Enabled grammar declarations become Source-shaped custom grammar tools. Request-level tools and anchored additions retain the accepted additive/fallback decision, order, text roles, cache markers and whole-history/output/final-payload quotas.

Assistant replay and incoming custom calls use the final declared tool by name, including removed declarations, as Pi's `getDeclaredTools` does. A function redeclaration removes its previous grammar mapping. Unknown names and names supplied after the initial custom header retain the Source `input` fallback. The stream converts raw custom input into escaped JSON fragments, emits the closing fragment before each successful tool end, and preserves complete custom scratch state and own-undefined presence in Source push observations. Mixed function/custom slots, empty input and function-to-custom conversion are covered. Strict final object arguments are the execution authority; raw partial display cannot authorize a tool.

The genuine offline SDK capture contains 36 profiles, 71 requests/finals and 638 complete producer publications. The fixture and provider probe DLL were frozen before production edits. The same DLL records accepted-base construction rejection for 34 profiles and complete successful replay for the candidate. Full bodies, publication objects, own-undefined paths, serialized JSON object values, finals, actual native continuations and ownership joins are compared. Raw SDK/native headers and publication byte-order differences are retained separately; delivered mutable-alias timing remains unqualified.

They compare complete request bodies/publications and tool-result messages, and exercise HTTP cleanup, assistant commit, final action validation, policy/effect identity and tool-result commit before continuation. This does not qualify native Agent startup tool-registration APIs or its complete public event ABI.
