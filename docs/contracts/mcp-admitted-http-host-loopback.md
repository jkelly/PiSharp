# Explicit HTTP host injection and unexecuted loopback controls

`PiSharp.Cli.Mcp.AdmittedMcpHttpChannelFactory.Create(exactAdmittedEntry, explicitlyAdmittedBinding, borrowedClient, admittedRuntimeOptions, limits?, notification?, clock?)` returns the existing McpAdmittedChannelFactory. It visibly composes AdmittedHttpClientRequestFactory -> McpStreamableHttpTransport -> McpJsonRpcRequestChannel. Each acquisition requires the exact captured entry reference and transfers a fresh independent channel. A canceled or foreign entry fails before effects. Entry metadata does not create a client, derive an endpoint, resolve headers/credentials or grant network authority; binding/client admission remains with the owning caller. The caller supplies the same runtime options to its actual runtime/capture. Wire MaximumFrameBytes cannot exceed the explicit runtime MaximumResponseBytes; the default wire ceiling is clamped to that admitted limit before acquisition.

Eleven NEW source-only controls are defined in McpAdmittedHttpLoopbackTests.Cases(), prefix mcp-http-loopback. Root owns registration and direct awaited execution; this author did not change Program or shared profiles. All controls are UNEXECUTED. No listener, socket, HTTP request, native process, restore/build or credential operation occurred while authoring.

The actual pre-open control injects the helper into McpPreOpenServerCapture through McpSessionRuntimeFactory, then PersistentSessionLifecycle runtimeForAttachment + AttachAsync. It checks real discovered schema/catalog identity, actual bound owner generation, catalog withdrawal, transferred resource settlement, and borrowed-client reuse after owner disposal. Config grants no transport authority. Additional existing McpPreparedServer controls separately traverse actual native final policy/tool invocation and owning normal close or final shutdown with held response headers, POST SSE body, and optional GET SSE body. Body observation delegates to the actual SocketsHttpHandler stream and deliberately omits the operation cancellation token on native ReadAsync, requiring owned response/body disposal to unblock the actual read original. It does not supply synthetic bytes or replace the physical read.

The bounded endpoint binds IPv4 127.0.0.1 on an ephemeral port only. Test-owned SocketsHttpHandler disables proxies, redirects and cookies; no DNS, TLS, external address, credential or environment acquisition is used. Headers cap at8192 bytes; request body at1MiB; accepted connections at32; client concurrency at8. Host request client timeout is infinite so it cannot masquerade as owner stop; only10-second observation-gate checks bound failure detection. On failure, fixture cleanup initiates listener/socket stop before joining all actual read/write/accept and host/channel originals, retaining failures. No canceled-await effect abandonment or global-client stop is used. Test-owned clients/handlers are disposed only after host/channel originals settle.

Blocked-header controls require peer-observed close/reset without releasing response headers as the completion cause. Concurrent and later requests on the same borrowed client must survive a different request's abort. Startup controls hold initialize headers until actual owning request cancellation is observed, then race late header delivery with shutdown, require all originals to join, and forbid initialize replay; a particular native race may abort before late response transfer, so existing synthetic late-transfer controls remain necessary. DELETE is explicitly disabled in these fixtures; opt-in DELETE native qualification remains separate.
