# Selected-branch session context projection

`PiSharp.Sessions.Context.SessionContextProjector` projects immutable validated `SessionEntry` tree records into a selected branch without opening files, calling providers, executing tools or mutating records. The input excludes the session header. It supports basic durable-session resume and stored compaction/branch-summary/context-edit/bash semantics from [P4-03/P4-04/P4-06](../plans/04-sessions.md); it does not close those work packages or the phase 4 gate.

`Project(entries, selectedLeafId, cancellationToken)` requires an initialized immutable array. An explicit null leaf selects empty ancestry, messages and default settings while retaining the forest index/root metadata. A non-null leaf selects that identity and walks parent links to a root, returning root-to-leaf ancestry. `ProjectLatest(entries, cancellationToken)` explicitly selects the last physical entry, or an empty selection for an empty array. Multiple disconnected roots and parents appearing later in the input array are valid. Every input record enters the immutable `ById` index, and `RootIds` retain physical root order.

The complete forest is validated before projection. Empty IDs/parents, null entries and headers fail `InvalidEntries`; duplicate IDs, missing parents, cycles and missing selected leaves have distinct fixed diagnostics. A malformed unselected sibling still fails graph validation. Diagnostics contain no rejected identity, content or path. This is explicit native hardening: pinned `buildSessionPath` uses last-write indexing, stops at missing parents and falls back to the last physical entry for a missing/empty selected ID, while malformed cycles can fail to terminate. Native selection is never silently changed by an invalid requested leaf.

`SessionContextProjection` contains `LeafId`, `Ancestry`, `ById`, `RootIds`, runtime `Messages`, separately converted `LlmMessages`, `ThinkingLevel` and nullable `Model` (`Provider`, `ModelId`). Its trailing `ContextEntries` property contains immutable `SessionContextContribution` values, each retaining its `SourceEntry` and immutable projected `Messages`, including entries with zero contribution. The trailing constructor argument defaults for existing callers; projector outputs always initialize it. It uses `TranscriptEntry` from `PiSharp.Contracts`; Sessions has no dependency on Agent or AI. Ancestry retains every state/metadata/unknown record on the selected branch, and the index retains all other branches. Unknown outer record kinds, custom state, usage, labels and session information contribute no messages or executable behavior. This slice does not calculate accounting totals, resolve labels/session names or implement a session manager.

Ordinary system/user/assistant/tool-result messages retain their complete owned nested raw bodies, order, opaque fields, signatures, exact numeric tokens and null/missing distinctions unless an applicable context edit replaces their content or omits their contribution. System sections and tool deltas remain messages in place until compaction selects a stored system checkpoint. Branch settings replay the complete selected ancestry, beginning with thinking level `off` and no model. Thinking/model change entries update their respective settings, and each assistant message updates provider/model as the source does, including failed, omitted and compacted assistant history. No model API, pricing or reasoning capability is inferred. Messages confer no execution authority; current provider conversion and Agent admission remain responsible for their own finalized-message/content/pairing constraints.

A `custom_message` entry generates the pinned runtime `custom` shape with custom type, content, display, present details and a Unix-millisecond timestamp. Absent details stay absent and explicit null stays null. An ordinary message whose role is already `custom` retains its raw body. `LlmMessages` applies the separate pinned `convertToLlm` rule: custom content becomes a user message with content/timestamp only; string content becomes one text block, and an array remains ordered text/image content. `display:false` does not remove context. Unknown message roles remain visible inert runtime values in `Messages` and have no contribution in `LlmMessages`; they are not coerced into a known role. Original session records remain untouched throughout both views.

Generated custom timestamps accept ISO forms with seconds, optional one-to-seven fractional digits, and `Z` or an explicit numeric timezone offset within the native `DateTimeOffset` range. Unsupported date syntax fails `UnsupportedTimestamp`. Already stored message timestamps remain untouched. This is a disclosed native timestamp profile; general JavaScript `Date` parsing/NaN behavior is unfinished qualification.

The latest compaction on the selected ancestry defines active `ContextEntries`: the checkpoint itself comes first, followed by earlier entries starting at `firstKeptEntryId`, followed by all entries after the checkpoint. Earlier system message entries are excluded from the retained range. A missing, sibling, checkpoint-self or later boundary retains no earlier entries, matching the public helper. A retained older compaction stays in provenance and contributes zero messages. An optional non-null `systemMessage` contributes its complete owned raw body before the newest `compactionSummary`; an absent/null checkpoint contributes only the summary, without reconstructing historical system state. No unselected checkpoint changes context.

Context edits are collected only from active entries, after compaction selection. The last active edit for a target wins. A null replacement removes the target's entire contribution, including both checkpoint messages if the target is a compaction. A non-null replacement changes content only for user, assistant, tool-result and custom messages; assistant/tool-result string replacement becomes one text block. Replacement arrays retain their exact owned values and order. Other message roles retain their content. Unknown targets have no contribution to change. Editing an edit entry does not undo that entry's influence: edits are collected before message projection, exactly as in the source. Replaced messages retain all other metadata and raw numeric/null/opaque/signature values; original append-only records always remain untouched. Historical call/result consistency after an edit remains a provider/Agent admission concern.

A nonempty `branch_summary` entry contributes `branchSummary` with summary/fromId/generated timestamp; an empty summary contributes zero messages and remains visible in provenance. The newest compaction contributes `compactionSummary` with summary/raw tokensBefore/generated timestamp, including empty summary text. Already stored summary message roles retain their full raw runtime bodies. Separate `LlmMessages` conversion wraps branch/compaction summaries in the exact pinned `<summary>` text, including their different suffix newline behavior, and converts them to user messages while retaining timestamps.

Stored `bashExecution` messages remain raw runtime history and acquire no shell authority. Model conversion emits the exact authored command/output text with output fences or `(no output)`, cancellation or nonzero exit status, and an optional truncation path notice. `excludeFromContext:true` retains runtime/provenance data while omitting the model contribution. Referenced output paths are text only and are never opened. Absent/null exclusion flags behave as false. The native conversion profile requires optional non-null exclusion flags to be booleans and optional non-null output paths to be strings; malformed values fail `UnsupportedMessage` rather than applying JavaScript coercion. A non-cancelled visible exit code beyond the exact JavaScript integer range also fails `UnsupportedMessage`; wider JavaScript number-to-text formatting is unfinished qualification. Other raw numeric values remain owned unchanged. A supplied checkpoint must have the known system role, string/array content and numeric timestamp; malformed checkpoint fields fail `UnsupportedMessage`. General malformed-file repairs/coercions performed by the upstream unvalidated reader remain outside the validated codec profile.

Defaults bound 100,000 input entries, 100,000 selected ancestor steps, 16,777,216 total raw input UTF-16 characters, 100,000 messages per output view and 16,777,216 raw serialized UTF-16 characters per output view. All limits must be positive. Cycle validation completes each identity once across walks and is bounded by admitted entry count; selected ancestry has its separate step limit. Runtime and model views are admitted independently. Bounds include unknown and unselected records at input, and converted custom bodies at output. Existing codec ownership supplies duplicate/Unicode/depth validation; this projector does not bypass it. The bounds are logical admission limits, not a complete heap cap or durable store capacity guarantee. Cancellation is checked before admission, during forest/ancestry/message traversal and before returning the immutable snapshot.
