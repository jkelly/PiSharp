# Durable native session lifecycle

This milestone extends the accepted `2f68abf57f84a0cb6087b0e01d2f437b93885f94` replacement owner with actual durable new, fork and clone. It is an experimental, explicit local-file profile. It does not close P4-08, P5-04, P6-07, P6-10 or any full phase gate. The complete 79 original scopes remain mandatory. A completion percentage is unsupported.

## Ownership and storage

`PersistentSessionLifecycle` borrows the configured model/tool registry, clock, entry-ID generator and persistence bounds. Fresh files are siblings of the explicitly attached file. It owns no default home, network provider, credentials or global registry. New session IDs are bounded safe filename components, distinct from the current header identity; filenames contain a UTC timestamp and that fresh identity. Existing files are never overwritten.

The planner validates the complete current-v3 source graph without effects. Fork-at retains the requested ancestry; fork-before requires a user message and returns concatenated text blocks with images excluded. Fork-before a root produces an empty session. Clone uses the current logical selected leaf, including when the physical file ends on a sibling. An empty selected branch cannot be cloned.

Fresh headers contain current session fields and an optional parent link, without copying opaque fields from the old header. Fork and clone record the source path as their parent; new accepts an optional bounded parent metadata value. Historical labels are removed from the copied path and parent links are repaired. Compaction references to removed label entries are remapped to the following retained entry; compaction self-references remain intact. Global resolved labels come from all physical entries, including siblings, and are recreated only for original retained targets. Overwrite/delete/re-add order follows the pinned JavaScript Map behavior. Opaque entry bodies, unknown fields, nulls and numeric token spelling are retained.

`SessionBranchPublisher` re-reads and validates the complete planned bytes before creating an owned temporary file. It awaits the write, asynchronous flush, real file-content `Flush(true)`, close and nonoverwriting move. This acknowledges file content durability under the local backend; it does not claim directory-entry crash durability or a transaction with session attachment. The provisional file can be visible to filesystem readers before attachment.

Known publication returns an owned receipt. Until attachment commits, rollback closes its actual coordinator before deleting that known file. Late cancellation after a known move retains cleanup authority. A failure around the move is explicitly uncertain: an unproven final file is retained, owned temporary cleanup is joined, and the old session remains current. Close/delete failures remain explicit; no blind retry or deletion of an unproven destination is performed.

The owner serializes mutation and reserves both source and actual staged target through preflight and publication. A typed pre-effect veto runs before generating IDs or creating files. The optional per-operation target preflight can reject the actual context or output budget before source retirement. Publication releases the target reservation before fresh callbacks. Previous contexts become stale by attachment generation; matching disk IDs do not restore authority. The originating admitted callback can continue through its returned fresh context while old physical writer retirement and final cleanup are joined. Notification failures retain the committed attachment and are reported as committed failures. Abort/EOF/disposal cancel cooperative old and current work and join owned cleanup.

## Native SDK and frontends

`IExtensionSessionCreationCommandContext.CreateSessionAsync` returns a fresh owned context plus fork-before selected text. `IExtensionSessionCreationRegistry` registers typed, ordered continue/cancel handlers separately from observations. Handler failure and cancellation are not veto decisions. Creation features are advertised only for a configured creation broker. Original interfaces and the two-argument replacement constructor remain available.

The required SDK return snapshot is validated with the registry's eventual policy on the actual staged target before source retirement/publication. Known rejection joins rollback and preserves the source writer. A later failure admitting the committed returned context has an explicit ID/generation/leaf receipt and joined scope cleanup. See [SDK creation admission](native-session-lifecycle-sdk-preflight.md), including the held predecessor finding and the additive broker overload that fails closed on older hosts.

An explicit trusted-host `IExtensionSessionOpaqueViewProvider` capability permits bounded strict JSON numeric tokens to be retained in readonly session views. Ordinary snapshot providers keep their original finite-number profile. Executable plugin arguments, descriptors, completions, metadata and tool results retain their existing validation. Depth, duplicate-property, Unicode, count, character and UTF-8 budgets still apply.

The explicit offline CLI profile supplies the actual lifecycle services. RPC implements `new_session`, `fork`, `clone`, `get_tree` and `get_fork_messages`. Fork defaults to before; optional `position:"at"` is a native RPC extension. Tree nodes retain raw entries, resolved labels/timestamps and chronological children, with explicit depth/output limits. Fork choices include all physical user messages with nonempty concatenated text. Actual staged response/event budgets are checked before attachment commits. Cooked CLI routes `/new`, `/clone`, `/fork <entryId>`, `/fork-at <entryId>` and `/tree`; a successful fork restores its selected text to the editable draft. Existing switch, JSON output and fresh subscription handoff remain integrated.

The ordinary compiled SessionCheckpoint sample adds an optionally enabled `/checkpoint-create` command. It saves only through the returned fresh context and proves that the original context rejects a physical append. The same approved package generation survives replacement. Direct RPC creation uses its real typed confirmation handler; unavailable/false/timed-out/cancelled UI is not approval. Headless sample commands can explicitly request `confirm:false`. A second postcommit checkpoint confirmation demonstrates abort/EOF while retaining the new session.

## Evidence and remaining scope

Development adds six planner, fifteen publisher, twelve coordinator, four registry, three RPC and five published-process groups. The latter cover all three recorded provider profiles without acquiring turns; report/print/JSON SDK use; rollback/veto/abort/EOF; postcommit original-callback cleanup; actual cooked CLI routing and fork draft restoration. Failed development runs are retained, including reader sharing/empty fixture corrections and the fresh opaque-view integration defect fixed in this milestone. Full native and original Commands/Input/real-terminal gates must pass for the exact immutable candidate, followed by separate Astra Medium review.

Source semantics were inspected against local pinned `earendil-works/pi` v0.99.1, commit `d86654abb8862e201933517d6f1fce9f88dd117f`, notably `core/session-manager.ts`, `core/agent-session-runtime.ts`, `core/agent-session.ts` and `modes/rpc/rpc-mode.ts`. New tests are authored native controls, not a claim that the complete upstream TypeScript lifecycle corpus was run.

Upstream lazy persistence and in-memory backends, complete discovery/listing/resume selection, import/export/read-only services, full cwd/store identity behavior, broader tree navigation and context editing, source session setup/preferences/resource reloads, complete extension event/UI parity and all other original clauses remain open. The native profile deliberately creates an eager durable file, including an empty new session; it does not imply lazy/in-memory equivalence. Paid/live provider calls, public pushes/releases, credential setup and permission expansion are outside this work.
