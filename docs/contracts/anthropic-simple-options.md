# Anthropic Simple option resolution

Source-only candidate based on `4429296e4135b53a38634a731fe7a9b3e43e5fad`. Reference: Pi v0.99.1 commit `d86654abb8862e201933517d6f1fce9f88dd117f`. Tests are authored, unexecuted native expectations from pinned source text. No genuine source capture, compilation, runtime parity or phase acceptance is claimed.

`AnthropicMessagesSimpleOptions` carries owned model metadata, the existing projection profile, the requested reasoning level, optional integer output cap/custom budgets/tool choice, an explicit supplied key and existing HTTP/DTO options. `AnthropicMessagesSimpleRequestFactory` implements `IChatTransport`, so the existing direct iterator, `ChatClient` and native `Agent` can consume it. `Resolve` is pure; `Create` returns the existing owned request; `StreamAsync` borrows the supplied `HttpClient` and composes the unchanged Anthropic key factory, HTTP/SSE transport and DTO mapper. Each invocation resolves the current request transcript again. No Agent thinking metadata is treated as a provider option.

`buildBaseOptions` always supplies a cap to the older-model helper, including when the caller omitted it. The implementation preserves that actual call order. ## Bounded contract

Model metadata must match the configured ID/API/provider and contain integer `maxTokens`/`contextWindow`, boolean `reasoning`, and any applicable adaptive flag/map. Model and caller caps are positive integers; custom budgets are nonnegative integers for minimal/low/medium/high. Usage counters are nonnegative Int32 values, timestamps are Int64, and aggregate overflow is rejected. Finite fractional or wider token values and malformed/missing metadata remain outside this slice. Message/character limits are explicit; the existing projection/request/transport limits continue to apply. The existing projector's admission of transcript content, schemas, Unicode, model compat and tool changes remains authoritative.

Simple owns cap and thinking resolution: it overrides the direct profile's cap, thinking fields and key-factory `MaxTokens`. Other direct profile values, including temperature/cache/header configuration, retain their existing behavior. Model `thinkingLevelMap.off = null` suppresses the disabled-thinking field. Simple tool choice overrides the profile tool choice when supplied. Supports-mid-conversation-effort metadata is explicitly rejected because its inserted effort messages and binding controls are not implemented by the direct projector. Other model compatibility projection flags must be supplied through the existing admitted projection profile.

Authentication remains the existing explicit printable ASCII API-key contract. The key is validated before transcript resolution/request effects and supplied literally by the caller; OAuth-shaped keys and Copilot/bearer modes remain unsupported. No environment lookup, stored credential lookup, OAuth identity/refresh, retry, provider registry or new callback machinery is added. Request/response hooks, sampling-parameter forwarding, metadata/telemetry forwarding, SDK parity, other source provider compatibility branches and source capture remain separate gaps.

Injected-auth candidate `fca581f14105d11a35e8a64b05e38582fc1ffec3` is independent. A later adapter may pass an owner-admitted `ResolvedAuthentication.Secret` when its `Kind` is `AuthenticationKind.ApiKey` to this explicit-key contract. It must preserve bearer results as a separate header path and the existing rejection of OAuth-shaped keys. That adapter belongs in a separate reviewed slice after authentication review; this candidate neither references nor duplicates the injected resolver and never reads the real environment or credentials.
