# Terminal input lifecycle reentry correction

This source-only successor addresses R662SDK-TUI-01 in commit 8afd82fc4e76c48c736948b9161546241ef9b0ba. The earlier source, bundle, patch and handoff are preserved. No compiler, native test, Node process, network or terminal operation was executed by this worker.

Closing a scope or hub from its own callback previously could await the callback's own pending observation and deadlock. Synchronous cancellation handlers could similarly join the in-progress close. The runtime now records active callback ancestry through AsyncLocal frames spanning the actual returned callback Task, including nested dispatch into another hub. Scope or hub DisposeAsync rejects owning and ancestor callback/cleanup closes with InvalidOperationException before acquiring the mutation lock, changing admission, or returning an already-running close task. Rejected calls leave scope and connection admission intact.

Cancellation cleanup has its own active frame. Because ordinary token registrations restore the ExecutionContext captured when registered, the guard also follows a scope's active cleanup frame from any captured input frame. This retains a later cleanup ancestor even when the registered callback predates that ancestor. UnsafeRegister callbacks execute in the cleanup context and are covered directly. Frames become inactive after invocation/cleanup settlement, so a later continuation carrying inherited inactive ancestry can close normally. A distinct unrelated scope may close from inside a callback, including a scope on the same hub as an ancestor.

External close semantics are retained: one stable close Task, cooperative cancellation, joins of admitted original callbacks, stale output suppression, and original fault Task/exception graph retention. An uncaught guard exception becomes an original callback fault or a cleanup exception; it is joined and retained by external retirement rather than detached or relabeled as cancellation. Synchronous unsubscribe stays source-compatible and does not call DisposeAsync or invoke the lifecycle guard.

TuiComponentFacadeTests now contains twenty source groups. Existing transformation, unsubscribe, generation, bounds and held external retirement controls remain; the old synchronous-OCE control now expects own close to reject before mutation. Added groups cover async own scope/hub await, nested ancestor rejection and unrelated scope allowance, inactive inherited frames, Register/UnsafeRegister synchronous cancellation reentry, restored cleanup ancestry, and uncaught callback/cleanup guard failures with original fault and stable external close preservation. These are authored and unexecuted. Shared runner registration, root serial compiler/test qualification and separately owned admitted CLI host wiring remain required. No whole SDK parity or native acceptance is claimed.
