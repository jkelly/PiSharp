# Published loader Windows path identity correction

The private managed-assembly resolver still requires an approved owned image with an exact assembly name/version/culture/public-key-token identity and a matching owned snapshot location. It loads the already captured, hash-verified bytes through LoadFromStream. This correction changes only comparison of the resolver's Windows path spelling; it does not load a dependency from the returned path, authorize a different location by hash, or introduce a Default/private fallback.

At candidate `7465f9fe11d5c05c1d8d8b2f0f76bd76787de9fb`, independent EXT-LOAD-1 evidence recorded the same readable Fixture.Private.dll at a captured 237-character path and a 302-character path. AssemblyDependencyResolver returned the latter with a `\\?\` prefix (306 characters). Both spellings had the same SHA256 and bytes, but Path.GetFullPath retained the prefix, so ordinal comparison rejected it with MissingDependency. The genuine callback never ran. The original review, LongPathProbe source/observations and failed 483/485 gate remain evidence; they are not relabeled as passing.

`PluginLoadContext.IsOwnedManagedPath` normalizes both compared paths. On Windows it requires a fully qualified local drive path. A Windows extended prefix may be removed only when its remainder is an already canonical, fully qualified drive-letter path. The comparison remains ordinal after this sole alias normalization: casing is not folded, alternate file identities are not guessed, and basename/hash equality never substitutes for location equality. UNC, extended UNC, device and volume paths do not become local snapshot paths. An extended spelling containing noncanonical separators or dot segments is not converted into an ordinary spelling. Non-Windows comparison retains full-path ordinal equality; this does not qualify a new platform for the published loader.

The surrounding metadata/execution trust binding, exact artifact hash capture, assembly identity checks, core-framework allowlist, shared host Assembly identity, native-dependency rejection, snapshot locks, collectible-context isolation and cleanup remain unchanged. This is lexical equivalence of two canonical local path spellings, not open-handle identity, symlink/hard-link equivalence, hostile-filesystem confinement or a sandbox. The broader origin/path-race and platform gates remain required.

`PublishedLoaderTests.Cases()` retains all six previous groups unchanged and adds one Windows x64 group. It executes the real published private callback at the ordinary shorter snapshot parent and a separately nested parent producing a captured path longer than 300 characters. It reads the actual dependency through captured, explicit extended and actual resolver spellings, compares complete bytes and SHA256 against the approved publication, and asserts the callback's private version plus shared host contracts. Existing durable published integration expectations are untouched.

The same group uses test-only reflection to invoke the private comparison method without exposing a public ABI or a friend assembly. These direct ownership controls prove symmetric normal/extended alias acceptance and rejection of a separately created same-basename, identical-hash DLL location, UNC/device/volume/relative paths and a noncanonical extended dot-segment spelling. They are comparison-level negative controls; no claim is made that a different-location assembly was executed or that the loader can recognize every physical alias. Tests preserve the ordinary fixture directory convention rather than shortening existing integrations to avoid long paths. Owned temporary directories retain the existing checked cleanup.

Source and tests were authored without .NET, process or Git execution by the delegate. Root owns approved fixture publishing, fresh isolated build/full gate, immutable commit and independent EXT-LOAD-1 retest. The repair remains unverified until those actual executions complete; no full P6 or frozen SDK claim is made.
