# Anthropic explicit-key HTTP/SSE integration

`PiSharp.AI.Protocols.AnthropicMessages.AnthropicMessagesKeyAuthRequestFactory` constructs a complete owned HTTP request from the accepted pure request projector. `AnthropicMessagesHttpSseTransport` sends it through an injected `HttpClient`, the shared `HttpSseTransport`/`SseDecoder`, strict owned DTO admission and the accepted `AnthropicMessagesTransport`. The result is a working native `IChatTransport` usable by `ChatClient` and `TurnRunner`, including a real tool call/result/next-request round trip. No credentials are discovered, SDK installed, network endpoint selected, retry scheduled or tool executed by these two classes.

Source authority is public Pi v0.99.1 commit `d86654abb8862e201933517d6f1fce9f88dd117f`: the complete unchanged [Anthropic wrapper](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/anthropic-messages.ts), its `createClient`, `buildParams` and `iterateAnthropicEvents` functions, and the upstream-locked SDK0.124.0 `src/resources/beta/messages/messages.ts`, `src/client.ts` and `src/internal/headers.ts` read from the reviewed local oracle. The actual SDK capture and its environment/source/dependency receipts are described in [the capture contract](../compatibility/anthropic-sdk-captures.md). No public helper was extracted or patched for native request expectations.

The API is:

```csharp
var factory = new AnthropicMessagesKeyAuthRequestFactory(baseUri, model, projectionOptions, keyOptions);
var transport = new AnthropicMessagesHttpSseTransport(httpClient,
    (request, token) => factory.Create(request, explicitKey, token), httpOptions, mapperOptions);
```

The factory borrows immutable model/options and receives the key explicitly on each call. The caller owns every successfully returned `HttpRequestMessage` and content. The HTTP adapter borrows the client and takes ownership of each fresh factory-returned request for one enumeration. Its token-aware factory receives the original immutable `ChatRequest` and enumeration cancellation token. A throwing factory retains responsibility for any resources it did not return. No authentication or endpoint is supplied by the HTTP adapter itself.

The base URI must be an absolute HTTP(S) URI without user information, query or fragment. The factory appends `/v1/messages?beta=true` to its configured path, including a base path such as `/tenant`, matching SDK `buildURL` resource-path concatenation. It has no default live endpoint. The request model must equal the configured descriptor. Key characters must be printable non-whitespace ASCII and fit the explicit bound. OAuth-looking keys containing the pinned `sk-ant-oat` marker fail with `UnsupportedOptions`, because the source switches those to a different authentication/body/header path. `OAuthProjection` and `github-copilot` likewise require unfinished authentication integration and are rejected explicitly; those workflows remain mandatory work.

The accepted projector supplies the complete `model`, `messages`, `max_tokens`, `stream` and conditional system/tools/thinking/output_config/temperature/metadata/tool_choice/fallback fields. Canonical source messages stay unchanged. Projected JSON values are written as their raw owned syntax rather than passed through a second numeric serializer. The SDK's `betas` member is removed from the JSON body and joined into `anthropic-beta`, including automatic fine-grained/interleaved/fallback betas and explicit configured beta selection. JSON content type is exactly `application/json`, with no invented charset suffix.

The pure projector's `MaximumTokens` is still a positive Int32 parameter. Factory `MaxTokens` is a separately explicit nullable double override for the public **direct stream** path: absent uses the projected model cap; zero, minus one and fractions are retained rather than clamped. The value must be finite and have magnitude at most `MaximumTokenMagnitude` (default1,000,000). Finite numbers use the same bounded invariant shortest round-trip and ECMAScript fixed/exponent thresholds as the accepted projector; negative zero becomes0. The eight captured `Number(authoredLexeme)` conversions and complete three request bodies are compared without normalizing numeric tokens. Exhaustive ECMAScript shortest-digit/tie parity, broader number profiles and the distinct `streamSimple` clamp/default path remain required qualification. This override does not change those existing projector contracts or certify server acceptance of a negative/fractional token limit.

Header inputs are immutable owned JSON objects with string or explicit-null values: `RuntimeHeaders`, `ModelHeaders` and `Headers`. Each is strictly reparsed before use. Runtime headers precede the source client defaults, optional session affinity, model headers and options headers. Within model/options merging, exact-case property replacement keeps its insertion position as in `Object.assign`; subsequent HTTP lookup is case-insensitive. Null removes an earlier header. Values trim outer HTTP spaces/tabs at publication. Configured beta selection uses the source case-insensitive scan, split/trim/deduplicate order and null suppression. The beta parameter header then overrides client defaults, as in SDK beta resource creation. JSON encoder content type overrides client defaults. Content-Type routes to the content-header collection with OrdinalIgnoreCase matching: replacing a value in the case-insensitive merged dictionary can preserve its first key spelling, so every admitted spelling must receive the same unconditional `application/json` encoding override. A supplied null likewise cannot remove the body's required JSON content type. `SessionId` supplies `x-session-affinity`, or explicitly selected `x-session-id`, only when affinity is enabled and cache retention is not None. No affinity capability is inferred from a provider name or endpoint.

Native defaults are `accept: application/json`, `anthropic-version: 2023-06-01`, `anthropic-dangerous-direct-browser-access: true`, `user-agent: PiSharp`, plus the explicitly supplied `x-api-key`. The factory does not pretend to be a Node runtime or inspect OS/runtime/catalog state. The genuine SDK requests have nine exact default-profile differences: a different user-agent and eight additional `x-stainless-*` metadata headers (arch, lang, OS, package version, retry count, runtime, runtime version and timeout). Tests inventory all nine differences and separately compare every header using **explicit authored** metadata inputs for the frozen SDK environment. Those configured equality checks qualify header merging/serialization, not automatic native runtime metadata parity. Source timeout values reflected in an explicitly configured `x-stainless-timeout` header do not install a native timeout or retry policy; caller `HttpClient`/cancellation supplies current work lifetime.

Header names use HTTP token characters; values use printable ASCII plus horizontal tab. CR/LF, unpaired/non-ASCII header data, malformed/null-array inputs, content-length/transfer-encoding/connection/host overrides and Authorization/Cloudflare alternate-auth fields fail with fixed diagnostics. Broader header character profiles and alternate-auth routing are explicit unfinished capabilities rather than a claimed permanent product exclusion. Explicit x-api-key replacement is allowed; its removal/empty final value fails the key-auth profile. Neither rejection nor mapper diagnostics include a rejected name/value/key, URI, body, reason phrase or inner exception.

Bounds are checked before acquiring request/content or sending: configured base-URI length, key characters, token magnitude, count/per-header/cumulative supplied and emitted header characters, projected input/output/depth limits, and exact compact UTF-8 body bytes. Default payload cap is1MiB and depth32. The effective intermediate projector output cap is also reduced to the factory payload cap; its pre-header-lift `betas` bytes and characters still count against that independent intermediate allowance. This can reject a projection even when its later beta-free wire body fits. The serialized body is measured before allocating the UTF-8 buffer and owned HTTP objects. Existing projector bounds cover per-entry/aggregate input characters, block/declaration counts and output construction. These are logical data limits, not a total heap cap; caller-owned input, framework buffers, parsed documents and immutable clones allocate separately.

HTTP enumeration sends once with `ResponseHeadersRead`, using the shared transport. It does not buffer the response through `SerializeToStreamAsync`. Non-success status is rejected without acquiring or reading the response body. Normal exhaustion, early consumer disposal, cancellation, strict-data failure and read faults all await body `DisposeAsync`, then dispose response/content, then dispose the factory-returned request. No terminal success/error is emitted before owned source cleanup settles. Shared response/content disposal is synchronous after the acquired body's asynchronous cleanup; an injected body must tolerate that later idempotent synchronous disposal. Failure of body cleanup still disposes response and request. The borrowed client remains usable. Cancellation is checked before the factory/send/acquisition, during framing and before DTO publication; cancellation during final cleanup still wins terminal choice in the existing mapper.

Framing is the shared incremental LF/CRLF/CR SSE decoder with strict UTF-8 enabled and `DispatchPendingEvent` at EOF, as the pinned Anthropic helper flushes a final partial line/event. Options that disable either setting are rejected before a send. JSON depth, event count, per-data UTF-16 characters and aggregate data characters are independent HTTP admission limits (defaults4096/65,536/1MiB/depth32). Every data-bearing frame is charged, including unknown/ignored frames; framing independently bounds lines, event fields and read buffers. Control-only SSE blocks do not consume data-event counts. Logical bounds include opaque fields rather than ignoring their storage.

The public wrapper accepts only named `message_start`, `message_delta`, `message_stop`, `content_block_start`, `content_block_delta` and `content_block_stop` data frames. This bridge preserves that name filter. JSON `type` then drives the mapper, as it does after the source filter; no invented event-name/type equality requirement is added. Named `error` is a provider signal before parsing, even if its data is not JSON. It becomes an inert sanitized error DTO for the accepted mapper, preserving provider-error settlement while excluding source error text from diagnostics. Other names, including the default `message`, `ping` and future events, are ignored after charging their data. The exact data `[DONE]` has **no sentinel behavior**: an unknown/unnamed frame containing it is ignored; one in an accepted event is invalid JSON. It never supplies or truncates a successful assistant. Missing stop reason/message_stop remains an error; the accepted mapper also validates block completion and all its existing structural rules.

Data admission uses strict JSON parsing, object-root validation, bounded depth, valid decoded UTF-16 and `JsonData` cloning/decoded duplicate rejection. Comments, trailing commas, invalid UTF-8, unpaired surrogates and duplicate escaped/plain names fail closed. Opaque JSON numeric tokens are retained without conversion at this bridge; known counts/arguments then follow the mapper's documented profiles. The source repairs some JSON and replaces malformed UTF-8 while this native bridge rejects them; these are disclosed hardening differences. The shared decoder emits data-bearing events only; event-only named-error frames are not yet representable through this seam. Matching the source's event-only callback/error behavior remains required framing work and is not a full decoder-parity claim.

The existing accepted mapper emits normalized Start before pulling HTTP source work, while the source wrapper emits Start after response acceptance. That timing difference remains explicit. Acquired source `MoveNextAsync` failures—including HTTP status/send/read/framing/bridge admission faults—are classified by that mapper as sanitized `anthropicFailure: SourceFailed`; actual named error frames become `ProviderError`. Mapper DTO structural errors and its own resource bounds retain `MalformedStream`/`ResourceLimit`, incomplete valid streams retain `UnexpectedEof`, and actual caller cancellation retains `Cancelled`/Aborted. `ChatRun` maps an admitted error terminal to Provider/Cancelled and may independently enforce lower reducer limits. A finer pre-start HTTP/auth/status/timeout/admission taxonomy remains required; this composition does not silently reinterpret the accepted mapper boundary.

The additional content-header regression crosses all three header sources with lowercase, title-case, uppercase and mixed-case Content-Type, each with a string override and explicit null. Header values are observed from complete `HttpHeaders.ToString()` field rendering, parsed by strict CRLF/name/delimiter handling with duplicate rejection. Field names alone are compared case-insensitively; values are not rewritten. The earlier generic observer joined every parsed value with a comma: root observed the source user-agent `pi (win32 10.0.26200; x64)` become the incorrect native observation `pi, (win32 10.0.26200; x64)`. The typed .NET User-Agent renderer separates product/comment tokens with spaces, while Accept and repeated opaque values use their actual field separators. Lexical controls check complete User-Agent/Accept/authentication/opaque/content-type fields, parsed-value stability and a negative control against the old comma join. This corrects observation syntax without changing native defaults, explicit header values, the genuine SDK array or the full comparison's field inventory.
