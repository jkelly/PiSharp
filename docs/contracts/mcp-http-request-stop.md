# MCP HTTP request-specific stop correction

The concrete streamable HTTP transport now requires an effect-free McpAdmittedHttpRequestFactory returning a fresh IMcpAdmittedHttpRequestOperation. SendAsync owns the header/send original. Stable StopAsync must initiate request-specific physical abort before joining that original, fence later sends, and never dispose a borrowed global client. The historical exchange-only constructor rejects before effects. Host construction must supply this new explicit admission; a cancellation token alone does not satisfy physical-stop authority.

The transport tracks bounded admitted request owners and acquired response owners. Close starts every request stop and acquired response/body disposal before awaiting them. Responses or bodies transferred after that fence start disposal on transfer and remain joined through the actual operation settlement. Response/body disposal and stop callbacks run as retained originals with lifecycle reentry rejection. Cleanup failure prevents further acquisitions and remains visible in stable close, including late cleanup failure. DELETE remains explicitly opt-in and uses a fresh admitted operation.

Synthetic HTTP fixtures now use explicit per-request stop leases. Added pending-header/cancellation-callback/late-response control and historical-constructor refusal; revised POST and GET held-body controls require disposal before the separately held read original can finish. Cleanup-failure controls assert stable close retains original cleanup exceptions. All fixtures are authored only: no build, test execution, native process, HTTP request, package operation, credentials or global-client disposal occurred.
