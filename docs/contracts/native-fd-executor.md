## Explicit host prerequisites

FdFindExecutor requires all of these host-supplied capabilities; none come from tool arguments or ambient discovery:

- FdBinaryDescriptor: canonical absolute executable, exact positive size <=64 MiB, SHA256, host-verified version, win-x64 and admission receipt identity. The mandatory FdBinaryAdmission callback must confirm the exact artifact belongs to a verified immutable admitted snapshot. Metadata/hash alone is not an approval service; an arbitrary user-supplied hash or a denied package must not be treated as admission. No package/loader policy is bypassed or changed.
- Explicit canonical workspace, complete copied child environment, and ISeparatedProcessRunner. No PATH lookup, shell command, inherited environment, speculative timeout or autodownload is used. The host must retain ownership of the immutable binary snapshot directory through the invocation. An actual FileStream image handle with read-only/no-write-or-delete sharing remains open through process and spill joins; size/hash are checked on those exact retained bytes, and canonical path is rechecked at the launch boundary. This does not claim a universal atomic executable-file-ID API or filesystem sandbox.
- FdRepositoryLookup: a qualified source-equivalent inside/outside Git-repository answer for the exact search path. Source checks ancestor .git presence to choose --no-require-git. The lookup's metadata probes must be inside separately admitted host scope; Unknown rejects rather than assuming ignore behavior or walking unapproved parent directories. A bool cannot substitute for qualified nested repository/ancestor ignore evidence. Actual fd handles glob and ignore files; this executor does not approximate either.
- IFdSpillLeaseFactory: a stable canonical root inside the admitted workspace, checked before acquisition; one exclusive per-invocation lease with awaited disposal. LocalFdSpillLeaseFactory creates a unique directory through existing file operations and deletes only its checked owned directory after original process/stream/output cleanup. It rejects changed canonical identities/root links and retains one stable disposal task. Spill artifact output must match the lease path. No spill target comes from tool arguments.

The host's original final Path-action policy still authorizes the search root before execution. The fd executor additionally contains search/spill paths in its captured workspace. Binary admission is a separate mandatory host capability, not ambient permission inferred from a directory read grant. CLI registration is withheld until a real verified binary, qualified repository lookup, explicit environment and actual native platform receipt are available.

## Source execution and formatting

Fd argv follows source order: --glob, --color=never, --hidden; add --no-require-git only outside a Git repository; --max-results and the explicit integral limit. A pattern containing '/' adds --full-path and gains a leading **/ unless it already starts '/' or **/ (or equals **). Windows separators become the source [/\\] character class; -- separates the untouched effective pattern and absolute search path. The actual admitted fd parses all glob syntax; unsupported/invalid syntax is not replaced by a hand-written matcher. Native admitted text is bounded non-control, non-surrogate BMP text; broader Unicode is pending.

Fd profile sends no custom .git/node_modules ignore array, because pinned default fd has no such argv exclusions. The existing custom-glob profile retains its original fixed filters and short notice. FindTool captures the profile once and chooses the default fd continuation notice only for fd. Source glob/gitignore matching, case behavior, result ordering and repository boundaries are delegated to the exact admitted binary and its qualified environment; no sort or deduplication is introduced.

Only separated stdout supplies paths. CRLF/CR/LF and final unterminated line normalize to lines, then each line is trimmed and empty lines skipped in source order. Nonzero exit with no stdout uses trimmed stderr or `fd exited with code N`; nonzero exit with useful captured stdout retains those results as source does. Successful empty stdout returns no results, independent of warning stderr. Spawn/invalid/incomplete/timeout/unexpected canceled receipts fail explicitly. Whitespace-only nonempty raw stdout is a documented unsupported corner: source can return an empty text content whereas this backend rejects; it is not silently reported as ordinary no matches.

FindTool retains source relative/POSIX/slash formatting, path containment and complete-line 51200-byte head truncation. Fd reached-limit notice is `N results limit reached. Use limit=2N for more, or refine pattern`, then the byte notice. Existing native integer/input/result/path bounds still apply. fd over-limit/oversized/NUL/truncated receipts reject rather than reporting unsupported partial output. Fractional/nonpositive source limits, unrestricted output, Unicode/path/platform behavior and exact source rejection shapes remain unqualified.

## Original process ownership

The old IProcessRunner receipt merges stdout/stderr and cannot honestly parse fd paths/errors. NativeProcessRunner now additionally implements ISeparatedProcessRunner. Its ordinary RunAsync passes no separated capture and retains original merged collector, callbacks, admission, cancellation, process/job/pipe joins, output finish/disposal and physical lifetime disposal. No Bash adapter behavior or configuration is changed.

RunSeparatedAsync uses those same original pipe pumps; each appends its raw bytes to one independent bounded capture before the unchanged merged channel write. Only one original pump writes each buffer. Both original pumps, collector, exit/drain, output stream disposal and process lifetime disposal are joined by the original RunCore/RunOwned flow before a SeparatedProcessRunResult retains that same ProcessRunResult object. The side buffers are decoded after the pump joins and disposed at method settlement. Each pipe is capped by existing StructuredMaxBytes (<=1 MiB); clipping is explicit per pipe and the fd executor rejects it. The original merged spill/diagnostic receipt is retained, not substituted with a fabricated child receipt.

The fd executor awaits the original separated runner without WaitAsync or detached work. It rejects absent/inconsistent/incomplete capture/cleanup/spawn/diagnostic facts, checks caller cancellation only after original settlement, then awaits spill disposal. Original operation and spill cleanup failures are retained as distinct original objects in order in AggregateException; cancellation token identity survives clean cleanup. Retained binary image disposal is also awaited by its owning scope. Physical native separated-pipe qualification is still pending; fake receipts are not that evidence.
