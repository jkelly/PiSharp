`AllowedToolSelection.Create` captures immutable ordinal allowed/excluded sets and stable initial order. Null allowed names are unrestricted; an empty set denies every name. `FilterCatalog` must run over every candidate catalog before registration, namespace lookup, nested callable construction or loadout preparation. `SelectInitial` selects only direct/model-only names, then appends default-active declarable extensions only for unrestricted policies. Script-only and hidden names can remain in a permitted catalog without becoming model-active. The projection performs no I/O, tool acquisition or grant changes. Native bounded name validation is stricter than unbounded upstream strings.

Existing CLI initial selection now captures `InitialToolSelection.LifetimePolicy` for explicit `--tools`/`-t`, including explicit empty. It does not yet enforce that policy: a coordinated core integration is required. Settings-only selection retains no lifetime cap. No new CLI flags are advertised in this leaf.

Required atomic integration: supply the captured policy and effective initial selection to the session open owner before resolving recorded tools. Keep original transcript bytes and unavailable/mismatched binding checks for declarations that remain selected. Build the runtime using only currently admitted, filtered bindings; never acquire or trust a historical tool. Retain the policy on the session owner across registry replacement, session replacement, fork and extension refresh; reapply it to each incoming catalog and ignore disallowed activation (Pi 1.1.0) without a durable mutation. This leaf therefore does not change shared session/runtime/profile files.
