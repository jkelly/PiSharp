# Catalog image-input declarations and caller ownership

`FrozenCatalogModel.DeclaresImageInput` answers one metadata question: does this admitted model's `input` array contain the decoded ordinal string `image`? It uses the existing catalog validator and immutable ownership. It does not select or register a transport. `ModelDescriptor` remains the three-field identity record.

The pinned [BaseModel contract](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/types.ts#L1097) declares input separately from operation type and output. The [model-data validator](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/scripts/model-data.ts#L53) admits nonempty arrays containing only `text` or `image`, including reordered or repeated entries. The native reader already enforces that shape. The new property adds no admission rule or default.

Pinned [`transformMessages`](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/transform-messages.ts#L35) uses the selected chat model's `input.includes("image")` to choose forwarding or placeholders. The [Completions provider](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-completions.ts#L1250) separately constructs request content. An `image` output declaration on an image-generation model does not choose either chat branch.

The bounded provider contribution `71fa34e3a390a552ca2b9d3d87a9c8460aa26380`, independently accepted separately, supplies `CompletionsTranscriptProjectionOptions.ModelSupportsImages`, a nonpositional init property defaulting false. That contribution is absent from this catalog branch's frozen base `c7ff736efa6d0a51e00877e30dab881e4446af55`. No provider commit is composed here. The caller owner must compose the accepted provider contribution before using that property.

## Required binding sequence

The frontend must admit one explicitly supplied provider shard, resolve `CatalogModelType.Chat` and the selected ordinal id, and verify the selected entry's `Provider`, `Id` and `DeclaredApi` against the expected `ModelDescriptor`. Completions additionally requires an explicitly configured `openai-completions` transport. A missing model or a provider/type/API mismatch must fail configuration before request acquisition; it must not acquire another same-id model or assume a capability.

After those checks, the per-model factory receives an immutable options snapshot containing `ModelSupportsImages = selectedCatalogModel.DeclaresImageInput`. Existing projection limits and compatibility options must be preserved. The factory's existing `Create` check requires the request descriptor to equal its bound descriptor. A model change therefore selects its own complete model/transport/options binding. It cannot reuse another model's capability flag.

Caller-supplied endpoint, authentication and transport registration remain separate explicit configuration. A catalog API name or base URL alone supplies none of those services. RPC model descriptions must agree with the same admitted model used to build its executable binding. RPC wire metadata must not become an alternate mutable capability source.
