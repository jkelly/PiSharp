# Bounded Completions response input

Public source invocations acquire a bounded prefetched input after successful HTTP status validation and before the awaited response hook. The response owner is transferred to the invocation before input acquisition or inspection, so a rejecting hook retains every admitted physical operation. Canonical invocations retain their existing preparation method, zero early acquisition, demand-driven physical reads and delivery acknowledgements. The reader factory receives a borrowed readable input: the prefetched input in source mode, or the physical stream in canonical mode. It must retain the response owner's physical disposal authority.

`CompletionsResponseInput` admits one actual physical packet on construction and one refill when that packet has been fully consumed. Partial consumption retains the remainder without another pull. Its admitted read size is 1..65,536 bytes, and queued bytes never exceed that read size. A refill waits for the source startup handoff before resuming, preserving the awaiting caller's initial live message. Byte packets are immutable; actual offset/bytes/physical-EOF publications run outside queue locks and are not retained internally. `BytesEnqueued`, `BufferedBytes`, and `PeakBufferedBytes` describe the actual queue. These are separate from decoder-consumed bytes and physical read counts.

One active consumer read is admitted. Repeated closed reads do not perform new physical reads. Cancellation closes enqueue admission, joins even a noncooperative physical pull, observes retained failures, drops queued bytes, releases the physical read lease once and disposes its cancellation resources. Late canceled bytes become neither enqueues nor provider events. The physical body remains borrowed. Async disposal joins the same cancellation task; synchronous disposal requires completed cancellation. A publication callback cannot join its own pull cancellation.

Normal source closure joins pending input cancellation before releasing the outer reader. Interrupted source closure retains that join separately, so the semantic abort result can settle while physical work remains owned. Canonical completion and response/body disposal still join all physical work. A queue's logical closed read can precede the outer cancellation-token callback; the transport also checks actual physical EOF before skipping reader cancellation. Logical closure grants no physical-EOF or cleanup authority.

Existing complete lifecycle assertions are retained. The source invocation additionally records exact enqueue/EOF rows from the production callback and compares them, in order, with the unchanged pinned source ledger. This separate comparison does not waive or remove the original reader/enqueue diagnostics. The early `OnResponse` failure now retains its real bounded enqueue without creating an SDK reader. A rejecting or canceled hook can settle source semantics while noncooperative prefetch or physical disposal remains pending. Canceled acquisition retains its response until the actual acquisition settles; rejected HTTP status opens no error body. Source reader-factory faults after preparation own and join their prefetched input.

The selected original scope is P2-04's bounded raw input and resource-cleanup work, related to P2-03/P2-08/P2-09/P2-10. Original 79 packages and eight OPEN phase gates remain unchanged. This unit is not full WHATWG reader ABI parity: actual acquire/cancel/release DTO shapes, callback/error representation, host headers, source/canonical authority distinctions and broader provider qualification remain mandatory. The integration lead explicitly released the additive internal `HttpSseTransport` preparation/inspection seam at immutable base `f95722a3c008e072ba7da24a757d3d9ec913d485`. Public shared contracts remain unchanged.
