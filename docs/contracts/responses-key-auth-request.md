# Explicit-key Responses request construction

## Bounded explicit cache policy (R551, authored and unexecuted)

`ResponsesKeyAuthRequestOptions.CacheRetention` accepts `none`, `short`, or `long`. Omission resolves to `long` only when the caller's immutable `ProviderEnvironmentSnapshot` supplies `PI_CACHE_RETENTION=long`; otherwise it resolves to `short`. Explicit retention wins over captured environment data. The factory performs no ambient environment lookup. This follows pinned [resolveCacheRetention/getPromptCacheRetention/getPromptCacheOptions/buildParams](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-responses.ts).

`none` omits the session cache key, including session validation/clamping because that value is unused. `SupportsLongCacheRetention` defaults to true and `SupportsExplicitPromptCacheMode` defaults to false. Long retention emits `prompt_cache_retention:"24h"` when long retention is supported and explicit mode is disabled. Explicit mode replaces that field with `prompt_cache_options:{ttl:"30m"}` for supported long retention, or `{mode:"explicit"}` for none. Short retention and unsupported long retention omit both duration fields. None omits the key regardless of either compatibility flag. Added fields participate in the existing aggregate payload byte limit.

The existing `NativeProviderFactory.CreateResponses` forwards request options into this factory. Its per-request thinking selection clones those same options, so the cache policy survives both the direct and thinking-specific transport paths. Six authored Transport families cover the 12 retention/compatibility combinations, absent session keys, captured scope/process fallback and explicit precedence, unused invalid session IDs, exact byte boundaries, actual provider/ChatClient fake-handler requests, request reuse, pre-cancel and borrowed handler ownership. They have not been compiled or executed.

This is an explicit key-auth profile implementation, not full original provider acceptance. Automatic extraction of cache compatibility flags from model JSON, host/CLI cache preference forwarding, and ChatGPT sign-in omission of unsupported cache fields remain open. The caller supplies the compatibility flags corresponding to its chosen model profile. No source/SDK captures, live requests, credentials, package/release acceptance or inherited runtime pass claims accompany R551.

`ResponsesKeyAuthRequestFactory` constructs one fresh `HttpRequestMessage` and owned `ByteArrayContent` per `Create(ChatRequest, explicitApiKey, CancellationToken)` call. It accepts a caller-supplied final absolute HTTP(S) endpoint, exact expected `ModelDescriptor`, immutable transcript projection options, and bounded request options. It never appends a path. Requests must match all three configured model identity fields; the configured API must be `openai-responses`.

This is a standalone explicit-key target profile. Construction rejects non-null `PayloadOverrides`, unsupported max-output capability, invalid identities/endpoints, or invalid limits. The accepted projector handles historical text/function calls, matched results, signatures, namespaces, and supported reasoning history according to its existing contract. The factory supports optional session prompt-cache identity, temperature and active standard function-tool declarations. Custom/grammar/image tools, tool choice, additional-tools/tool-search anchoring, service tier, arbitrary sampling parameters, model headers, and request/response hooks remain unfinished provider work. An attempted payload override or unsupported tool form fails explicitly before request allocation. These remaining gaps do not remove requirements from the full provider plan.

The payload contains `model`, `input`, `stream:true`, and `store:false`, with optional `prompt_cache_key`, `max_output_tokens`, `temperature` and `tools`. Within the native `int?` token profile, null/zero omit `max_output_tokens`; every nonzero value uses the pinned truthiness/floor behavior `max(requested,16)`, including negative values and `int.MinValue`. The positive emitted value must not exceed the configured cap, which must allow at least 16. Explicitly supplying any max-output value without declaring its capability remains unsupported native admission; the source would ignore values for an unsupported capability. No `streamSimple` context-window estimate or thinking-token adjustment is implemented.

`ResponsesToolDeclarationProjector.Project(ChatRequest, CancellationToken)` replays every owned system message in canonical order. A delta removes `toolsRemoved` names before applying `toolsAdded` definitions. Unknown removals are no-ops. Replacing a name retains its insertion position; removal and later re-addition places it at the end, including removal/addition in one delta. Every added declaration is validated, including definitions subsequently replaced or removed. The resulting array contains the complete current standard tool set; the factory omits `tools` when that array is empty. This follows pinned [getCurrentTools/getDeclaredTools/resolveTranscriptTools](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/utils/transcript.ts#L59-L240) and [convertResponsesTools/buildParams](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/openai-responses-shared.ts#L361-L406) with addition anchoring disabled. Canonical history is never filtered or rewritten. The input-array projector now validates and accepts these deltas by default while retaining its existing system-text folding and function-call/result pairing.

Standard declarations require a nonempty string `name`, string `description`, and owned object-shaped JSON `parameters`. The payload contains `type:"function"`, name, description and parameters. `ResponsesTranscriptProjectionOptions.ToolDeclarations` supplies immutable `ResponsesToolDeclarationProjectionOptions`: strict capability defaults to true, and default strictness is false. With capability disabled, the `strict` field is omitted; an explicit null strict default remains a JSON null when supported. The source's `constrainedSampling:{type:"json_schema",strict:"prefer"|"require"}` selects strict conversion when available. Prefer falls back to the configured default when the schema cannot be converted; Require fails explicitly when capability/conversion is unavailable. Strict conversion clones schemas, marks object properties required, adds nullable alternatives for formerly optional properties, and sets `additionalProperties:false`, including nested item/object schemas. Unsupported strict schema keywords, tuple/boolean schemas, malformed required lists, and object/array unions follow the pinned [constrained-sampling converter](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/ai/src/api/constrained-sampling.ts#L1-L129). This supplies provider schema declarations; host argument-schema validation and effect authorization remain separate Agent responsibilities.

Grammar constrained sampling, custom and other non-function declaration kinds are explicit `UnsupportedContent` failures while their provider support remains unfinished. They are never dropped or silently reinterpreted as ordinary functions. Declaration shape failures use the same fixed diagnostic, with no name, description, schema or grammar fragment. Owned `JsonData` rejects decoded duplicate keys throughout every object; declaration traversal also checks decoded names before any `JsonNode` conversion. All declaration strings and property names must have paired UTF-16 surrogates. Opaque schema fields, arrays and explicit nulls survive non-strict projection. Numeric schema constraints retain exact owned tokens, including fractional values, exponent notation, wide integers and trailing scale, during both ordinary projection and supported strict conversion. The assistant function-argument stringifier's safe-integer profile applies only to actual call arguments. Source `getJsonSchemaToolParameters` passes non-strict schemas through and clones schemas for strict conversion; native raw schema number preservation is supported. General JavaScript binary64 serialization/rounding equivalence for arbitrary schema numbers remains unfinished differential qualification, with no permanent exclusion of numeric schemas.

An optional `SessionId` becomes `prompt_cache_key`; null is omitted and an empty string remains present. After bounding the complete admitted UTF-16 string and rejecting unpaired surrogates, the factory retains the first 64 Unicode code points, matching pinned `Array.from(key).slice(0,64).join("")` for supported well-formed strings. Raw input admission applies before truncation, so invalid/oversized tails cannot bypass it. This supplies no session headers or cache-retention/mode inference.

Optional `Temperature` is a finite `double` with a configurable positive finite magnitude cap (default 2). Null is omitted; both zero signs serialize as the exact token `0`. Nonfinite values fail configuration admission and values outside the magnitude cap fail resource admission. The magnitude cap is deliberate native hardening, not a provider acceptance/range claim. Other admitted values use .NET JSON numeric formatting. General JavaScript/.NET binary64 number-lexeme/rounding parity, especially exponent formatting, remains unqualified; the genuine corpus compares captured temperature zero strictly without numeric normalization. Opaque argument/signature tokens are unchanged.

The key is supplied explicitly for each `Create` call, is not stored on the factory, and must be nonempty bounded printable ASCII without whitespace or control characters. There is no guessed `sk-` prefix requirement. The returned request necessarily retains an `Authorization: Bearer <key>` header. This API promises no secure erasure. It does not inspect the environment, persistent credentials, OAuth, header-only authentication, provider auth precedence, or the wrapper's ChatGPT sign-in heuristic. Callers explicitly select key mode; no automatic authentication-mode inference occurs. Content uses the authored native header `application/json; charset=utf-8`; SDK-generated headers and header precedence are unqualified.

The factory returns ownership of both request and content to its caller. It disposes partially allocated request/content if construction fails or observes cancellation after allocation. Direct callers must dispose returned requests. In the accepted `ResponsesHttpSseTransport`, a delegate such as `chat => factory.Create(chat, ephemeralKey)` transfers the returned request to that transport. Its existing scope awaits body cleanup and disposes response/content before disposing the request. The factory neither acquires nor disposes an `HttpClient`. The delegate seam does not receive a cancellation token; the surrounding transport checks cancellation before and after calling it. Direct `Create` callers can supply a token, which is checked before admission, through key/projection/depth checks, and around allocation. No interruptible mid-instruction or secret-erasure guarantee is implied.

Request limits bound key characters, endpoint characters, model/provider characters, complete raw session characters (default 4096), finite temperature magnitude, complete UTF-8 payload bytes, complete payload container depth, and emitted output-token values. Projection keeps its separately configured transcript and projected-output bounds. Declaration defaults allow 1,024 total additions/removals, 128 simultaneously active tools, 1,048,576 output UTF-16 characters and UTF-8 bytes, and 32 container levels. If declaration options are omitted, their message/input-character/depth admission inherits the configured transcript limits; explicit options have independent bounds for those values. Counts include removed/replaced definitions, and invalid/oversized discarded definitions cannot evade admission. Strict conversion's added schema containers count toward output and complete-payload depth. The added payload object counts toward depth. Byte admission includes tools and all other optional fields and runs before allocating the final UTF-8 byte array or request/content; projection and bounded temporary strings already exist at that point. These are logical admission limits, not a total heap cap. Opaque argument/signature strings and numeric tokens from the accepted projector are not rewritten by this envelope. The projector's canonical safe-integer argument profile and other unfinished capabilities still apply.

`ResponsesKeyAuthRequestException.Failure` distinguishes invalid configuration, unsupported options, mismatched request identity, invalid key, and resource limits. Its messages contain no endpoint, key, model, or payload fragments. Projection failures retain the projector's sanitized typed taxonomy. Cancellation remains `OperationCanceledException`. The existing `ChatClient` treats these factory exceptions as sanitized provider failures; no accepted core failure classification was changed.
