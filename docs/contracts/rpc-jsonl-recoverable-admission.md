# Recoverable JSONL frame admission

`JsonlReader.ReadAdmissionsAsync(cancellationToken)` adds per-frame admission to the accepted [bounded transport](jsonl-rpc-transport.md). It uses the same LF-byte framing, optional terminal CR removal, strict owned JSON values, limits and cooperative cleanup as `ReadAllAsync`. Both methods compete for the same single enumeration claim; a second enumeration cannot consume or dispose an active first enumeration. The existing `ReadAllAsync` remains fail-fast, including its failure categories and awaited stream cleanup.

Each `JsonlFrameAdmission` contains either an owned immutable `Record` or a `Failure` and fixed `FailureMessage`, with `IsAccepted` describing that exclusive result. Rejections do not retain the untrusted frame text. `IsFinalFrame` means the source produced a nonempty remaining byte buffer at EOF rather than an LF-terminated frame. It does not mean the frame is malformed. A successful final JSON object without LF is still admitted.

The pinned [jsonl.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/rpc/jsonl.ts) calls its listener for every LF-delimited line, including blank lines. Its EOF handler calls the listener only when a remaining buffer is nonempty, then removes one terminal CR. The pinned [rpc-mode.ts](https://github.com/earendil-works/pi/blob/d86654abb8862e201933517d6f1fce9f88dd117f/packages/coding-agent/src/modes/rpc/rpc-mode.ts) catches each `JSON.parse` failure, emits a no-ID `command: "parse"` response and continues admitting other input lines. The native reader now exposes enough information to implement that response/recovery behavior; it emits no RPC responses itself.

| Native result | Admission behavior |
| --- | --- |
| `MalformedJson` on an LF frame, including blank/whitespace-only lines, comments, trailing commas and BOM | Yield one rejected admission, then resume at the next frame. |
| `PartialFinalFrame` on a nonempty malformed/incomplete EOF tail | Yield one rejected final admission, then finish and await cleanup. |
| `InvalidRecord` for a complete non-object JSON value | Yield one rejected admission; continue if another frame exists. Object-only admission is a disclosed native protocol boundary. |
| `FrameLimit`, `DepthLimit`, `InvalidUtf8`, `InvalidUnicode`, `DuplicateProperty` | Throw the existing fixed transport failure and await cleanup; no later frame is admitted. |
| Stream read/cleanup failure or cancellation | Propagate the existing exception after cooperative cleanup; no failure admission disguises an I/O or cancellation failure. |

Empty input and EOF immediately after an LF produce no extra admission. A final CR-only or whitespace-only tail produces one rejected final admission because the original remaining buffer was nonempty, even if CR removal leaves no JSON text. Literal U+2028/U+2029 and bare CR remain payload bytes, never separators. Repeated terminal CR is subject to the same one-CR framing removal and strict JSON parsing; any remaining CR outside a string can be ordinary JSON whitespace.

Terminal hardening intentionally differs from upstream JavaScript behavior: Node's decoder can replace invalid UTF-8, and JavaScript JSON parsing can accept escaped unpaired surrogates or use the last duplicate property. Native admission retains the already disclosed strict ownership policy instead of silently normalizing these values. Resource-limit violations terminate rather than scanning or allocating beyond a bound. Depth checking remains the existing lexical guard, so an excessive nesting prefix is fatal even when the complete frame would also be malformed. Rejected syntax frames are bounded before decoding and parsing, and contain no stored payload in their result. There is no background read, recovery queue, unbounded resynchronization scan, numeric conversion or cumulative transcript buffer.

Returned admitted records preserve raw numeric and string tokens, opaque nested values, property and array order, signatures, and absent/null distinctions. A caller may retain them after stream cleanup. Advancing either iterator drives input work; pausing on a rejected result behaves like pausing on an accepted record. Disposal cancels active reads and awaits their asynchronous finally work before borrowed-stream settlement or owned-stream cleanup; repeated disposal shares the same task. The core releases its active-work lease before joining cleanup, retaining the accepted self-deadlock avoidance.

`RecoverableJsonlReaderTests.Cases()` exposes four source-linked authored groups for root registration: malformed/blank recovery over every split and bytewise Unicode input with raw ownership; exact final-EOF behavior and preserved fail-fast/cross-API single-enumeration admission; terminal hardening/resource controls after a recoverable prefix; and pull behavior, cancellation, borrowed/owned concurrent disposal with gated read-finally and stream cleanup. No new upstream capture, native execution result, dispatch completion or P5A acceptance is claimed by this prerequisite alone.
