# Native current-branch and original lifecycle counterpart

Base dbcd3f58a0803772e89e0ead7c5922817c52d34f. This isolated leaf changes only Node native compatibility wiring and adds its read-only metadata helper and two authored registry controls. Renderer/component/native-open owners, Node worker/loader sources, core session and terminal sources are untouched.

Load receipt `sessionHandlers` is an optional array of `{callbackId,sourcePath,topic}`. Every selected unchanged todo factory requires exactly one `session_start` and one `session_tree`, with original todo source path and callback identities unique across all registration kinds. Legacy and other currently pinned sources require no lifecycle handlers. Absent array remains valid for legacy; absent todo handlers refuse admission. There is no arbitrary event or package admission.

Each handler is an actual native `IExtensionRegistry.Observe` descriptor. Registry admission, callback frame, active callbacks, context acquisition and removal own its original lifetime. It sends `command-input.session-event` with `callbackId`, exact raw `eventJson`, existing owner/operation identities, UI capabilities and actual captured session snapshot. It directly joins the worker callback/settlement original, preserves full faulted Task.Exception/direct references in NodeSessionLifecycleOriginalException, requires publication joined and undefined result, and retires its borrowed context in finally. It invents no observation or mutation.

Every context-bearing request adds `sessionSnapshotPresence`: `unavailable` when the host has no read interface, `none` when its actual read interface supplies null, or `json`. Only json adds `sessionSnapshotJson`, a JSON string containing `{sessionId,generation,selectedLeafId,branchEntries,persistence}`. Entries are the complete raw selected ancestry JSON objects, with unknown properties retained and no graph reinterpretation. Selected leaf may be null. These are host attachment identities, not Node owner/launch identities. Token fences run before and after read serialization; per-snapshot 131072 UTF8 bytes/characters and existing total request262144 bound refuse excess without truncation.

Task7 must consume this ABI through its actual original Runner and a caller-admitted read-only SessionManager facade. Genuine `getBranch`, `getLeafId`, `getSessionId` can use the actual supplied values. Full-tree, header, session file, cwd, appendEntry and other mutation/file APIs are not supplied or inferred here. Pure unchanged todo reconstruction needs getBranch only. Native current-branch transport is supplied for command/tool/input contexts too, so reconstruction and subsequent pure todo invocation share the actual admitted view.

Actual CLI `session_start` emitters already exist in NativeExtensionActivation and NativeReplacementSessionStartBinding. There is no current `session_tree` producer in CLI/core source. Registering its descriptor does not create this host effect: an owner must wire actual committed selected-leaf movement to registry observation dispatch after the branch changes. This remains a concrete missing host seam, outside this leaf's allocated files. No default SessionManager or synthetic actual host event closes it.

Two unexecuted controls use actual ExtensionRegistry callback admission and a caller-supplied snapshot provider: raw branch/selected-leaf preservation, changed/empty branch and null read distinction; held actual observation callback with external scope retirement joining it and own callback close refused before mutation. They do not launch Node or assert whole plugin parity. A task7 worker counterpart and independent source review are mandatory before integration/runtime claims. No native/compiler/Node/network/credential execution occurred.
