# Pi v1.1.0 sync

Status: approved by the project owner on 2026-10-08. This supersedes the deferral gate in [post-port-pi-v1-upgrade.md](../plans/post-port-pi-v1-upgrade.md).

## Target

PiSharp retargets from Pi `v0.99.1` (`d86654abb8862e201933517d6f1fce9f88dd117f`) to Pi **`v1.1.0`**: commit `abe508e1b89912adde45528136c3221eb69acdd7`, tree `77d78fae728879c16550b1f874785aed7851233c`, released 2026-10-07. The range covers v0.99.2, v1.0.0 to v1.0.4 and v1.1.0: 227 commits and 968 changed files.

The source comparison found the RPC protocol and docs, the session JSONL format, compaction, `messages.ts` and the `edit`/`write`/`grep`/`find`/`ls` tools unchanged. Do not invent migrations for them; re-verify their hashes when re-freezing.

## Timing

The sync starts now and is not deferred until the v0.99.1 port is accepted. Every gap and open gate recorded against v0.99.1 carries forward to the new baseline unchanged. None is closed or dropped by retargeting.

## Evidence

The re-freeze is **source-level**:
- The new `compatibility/target.lock.json` pins v1.1.0 under the existing hash policy. `compatibility/baseline.lock.json` stays byte-for-byte the v0.99.1 evidence lock, because frozen fixtures, inventories and the license evidence matrix hash it.
- Target pins move to v1.1.0.
- `fixtures/pi-v0.99.1/` and every pin that records where that evidence came from stay unchanged as historical evidence.
- Oracle fixtures are not recaptured for v1.1.0.
- Each ported change is covered by authored tests. Authored expectations are never labelled as captures.

## Releases

PiSharp **1.1.0** is released when the sync changes and the re-freeze are complete. Codemode, `tool_search`, classifiers and image generation already existed upstream at v0.99.1, so they are gaps in the port, not sync changes. They ship as **1.1.0.x** releases on the unchanged 1.1.0 baseline, following the fourth-segment rule for C#-only work.

## Excluded scope

The following stay outside the port, under [architecture.md](../architecture.md) "Scope for native version 1":
- `pi-durable` and its harness, tools and storage adapters;
- the new `pi-env` remote execution daemon;
- the experimental `durable`, `vacation`, client/server and session-catalog modes in `coding-agent/src/experimental`;
- the Nix flake and packaging;
- npm/managed-installer distribution policy.

The removed `pi-agent-core` harness and `session-backends/sqlite-node` were already outside scope. Each exclusion is recorded in [sync-1.1.0-applicability.json](../../compatibility/sync-1.1.0-applicability.json).
