# Explicit ECMAScript JSON boundary

The retained native JSON domain and JavaScript's parsed JSON domain differ. Native owned values preserve original number tokens, including integers beyond binary64's exact range, negative zero and overflow-sized literals. A JavaScript reader converts number literals to Number values and may later serialize different text or null. The reported native-export comparison's 227 numeric differences remain evidence until a deliberately integrated and tested adapter closes that boundary. This change does not alter any codec, session, export, provider, tool-result or durable-log default.

`PiSharp.Contracts.Compatibility.EcmaScriptJsonProjection.Project(JsonData|string, options?, cancellationToken)` returns a new compact **string** corresponding to default `JSON.stringify(JSON.parse(text))` for admitted JSON text. It retains the original owned value and syntax unchanged. The API accepts no reviver, replacer, indentation, executable objects or host callbacks. Its string return can represent ECMAScript's escaped lone UTF-16 surrogates without forcing framework JSON string access to decode them.

For finite numbers, ECMAScript selects a shortest decimal that rounds back to the same Number and uses fixed notation within its specified exponent window. The more accurate selection guideline chooses the nearest decimal, breaking a tie with an even significand. Zero serializes without its sign. [ECMA-262 Number::toString](https://tc39.es/ecma262/2025/multipage/ecmascript-data-types-and-values.html#sec-numeric-types-number-tostring)

The new arithmetic implementation does not use `double.Parse`, `ToString("R")`, `G17` or a framework floating-point formatter. It builds an exact decimal rational using bounded `BigInteger` values, compares it against finite binary64 bit patterns to find adjacent values, and selects the nearest using exact midpoint arithmetic and even-bit ties. The overflow midpoint is computed with a hypothetical 2^1024 successor. Underflow uses the exact midpoint between zero and the least subnormal. This also retains the parsed zero sign internally until serialization.

The formatter expresses each finite value and its neighbors in integral units of 2^-1074. Their exact midpoints define the decimal rounding interval; the interval includes midpoint endpoints precisely when the significand is even. For increasing significand lengths from one through seventeen, it finds admissible decimal integers in that interval. It considers neighboring decimal orders as well as the value's own order, because the interval may cross a power of ten. It selects the candidate closest to the exact value, with an even decimal tie, then applies the decimal layout rules. Seventeen digits suffice for binary64 round-trip selection; failure to find a candidate is an implementation defect and throws rather than adopting a different formatter.

The pure parser retains string code units, explicit null, arrays and ordinary own-property values. Output quotes control characters, quotation marks, backslashes and lone surrogates; other characters, including NUL after escaping, paired supplementary characters, U+2028/U+2029 and HTML punctuation, follow the JSON string operation. Nonfinite parsed numbers become null. There is no undefined/function/Symbol/BigInt value in parsed JSON. [ECMA-262 JSON operations](https://tc39.es/ecma262/2025/multipage/structured-data.html#sec-json.stringify)

Object properties with canonical decimal array-index names from 0 through 4294967294 serialize first in ascending numeric order. Other string keys retain creation order. The raw-text overload implements JSON.parse's last-value duplicate handling while retaining the first creation position; decoded duplicate names count against resource budgets even when overwritten. `JsonData` already rejects duplicates during native admission, which is unchanged. `__proto__`, `constructor` and `toJSON` are inert JSON data properties in this parser. Arrays preserve element order. [ECMA-262 ordinary own-property order](https://tc39.es/ecma262/2025/multipage/ordinary-and-exotic-objects-behaviours.html#sec-ordinaryownpropertykeys)

Input/output characters and UTF-8 bytes, depth, visited value nodes, object-property occurrences, number count, individual/cumulative number characters and decoded string characters have explicit limits. Input byte accounting uses the framework UTF-8 replacement count for a caller's raw lone UTF-16 code unit; projection still preserves and escapes that code unit. Output byte accounting is exact for the well-formed serialized text. Character limits are UTF-16 code-unit limits. Numeric-token capacity has a hard ceiling of 16384 characters to bound exact arithmetic allocations; this is a resource limit, not a claim that other numeric semantics are permanently unsupported. Bounds are checked before building each retained string/node or appending output. Cancellation is checked during parsing, numeric search and output; framework integer operations are individually bounded and do not abandon owned asynchronous work.

`EcmaScriptJsonProjectionTests.Cases(repo)` supplies five groups. Native controls cover authored numeric midpoint/threshold/precision cases, recursive structures, complete key ordering and quoting, retained unknown/numeric/NUL ownership, strict grammar rejection, inclusive resource bounds and canceled admission. The independently authored Node v24.19.0 built-in corpus contains 17984 cases, including 17920 observed scalar-number sidecars. All serialized strings are compared ordinally without reparsing away spelling or property order. Finite output numbers additionally compare their represented binary64 values with genuine DataView receipts; signed-zero collapse and nonfinite-to-null conversion are checked explicitly. Its qualification is limited to the recorded Node runtime and JSON built-ins; it is not whole-Pi qualification, and it does not retroactively erase the 227 recorded differences.
