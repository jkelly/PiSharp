## Failure reporting correction

R41 addresses Astra finding `KEYBINDINGS-FAILURE-REPORT-1`. The consumer reserves `<report>.journal.jsonl` using CreateNew before admission, appends each stage, case start, partial observation and completed row, and flushes the writer and disk for each entry. It then creates the fresh final report exactly once, including when admission, a matcher, editing or fixture handling throws. It retains completed passing and failing rows, the active case's observations and original scenario, exact exception type/message/HResult/stack/detail, and all remaining unexecuted IDs. Exceptions print to stderr and return nonzero. Malformed result rows are retained without reparsing their missing `passed` field during failure serialization.

Schema version 2 has `completedObservations`, `incompleteCases`, `unexecutedCases`, `exception`, `ioFailures`, `requestedInputs`, observed unverified input/host/DLL identities and separately admitted identities. Requested or observed identities never imply successful admission. The production entrypoint requires admission and completion of its 108 planned work units; the ten nested reporting controls remain part of one work unit. All three fixtures remain unchanged. Failure controls derive remaining-unit counts from the complete plan rather than discarding new units. Async route exceptions persist an incomplete observation before awaiting original task cleanup; no watchdog detaches or kills an owned task. Environment setup/restoration exceptions remain nonpassing and preserve the primary failure together with any cleanup failure.

The reporting controls retain ten separate results under a fresh `<report>.failure-controls` directory: a real admission pin exception, a prior assertion failure followed by an exception, a real registry matcher exception, a real editor dispatch exception, a malformed result, missing-admission rejection, successful durable recording, existing report/journal preservation, and a final-path collision. Only these nested reporter controls explicitly waive admission to test the reporter in isolation; their synthetic reports cannot qualify native product behavior. The admission-pin control and production entrypoint continue to require admission. The controls themselves publish each completed result into the parent journal, so a later control exception also preserves earlier diagnostics. All controls are currently uncompiled and unexecuted.

Existing reports or journals are never overwritten. A collision or unusable output path returns nonzero and preserves stderr; a final-path collision retains the append-only journal. An unavailable destination cannot receive a structured report. A crash can leave the valid journal prefix and no final JSON; retain that prefix and wrapper stderr/exit status as incomplete evidence.
